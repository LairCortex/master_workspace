# ui-theme Specification

## Purpose

Единый набор semantic-токенов оформления приложения: dark/light для chrome мастера (лаунчер и главное окно) и генерация стилей без копий цветов в трёх местах.

## Requirements

### Requirement: Файл semantic-токенов

Поставка приложения SHALL содержать один файл semantic-токенов. Каждый токен SHALL задавать значения для светлой и тёмной темы. Файл SHALL не храниться в базе игры. Цвет, отступ, радиус и кегль, нужные chrome W1, SHALL быть токенами. Сгенерированные QSS и CSS SHALL не быть вторым исходником в репозитории.

#### Scenario: Смена значения токена

- **WHEN** в файле токенов меняют hex роли фона chrome и пересобирают/перезапускают приложение
- **THEN** лаунчер, chrome главного окна и CSS chrome страницы стола отражают новое значение без отдельной правки трёх копий цвета

#### Scenario: Не база игры

- **WHEN** открывают другую игру
- **THEN** набор токенов тот же (тема не переезжает в `game.db`)

### Requirement: Предпочтение dark/light

Система SHALL хранить выбранную тему глобально для пользователя приложения, не в базе игры. Пока файл предпочтения отсутствует или нечитаем, тема SHALL быть тёмной. После явного переключения выбор SHALL переживать перезапуск. Светлая и тёмная темы SHALL быть доступны переключателем в диалоге выбора игры и в меню главного окна.

#### Scenario: Первый запуск

- **WHEN** файла предпочтения темы нет
- **THEN** chrome лаунчера и, после открытия игры, chrome главного окна используют тёмные значения токенов

#### Scenario: Сохранение выбора

- **WHEN** пользователь переключает тему на светлую и перезапускает приложение
- **THEN** снова светлая тема независимо от открываемой игры

#### Scenario: Битый preference

- **WHEN** файл предпочтения темы есть, но содержимое невалидно
- **THEN** используется тёмная тема, приложение не падает

#### Scenario: Preference повреждён на уровне байт

- **WHEN** файл предпочтения темы содержит байты, не являющиеся корректным UTF-8
- **THEN** используется тёмная тема, старт приложения не завершается исключением

### Requirement: Область применения QSS

Сгенерированный QSS SHALL применяться к chrome-контейнерам диалога выбора игры и главного окна (центральная область и строка меню; строка статуса — если она есть). QSS SHALL не назначаться на всё главное окно так, чтобы дочерние диалоги с родителем-окном наследовали скин. Диалоги кроме лаунчера SHALL не обязаны следовать токенам в этом куске. Chrome-контейнер лаунчера SHALL закрывать всё поле диалога: по краям не должно оставаться полосы палитры ОС.

#### Scenario: Карточка сущности не скинается правилами главного окна

- **WHEN** на главное окно применена тема и открывают диалог, родителем которого является главное окно
- **THEN** фон и кнопки этого диалога не обязаны совпадать с токенами chrome (наследуют палитру ОС, пока нет W2)

#### Scenario: Лаунчер скиннут

- **WHEN** лаунчер показан при валидных токенах
- **THEN** его chrome-контейнер использует сгенерированный QSS текущей темы

#### Scenario: Лаунчер без полосы палитры ОС

- **WHEN** лаунчер показан при валидных токенах и снят пиксель у самого края диалога
- **THEN** пиксель равен фону chrome текущей темы, а не цвету палитры ОС

### Requirement: Битые токены

Если файл токенов отсутствует, не читается как UTF-8 или не разбирается, приложение SHALL стартовать. Ошибка SHALL попасть в лог. Переключатель темы SHALL не менять оформление, пока токены невалидны. Chrome SHALL остаться на палитре ОС. Ни один переключатель SHALL при этом показывать состояние, не соответствующее реальному оформлению.

#### Scenario: Нет файла токенов

- **WHEN** файл токенов недоступен при старте
- **THEN** окна открываются, переключение темы не подставляет QSS из токенов

#### Scenario: Файл токенов не является UTF-8

- **WHEN** файл токенов повреждён на уровне байт
- **THEN** набор считается невалидным целиком: запись в логе, окна открыты, chrome на палитре ОС

### Requirement: Переключение без перезапуска chrome

Пока токены валидны, переключение dark/light SHALL сразу обновить QSS chrome лаунчера (если он открыт) и chrome главного окна (если оно открыто). Состояние и подписи всех доступных переключателей темы SHALL соответствовать текущей теме независимо от того, каким из них тема была изменена.

#### Scenario: Смена в главном окне

- **WHEN** главное окно открыто и пользователь переключает тему
- **THEN** QSS chrome главного окна соответствует новым значениям токенов без перезапуска процесса

#### Scenario: Смена из лаунчера поверх открытого окна

- **WHEN** главное окно открыто, поверх него показан лаунчер и тема переключена в лаунчере
- **THEN** пункт меню «Светлая тема» в главном окне отражает новую тему без дополнительного клика
