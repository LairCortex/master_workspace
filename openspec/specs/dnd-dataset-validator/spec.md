# dnd-dataset-validator Specification

## Purpose

Проверяемость D&D-датасетов Long Story Short средствами приложения: валидация загружаемого и импортируемого файла по публичным JSON-схемам и списку межполевых проверок LSS с разделением на ошибки и предупреждения.

## Requirements

### Requirement: Валидатор — чистая проверка без сети

Валидатор датасета SHALL быть проверяющей функцией без сетевого доступа: на вход — содержимое файла, на выход — структурированный отчёт (список ошибок, список предупреждений), каждый пункт с русским сообщением и путём к месту в документе (секция, идентификатор сущности, тип гранта). Одна и та же проверка на одном файле SHALL давать один и тот же результат.

#### Scenario: Детерминированность

- **WHEN** один файл проверен дважды
- **THEN** отчёты идентичны
### Requirement: Проверка формы по встроенным схемам

Валидация формы SHALL выполняться по JSON-схемам Long Story Short (схема датасета, по-сущностные схемы, схема гранта), вложенным в пакет приложения и привязанным к версии формата; при неизвестной версии схемы отчёт SHALL содержать ошибку о неподдерживаемой версии, а не молчаливый пропуск.

#### Scenario: Опечатка в поле

- **WHEN** в файле поле с неизвестным именем или неверного типа
- **THEN** отчёт содержит ошибку схемной проверки с путём к месту

#### Scenario: Неизвестная редакция схем

- **WHEN** файл датасета заявляет версию формата, под которую нет встроенной схемы
- **THEN** проверка формы возвращает ошибку о неподдерживаемой версии
### Requirement: Межполевые проверки по списку LSS

Поверх схем валидатор SHALL выполнять полный список межполевых проверок, зафиксированный в документации форматов LSS, с теми же категориями error/warning, в том числе: `bonus` несёт ровно одно из значения или формулы, и формула вычисляется; ключи навыков, характеристик, брони и оружия и все таргеты бонусов — из известных закрытых перечней схем; каждый грант выбора предлагает хотя бы один слот; идентификаторы уникальны внутри коллекции; межсущностные ссылки (`classId`, `raceId`, `featId`, `pairId` счётчиков) ведут в существующие сущности — по всем подключённым наборам хранилища, а не только по проверяемому файлу; именованный `pick-one` лежит там, где раскрывается, рекурсия обходит вложенные гранты; счётчик (`resource`) несёт ровно одно из предельного значения или формулы; лицензия — из белого списка; для заклинаний: грант выбора предлагает хотя бы одно заклинание заданного круга и непустой список, два выбора одного круга на одной сущности запрещены, `uses` согласован, `shortRestRegain` вычисляется и не стоит при длинном отдыхе, собственный класс-заклинатель объявляет `spellList`, таблица ячеек полная и корректной длины; текстовый `trait` не дублирует каналы. Предупреждениями: `trait` с и параметрами и прозой; нераспарсенная формула броска; счётчик без читателя; реальный тип гранта без канала-потребителя; открытый фит-слот без кандидатов; `spell-fixed` со слагом вне публичного SRD-списка (сверка по скачанным спискам слагов, при их отсутствии — молчаливый пропуск именно этой проверки); предупреждения таблицы ячеек.

#### Scenario: Дубликат идентификатора

- **WHEN** внутри одной коллекции датасета два одинаковых идентификатора
- **THEN** отчёт содержит ошибку категории error с путями к обоим

#### Scenario: Ссылка через подключённый набор

- **WHEN** хоумбрю-набор ссылается `classId` на класс другого подключённого набора
- **THEN** проверка считает ссылку валидной

#### Scenario: Два выбора заклинаний одного круга

- **WHEN** на одной сущности два гранта выбора заклинаний одного круга
- **THEN** отчёт содержит ошибку этой проверки
### Requirement: Отчёт для показа и для сборки

Отчёт валидатора SHALL быть пригоден и для показа пользователю (экран датасетов, импорт), и для машинного использования последующими фазами (генерация с перегенерацией): категория, код проверки, путь, текст. Путь записи отчёта SHALL использовать единую нотацию от корня документа — последовательность имён полей и индексов вида `поле.поле[индекс].поле`; нотация SHALL быть одинаковой во всех проверках и каналах и закрепляться тестами. Импортоёмкость файла определяется единственной категорией ошибок: предупреждения импорту не мешают.

#### Scenario: Порог импорта

- **WHEN** файл имеет предупреждения без ошибок
- **THEN** импорт разрешён и предупреждения показаны

#### Scenario: Путь ведёт к месту в одной нотации

- **WHEN** отчёт содержит ошибки разных проверок (в т.ч. внутри списков)
- **THEN** каждая запись указывает место записи вида `поле.поле[индекс].поле`, и по этому пути мастер находит виновное поле в файле
