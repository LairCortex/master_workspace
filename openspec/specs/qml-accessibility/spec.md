# qml-accessibility Specification

## Purpose

Дерево доступности QML-островов: каждый интерактивный элемент острова виден в accessibility-дереве с ролью и именем и управляется через него (одиночная активация, фокус), чтобы компьютерный обзор обходился без кликов по координатам; пределы доступности зафиксированы явно.

## Requirements

### Requirement: Дерево доступности содержит каждый интерактивный элемент

Каждый интерактивный элемент QML-острова (кнопка, переключатель, поле, кликабельная область, строка списка) SHALL быть представлен в системном дереве accessibility с ролью и именем; роль SHALL отражать природу элемента (строка списка — пункт списка, одиночный выбор — переключатель, открывающая область — кнопка, текстовый редактор — редактируемый текст). Имя элемента SHALL соответствовать правилу: у контролов ввода — целевая подпись из точки применения, у строк списков — видимое содержимое строки. Значение контролов, умеющих его отдавать (текстовое поле, числовое поле), SHALL быть доступно отдельным слотом значения дерева; неотредактируемые области SHALL не выдумывать слот значения. Обычные текстовые подписи (заголовки, ярлыки «Дата:», подсказки) SHALL не плодить узлы дерева, а узел-«заглушка» без имени SHALL не заводиться никогда.

#### Scenario: Строка списка опознаваема

- **WHEN** компьютерный обзор запрашивает дерево лаунчера с открытой игрой «Игровка» от 01.01
- **THEN** в дереве есть строка с ролью пункта списка и именем «Игровка (01.01)», и её можно указать как цель действия без координат экрана

#### Scenario: Имя поля — назначение, значение — отдельно

- **WHEN** в карточке сущности в поле «Название» набрано «Багир»
- **THEN** в дереве элемент поля имеет имя «Название», а «Багир» доступен отдельным слотом значения

#### Scenario: Дерево без безымянного мусора

- **WHEN** дерево снято с острова, заполненного подписями «Дата:», «Музыка:», «Предыстория:»
- **THEN** отдельных безымянных узлов или узлов-подписей в дереве нет, имена ярлыков живут только внутри имён полей

### Requirement: Одиночная активация выполняет элементное действие

Для элементов, штатное действие которых (переход к карточке, чар-листу, игре, переключение выбора) доступно пользователю мышью, ОДИНОЧНАЯ активация через accessibility SHALL выполнять это переходное действие; поведение элемента для реальных мышиных нажатий SHALL оставаться прежним (одиночное — выбор, двойное — открытие там, где было).

#### Scenario: Игра открывается активацией строки

- **WHEN** компьютерный обзор однократно активирует строку игры в лаунчере
- **THEN** игра открывается, тогда как пользовательский одинарный клик по строке по-прежнему только выделяет её, двойной — открывает

#### Scenario: Карточка события и сущности открываются активацией

- **WHEN** одиночная активация послана строке события на шкале и строке карточки в панели деталей
- **THEN** открываются диалог события и карточка сущности соответственно

#### Scenario: Выбор и переход работают

- **WHEN** активация послана образцу цвета, картинке в панели деталей и чипу упоминания
- **THEN** цвет выбирается, изображение открывается, упомянутая сущность открывается

### Requirement: Текстовые поля reachable фокусом

Поля упоминаний и инлайн-редактор чар-листа SHALL представляться редактируемым текстом; одиночная активация такого поля SHALL передавать фокус текстовому слою так, чтобы последующий клавиатурный ввод попадал в поле.

#### Scenario: Ввод после активации

- **WHEN** поле «Предыстория» активировано через accessibility, затем послан клавиатурный текст
- **THEN** фокус стоит в поле, текст появляется в поле как при обычном наборе и доходит до storage-значения хоста

### Requirement: Скрытый смысл активации описан в дереве

Элементы, у которых из имени неясно, что произойдёт при активации, SHALL нести короткое accessibility-описание действия («Открывает игру», «Открывает карточку», «Открывает упомянутую сущность», «Выбор цвета типа», «Открыть изображение»); контролы с самодостаточной текстовой подписью SHALL не дублировать её описанием. Описание SHALL читаться потребителем accessibility (ридер, inspect); вывод конкретного обзора может его не отображать, и это SHALL не считаться дефектом.

#### Scenario: Описание скрытого перехода

- **WHEN** сырое дерево строки события или чипа упоминания прочитано программно
- **THEN** описание содержит формулировку открываемого действия, а для кнопки «Сохранить» описание отсутствует

### Requirement: Оффскрин-тест закрепляет содержимое дерева

Каждый аннотированный интерактивный элемент SHALL быть закреплён offscreen-тестом: роль и имя (для динамических — с данными модели); для pressable — активация через accessibility-действие вызывает ожидаемый обработчик/сигнал; для editable-text — действие фокуса отдаёт фокус. Штатные контролы SHALL не annotated вторично (их поведение не меняется).

#### Scenario: Активация вызывает обработчик в тесте

- **WHEN** тест вызывает accessibility-нажатие на строку события в острове
- **THEN** сигнал открытия события испущен ровно один раз

#### Scenario: Живой предел не прикрывается тестом

- **WHEN** что-то видно только на реальном экране (реакция обзора, описание у ридера)
- **THEN** это проверяет сценарий live-аудита, а offscreen-гейт этого не имитирует

### Requirement: Пределы координатности зафиксированы

Следующее SHALL честно оставаться вне адресации через дерево и SHALL быть перечислено в AGENTS.md как известные пределы: строки попапа упоминаний (навигация клавиатурой после фокуса поля), текст value в полях без value-слота (только скриншот), нативные попапы дат/выпадающих списков (отдельные системные окна), текст tooltip-моста (в дерево не переносится). Live-аудит accessibility SHALL сверять дерево с этим списком; молчаливое расширение списка SHALL считаться дефектом.

#### Scenario: Аудит сверяется со списком

- **WHEN** live-аудит прошёл по всем островам
- **THEN** все интерактивные элементы доступны из дерева, кроме зафиксированных четырёх пределов, текст AGENTS.md соответствует фактическому дереву
