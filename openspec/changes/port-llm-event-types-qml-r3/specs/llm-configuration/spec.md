## MODIFIED Requirements

### Requirement: Маскирование ключа в интерфейсе

Система SHALL отображать поле ввода ключа API в замаскированном password/echo-режиме библиотечного тематического поля; ключ SHALL не отображаться в открытом виде ни в одном UI-элементе. Перенос формы на QML-остров SHALL сохранять фактическое значение ключа для проверки и сохранения, не раскрывая его визуально.

#### Scenario: Ввод ключа

- **WHEN** пользователь вводит ключ API в диалоге настройки
- **THEN** вводимые символы отображаются замаскированными

#### Scenario: Переключение темы не раскрывает ключ

- **WHEN** ключ введён и тема меняется при открытом диалоге
- **THEN** поле перекрашивается без потери значения и без показа открытых символов

### Requirement: Форма подключения в диалоге настройки

Диалог «Настройка AI-ассистента» SHALL быть QML-островом в прежнем нативном диалоговом контейнере и SHALL содержать страницу подключения с полями endpoint, модель, ключ API (маскируется, необязательное) и кнопкой «Проверить соединение». Все страницы и поля диалога SHALL выводиться моделью из единственного Python-источника `FIELD_CONFIG` через повторяемый делегат; независимого списка полей в QML SHALL не быть. Страница SHALL не содержать функций скачивания, удаления или загрузки модели. Сохранение настроек SHALL быть невозможно при пустых endpoint или модели. Проверка подключения и сохранение SHALL запускаться запросами из QML, тогда как внешний сервис, HTTP-клиент, `_run` и `check_connection` SHALL оставаться на Python-фасаде с неизменным публичным API. Сохранение SHALL завершаться явным `finish_saving`; от начала сохранения до этого завершения Esc и закрытие диалога SHALL быть заблокированы.

#### Scenario: Открытие диалога

- **WHEN** пользователь открывает «Настройка LLM…»
- **THEN** открывается QML-страница подключения с подставленными значениями сохранённых настроек и кнопкой проверки

#### Scenario: Поля выводятся из единственного источника

- **WHEN** диалог строит страницы настройки
- **THEN** набор и порядок полей соответствуют `FIELD_CONFIG`, повторяются моделью, а отдельного списка тех же полей в QML нет

#### Scenario: Пустая форма

- **WHEN** поле endpoint или модели пустое
- **THEN** сохранить настройки нельзя

#### Scenario: Проверка остаётся на фасаде

- **WHEN** пользователь нажимает «Проверить соединение»
- **THEN** QML эмитит запрос, а `check_connection` выполняется Python-фасадом через существующий HTTP/service путь без передачи этих объектов в QML

#### Scenario: Esc заблокирован при сохранении

- **WHEN** пользователь запустил сохранение и `finish_saving` ещё не вызван
- **THEN** Esc и попытка закрыть диалог не закрывают его

#### Scenario: Завершение сохранения

- **WHEN** Python-фасад вызывает `finish_saving` после успешного или неуспешного результата
- **THEN** состояние сохранения снимается, после чего закрытие снова разрешено согласно прежнему результату операции
