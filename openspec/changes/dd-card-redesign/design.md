# Дизайн: dd-card-redesign

## Context

Состояние после `add-dnd-game-face`: `EntityCardRoot.qml`/`EventDialogRoot.qml` рисуют поле через `ThemeTabBar` + `StackLayout` по группам ядра (`overview`/`texts`/`relations`), модульные табы — нативные виджеты поверх слота тела (`reportBodyRect`). Расширение персонажа: таблицы `dd_character_ext` (ссылки вид/подвид/класс/подкласс/предыстория, уровень, `lss_sheet_id`, `raw_document`, `text_blocks`), `dd_character_spell_link`, `dd_encounter`. Импорт LSS уже приносит `stats`/`skills`/`spells.slots`, но укладывается текстовыми блоками (`character_render.py`). Предпросмотр читает только ядреные поля. Мотивация и объём — в proposal.md.

## Goals / Non-Goals

**Goals:**
- Ядро: одноэкранные карточки 0.19.1 для всех типов и события; полоса табов живёт только чужими табами.
- Модуль: два таба у события; четыре у персонажа; механики со структурированным хранением и формулами; связи пришиты внизу; предпросмотр — зеркало.
- Неотличимость ядра под `NRI_DISABLE_DD_MODULE=1` закреплена тестами.

**Non-Goals:**
- Не трогаем: лестницу, поиск, листы персонажа, бестиарий/датасеты/гримуары как экраны, сам протокол импорта-файла, LSS-веб-встраивание (веб-движок внутрь окна запрещён), генерацию ИИ кроме чтения новых механик, предпросмотр прочих типов.
- Не удаляем тексты ядра и старые колонки; миграция только аддитивна.

## Decisions

### Д1. Откат = одна ядреная группа, а не удаление механизма
`card_tab_groups` ядра объявляет ровно одну группу — прежний экран 0.19.1 целиком (компоненты `overview/texts/relations` страниц склеиваются обратно в одну прокрутку). QML уже прячет полосу при одной вкладке — правило сохраняется. Отказ: вырезать табы из QML ядра — тогда модулю некуда крепиться, окно собиралось бы дважды (дубли жизненного цикла листа/сохранения отвергнуты при грилле, Q2-A).

### Д2. Вкладка «Основное» персонажа: декларативный канал модульных блоков
Порядок «короткие поля → списки+уровень → таблица характеристик → возраст/музыка → двери» вставляет чужое содержимое в середину ядренной прокрутки. Решения:
- **Выбрано:** канал `module_blocks` у ВМ карточки: модуль отдаёт список дескрипторов секций `{kind: combo|number|switch|text|buttons|table, id, label, options/value/rows…}`; ядро рисует их штатными Theme-контролами QML на объявленных позициях (после коротких полей, после музыки), значения пишет обратно по `block/field` в обработчик модуля. Ядро не знает `app/dd` (протокол живёт в `presentation/modules/protocol.py`, как `CardTabSpec`).
- Отказ — нативная оверлей-завеса поверх прокрутки с прорезями под модульные блоки: ломается на прокрутке/обрезке, живёт вне скролла QML.
- Отказ — дублирование ядреных полей в нативном фрейме: два хозяина одних полей.
Виды дескрипторов ограничены перечнем (таблица характеристик = `table` со строками ячеек); рост набора — только через протокол с тестами.

### Д3. Служебные вкладки остаются нативными страницами
«Способности», «Личность», «Заклинания», «Встреча» — целиком виджеты модуля поверх слота тела (отработанный механизм `bodyRect`). Смешанность двух лиц сознательная: «Основное» — ядреные поля с прокруткой и инлайн-блоками, остальные — целостраничные виджеты без чередования с ядром.

### Д4. Связи: два пути в одном компоненте
`RelatedSection` остаётся один компонент. Одноэкранное ядро — он в конце прокрутки (0.19.1). В оконной сборке с табами — `Loader` переносит его в пришитую нижнюю полосу (свой `ScrollView`, потолок = треть высоты окна), кнопки под полосой. Разъезд поведения защищен двумя offscreen-пинами.

### Д5. Предпросмотр — обобщённый канал читаемых секций
Тот же профиль решения, что для «Основного», только read-only: ВМ предпросмотра принимает `module_sections(pair) -> [(title, [lines])]` от провайдера, wiring связывает с фасадом модуля; предпросмотр печатает секции под полями ядра. Персонаж: список списков/уровня, характеристики строками («Сила 16: проверка +3, спасбросок +5»), прыжки/вес/скорость, черты, «Личность», заклинания+ячейки; событие: секция «Встреча». Скрытые ядреные тексты персонажа — по флагу модуля. Без модуля канал пуст; пины «без модуля предпросмотр не отличается» в тесте профиля. Отказ — оверлей поверх предпросмотра: второй слой поверх прокрутки, ломает переходы по связям/упоминаниям.

### Д6. Хранение механик
`dd_character_ext` получает nullable-колонки: шесть характеристик, `speed`, `alignment`, `slots_json` (уровень 1…9 → число), `prof_json` (владения навыками; владения спасбросками — либо «по классу», либо ручной набор); новые тексты «Личности» — стабильные ключи в существующем `text_blocks` (карта «название → текст» уже ездит туда-обратно). Черты — новая таблица `dd_character_feat_link` (пара «источник + id» + снимок имени), копия формы ссылок заклинаний. Ядро не мигрирует: всё в таблицах модуля, добавляется списком `_MIGRATIONS`/перестройкой в `infrastructure/db/migrations.py` (штатный путь проекта, alembic не используется). Производные значения НЕ хранятся — чистая функция.

### Д7. Формулы — Qt-free домен модуля
`app/dd/domain/character_mechanics.py`: `modifier`, `proficiency_bonus(level)` (1–4→+2, 5–8→+3, 9–12→+4, 13–16→+5, 17–20→+6, None→+2), `check/save/skill/passive`, `jumps_and_carry(str)` (15×значение; разбег=значение; с места=половина; высота=3+мод). Слой представления и экспорт вызывают только её; покрытие — ядреный гейт 100%.

### Д8. Владение спасбросками
Класс из подключённого датасета с указанием спасбросков задаёт владение (пересчёт при смене класса); без него — шесть ручных переключателей. Хранится выбор режима-факта: ручной набор + кэш класса пересчитывается на чтение, чтобы смена датасета не ломала данные.

### Д9. Охрана нормы «ядро неизменно»
Профиль `NRI_DISABLE_DD_MODULE=1` дополняется пинами: карточки всех типов одноэкранные (полосы табов нет, связи в прокрутке), предпросмотр без секций; AST-охраны существующих слоёв не расширяются (канал данных, а не импорт — как `CardTabSpec`).

## Risks / Trade-offs

- [Канал дескрипторов разрастается в «воторой UI-движок»] → набор видов конечен и закреплен тестами-охранами; новые виды — только изменением протокола.
- [Пересборка QML карточек задевает пины пиксельных контрактов (`test_theme_grab`, размеры островов)] → откат страниц выполняется переносом прежних компонентов, прогоняется полный изолированный гейт; размеры островов (`island_size.py`) синхронизируются.
- [Перешитованные связи Loader'ом могут потерять фокус/скролл] → поведение пинится offscreen-тестами перемещения между хозяевами.
- [Импорт не всегда различит «структура vs текст»] → правило: сначала структура, не легшее — читаемые блоки как прежде; сырой документ остаётся источником правды (spec импорта не меняется).
- [Формулы LSS vs 5e расходятся в деталях (вес от значения, а не модификатора)] → зафиксировано решением владельца; расхождение с LSS-листом лечится правкой одной функции домена.
- [Смена ядра после «заморозки 0.19.1» выглядит как её нарушение] → норма трактуется как «поведение и вид ядра без модуля = 0.19.1», фиксируется тестами, а не байтами файлов.

## Migration Plan

1. Довести и закоммитить незавершённую работу текущей рабочей версии (отдельный коммит до начала).
2. Миграция модуля — аддитивные колонки/таблица; старые `text_blocks`-блоки читаются и на «Личность» (стабильные ключи), и как прежде — дублирования нет.
3. Откат изменения = выключение модуля на игре; данные расширений не трогаются.
