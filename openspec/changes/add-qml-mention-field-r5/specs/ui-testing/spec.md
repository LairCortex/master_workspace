## MODIFIED Requirements

### Requirement: Widget-тесты интерактивных views

Система SHALL иметь widget-тесты, инстанцирующие и управляющие (мышию и клавиатурой) изолированно интерактивными views приложения: таймлайн (отрисовка событий, выбор элемента, контекстное меню), диалог события (валидация, связанные сущности), детальная панель (отображение и редактирование), карточка сущности (валидация, режим редактирования, дополнительные поля), дат-виджет (специальные даты), mentions (вставка и клик — widgets-редактор и библиотечное поле упоминаний через `QQuickWidget` с хостом, без продуктового диалога-стенда), обзор мира (режим «Показать всё»), кнопка AI-ассистента (статусы) и состояние приложения.

#### Scenario: Валидация блокирует сохранение

- **WHEN** пользователь пытается сохранить сущность или событие с незаполненными обязательными полями
- **THEN** диалог не принимает данные и указывает на ошибку

#### Scenario: Взаимодействие с таймлайном

- **WHEN** пользователь кликает по отображаемому событию
- **THEN** в детальной панели загружаются данные этого события

#### Scenario: Клик по mention-ссылке

- **WHEN** пользователь кликает по mention-ссылке сущности в тексте
- **THEN** открывается соответствующая детальная карточка

#### Scenario: Статусы кнопки AI-ассистента

- **WHEN** LLM не настроен, а затем настроен
- **THEN** кнопка AI-ассистента сначала неактивна, затем активна с соответствующими текстами

#### Scenario: QML-поле упоминаний через хост

- **WHEN** тесты библиотечного поля упоминаний поднимают `QQuickWidget` с хостом
- **THEN** контролы адресуются по `objectName` (корень, plain-слой, каретка, `mentionChip_<type>_<id>`); round-trip storage, попавер ≥2 символов / Esc / Space / backspace за `@` / Enter|клик вставки проходят без инстанцирования диалога события или карточки
