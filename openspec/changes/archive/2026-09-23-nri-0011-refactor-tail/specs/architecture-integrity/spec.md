# architecture-integrity — delta для nri-0011-refactor-tail

## ADDED Requirements

### Requirement: Представление не знает конкретный класс LLM-провайдера

Код слоя представления НЕ SHALL импортировать класс конкретного провайдера LLM и НЕ SHALL самостоятельно собирать объект провайдера; единственная фабрика провайдеров SHALL создаваться в точке сборки зависимостей и передаваться туда, где провайдер нужен. Ограничение сторожится автоматическим статическим тестом общего прогона.

#### Scenario: Импорт конкретного провайдера в представление

- **WHEN** в любой модуль `app/presentation/` добавлен импорт класса конкретного провайдера LLM
- **THEN** автоматический статический тест падает с указанием файла и строки

#### Scenario: Проверка соединения без знания конкретного класса

- **WHEN** пользователь нажимает «Проверить соединение» в диалоге настройки AI-ассистента
- **THEN** проверкой руководит модель представления через внедрённую фабрику, а проверка соединения, отобразимая ошибка при отказе и успешный ответ при успехе для пользователя не меняются

### Requirement: Единственный источник статуса подключения LLM

Текстовые значения статусов подключения AI-ассистента (`не настроен`, `готов`) SHALL иметь единственный источник в прикладном слое; код приложения НЕ SHALL сравнивать или присваивать эти статусы строковыми литералами вне единственного источника. Ограничение сторожится автоматическим статическим тестом общего прогона.

#### Scenario: Дубль строки статуса

- **WHEN** в коде приложения вне единственного источника появляется строковый литерал статуса подключения LLM
- **THEN** автоматический статический тест падает с указанием файла и строки

#### Scenario: Поведение статусов для пользователя

- **WHEN** конфигурация подключения неполная или полная
- **THEN** состояние готовности определяется ровно по двум значениям единственного источника, поведение диалога настройки и доступности AI-кнопок не меняется
