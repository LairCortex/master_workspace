# Proposal: nri-0011-refactor-tail

## Why

Применение `nri-0005-architecture-refactor` закрыло почти все находки аудита 2026-09-22, но четыре хвоста остались явно перенесёнными (таблица статусов в `docs/refactoring-audit.md`): нераздробленный `ApplicationWiring.connect()` с цепочками закона Деметры (`B3`/`C6`), самостоятельная сборка конкретного LLM-провайдера и проверок соединения в представлении с задвоенной строкой статуса (`C2`), строковое задвоение контракта `aiState` в двух прокси (`C5`), и приём картинок из диалогов листов персонажа сырым `asyncio.ensure_future` вне единицы работы (`Q14-остаток`). Пока они открыты, таблица статусов врёт, а нормы «Coding principles» из `AGENTS.md` (п. 2, 3, 4) формально нарушены в живом коде.

## What Changes

- `ApplicationWiring.connect()` (~530 строк) становится тонким диспетчером: подключение областей вынесено в приватные `_connect_*` методы того же класса; вся цепочка `window.timeline_widget.*` локализована в одном приватном помощнике таймлайна. Публичный контракт `ApplicationWiring` (`connect`, `run_locked`, `open_event_editor`, акцессоры) не меняется.
- Вьюмодел LLM больше не конструирует `RemoteLlmProvider`: конфигурируемая фабрика провайдеров внедряется из собирающего файла (`app/main.py`); проверка соединения переезжает из `llm_setup_dialog` в `LlmViewModel`; статусы подключения получают единственный источник — прикладное перечисление `LlmStatus` (`not_configured`/`ready`), используемое обоими вьюмоделями вместо литералов.
- Общий `AiStateHolder` (примесь) заменяет продублированные `_ai_state` / `Property("aiState")` / `update_llm_state` в `AiFieldProxy` и `EntityGenerateProxy`; имена QML-свойств и тестовый маркер кнопок (`ai_state_is`) неизменны.
- Приём картинки и прочие отложенные задачки в `fill_dialog`/`editor_dialog`: все `asyncio.ensure_future` этих обработчиков получают управление (хранение задачи, отмена при закрытии, видимая ошибка); приём картинки (`ImageStore.store` + запись `image_id` в поле) выполняется в транзакции внедряемого `GameSessionUoW`.
- Хранители: в `tests/test_architecture_layers.py` добавлены два пина на дереве синтаксиса: запрет импортировать `RemoteLlmProvider` (и собирать конкретного провайдера) в `app/presentation/`, запрет текстовых литералов статусов LLM вне единственного источника.
- Документация: статусы находок B3/C5/C6/C2/Q14 в `docs/refactoring-audit.md` закрываются коммитом своей волны; `docs/CHANGELOG.md` — запись по итогам заявки.
- Вне рамок (зафиксированные решения проектной сессии): процесс-глобал `current_calendar()` остаётся отказом (DECISION-комментарий в коде); периодические SIGSEGV PySide6 offscreen — среда, не код.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `architecture-integrity`: добавляются два автоматически сторожимых ограничения — представление не знает конкретный класс LLM-провайдера (единственная фабрика из точки сборки) и статусы подключения LLM имеют единственный источник без текстовых литералов-дублей. Существующие требования (слои, граница БД, одна точка завершения транзакции, реестр типов) неизменны; волна 4 приводит код к уже существующему требованию «единая точка завершения транзакции» на траектории приёма картинки.

## Impact

- Код: `app/presentation/wiring.py`, `app/presentation/viewmodels/llm_viewmodel.py`, `app/presentation/viewmodels/event_dialog_island_view_model.py`, `app/presentation/views/llm_setup_dialog.py`, `app/presentation/views/character_sheet/{fill,editor}_dialog.py`, `app/main.py`, новый модуль статуса LLM в `app/application/`.
- Тесты: `tests/test_architecture_layers.py` (два новых правила), новые юнит-тесты управления задач/транзакции приёма картинки; существующие e2e (`test_e2e_wiring_gaps.py`, `test_e2e_llm.py`, листы) — без правок (контракты сохранены).
- Шлюз покрытия 100% (линейный) остаётся зелёным на каждой волне; поведения для пользователя не меняется (рефакторинг в зелёных срезах, rule 5).
