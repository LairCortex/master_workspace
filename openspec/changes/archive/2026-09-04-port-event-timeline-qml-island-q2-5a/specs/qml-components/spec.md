# qml-components Delta Specification

## MODIFIED Requirements

### Requirement: Библиотека QML-компонентов chrome

Приложение SHALL предоставлять одну библиотеку QML-компонентов chrome (кнопка, текстовое поле, чекбокс, выпадающий список, заголовок, подсказка-подпись, карточка-панель, строка списка, объявление всплывающей подсказки для tooltip-шима) как qmldir-модуль, доступный любому QML-острову через штатный импорт. Каждый новый темизуемый QML-экран SHALL собирать chrome из библиотеки; локальное копирование стилизации этих контролов внутри острова SHALL быть запрещено. Пилотный лаунчер SHALL использовать библиотечную кнопку; его видимое поведение, сигналы и контракты `objectName` при этом НЕ SHALL меняться. Объявление подсказки предоставляется как прикреплённое свойство библиотеки: остров лишь задаёт текст (в том числе динамический), механизм показа остаётся за Python-стороной острова по правилу `qml-shell`; специфичные делегаты отдельных экранов (строки ленты шкалы) в библиотеку НЕ SHALL выноситься до появления второго реального потребителя.

#### Scenario: Остров собирается из библиотеки

- **WHEN** новый QML-остров рисует кнопку или поле
- **THEN** он импортирует компонент из модуля библиотеки, а не переопределяет его оформление локально

#### Scenario: Лаунчер на библиотеке без регресса

- **WHEN** лаунчер построен на библиотечных кнопках
- **THEN** все прежние тесты лаунчера (навигация по `objectName`, клики, Enter, переключатель темы) проходят с прежней семантикой

#### Scenario: Подсказка объявляется свойством библиотеки

- **WHEN** острову нужна всплывающая подсказка над контролом
- **THEN** текст задаётся прикреплённым свойством из модуля библиотеки; в острове не заводится собственный оверлей-подсказка и не дублируется механизм показа
