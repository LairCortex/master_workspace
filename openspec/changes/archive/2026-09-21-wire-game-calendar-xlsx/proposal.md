# Proposal: wire-game-calendar-xlsx

## Why

С C3a приложение подписывает даты игровым календарём («3 Зимостой 44 г. до н.э.»), но импорт таких дат не понимает: парсер `parse_cell_date` знает только жёстко зашитые григорианские имена, а статический шаблон «Скачать шаблон» в кастомной игре показывает примеры дат, которые при импорте уедут в другие дни. В кастомной игре получается тупик: вывезенную из приложения дату обратно не внести, а шаблон врёт о её календаре. Кусок C5 дорожной карты.

## What Changes

- Парсер текстовых дат ветвится по активному календарю: кастомный (календарь с `spec`) понимает словарь имён активного календаря, пресет «Стандартный» разбирает ровно то, что и сегодня, — без расширения.
- Новые текстовые формы кастомной ветки: `день Имя год` — наша эра, он же с хвостом `г.` / `г. до н.э.` — суффикс единственный источник эры, ничего не доспрашивается; вставной день — `Имя год[хвост]` без номера дня и только если имя объявлено во вставных днях активного календаря. Номер дня при вставном имени и месяц без номера дня — проблемы пред-анализа с предметной причиной («месяц «…» не найден в календаре игры» и т.п.).
- Сопоставление имён: `strip()`, регистронезависимо, внутренние повторные пробелы схлопываются; родительный падеж — только старый григорианский справочник, эвристики окончаний нет. Нативная ячейка Excel, голое ISO и знаковое `-ГГГГ-ММ-ДД` остаются в обеих ветках; политика сдвига невалидных координат в отчёт — без изменений.
- `parse_cell_date` получает необязательный параметр календаря (по умолчанию `current_calendar()`) и меняет валюту возврата на `DateParse` — разбор с координатой активного календаря (включая вставной день), флагом эры и, при неразобранной форме кастомной ветки, предметной проблемой пред-анализа. Григорианский кортеж `(date, bool)` из публичного API уходит вместе с этим изменением; единственный вызов в сервисе и позитивные проверки схемы мигрируют на `DateParse` в этом же изменении (никакого переходного кортеж-фасада).
- **BREAKING (репозиторий):** статический `resources/import_template.xlsx` удаляется вместе с datas-записью в `nri_manager.spec`; генератор содержимого из теста переезжает в прод, «Скачать шаблон» собирает файл под активный календарь: примерные даты корректируются до валидных координат (при наличии вставных дней — примерная строка с вставным днём), шаблон обязан импортироваться в свою игру без строк переноса; для «Стандартного» содержимое совпадает с нынешним файлом клетка-в-клетку.
- Подсказка «Даты: …» в диалоге и подпись колонки «Дата начала» строятся от активного календаря с живым примером имени месяца; имя файла при сохранении не меняется.

## Capabilities

### New Capabilities

- (нет — изменение живёт внутри существующей возможности импорта)

### Modified Capabilities

- `xlsx-import`: requirement «Колонки листа» — словарь и грамматики текстовых дат ветвятся по активному календарю (кастомный: имена календаря, наша эра без суффикса, вставные дни; стандартный: сегодняшнее поведение слово в слово), предметные причины пропуска; requirement «Скачивание шаблона файла» — генерация под активный календарь вместо выдачи статического файла, клеточная идентичность для пресета, гарантия чистого импорта шаблона; requirement «Подсказка о колонках в диалоге» — блок «Даты» строится от активного календаря.

## Impact

- **Application:** `xlsx_schema.py` (ветвящийся `parse_cell_date` на `DateParse` с параметром календаря, типы `DateParse`/`DateProblem`, причины пропуска, переезд генератора шаблона в прод из `tests/application/test_xlsx_import_template.py`), `xlsx_import_service.py` (`_row_to_draft`/`_to_coord`/`_era_text` мигрируют на координатную валюту `DateParse` с вставным днём в этом же изменении — переезд API и потребителя в одной группе, переходного кортежного фасада нет), `calendar_settings_service`-потребители не трогаются.
- **Presentation:** `xlsx_import_dialog.py` (`save_template_as` — генерация вместо `shutil.copyfile`; `build_format_text` — динамический блок «Даты»), тексты колонок в реестре `xlsx_schema`.
- **Репозиторий/сборка:** удаление `resources/import_template.xlsx` и записи в `nri_manager.spec`; бандл больше не возит шаблон.
- **Тесты:** золотые снимки генератора (стандартный — нынешний файл 1-в-1, кастомный — фиксированный календарь со вставным днём и BC), матрица грамматик парсера по обеим веткам, «шаблон кастомной игры импортируется чисто без переносов»; `test_spec_template_bundle.py` заменяется проверкой отсутствия файла в спецификации; тесты диалога/VM — за генерацию.
- **Дорожная карта:** закрывает строку C5; e2e-приёмка кастомного календаря остаётся в C6.
