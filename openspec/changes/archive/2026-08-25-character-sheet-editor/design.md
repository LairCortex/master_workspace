## Context

См. proposal.md — мотивация. Связанные факты текущего кода:

- Приложение PySide6 + qasync (весь async-код — через event loop), архитектура MVVM: `presentation/views` (widжеты + viewmodels с Qt-сигналами) → `application/services` (plain async) → `infrastructure/repositories` → `infrastructure/db` (SQLAlchemy 2.0 async, одна база игра — `games/<name>/game.db`).
- Миграции не через alembic: `init_db()` (`app/infrastructure/db/migrations.py`) делает `Base.metadata.create_all` + точечные `_MIGRATIONS` (ALTER) для существующих БД. Новые таблицы создаются `create_all` автоматически при первом открытии старую игру.
- Меню главного окна: `QAction`-ы в `MainWindow` + Qt-сигналы, обрабатываемые в `Application._wire_signals` (`app/main.py`) — паттерн `switch_game_requested` / `export_requested`.
- Сборка PyInstaller (`nri_manager.spec`, папочный бандл, hiddenimports перечислены явно), версия дублируется в `pyproject.toml`, spec-файле и `docs/CHANGELOG.md`.
- Тесты: pytest + pytest-qt (offscreen), порог 100% linear coverage; E2E-слой `tests/ui/` поднимает настоящий `Application` на временной игре.

## Goals / Non-Goals

**Goals:**
- Полный цикл «шаблон → PDF» внутри существующего приложения без новых архитектурных слоёв (используем существующие слои MVVM/репозитории/миграции)
- Модель шаблона как единый самодостаточный документ (простота чтения/записи и 1:1-соответствие JSON)
- Детерминированное, проверяемое генерирование PDF: чистая синхронная функция «модель → файл», проверяемая парсингом pypdf без запуска Qt
- Минимально инвазивная интеграция: одно новое меню, новые таблицы, две новые зависимости

**Non-Goals:**
- Импорт заполненных значений из PDF (только совместимость имён), фоновая графика листа, размеры страниц кроме A4, кастомные шрифты — см. proposal «Не входит в v1»
- Совместный доступ/синхронизация шаблонов, версионирование шаблонов
- Оптимизации под крупные документы (лист — десятки-сотни полей)

## Decisions

### D1. Хранение: одна таблица + JSON-колонка для страниц

Новая таблица `character_sheets`: `id`, `name` (UNIQUE — уникальность в пределах игры, база и так одна на игру), `orientation` (`portrait`/`landscape`), `pages` (JSON-строка: массив страниц `{name, fields:[...]}`), `created_at`, `updated_at`.

Поле в JSON — `{id, type, x, y, w, h, label, default_value, font_size, ...типоспецифичное}`; `id` = uuid4 (hex), назначается в сервисе при создании поля, никогда не переиспользуется и не меняется — из него же строится имя поля в PDF.

**Почему:** поля листа не запрашиваются по отдельности (нет поиска/связей), документ читается и пишется целиком; JSON-колонка даёт атомарную запись, простейший репозиторий и фактически бесплатный JSON-экспорт проекта (модель ↔ файл — почти то же дерево). Альтернатива — нормализованные таблицы `sheets/pages/fields`: отклонена, она усложняет репозиторий и миграции без выигрыша в запросах.

### D2. Доменные dataclass'ы

В `app/domain/` (по существующему паттерну): `SheetTemplate(name, orientation, pages)`, `SheetPage(name, fields)`, `SheetField(id, type, x, y, w, h, label, default_value, font_size, **type-specific)`, enum'ы `FieldType` (9 значений) и `SheetOrientation`. Геометрия — float в pt; при записи в хранилище/JSON координаты округляются до 2 знаков (защита от накопления погрешности при многократных масштабированиях).

### D3. Репозиторий и сервис

`CharacterSheetRepository` — по образцу `BaseRepository` (get_by_id, get_all, create, update, delete) + проверка уникальности имени. `CharacterSheetService` (async) поверх него: create (с проверкой имени, до и по IntegrityError), update (pages + updated_at), delete; операции страниц и ориентации — чистые функции над `SheetTemplate` (`scale_templates_for_orientation(template, new_orientation)` и т.п.), unit-тестируются без БД. JSON export/import — в этом же сервисе: метка формата `"nri-charsheet"`, `version: 1`; валидация метки, версии, enum-ов типов и числовой геометрии; конфликт имени при импорте → суффикс « (копия)», « (копия 2)», …

### D4. Генерация PDF: чистая функция на ReportLab

`app/infrastructure/pdf/sheet_pdf.py`: синхронная `generate_sheet_pdf(template: SheetTemplate, path: Path)`. ReportLab `canvas.Canvas`:
- координаты: PDF — origin снизу-слева, редактор — сверху-слева → `y_pdf = page_h - y - h`;
- страницы: `canvas.setPageSize((w, h))` на каждую (ориентация из шаблона); A4 = 595.28 × 841.89 pt;
- статика и подписи: `drawString` (заголовки — Bold); подпись вводимого поля — строкой над рамкой;
- рамки полей: `canvas.rect` (stroke, белый fill); портрет — рамка + текст «Портрет» внутри;
- form-поля: textfield (короткий текст, число, дата), checkbox с начальной отметкой, dropdown (список); значение по умолчанию — `/V`/`/DV`, имя поля — стабильный id.

**Результаты spike (задача 1.2, ReportLab 5.0.1 + pypdf 6.16):**

1. Используется **legacy-механизм** `reportlab.pdfbase.pdfform` (`getForm(canvas)` + паттерны `TextFieldPattern`/`SelectFieldPattern`/`ButtonFieldPattern`, объект добавляется через `canvas._addAnnotation` + `form.fields.append`). Новый модуль ReportLab 5 (`canvas.acroForm` → `reportlab.pdfbase.acroform`) отклонён: `choice()` падает `UnboundLocalError` на пустом значении, а статические appearance-потоки падают `KeyError` на не-WinAnsi-тексте (escPDF).
2. **Флаги `/Ff` ставятся нативно**: паттерн `TextFieldPattern` принимает `Flags` (multline = 1<<12 = 4096). Отдельного Num-флага у AcroForm **нет** (в ISO 32000 флаги числовой валидации отсутствуют — они существуют только в XFA; подтверждено таблицами reportlab `fieldFlagValues` и pdf.js `AnnotationFieldFlag`). Числовая валидация min/max — JavaScript-действие `/AA /V` (Validate) на поле: в JS-поддерживающих просмотрщиках (Adobe Acrobat) поле принимает только число в границах; во всех остальных — деградирует в обычный текст-поле. Специфические требования spec при этом не меняются.
3. **Кириллица**: статический текст — шрифт **DejaVu Sans (Regular + Bold)**, TTF в пакете `app/infrastructure/pdf/fonts/`, встроен в PDF подмношением (ReportLab TTFont-сабсэттинг) — pypdf корректно извлекает кириллицу. Шрифт выбран как свободный sans-serif с полной кириллицей: стандартные 14 шрифтов PDF (WinAnsi) кириллицы не имеют, а метрические клоны Helvetica (FreeFont — только CFF/OTF, ReportLab не встраивает; Arimo/Liberation — недоступные источники) отклонены. Font-имена в /DA полей форм — не-встроенный `/Helv` (стандартные 14, решаются просмотрщиком локальным шрифтом с кириллицей на Windows/macOS) + `/NeedAppearances true`: значения и опции форм пишутся `PDFString`'ом (ReportLab сам кодирует не-PDFDoc-текст как BOM+UTF-16BE, что pypdf и просмотрщики декодируют корректно).
4. **Dropdown** = `SelectFieldPattern` (`/FT /Ch` без LIST-bит = combobox) с `/Opt`; **checkbox** = `ButtonFieldPattern` c зафиксированным прямоугольником (в оригинальной функции `buttonField` высота в `/Rect` заменяется шириной — баг ReportLab, обходим прямым построением паттерна), начальная отметка — `/V`/`/AS` = `Yes`/`Off`, Appearance-статы на ZapfDingbats.
5. `pypdf` остаётся **dev-зависимостью** (тесты): постпроцессинг PDF не требуется, runtime-зависимость от pypdf **не нужна**.

**Почему ReportLab:** зрелый AcroForm API, чистый Python (без системных зависимостей — дружит с PyInstaller и CI на 3 ОС). Альтернативы: fpdf2 (нет form-полей), WeasyPrint (HTML→PDF, нет AcroForm), генерация PDF «вручную» (неоправданная сложность) — отклонены.

### D5. Редактор: QGraphicsView + continuous scroll

Окно редактора — `QDialog` (единый с приложением паттерн окон поверх MainWindow) с верхней строкой кнопок (toolbar-стиль): Сохранить (Ctrl+S), Экспорт PDF, Undo/Redo, чекбокс «Сетка» + spin шага, combo ориентации, «+ Страница», «Страницы…», зум −/+/«вписать».

- Канвас: один `QGraphicsScene` — страницы вертикальной колонкой с отступом ~40 pt; `QGraphicsView` со встроенными скроллбарами: левая кнопка — rubber-band выбор/перетаскивание, середина (или Space+левая) — панорама, Ctrl+колесо — зум к курсору, 25–400%, «вписать в окно».
- Страница — `QGraphicsObject`-обёртка: белый прямоугольник A4, рамка, полупрозрачная сетка (рисуется в `paint()` только при включённом «Сетка»).
- Поле — `QGraphicsObject`-обёртка: рамка (введённые) / текст (статика); у выбранного — 4 угловые ручки ресайза (мин. размер ~20×10 pt); подпись — текст над рамкой, редактируется в панели свойств.
- Палитра слева: кнопка на каждый из 9 типов → поле добавляется в центр страницы, ближайшей к центру вида, и выбирается.
- Панель свойств справа: форма с виджетами label/default/шрифт + типоспецифичной секцией (min/max — QSpinBox'ы; опции — редактор списка; начальное состояние чекбокса).
- Копирование/вставка — внутренний буфер viewmodel (JSON поля), не системный clipboard (простота, не тащим чужие данные).
- z-порядок = порядок в массиве полей страницы; «на перед/назад» — move в списке + `item.setZValue`.

**Почему один QGraphicsScene на все страницы (Word-стиль), а не QStackedWidget-табы:** непрерывный поток страниц — согласованный UX; технически это штатный QGraphicsView-паттерн (сцена выше окна, скроллбара уже есть), сложность ниже, чем у «табов + отдельная навигация», и зум единый для всего документа. Альтернатива (вкладки) — fallback, отклонён как менее удобный при мультистранице.

### D6. Undo/redo — снапшоты модели

Viewmodel хранит `SheetTemplate` в памяти; undo-стек — Список глубинных копий шаблона (dataclasses `copy.deepcopy`), лимит 100. Каждая значимая операция (add/move/resize/remove/duplicate/copy-paste/z-операции/свойства/операции страниц/смена ориентации) делает снапшот до применения. Redo — параллельный стек, сбрасывается новой операцией.

**Почему снапшоты, а не command-паттерн:** документ мал (сотни полей), снапшоты тривиально корректны и покрывают все операции одним механизмом; command-паттерн — лишняя структура без выигрыша.

### D7. Viewmodel и интеграция

`CharacterSheetViewModel` (Qt-сигналы, синхронная работа с моделью): `dirty` сигнал, `template`-accessor, операции из D6 + `save()`/`export_pdf()` — корутины, вызывающие сервис через `qasync`-паттерн приложения (как остальные viewmodels). В `Application` (`app/main.py`): `character_sheet_list_requested` сигнал на MainWindow (новое меню «Чар-листы»), провайдинг repo → service → обработчик диалога списка; смена игры закрывает редактор.

### D8. Миграция

Только новая таблица → `Base.metadata.create_all` в `init_db()` создаст её и в свежих, и в существующих играх автоматически; `_MIGRATIONS` (ALTER) не нужен. Откат: таблица избыточная (аддитивная), откат версии приложения безопасен (старая версия её игнорирует); данные `.nri` v2 не ломаются (архив = каталог игры, БД целиком).

### D9. Зависимости и сборка

- `reportlab` — runtime-зависимость (чистый Python). В `nri_manager.spec` → hiddenimports (плюс фактические субмодули, если PyInstaller не подхватит — проверить на Т-задаче сборки).
- `pypdf` — dev-зависимость (тестирование PDF); становится runtime-зависимостью только если понадобится постпроцессинг флага из D4.
- Версия 0.16.0 → 0.17.0: `pyproject.toml` + `CFBundleShortVersionString` в spec + `docs/CHANGELOG.md` (обязательные правила проекта); guard совпадения тега работает как есть.

## Risks / Trade-offs

- ~~[API ReportLab AcroForm не выставляет PDF-флаги (Num/Multiline) и часть опций]~~ — снято spike (D4.1/D4.2: Multiline нативно; Num-флагов в AcroForm нет по спецификации — валидация через JS-действие /AA /V; pypdf-постпроцессинг не нужен).
- [pypdf-тесты хрупки к деталям внутреннего представления PDF (имена полей как bytes/Name objects, порядок флагов)] → тесты утверждают семантику (FT, V, имена после decode, биты Ff), а не байт-выдачу; один эталонный «golden» тест на структуру AcroForm-дерева.
- [Float-скоординаты накапливают погрешность при серии масштабирований/ресайзов] → округление до 2 знаков при каждом сохранении модели; сетка snap даёт «круглые» значения.
- [Игнорирование пользователем несохранённых изменений / потеря при смене игры] → подтверждение при закрытии редактора (spec), смена игры закрывает редактор с тем же подтверждением.
- [100% line coverage при новом модуле PDF] → генератор PDF — чистая функция без Qt, покрывается unit-тестами без offscreen-окон; Qt-часть — offscreen-тесты по образцу `tests/ui/`.
- [ReportLab в PyInstaller] → явный hiddenimport + задача «собрать dist и запустить экспорт из бандла» в чек-листе перед релизом.
