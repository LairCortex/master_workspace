## Why

Игра, сценарии которой ведёт в этом приложении, требует лист персонажа (чар-лист) для игроков. У автора нет инструмента, чтобы спроектировать лист под свою систему правил и раздать игрокам заполняемый файл: сегодня это делается вручную в графических редакторах, лист не соответствует правилам игры и не обновляется при правках.

## What Changes

- Новый модуль «Чар-листы»: редактор шаблона чар-листа в главном окне приложения (отдельное окно-диалог)
- Шаблон = N страниц A4, общая на весь шаблон ориентация (книжная/альбомная; по умолчанию альбомная); переключение ориентации пропорционально масштабирует координаты и размеры всех полей
- Свободный канвас в режиме непрерывной прокрутки страниц (Word-стиль): палитра типов полей слева, выбор/перемещение/ресайз, undo/redo, snap к настраиваемой полупрозрачной сетке, панель свойств справа
- 9 типов полей в v1: число (min/max), короткий текст, длинный текст, чекбокс, список (dropdown), дата, портрет (рамка-плейсхолдер), заголовок/подпись, статический текст; у поля — подпись, значение по умолчанию, размер шрифта, стабильный id
- Сохранение шаблонов в базе текущей игры; имя листа уникально в игре; лист уезжает в экспорт `.nri` вместе с игрой
- JSON-экспорт/импорт проекта шаблона (раздача шаблона без приложения, бэкап)
- Экспорт шаблона в интерактивный PDF (формы AcroForm): игрок заполняет лист в любом PDF-просмотрщике; ReportLab, шрифт Helvetica-совместимый с кириллицей; стабильные имена form-полей = задел на будущий импорт заполненных значений (не входит в v1)
- Управление страницами: диалог «Страницы…» (переименование, удаление с подтверждением, перемещение) + кнопка «+ Страница»
- Тестирование PDF-экспорта — парсинг сгенерированного файла (pypdf, dev-зависимость)

Не входит в v1: импорт заполненных значений из PDF, фоновая картинка/орнамент листа, произвольный размер страницы (кроме A4), кастомные шрифты, perst-перетаскивание вкладок.

## Capabilities

### New Capabilities
- `character-sheet-editor`: редактор шаблона чар-листа — канвас, типы полей, операции с полями (добавление, перемещение, ресайз, удаление, дублирование, copy/paste, z-порядок), undo/redo, страницы (добавление/переименование/удаление/порядок, общая ориентация со слайдом под новую геометрию), snap-сетка
- `character-sheet-storage`: хранение шаблонов в базе игры (таблицы, модель страницы/поля, уникальность имени), JSON-экспорт и импорт проекта
- `character-sheet-pdf-export`: экспорт шаблона в интерактивный PDF — AcroForm-поля для вводимых типов, статический рендер заголовков/подписей/текста/портрета, имена полей, обрезка за краем страницы, метаданные

### Modified Capabilities
(пусто — требования существующих capabilities не меняются; интеграция — новое меню в главном окне и новые таблицы, которые создаёт существующий конвейер init_db/create_all)

## Impact

- **Код (новый):** `app/infrastructure/db/models.py` (таблицы чар-листов), `app/infrastructure/repositories/` (репозиторий), `app/application/services/` (сервис шаблонов + генерация PDF), `app/presentation/viewmodels/` и `app/presentation/views/` (окно редактора, диалог списка листов, диалог страниц), `app/main.py` (DI-провайринг, новое меню «Чар-листы» в MainWindow)
- **Миграция:** новые таблицы создаются `Base.metadata.create_all` при старте (`init_db`, проект не использует alembic); существующие игры получают таблицы при первом открытии
- **Зависимости:** + `reportlab` (runtime), + `pypdf` (dev)
- **Сборка:** `nri_manager.spec` — `reportlab` в hiddenimports; версия bump'ится в `pyproject.toml`, spec и `docs/CHANGELOG.md` (0.16.0 → 0.17.0)
- **Тесты:** новые модульные, сервисные и UI-тесты (offscreen Qt); PDF проверяется парсингом pypdf; порог 100% linear coverage сохраняется
