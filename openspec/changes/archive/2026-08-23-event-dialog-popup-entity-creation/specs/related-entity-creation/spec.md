## Purpose

Единый паттерн создания и привязки связанных сущностей из диалогов редактирования (событие, карточка сущности): отдельное окно-поппап вместо инлайн-формы, атомарная запись вместе с родителем.

## ADDED Requirements

### Requirement: Секции связанных сущностей в диалогах редактирования

Диалог события (и в режиме создания, и в режиме редактирования) и карточка сущности SHALL управлять связанными сущностями через одинаковые секции: список сущностей, «Привязать существующего» (выбор из нескольких), «Создать нового», «Отвязать». Инлайн-форма создания сущности непосредственно в диалоге события не используется. В списках отображаются лишь имена сущностей, без различающих маркеров.

#### Scenario: Табы диалога события

- **WHEN** пользователь открывает диалог события — для создания или для редактирования
- **THEN** диалог содержит четыре секции (организации, персонажи, предметы, локации), каждая со списком и кнопками «Привязать существующего», «Создать нового», «Отвязать»

#### Scenario: Предзаполнение при редактировании события

- **WHEN** пользователь открывает диалог существующего события
- **THEN** каждая секция предзаполнена сущностями, уже связанными с этим событием

### Requirement: Создание связанной сущности в отдельном окне

Нажатие на «Создать нового» в любой секции диалога события или карточки сущности SHALL открывать отдельное окно карточки сущности соответствующего типа. По нажатию «Сохранить» в этом окне сущность SHALL создаваться немедленно (без фиксации транзакции) и добавляться в список секции диалога-родителя; фиксация записи происходит вместе с сохранением диалога-родителя.

#### Scenario: Создание персонажа из диалога события

- **WHEN** пользователь нажимает «Создать нового» в секции «Персонажи» диалога события и сохраняет открытое окно нового персонажа
- **THEN** окно закрывается, персонаж появляется в списке секции «Персонажи»

#### Scenario: Сохранение события фиксирует созданную сущность

- **WHEN** пользователь сохранил созданную в поппапе сущность в диалоге события и сохраняет само событие
- **THEN** сущность записана в базу данных и связана с событием

#### Scenario: Отмена диалога родителя

- **WHEN** пользователь создал сущность в поппапе, а затем отменяет диалог родителя (события или карточки)
- **THEN** база данных не изменяется: сущность и все её связи отсутствуют

### Requirement: Привязка существующих сущностей из окна создания

Окно создания связанной сущности SHALL предлагать для привязки существующие сущности соответствующих типов: после сохранения окна выбранные в нём связи SHALL быть установлены у созданной сущности.

#### Scenario: Привязка локации к новому персонажу

- **WHEN** в окне создания персонажа из секции диалога события пользователь привязывает к нему существующую локацию и сохраняет окно
- **THEN** после сохранения события новый персонаж связан с этой локацией в базе данных

### Requirement: Отвязывание не удаляет сущность

Действие «Отвязать» SHALL удалять только связь «сущность — событие/сущность»; сама сущность SHALL оставаться в игре.

#### Scenario: Отвязание созданной сущности

- **WHEN** пользователь создаёт сущность в поппапе, отвязывает её в секции и сохраняет событие
- **THEN** сущность существует в базе данных, но не связана с этим событием

### Requirement: Синхронизация связей события при сохранении

При сохранении события связи SHALL синхронизироваться полной заменой по четырём типам: связанные будут все сущности из текущих списков секций, остальные связи события сняты. Создавать сущности при сохранении события система не SHALL.

#### Scenario: Смешанный состав секций

- **WHEN** секция диалога события содержит ранее связанные сущности, созданные в поппапе сущности и отвязанные ранее сущности
- **THEN** после сохранения события связаны только присутствующие в списке, ранее связанная и отсутствующая в списке связь снята
