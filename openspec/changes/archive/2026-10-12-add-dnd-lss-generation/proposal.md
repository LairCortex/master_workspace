# Proposal: add-dnd-lss-generation

## Why

Фаза 3 roadmap'а D&D-модуля: мастер получает ИИ-генерацию в форматах, которые Long Story Short принимает без ручной доводки, — хоумбрю-датасеты, документы персонажей (`character.json` v2) и файлы заклинаний (Foundry VTT). Фазы 1–2 дали валидаторы, хранилища и импортные конвейеры; без генерации это только приём чужих файлов, а без приёмки через те же валидаторы генерация была бы выбросом непроверенного JSON.

## What Changes

- Единый круг «генерация → валидатор → перегенерация»: до 2 автоматических кругов, обратная связь — прежний ответ + список ошибок валидатора; предупреждения не шлются; после лимита — ручная «Ещё круг».
- Генерация датасетов: задача из листа «Датасеты D&D…», одна секция = один вызов = один файл `dataset-<тип>.json`, число сущностей задаёт мастер (по умолчанию 5); конверт датасета собирает приложение; few-shot — фиксированные SRD-образцы из ресурсов модуля; предпросмотр с отчётом валидатора, выбор лицензии (CC0/CC-BY/CC-BY-SA, дефолт CC-BY 4.0), принятие в глобальное хранилище с автоподключением к игре.
- Генерация заклинаний: содержательную часть пишет ИИ, конверт Foundry Item — приложение; гейт «структура импортёра = ошибки, семантика и «вне SRD» = предупреждения»; принятие — новый хоумбрю-гримуар в глобальное хранилище.
- Генерация персонажей: два режима — «с нуля» (концепция + опциональные пре-выборы уровня/расы/класса) и «дозаполнение» (только пустые содержательные поля); ИИ пишет только содержательную часть (`name`, `info`, `blocks`, `choices`, привязки и заклинания слагами), числа не выдумывает; скелет `data` по схеме и неразрешимые слаги — ошибка круга; персонаж с нуля создаётся через существующий импортный конвейер, дозаполнение заменяет сырой файл.
- Новый сборщик «карточка → `character.json`» и кнопка «Экспорт для LSS…»: экспорт любого персонажа (импортированного, рукотворного, дозаполненного) из текущего состояния карточки; он же опирается дозаполнению.
- Все вызовы одиночные с `with_thinking=True`; промты жёсткие в модуле (каноны каналов + описание мира + идея мастера); содержимое по-русски, протокольные поля латиницей; задача живёт только в своём листе (закрытие = подтверждение + отмена); гейт активации общий AI + (для персонажа) ≥1 подключённый датасет.
- Монстры и встречи генерации не получают.

## Capabilities

### New Capabilities

- `dnd-generation`: круг генерации с обратной связью валидатора; три канала (датасеты, персонажи, заклинания) — входы, зерно вызовов, предпросмотр/принятие, лицензии, гейты активации, жизненный цикл задачи, язык и режим мышления.
- `dnd-character-export`: сборщик документа `character.json` v2 из текущего состояния карточки персонажа и кнопка «Экспорт для LSS…» (дверь для мастера и для дозаполнения).

## Impact

- Только `app/dd/` (модуль): новые сервисы генерации и сборщика документа в `application/`, доменные значения/промты/эталоны few-shot в `domain/` и `resources/`, листы задач в `presentation/`; composition корня передаёт модулю существующий LLM-канал (провайдер/`LlmService`), ядро о D&D ничего не узнаёт.
- Ядро, миграции базовой схемы, обычные игры — без изменений; второй профиль сборки (без модуля) не затрагивается.
- Сетевой канал один — существующий `BaseLlmProvider` (с ним же `with_thinking` и авто-бюджет вывода); новых зависимостей и ключей `game_settings` нет.
- Тесты: стаб-провайдер + живые валидаторы, golden-проверка сборки промта; гейка `ruff` + `run_tests_isolated.py` в обоих профилях, покрытие 100 %.
