# Proposal: add-generate-entity

## Why

Чтобы описать новую сущность, пользователю приходится нажимать AI-кнопку на каждом из 3–5 полей по отдельности. Нужна одна кнопка «Сгенерировать сущность», которая запускает генерацию всех полей разом, и сами генерации должны идти параллельно (а не по одному, как сейчас) — на нескольких полях разница ощутима, особенно на локальной LLM.

## What Changes

- Новая кнопка «Сгенерировать сущность» (24×24 ✨, правый верх формы) в `EventDialog` и `EntityCardDialog`: запускает генерацию всех AI-полей диалога (событие: 3, предмет: 3, локация: 4, организация: 4, персонаж: 5), включая уже заполненные — их текст подмешивается в промт, переопределение безопасно.
- Генерации выполняются **параллельно**: из `LlmService` убирается sequential-очередь, каждый запрос (одиночное поле или бандл сущности) выполняется в отдельной корутине.
- UI во время генерации: все целевые поля в generating-состоянии (read-only + прогресс-индикатор, как при одиночной генерации), кнопка сущности становится отменой (toggle), «Сохранить» disabled, ESC и клик мимо окна не закрывают диалог.
- Отмена: повторный клик по кнопке сущности отменяет все запросы этого диалога; закрытие X / «Отмена» при in-flight запросе — через подтверждение, при запросах только в ожидании/ретраях — молча. Отмена ≠ ошибка: диалога об ошибке не показывается, пришедшие результаты сохраняются.
- Ошибки видны пользователю: одиночная генерация — диалог с именем поля (в коде сегодня молча); бандл — единый агрегированный диалог после завершения волны; успешные поля остаются заполненными.
- **BREAKING (spec-level)**: сценарий «Последовательная генерация нескольких полей» в `llm-remote-provider` заменяется параллельным выполнением.

## Capabilities

### New Capabilities

- `entity-generation`: кнопка генерации всех полей открытой сущности, состояния UI во время генерации (кнопка-отмена, блокировка полей, «Сохранить» disabled), отмена (toggle + phase-зависимое подтверждение закрытия), защита от закрытия диалога (ESC / клик мимо / save), агрегированный отчёт об ошибках бандла.

### Modified Capabilities

- `llm-remote-provider`: требование «Генерация через OpenAI-совместимый endpoint» — сценарий последовательной генерации нескольких полей заменяется параллельным выполнением (запрос на каждую корутину, без очереди); требование «Обработка ошибок генерации» — ошибка одиночной генерации показывается диалогом с именем поля, ошибка бандла — единым агрегированным сообщением после завершения волны.

## Impact

- `app/application/services/llm_service.py` — removal очереди/одиночного worker, фазы запроса (in-flight / ожидание ретра), реестр активных запросов пер-диалог, отмена, статусы `any_in_flight()` / `any_active()`.
- `app/presentation/views/ai_assist_button.py` — состояние-отмена (toggle) для кнопки сущности.
- `app/presentation/views/event_dialog.py`, `app/presentation/views/entity_card_dialog.py` — кнопка сущности, «Сохранить» disabled во время генерации, guard путей закрытия (closeEvent + reject + ESC), disabled состояния.
- `app/main.py` (`_wire_ai_buttons`) — старт/отмена бандла, агрегация ошибок волны.
- `app/presentation/viewmodels/llm_viewmodel.py` — сигналы/методы для бандла по необходимости.
- Тесты: `tests/application/test_llm_service.py`, `tests/presentation/test_llm_viewmodel.py`, `tests/ui/test_e2e_llm.py` + новые UI-тесты диалогов (MockTransport, без сети).
- `docs/CHANGELOG.md` — запись о фиче (миграции БД не требуются).
- Без изменений: тексты промтов, `RemoteLlmProvider` (таймауты/ретраи), `LlmSetupDialog`, настройки per-game.
