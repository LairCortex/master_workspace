## 5. Защита от закрытия диалога

- [x] 5.1 Тесты блокировок: ESC во время одиночной генерации и бандла → диалог не закрывается; синтетическое закрывающее событие (close) во время генерации → молча не проходит (уходит в guard); ESC без генерации → диалог закрывается (текущее поведение сохранено). Проверка: красные до 5.3.
- [x] 5.2 Тесты phase-зависимого закрытия (подмена/шпион `QMessageBox`): X или «Отмена» при in-flight → подтверждение с предупреждением; «Нет» → диалог открыт, генерация продолжается; «Да» → `cancel_all` + закрытие. X / «Отмена» при запросах только в ожидании ретраев → закрытие без подтверждения + отмена. Отмена (бандл-кнопка или закрытие) не показывает диалог об ошибке и сохраняет уже пришедшие результаты. Проверка: красные до 5.3.
- [x] 5.3 Реализовать `set_close_guard(fn)` в обоих диалогах: `closeEvent` → guard при активной генерации; `keyPressEvent` → `Escape` during генерации игнорируется; клик «Отмена» → guard вместо прямого `reject()`; guard-замыкание в `_wire_ai_buttons` (`any_in_flight` → подтверждение / молча, затем `cancel_all` + `reject()`); существующий guard в `reject()` оставить как safety net. Проверка: тесты 5.1–5.2 зелёные.
