# Proposal: close-custom-calendar-map

## Why

Дорожная карта кастомного календаря дошла до C6 — зачистки. Инвентарь C6 «миграция тестов QDate-прокси (89 упоминаний, 13 файлов)» устарел: Qt-прокси дат убраны ещё в C3b (design D12), `QDate` нет ни в тестовых, ни в продуктовых исходниках — ни одной ссылки вне текстовых упоминаний в docstring. При этом сам кастомный календарь ни разу не проверялся сквозным прогоном «реальными кликами»: сетка, мастер, вставные дни и эра покрыты островными widget-тестами и двумя e2e-файлами, но полный пользовательский путь новой кастомной игры (мастер до конца → события на плашке и в BC → подписи везде → правка в середине игры с отчётом) не проходил. Плюс пользовательская документация о календаре молчит: README упоминает его вскользь, сверять пользовательские проверки не с чем. Карта без этих трёх вещей закрывается только на бумаге (решения grill-сессии 2026-09-21).

## What Changes

- Тест-запрет возвращения Qt-носителей дат: автоматическая проверка, что `QDate`, `QCalendarWidget` и прокси-методы `date()/setDate()` попапов не появляются в прод-коде и тестах (по прецеденту «спецификация не перечисляет шаблон в datas»). Григорианская `datetime.date` на входе API остаётся штатной — запрет касается только Qt-класса даты и виджета.
- E2E-приёмка кастомного календаря реальными мышиными кликами, две сцены на временной игре:
  1. новая игра → мастер до конца (неделя 8 дней, свои длины месяцев, вставной день) → применить → событие на вставном дне и с эрой «до н.э.», выбранное кликами по сетке-попапу → подписи на шкале/ленте/в детальной/на снимке → перезапуск игры → всё на месте;
  2. укорочение месяца через мастер в середине игры → экран отчёта о переносе → перенесённые записи показывают новые даты.
  Xlsx-круг кастомной игры остаётся покрытым сервисным слоем (`test_xlsx_template_generator`, `test_xlsx_import_*`) — e2e-диалог импорта ради него не заводится. e2e водится в одной теме; кожи сетки/мастера остаются на юнит-покрытии.
- Пользовательская документация: раздел «Календарь игры» в `docs/README.md` (что настраивается, вставной день ≠ праздник, где мастер), актуализация строк календаря в `docs/functional-checklist.md`.
- Служебное закрытие карты: строка C6 в `docs/custom-calendar-roadmap.md` исправлена под фактическое содержание (Qt-прокси убраны ещё в C3b; остаток — пин-тест, e2e-приёмка, документация) и помечена закрытой итоговой строкой статуса; запись CHANGELOG по изменению (версии не трогаются — подъём версии будет отдельным будущим запросом).
- Полная копия тестов зелёной (`QT_QPA_PLATFORM=offscreen python -m pytest`) — критерий «всё нажимается и проходит»; существующие helpers на `vm.set_dates` не переписываются.

## Capabilities

### New Capabilities

- (нет — изменения не вводят новых системных возможностей)

### Modified Capabilities

- `ui-testing`: requirement «E2E-сценарии основных пользовательских потоков» — устаревший сценарий «Кастомные месяцы» (описывал переходное состояние «мастер ещё не существует») заменён сквозной приёмкой кастомного календаря реальными кликами; добавляются requirements «E2E-приёмка кастомного календаря» и «Запрет Qt-носителей даты в коде и тестах».

## Impact

- **Тесты:** новые `tests/test_no_qt_date_carriers.py` (пин-запрет), `tests/ui/test_e2e_custom_calendar_acceptance.py` (две приёмочные сцены через реальный `Application` и клики по `GameCalendarCell`/плашке/чекбоксу эры/кнопкам мастера); актуализация сценария в спецификации `ui-testing`.
- **Продуктовый код:** не меняется — C6 не трогает прод (ни одного изменения поведения); все правки — тесты и документация.
- **Документация:** `docs/README.md` (новый раздел), `docs/functional-checklist.md` (строки календаря), `docs/custom-calendar-roadmap.md` (C6 + итоговая строка статуса), `docs/CHANGELOG.md` (запись изменения).
- **Версии:** `pyproject.toml` / `nri_manager.spec` / CHANGELOG-версии НЕ трогаются — подъём версии отдельным будущим запросом вне карты.
- **Дорожная карта:** изменение закрывает C6 и всю карту кастомного календаря (C0–C6).
