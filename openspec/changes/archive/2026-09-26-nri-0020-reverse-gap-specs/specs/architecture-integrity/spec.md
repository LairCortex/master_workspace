# architecture-integrity Delta Specification

## ADDED Requirements

### Requirement: Каждое обращение из интерфейса к сессии идёт под единым замком

Единственный замок сериализации доступа к сессии базы данных SHALL принадлежать блоку работы (`GameSessionUoW`); коннектор проводки SHALL запускать через него каждую задачу, порождённый сигналом Qt, а окно/диалог вне проводки SHALL получать доступ к замку только через переданную функцию `run_locked` — собственных обходов или второго замка в приложении SHALL не быть. Вложенные корутины, достигаемые обычным `await` из уже запущенной задачи, SHALL работать под тем же замком и повторно брать его НЕ SHALL. Причина закреплена фактом: два одновременных обращения к одному соединению SQLAlchemy оставляют приложение в вечном зависании, а не в разборчивой ошибке.

#### Scenario: Два сигнальных обработчика не лезут в сессию одновременно

- **WHEN** два пользовательских действия породили две задачи с обращением к базе
- **THEN** задачи выполнились последовательно под одним замком, зависания нет

#### Scenario: Диалог чар-листа входит через переданный замок

- **WHEN** диалог чар-листа запускает шаг, касающийся сессии
- **THEN** шаг выполнен через `run_locked`, предоставленный композиционным корнем, а не через собственный запуск задачи

#### Scenario: Вложенный await не берёт замок повторно

- **WHEN** обработчик внутри своей задачи вызывает вспомогательную корутину через `await`
- **THEN** повторного захвата замка не происходит, блокировки нет

#### Scenario: Обход замка не остаётся незамеченным

- **WHEN** обработчик, порождаемый сигналом, пытается обратиться к сессии в задаче, запущенной мимо замка
- **THEN** такое место считается нарушением проводки: каждый сигнальный обработчик обязан идти через `_spawn`/`run_locked`
