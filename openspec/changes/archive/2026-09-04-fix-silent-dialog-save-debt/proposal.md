# Proposal: fix-silent-dialog-save-debt

## Why

Сохранение из диалогов (событие: создание и правка; карточка сущности: обновление и одиночное создание) молча откатывается при сбое записи: сервисы `*_with_relations` проглатывают исключение и возвращают `None`, а `wiring` игнорирует результат — диалог к тому моменту уже закрыт, введённые данные потеряны, пользователь не узнаёт ничего. Долг зафиксирован в дорожной карте (W5 → Q2.5) и гасится отдельным маленьким куском до переезда шкалы в QML, потому что фикс — чистый `wiring`/сервисы, к QML не относится и не ждёт остального Q2.5.

## What Changes

- `EventService.create_event_with_relations` / `EventService.update_event_with_relations` / `EntityService.update_entity_with_relations` перестают глотать ошибку: `rollback` остаётся, исключение пробрасывается наружу (никого из вызывающих кроме `wiring` у этих методов нет).
- Три save-handler'а в `wiring` (`on_saved`, `on_event_updated`, `on_entity_saved`) и обработчик одиночного создания сущности из «+»-меню (`wiring.py:311-323`, голый `except → rollback`) получают ту же семантику, что уже принят drag-путь `on_event_dates_moved`: `try/except` → `rollback` → перезагрузка ленты → ровно один `QMessageBox.critical` с текстом ошибки.
- Поведение при успехе не меняется; диалоги не меняются (в частности «не закрывать диалог при провале» — вне объёма, это решение будущего переезда диалогов).
- Диалог-путь создания связанной сущности во всплывающем окне уже честный (`try` + rollback + `QMessageBox.critical`) — не трогаем, только сверяем формулировку.

## Capabilities

### New Capabilities

- `save-error-reporting`: любое сохранение события/сущности из UI при сбое записи откатывает транзакцию, оставляет приложение в согласованном состоянии и показывает ровно одно модальное сообщение об ошибке.

### Modified Capabilities

_(нет — `event-timeline` уже требует ровно такое поведение для drag-пути; новые пути подпадают под новую capability, старых требований не меняют.)_

## Impact

- `app/application/services/event_service.py` — два метода `*_with_relations`: убрать проглатывание (rollback + raise).
- `app/application/services/entity_service.py` — `update_entity_with_relations`: то же.
- `app/application/wiring.py` — `on_saved` (:265-284), `on_event_updated` (:349-374), `on_entity_saved` (:559-573), одиночное создание (:311-323): обёртка rollback + перезагрузка + `QMessageBox.critical`.
- Тесты: юниты сервисов (проброс), wiring-тесты на каждый путь сбоя (сейчас таких тестов нет вообще); поведение успеха покрывается существующими тестами.
- Модель данных, БД, миграции, UI-код диалогов — без изменений.
