# save-error-reporting Delta Specification

## Purpose

Единое правило реакции на сбой записи в базу из UI: любое сохранение события или сущности, не дошедшее до базы, откатывается, оставляет приложение в согласованном состоянии и обязательно сообщает пользователю одним модальным сообщением.

## ADDED Requirements

### Requirement: Сбой сохранения всегда виден пользователю

При сбое записи в базу на любом пути сохранения из UI — создание события из диалога, редактирование события из диалога, обновление карточки сущности, одиночное создание сущности из «+»-меню шкалы, перенос дат жестом на шкале, инлайн-создание события из пустого дня — система SHALL откатить незавершённую транзакцию и показать ровно одно модальное сообщение об ошибке, из которого понятна причина. Молчаливый откат (без сообщения) SHALL NOT остаться ни на одном пути.

#### Scenario: Сбой при создании события из диалога

- **WHEN** пользователь нажал «Сохранить» в диалоге нового события и запись в базу не удалась
- **THEN** показано ровно одно модальное сообщение об ошибке, база не изменилась, шкала отображает прежнее содержимое

#### Scenario: Сбой при редактировании события из диалога

- **WHEN** пользователь сохранил правки существующего события и запись не удалась
- **THEN** показано ровно одно модальное сообщение об ошибке, событие в базе осталось в прежнем виде, детальная панель и шкала показывают прежние значения

#### Scenario: Сбой при обновлении карточки сущности

- **WHEN** пользователь сохранил карточку существующей сущности и запись не удалась
- **THEN** показано ровно одно модальное сообщение об ошибке, сущность в базе осталась в прежнем виде

#### Scenario: Сбой при одиночном создании сущности

- **WHEN** пользователь создал сущность из «+»-меню шкалы и запись не удалась
- **THEN** показано ровно одно модальное сообщение об ошибке, сущность в базе отсутствует

### Requirement: После сбоя сессия остаётся рабочей

После откатa из-за сбоя сохранения приложение SHALL оставаться usable: последующие сохранения (в том числе повторная попытка с теми же или исправленными данными) обязаны работать без перезапуска приложения.

#### Scenario: Повторная попытка после сбоя

- **WHEN** сохранение не удалось, пользователю сообщено, и после этого пользователь успешно сохраняет другую запись
- **THEN** второе сохранение проходит штатно, без сообщений об ошибках сессии

### Requirement: Успешное сохранение не показывает сообщений

Успешное сохранение любого вида SHALL завершаться без каких-либо сообщений об ошибке; подтверждение об успехе не требуется.

#### Scenario: Штатное сохранение

- **WHEN** сохранение события или сущности дошло до базы
- **THEN** модальных сообщений нет, шкала и панель деталей отразили новые данные
