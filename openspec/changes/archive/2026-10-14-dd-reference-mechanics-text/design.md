# Дизайн: dd-reference-mechanics-text

## Д1. Сборщик живёт в domain, карточка только вставляет блоки

Новый Qt-free модуль `app/dd/domain/grant_render.py` с единственной публичной дверью:

```python
def render_record_mechanics(record: Mapping[str, Any]) -> str:
    """Читаемый русский текст механики записи; '' если механики нет."""
```

Слои (принцип 1): domain не знает ни про `ExternalTextBlock`, ни про Qt. `reference_source._record_blocks` вызывает сборщик и оборачивает непустой результат в `ExternalTextBlock("Механика", ...)`. Порядок блоков: `desc`→«Текст» (как был), затем «Механика». Одна точка знания (принцип 2): словарь подписей живёт только в `grant_render.py`; карты характеристик/навыков переиспользуются из `character_render.STAT_LABELS/SKILL_LABELS`.

## Д2. Таблица типов грантов — закрытый словарь 28 типов

Каждый тип схемы `grant.json` получает собственный ветку-функцию; таблица `dict[str, Callable]` покрывает все 28 типов (проверяется тестом-равенством со списком типов из схемы). Формулировки строк ( RU, одна грант — одна строка, кроме трейта):

| тип | строка |
|---|---|
| hp-die | `Кость хитов: к<d>` |
| saving-throw | `Владение спасбросками: <хар-ки через запятую>` |
| armor-prof / weapon-prof | `Владение доспехами: …` / `Владение оружием: …` (enum-ключи → подписи: light/medium/heavy/shield, simple/martial; `armor-label`/`weapon-other` печатают своё поле `label`, если оно есть) |
| skill-fixed / skill-choice | `Навыки: …` / `Выбор <N> навыка(ов) из: …` (перечисление, если options — список ключей; иначе «из списка класса») |
| expertise-choice | `Владение (мастерство): выбор <N> из …` |
| tool-fixed / tool-choice | `Владение инструментами: …` / `Выбор <N> инструмента(ов)` (значения — русские строки как есть) |
| language-fixed / language-choice | `Языки: …` / `Выбор <N> яз.` (значения — строки как есть) |
| speed | `Скорость: <value> фт.` |
| size | `Размер: <подпись>` (tiny…gargantuan → Крохотный…Огромный) |
| asi-fixed / asi-flexible / asi-pool | `Улучшения характеристик: …` по полям values/sets/total |
| resource | `Ресурс: <name>` + строки max/maxExpr/rest |
| bonus | `Бонус: <label или target> <mode> <value/expr>` |
| feat | `Получает черту: <featId>` |
| equipment-fixed / equipment-choice | `Снаряжение: …` / `Выбор снаряжения` (options/items — строки как есть) |
| gold / gold-dice | `Золото: <amount>` / `Золото: <dice>` |
| pick-one | `<label>: выбор одного из <options>` |
| spellcasting | `Заклинательность: <ability>, тип <casterType>` |
| spell-fixed / spell-choice | `Заклинание: <slug>` / `Выбор <N> заклинаний` |
| trait | заголовок `«<name>»` отдельной строкой, ниже — `description` абзацем |

Неизвестный тип (будущая ревизия формата) → `Признак без перевода: <type>`. Неизвестный ключ enum (напр. новое оружие) → печатается как есть, строка не теряется.

## Д3. Полевой обход записи

До грантов, в фиксированном порядке: `prerequisite` → строка `Требование: <текст>` (обычная строка формата); record-level `speed`? — нет, только в grants; `size` → строка размера; `subclassLevel` → `Подклассы доступны с <n>-го уровня`; `info.primaryStats` → `Ключевая характеристика: …`; `info.tagline` → отдельная строка-слоган; `info.tags` → `Теги: …`; `info.complexity` → `Сложность: …`. `leveledGrants` — после плоских грантов, секциями `На уровне <n>:` (порядок по возрастанию level, сортировка устойчивая).

## Д4. Постулат честности untouched

SRD-слаг-заклинания (ветка `SPELL_TYPE` со слагом) печатают прежнюю строку «полный текст в LSS»; гримуар — прежнее «Описание». Сборщик вызывается только для шести типов записей. Никакого текста, отсутствующего в записи, не генерируется: каждая печатаемая строка обязана быть следствием конкретного поля (пин-тест на записи без грантов = карточка как раньше).

## Д5. Тестостратегия (планка 100 %)

- Модульный тест рендерера: по одному случаю на каждую ветку всех 28 типов + неизвестный тип + неизвестный enum-ключ + пустая запись + leveledGrants-порядок + precondition-строки (требование/размер/slug-поля).
- Тест равенства покрытия типов: список обработчиков == множество `type` из `grant.json` (защита от расширения схемы).
- Тесты `reference_source`: карточка класса SRD содержит «к12» и заголовок трейта; пустая запись — блоков нет; desc+grants — порядок «Текст», «Механика».
- Регрессия: `tests/dd/test_reference_source.py`, `tests/presentation/test_card_group_tabs.py` зелёные без правок ожиданий (кроме добавленных).
