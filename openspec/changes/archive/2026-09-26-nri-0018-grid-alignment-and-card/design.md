# Design: nri-0018-grid-alignment-and-card

## Context

См. proposal.md — Why. Техническая опора из кода:

- Мелкие глимф-контролы сегодня: ✕ и ✎ — текстовые `ThemeButton` без фиксированного размера; ✨ — `ThemeAiButton` (наследник `ThemeButton`, padding 8, ≈32 высоты); «+» шкалы — уже паттерн фиксированного квадрата (`TimelineRoot.squareSide: 30`); ◀▶ — нативные `QPushButton` 28×28 в `calendar_grid.py:161-175`.
- `ThemeCheckBox.qml`: индикатор 16 px геометрически центрирован стилем Basic, подпись центрируется `verticalAlignment: AlignVCenter` по строковому боксу шрифта, вертикальные padding'и равны нулю — отсюда оптический перекос.
- `ThemeSheetHeader.qml`: ряд «заголовок + кнопка ✕», слота действия нет; потребители — `EntityCardRoot`, `EventDialogRoot`.
- Заголовок карточки: `entity_card_dialog.py:286` `f"Карточка: {entity_type}"` — сырой ключ; русская метка уже есть в реестре (`display_label`), до заголовка не доходит.
- Вкладки деталей: `entity_registry.py` несёт `tab_label` (короткую подпись, NRI-0015); `DetailPanelRoot.qml` показывает её, полная `plural_label` — имя/подсказка; вкладки с `width: implicitWidth` (хвост M1 П2).
- Окно: `main_window.py:75` минимум 1024×680, явного resize нет — старт от sizeHint; `geometry_memory.py` восстанавливает сохранённую рамку с clamp в экран.
- Мастер: `calendar_wizard.py` — колонки фиксированной пропорцией `root.addLayout(left, 3) / right.addLayout(2)` (строки 160-164), центры шагов — поштучные `Qt.AlignHCenter` радио (293-294), минимум 860×620 (158); радио/чекбокс нативные, QSS-правил индикаторов в `theme/compiler.py` нет вообще.

## Goals / Non-Goals

**Goals:**
- Одна квадратная геометрия мелких действий, одна полоса высот в рядах, одна оптическая метрика подписей переключателей — живущие в компонентах, а не в местах применения.
- Детерминированная ширина каждого окна из шкалы 40; воспроизводимый оффскрин-пин каждой ступени.
- Заголовок карточки и размещение полной генерации — из реестра и слота шапки; поведение AI-контрактов (aiState, гейты, бандл) — без изменений.

**Non-Goals:**
- FI-5-остаток (живой ре-аудит реального мышиного контура) — отдельный прогон.
- Перекраска канваса чар-листа, поведение реестра окон меню, формат модальности — не трогаем.
- Новые токены темы не заводим: геометрия мелкого квадрата — константа внутри библиотечного компонента; QSS-индикаторы черпуют существующие токены (border/accent/radius/space).
- Движение текстовых (не-глимф) кнопок и нижнего ряда мастера — вне правок.

## Decisions

**Д1. `ThemeIconButton` в библиотеке — единственный носитель квадрата 32.**
Новый компонент: `Button` фиксированных 32×32 (константа компонента, не токен), radius/skin из токенов, доступные роль+имя через штатный контракт `qml-accessibility`. ✕ (`ThemeSheetHeader`), ✎, «+», ↑↓−+ перестраиваются на него; `ThemeAiButton` сохраняет своё оформление и состояния («✨»/«…»), но принимает фиксированный квадрат 32 (наследование от `ThemeButton` остаётся, сторона проставляется в нём же). Почему не `squareSide` -свойство на `ThemeButton`: «одно знание — одно место», калибр живёт в одном компоненте (AGENTS), иначе каждая островная кнопка сможет выбрать свою сторону. Альтернатива (макеты через padding) отброшена — padding не даёт точного 32×32 на всех глифах.

**Д2. Оптическое центрирование `ThemeCheckBox` внутри компонента.**
`FontMetrics` контрольного шрифта: индикатор ставится в `topPadding + (availableHeight − box)/2 + min((descent + leading)/2, 1)` (кап 1 px — чтобы поправка никогда не выходила за допуск пина ±1 px на шрифтах с большой descent; решение владельца change от 2026-09-25), control'у проставляются верх/низ padding из `space.sm` — полоса чекбокса совпадает с кнопками ряда (≈32). Пин — оффскрин-геометрия: центр индикатора и центр строки чернил подписи (по `FontMetrics.boundingRect("Х")`) с точностью до 1 px; плюс пин полосы (implicitHeight чекбокса = полоса ряда). Альтернатива — ручная подстройка в точках применения: против контракта компонентной библиотеки.

**Д3. `ThemeSheetHeader`: слот действия после текста заголовка.**
В ряд добавляется группа действий между `TitleText` и кнопкой закрытия (отступ `space.sm`, горизонтальное центрирование как у заголовка); API — default-свойство строки (`default property list<Action>` или alias), закрытие остаётся у правого края. Карточка кладёт в слот `ThemeAiButton` (объектное имя `entityGenerateButton` сохраняется — пины e2e/wiring), диалог события — свою кнопку полной генерации. Заголовок становится хостом, а не конвейером: сигнал закрытия не меняется.

**Д4. Заголовок карточки — `display_label`.**
`setWindowTitle(f"Карточка: {entity_registry.display_label(entity_type)}")` в `entity_card_dialog.py`; сырой ключ остаётся только в window-object-контрактах. Тест: карточка каждого типа — русский заголовок; grep-пин «Карточка: {entity_type}» отсутствует.

**Д5. Полные вкладки + старт.**
`tab_label` удаляется из `EntityDescriptor`, viewmodel отдаёт `plural_label` как текст/имя/подсказку; пины коротких подписей (NRI-0015) переустанавливаются на полные. Дефолт: при отсутствии сохранённой рамки окно ставится 1280×800 (Resize на show в composition-root-механике `WindowGeometryMemory.restore`). При восстановлении — ширина = max(сохранённая, `min_tabs_width`); минимум считается панелью деталей (сумма `implicitWidth` четырёх полных вкладок + отступы TabBar), константа живёт в панели, `attach(role="main")` принимает провайдер ширины. `setMinimumSize(1024,680)` остаётся жёстким полом системы; правая панель сплиттера получает минимум по той же константе — OBS-1 («Показать всё» в обрез) исчезает на типовых 1280 и на сохранённых 1028+ после расширения.

**Д6. Ширины окон — константы в существующих точках.**
Правки значений: QML `implicitWidth` (лаунчер 480 остаётся, event 700→720, viewer 720, xlsx 620→640, preset 540→560, llm 620→640, sheet list floor 440) и python-_floor'ы диалогов синхронно (event_dialog 700→720, preset 540→560, xlsx 620→640, llm 620→640, doc viewer min 640→720, table panel 420→440, card floor 750→760). Отступы: `SearchBarRoot` space.xs→space.md, `DocViewerRoot` space.sm→space.md. Пины — табличный оффскрин-тест «все естественные ширины кратны 40 и равны целевым».

**Д7. Мастер: левая граница и колонка по содержимому.**
Снимаем `Qt.AlignHCenter` у радио (и любые future-центрирования шага); левая колонка: вместо stretch 3:2 — ширина левой колонки = natural `QStackedWidget.sizeHint().width()` (максимум по всем страницам), округлённая к 40 с запасом отступов и потолком ~520; предпросмотр получает stretch 1; `setMinimumSize` = (ширина левой колонки + минимум предпросмотра, прежняя высота); тест-пин: ширина шага-выбора ≤ колонки, радио на левой границе заголовка (layout-позиции через `QTest`), минимум окна покрывает колонку+сетку. Альтернатива (фикс-константа 440/480) отброшена: месяцы/вставные дни шире фиксированного предположения.

**Д8. Индикаторы `QCheckBox`/`QRadioButton` — QSS генерируемого листа.**
В `compile_qss` (chrome-область) и в лист попапов даты добавляются правила `::indicator`: бокс 16, рамка `border`, радиус (чек — `radius.sm`, радио — круг), выбранное состояние — `accent`+`accent.fg` галочка/точка; имена style-facing правил укладываются в существующий механизм «переименование классов ловится тестом темы». Off-skin: лист не применяется → нативность автоматом. Высоты строки навигации попапа: `setFixedHeight(32)` стрелкам/комбо/спиннеру/чекбоксу (+ стрелки с 28→32).

## Risks / Trade-offs

- Изменение полосы `ThemeCheckBox` (padding) сдвигает пиксельную приёмку grab-тестов → обновить эталоны в том же комите; проверить точки применения (7 мест) глазами в живом ре-аудите.
- QSS `::indicator` на macOS частично игнорирует размеры без заданных границ → правила задают полный набор (size/border/radius/background); при отказе стиля — откат к нативным индикаторам только для радио с фиксацией исключения в QA-отчёте (не молча).
- `sizeHint` календарного стека мастера может оказаться больше удобной колонки (страница месяцев) → потолок 520 + горизонт скролл-лист уже есть у строк месяцев; живой ре-аудит подтверждает плотность.
- Полные вкладки не влезают при искусственно-узком окне (<порога) → вкладкам остаётся `implicitWidth`-право без обрезки подписи; панель «схлопывается» до своего минимума — окно шире порога по Д5, крайний случай задокументирован сценарием main-window.
- Перенос ✨ полной генерации в шапку обоих листов меняет хук-позиции e2e → обновить селекторы (objectName сохраняется, меняется родитель).

## Migration Plan

Правки только интерфейсные: схема БД и форматы файлов не задеты, миграций нет; откат — реверт коммита пакета. Документация (AGENTS-шаблон дерева, чек-лист, CHANGELOG, строка П5 в дорожной карте) — в том же изменении.

## Open Questions

- Точная целевая ширина левой колонки мастера (из таблицы 40: 440 или 480) решается измерением `sizeHint` в первом же таске Д7 — на спецификацию влияет только через сценарий «нет мёртвой зоны», который от значения не зависит.
