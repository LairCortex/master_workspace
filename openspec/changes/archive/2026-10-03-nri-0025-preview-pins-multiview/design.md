## Context

См. `proposal.md` — Why. Текущее состояние, важное для подхода:

- Колонка предпросмотра — QML-остров `EntityPreviewWidget` (`presentation/views/entity_preview.py`) поверх `EntityPreviewViewModel` (один объект «показанная сущность → готовые к риске тексты, секции, связи»). Остров только красит; жизненные правила колонки живут в коннекторе `ApplicationWiring` (`_connect_preview`, `_show_in_preview`, `_preview_shown`, `_on_preview_entity_requested`) — это зафиксированная норма AGENTS/Main-window columns.
- Правила дерева доступности: роль и нажатие принадлежат библиотечному компоненту, имя — месту применения; для значковых кнопок эталон — `ThemeIconButton` (штатный `Button` + компонентный `onPressAction`, NRI-0018/0023); фиксированные формулировки `description` защищаются словарём `DESCRIPTION_VOCABULARY`.
- Настройки одной игры живут в ключе/value `game_settings` (репозиторий `GameSettingsRepository` — единственное место обращения к таблице, ключи — именованные константы), запись идёт через транзакцию `GameSessionUoW`; примеры — ключ «сейчас» (NRI-0021/0023) и черновик календаря.
- Путь клика по сущности в поиске сейчас: `get_last_event_for_entity` → выбор события на шкале → `_on_preview_entity_requested` (wiring.py, `on_search_result`).

## Goals / Non-Goals

**Goals:**
- Колонка = до 3 закреплённых карточек + 1 живая; жизненные правила (порядок, дубли, лимит, хранение) — у коннектора, остров остаётся «только красит».
- Разложение VM на панель-на-карточку без переписывания правил отрисовки (заголовок, поля, возраст, картинки, связи, упоминания — один источник, как сейчас).
- Канал закрепления — второй сигнал острова наружу по той же шине `(тип, id)`.
- Кликабельная булавка по контракту дерева доступности без новых пределов координатности.

**Non-Goals:**
- Перетаскивание карточек, изменение порядка закрепления, свои размеры pane-ов — только порядок закрепления и равные высоты.
- Закрепление событий (только сущности четырёх типов — живая область и так события не показывает).
- Сохранение закреплений между разными играми, синхронизация с ui.json.
- Изменение двойного клика поиска и поведения результатов-событий.

## Decisions

### Д1. Слоты владеет коннектор; остров получает готовый список pane-ов

`ApplicationWiring` хранит `_preview_pins: list[tuple[str, int]]` (до 3, порядок = порядок закрепления) и `_preview_live: tuple[str, int] | None` — замена `_preview_shown`. По событию выбора коннектор грузит сущность через entity service и толкает фасаду полный кадр: `show_slots(pins: list[(type, entity)], live: (type, entity) | None)`. Фасад и VM не знают ни правил лимита, ни хранения — ровно как сейчас с жизненным правилом колонки.
Альтернатива (перенести правила в VM) отвергнута: VM синхронная и не видит сервисы, а норма «lifecycle rule lives in ApplicationWiring» уже записана в AGENTS.

### Д2. VM колонки списком управляет, карточка рендерит

Из нынешнего `EntityPreviewViewModel` выделяется `EntityCardViewModel` (всё поле-за-полем существующего `_rebuild`: заголовок-полоса «Карточка: <тип>`, поля, возраст по «сейчас», картинка, секции, связи; плюс флаги `pinned`/`slotIndex` для места применения). `EntityPreviewViewModel` становится списочным: свойство `panes` (QVariant-список карточек + признак пустой живой области), `contentChanged` на любой смене. Подписка на «сейчас» — одна на VM колонки, перекрашивает все pane-ы (возраст живёт у каждого). Слоты-обработчики острова несут пару: `requestEntity(type, id)` без изменений (pane поднимает её вверх), новый `requestPinToggle(entity_type, entity_id, pinned)` — булавка работает по паре, не по индексу (индекс протухает между нажатием и ответом коннектора). Картинка: фасад строит просмотр от pane-а, поднявшего `imageRequested` (пара + loaded-сущность), — прежняя поза 4096-слота сохраняется.
Альтернатива (четыре отдельных VM-экземпляра нынешнего класса) отвергнута: подписка на «сейчас» и перекрас по сохранениям размножились бы на четыре владельца.

### Д3. Закрепление/открепление — канал коннектора + тонкий сервис настроек

Фасад поднимает `pinToggled(entity_type, entity_id, pinned)`; коннектор: если `pinned=False` и лимит не исчерпан — добавляет пару в конец `_preview_pins`; если `pinned=True` — убирает пару. Затем одно сохранение в игру и один новый кадр `show_slots`. Живая область при закреплении её пары очищается (`_preview_live = None`) — визуально карточка «остаётся на месте», потому что тот же кадр показывает её закреплённой, а под ней пустая живая область (решение пользователя Q12: закрепление живой карточки делит колонку, вторая часть — пустой живой слот).
Хранение: ключ `PREVIEW_PINS_KEY = "preview_pins"` в `game_settings_repository.py` (JSON `[{"t": "character", "i": 3}, …]`, порядок значим), доступ — новый application-сервис `PreviewPinsService(get_pins/save_pins)` поверх `GameSettingsRepository` с одной транзакцией `GameSessionUoW` на действие; композиция в `main.py`. Читается при открытии игры (после сборки главного окна): пары грузятся через entity services, грузящиеся не удалось — пара молча отбрасывается и списком НЕ перезаписывается (молчаливое излечение хранилища — следующий pin/unpin запишет чистый список; фоновая запись на ровном месте не нужна).
Альтернатива (роль окна в ui.json) отвергнута: закрепления — данные мира игры, а не размещение окна; ui.json глобален, а колонка не помнит размещений с NRI-0024.

### Д4. Живой указатель: без дедупликации с закреплениями

`_show_in_preview` становится «показ в живую область»: no-op только если пара уже равна `_preview_live`; совпадение с закреплением НЕ проверяется — дубль разрешён (spec `preview-pins`). Переходы по связям/упоминаниям из pane-а любое пишут живую область; синхронизация средней колонки (прежний дизайн D4 NRI-0022) не меняется. Перекрас по сохранению карточки (сейчас сравнение с `_preview_shown`) — проверка членства пары в `_preview_pins + {_preview_live}` и перекрас каждой копии свежим чтением. Удаление: пара в закреплённых — вычёркивание + сохранение списка + кадр; пара живая — чистка живой области (прежний канал очистки удалённых popup-сущностей переписывается на слоты).

### Д5. Булавка — компонентная seat, имя говорит состояние

Кнопка — `ThemeIconButton` (лицо `ghost`, как шеврон шкалы NRI-0023: роль `Button` и `onPressAction` внутри компонента), сидит в полосе заголовка карточки справа от подписи «Карточка: <тип>». Имя — местом применения, ровно четыре фиксированные формулировки: «Закрепить карточку» (живая, можно), «Открепить карточку» (закреплённая), «Уже закреплена» (живая копия закреплённой, неактивна), «Можно закрепить только 3 карточки» (достигнут лимит, неактивна); те же тексты — подсказки (`tooltip_shim`, в дерево не попадает — известный предел ④). `description` не заполняется: имя уже называет действие. `DESCRIPTION_VOCABULARY` не расширяется; новые строки имён фиксируются guard-тестом соглашений и offscreen-пином `doAction("Press")` по образцу `test_theme_checkbox_accessibility.py`.
Альтернатива (своя кнопка с чекбоксоподобным состоянием) отвергнута: штатный `Button`-seat уже покрывает и нажатие, и доступность, и внешний вид призрака.

### Д6. Раскладка: равные pane-ы вертикально, пустая живая область — подсказка

Колонка — вертикальный список (`ColumnLayout`), каждый pane `Layout.fillHeight` + собственная `Flickable/ScrollView`, полоса заголовка pane-а прикреплена сверху и не прокручивается (прижатие булавки к прокручиваемому контенту — отдельная мелочь, решается фиксацией полосы). Один pane = вся колонка (внешне как сегодня); пустая живая область = подсказочный текст без полосы заголовка. Визуальные детали (отступы pane-ов, разделители, минимальная высота, вид пустой живой области) — checkpoint у `ui-ux-designer` на реальном экране ДО задачи по раскладке (зафиксировано в tasks).
Альтернативы (табы, гармошка) отвергнуты пользователем: «держать в фокусе» требует одновременной видимости.

### Д7. Поиск: путь сущности укорачивается до живой области

`on_search_result` для не-событий — только `_show_in_preview(type, id)` (раньше: `get_last_event_for_entity` → выбор события → подсветка). Единственный потребитель `get_last_event_for_entity` — этот путь; если за время реализации других потребителей не найдётся, метод сервиса и его тесты удаляются (мёртвый код не оставляем). Событийная ветка и двойной клик не трогаются.

## Risks / Trade-offs

- [Четыре pane-а по ~170 px при сохранённом 1028×708 — карточка едва читается] → равные высоты зафиксированы решением пользователя; независимая прокрутка + checkpoint ui-ux до реализации раскладки; колонка растёт с окном.
- [Дубль одной сущности грузит её картинку дважды] → оба pane-а грузятся через общий `image_utils`-конвейер с тем же слотом 240 px; двойное чтение файла дешевле кэша, решено не усложнять.
- [Имя булавки меняется по состоянию — живые audit-реестры видят другие строки] → фиксированный набор из четырёх формулировок пинится guard-тестом; живой аудит сверяется с ним же.
- [Переход `_preview_shown` → слоты задевает существующие тесты NRI-0022] → тесты обновляются в той же нарезке; поведение «при нуле закреплений всё как раньше» пином отдельно, чтобы регрессия не спряталась.
- [Протухание ссылки `{"t","i"}` после удаления сущности в другой сессии] → молчаливый отброс при восстановлении (spec-сценарий), повторная запись списка — только по следующему действию пользователя.

## Migration Plan

Схемы БД не меняются (только новый ключ `game_settings`) — миграций нет, откат = удаление кода, устаревший ключ молча игнорируется (образец отсталых ролей размещения из NRI-0024). Пользовательских данных не затрагивается.

## Checkpoint раскладки (задача 3.1, решено ДО 4.1)

Эталон живых замеров и аргументация — `docs/qa/2026-10-02-preview-pins-layout.md`; реализующая группа 4 берёт числа отсюда, повторного обсуждения пикселей нет.

1. **Pane** = полоса заголовка 32 px (`PanelHeader.band()`) + свой `CardPanel` (рамка 1 px `color.border`, `radius.sm`, канва `color.bg.canvas`) с собственным `Flickable`; полоса лежит ВНЕ прокрутки, её фон `color.bg.surface`. Отдельных разделительных линий между pane-ами нет — «рамка + воздух»: зазор между pane-ами `space.sm` (8 px), внутри pane `space.xs` (4 px), отступ колонки `space.xs`. Минимальная высота pane 88 px (32 + 4 + канва ≥ 48 ≈ две читаемые строки); на окне 708 px минимум не выбирается (4×88 + 3×8 + 2×4 = 384 ≤ ~535 доступных).
2. **Ось заголовков**: колонная полоса «Карточка» рисуется только при нуле pane-ов; при одном и более pane-ов общую ось трёх колонок занимает полоса первого pane-а (та же высота 32 px и тот же отступ), выравнивание оси (живой фикс 2026-09-26) сохраняется.
3. **Пустая живая область** = `CardPanel` БЕЗ полосы заголовка + `HintText` ровно дельтинского текста («Выберите сущность — здесь появится её карточка»), `color.fg.muted`, italic, `font.size.md`, по центру канвы с `wrapMode: WordWrap` (до 3 строк; на колонке 220 px elide съедал бы фразу). Участвует в равных высотах на тех же правах (`Layout.fillHeight` + `minimumHeight: 88`) — первое закрепление даёт ровно 50/50.
4. **Булавка**: `ThemeIconButton` с лицом `ghost`, квадрат 32×32, правый край на inset `space.sm` от края pane, вертикаль — центр полосы. Глиф Lucide `pin` — в вендореном `icons.js` его нет, доввендорить через `scripts/vendor_lucide.py` (второго пути глифов не заводим). Четыре имени ровно Д5, те же строки — `Nri.tooltip`; `description` пустой, `DESCRIPTION_VOCABULARY` не расширяется. Неактивное состояние призрачного лица = глиф `color.fg.muted` без подложки (активное — `color.fg.primary`); контрасты по токенам 16,3:1 / 11,4:1 активное и 5,6:1 / 4,9:1 неактивное (light/dark) — выше порога 3:1; собственного hover-лица у ghost нет (норма после живого аудита 2026-09-30), ответ hover — подсказка.
5. **Один владелец состояний булавки**: в `pane()` добавляется `pinState` живой карточки (`"unpin"` / `"duplicate"` / `"limit"`), чтобы четверка имён и число «3» жили в одном месте рядом с VM, а не в QML-ветвлении. Запрет: вычислять лимит в двух местах.
6. **Читаемость при 3–4 pane-ах** (менять равные высоты нельзя): правило верхнего среза — identity-полоса (картинка слева, короткие поля справа) даёт имя/рейтинг/даты/возраст в верхних ~95 px; у имени — `maximumLineCount: 2` при канве pane-а < 110 px; внутренний скролл при 4 pane-ах — принятая цена равных высот, не дефект; главному окну рекомендуется `minimumHeight ≈ 600`, чтобы сплиттер не срезал минимальные pane-ы.
7. **Доступность**: новый интерактив ровно один (булавка на штатном `Button`-seat `ThemeIconButton`), шесть пределов координатности не расширяются; `objectName`-контракт для тестов — `previewPane_<slotIndex>`, `previewPaneBand_<slotIndex>`, `previewPinButton_<slotIndex>`, `previewLiveEmptyHint` (отдельно от сегодняшнего `previewEmptyHint` полностью пустой колонки).
