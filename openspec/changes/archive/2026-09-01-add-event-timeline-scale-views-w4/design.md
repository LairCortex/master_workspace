# Design: add-event-timeline-scale-views-w4

## Context

См. proposal.md — Why; поведение — в delta-спеках (grill-сессия 2026-08-31 зафиксировала все 19 решений, этот документ только «как»). Текущее состояние, важное для формы решений:

- `app/presentation/views/timeline_rows.py` — Qt-нулевое ядро: `build_rows` (сутки→строки `EVENT/EMPTY_DAY`), `index_at_y` (равновысокие строки → деление), `normalize_range`, `prev/next_event_index`.
- `app/presentation/views/timeline_widget.py` — `TimelineListView` + `_RowDelegate`: константа `ROW_HEIGHT = 24`, `setUniformItemSizes(True)`, `ScrollPerItem`, захват жеста рейки (клик-прыжок/drag), липкая `QLabel`, `bracket_lanes` сейчас живёт здесь же (принимает домены, возвращает lane по id); палитра-пасхалка `_Palette` из `token_rgb`, оф-скин на Qt-глобалах; инвариант `tests/presentation/test_no_chrome_hex.py` сканирует файл.
- `app/presentation/viewmodels/timeline_viewmodel.py` — держит `_all_events`, фильтр-пару, `rows = build_rows(events, start, end)`; id-контракт `select_event_by_id`.
- Модель данных: `Event` (domain) / `EventModel` (SQLAlchemy) без типа; связи M2M: characters/locations/organizations/items. Миграции — список `_MIGRATIONS` в `init_db()` (`app/main.py`), alembic не используется.
- Токены: `app/presentation/theme/tokens.json`, каждый `{light, dark}`; обязательный токен без читателя запрещён спекой ui-theme — этот кусок вводит для chart-палитры читателя-делегат (зафиксировано в delta ui-theme).

## Goals / Non-Goals

**Goals:**
- Единый механизм «единица ступени» для строк, рейки, липкой, drag'а и скобок — один код на сутки/месяц/год, а не три режима.
- Все новые данные — per-game и переживающие миграцию; цвета — только токены.
- Сохранить без изменений: id-контракт, чип-фильтр, wheel-без-Ctrl, Alt+↑/↓, семантику попадания фильтра, оф-скин, live-retheme, инвариант «ни hex, ни palette()».

**Non-Goals:**
- Drag-редактирование дат (W5), сохранение вида, colorpicker, дорожки по сущностям на суточной ступени, типы в LLM-промптах/поиске/деталях, types в HTML web-игрока.

## Decisions

### D1. Единица ступени — параметр ядра, а не третий виджет

`timeline_rows.py` расширяется, виджет остаётся один:

```python
class ScaleUnit(Enum): DAY="day"; MONTH="month"; YEAR="year"

class RowKind(Enum):
    EVENT="event"; EMPTY_DAY="empty_day"; UNIT="unit"; SECTION="section"

@dataclass(frozen=True)
class Row:
    kind: RowKind
    date: date                      # якорь позиции: сутки или первый день единицы
    event_id: int | None = None
    start: date | None = None
    end: date | None = None
    name: str = ""
    unit: ScaleUnit = ScaleUnit.DAY # смысл kind для этой позиции
    unit_count: int | None = None   # счётчик событий для UNIT
    group_key: str | None = None    # заголовок/секция для SECTION
```

- `build_rows(events, range_start, range_end, unit=DAY, group_by=None)`: при `unit=DAY` возвращает ровно текущий выход (обратная совместимость вызова и юнитов W3b). На MONTH/YEAR перечисляет все единицы окна (мин–max диапазона или границы фильтра, выровненные к границам единиц: месяц окна начинается с месяца минимальной даты, год — с года), пустые единицы → `UNIT` с `unit_count=0`.
- `group_by` (`char/loc/org/item`) влияет на `DAY` только как порядок внутри дня: сортировка `(has_group, group_name, start, id)` — сначала связанные с сущностями (по названию группы), затем несвязанные по `(start, id)`; на `MONTH/YEAR` с `group_by` список разбивается секциями (см. D8).
- Событие попадает в единицу/секцию, если её промежуток пересекает `[start, end|range_end]` (открытый конец — до конца окна). Дублирование в секциях — просто повторная выдача строки `UNIT` с `event_id=None` и своим `group_key`.
- `index_at_y` переименован-в-себе не будет: contract «равновысокие строки → `y // ROW_HEIGHT`» инвариантен к высоте и виду строк; `prev/next_event_index` на не-суточных ступенях возвращают `UNIT`-позиции с `event_id=None`, и view трактует «строки событий отсутствуют» как сигнал спустить лестницу (D4).

Почему не отдельный unit-модуль: одна модель строк — один делегат — один путь жестов; два файла поделили бы половинки общих хелперов. Альтернатива (свой `QListView` на ступень) отвергнута: пришлось бы удвоить липкую/рейку/hover/hit-test.

### D2. Лестница и якорь — состояние виджета, не VM-контракта

`TimelineListView` получает `_unit: ScaleUnit` и `_group_by: EntityKind | None` (по умолчанию `DAY/None`, НЕ сериализуются — «вид не переживает перезапуск» из спеки). Смена публичным API: `set_view(unit=..., group_by=...)`; VM (`TimelineViewModel`) хранит те же два поля, прокидывает в `build_rows` и в `update_events` — единый источник правды остаётся VM (view не переживает закрытие панели, VM тоже, но фильтр живёт в VM).

`Ctrl/Cmd + колесо` в `wheelEvent`: событие с модификатором не трогает скролл; шаг лестницы вычисляется от текущей ступени, якорь — дата под липкой (верхний видимый ряд) или первая видимая дата при отдалении; после перестроения позиция чтения ставится scrollToItem(PositionAtTop) на первую позицию якорной единицы. Переключатель в шапке — три кнопки (checkable) в стиле чипа W2b + `QMenu`-подобный поповер для группировки не нужен: пять пунктов делает компактным `QToolButton`-меню или сегментом кнопок — решение оставлено верстке, контракт: кнопки `uiRole="chip"`-класса, состояние видно.

Двойная прокрутка-на-одну-позицию и отсутствие Ctrl-жеста на macOS trackpad (angleDelta без модификатора) остаются прежними — Ctrl не покидает wheelEvent.

### D3. Границы фильтра нормализуются в виджете, фильтр не меняется

Drag рейки на MONTH/YEAR работает по index-единицам (`index_at_y` тот же); на отпускании виджет маппит `(anchor_idx, end_idx) → (min_unit_start, max_unit_end_excl - 1 день)` как `date`-границы: месяц → `1 число … last-day-of-month`, год → `1 января … 31 декабря`. Эмит прежний: `day_range_applied(start: date, end: date)` — чип-путь `_on_filter_range` и семантика VM («целиком внутри диапазона») НЕ меняются (grill Q15(a)). Клик-прыжок остаётся без emit.

### D4. Спуск лестницы при внешнем выборе — в VM-методе выбора

`select_event_by_id` остаётся контрактом. Когда VM получает id выбранного/наведенного извне события (поиск, jump-команды): если `self._unit != DAY` или событие отфильтровано текущей ступенью/секцией не представлено — VM ставит `unit=DAY`, пересобирает rows, затем выбирает. Реализация — точечный хелпер `_ensure_day_unit_for(event)` в VM перед установкой выделения; view к этому моменту уже перестроен по `events_changed` и выделяет строку привычным `set_selected`/`scroll_to`. `jump_prev/next_event` из шапки вызывают тот же путь. Промах (event вне фильтра) — поведение не меняется: сброс во всех слоях.

### D5. Типы: отдельная сущность данных, цвет — индекс палитры

- БД: новая таблица `event_types` (`id, name, color_index INT, sort_order INT`) + колонка `events.event_type_id NULL FK` — миграция в `init_db()`: `CREATE TABLE` + `ALTER TABLE events ADD COLUMN` + conditional-засев шести дефолтов (`Сюжет, Побочное, Слух, Встреча, Ров будней, Находка` → `color_index=1..6, sort_order=i`) при пустом SELECT. Откат = удаление таблицы/колонки не делается (привычка репозитория: only-forward).
- Domain: `EventType(name, color_index, sort_order, id)`; `BaseEntity` не трогаем, у `Event` появляется `event_type: EventType | None`.
- Материализация типа в строку шкалы: `timeline_rows.Row` несёт `token_key: str | None` — `"color.chart.{color_index}"` для события с типом и `None` для события без типа; delegate вызывает `token_rgb(runtime, theme, row.token_key or "color.fg.muted")`. Так ядро остаётся Qt-нулевым, а delegate не знает про типы.
- Цвет-индекс замкнут `1..8`: валиден только диапазон токенов, colorpicker'а нет. Прокрутка индексов при добавлении 9-го типа: индекс = первый неиспользуемый, иначе `((max_index+1) % 8)`.
- `EventTypeRepository` + методы `EventService` (`get_event_types/save_event_type/delete_event_type` — delete делает `UPDATE events SET event_type_id=NULL WHERE ...` затем DELETE типа, в одной транзакции — «удаление отвязывает»). Domain-маппинг: базовый репозиторий событий подтягивает join `event_type` (load relationship; N+1 не плодим — выборка событий одна).
- Диалог `EventTypesDialog` — по образцу `MonthSettingsDialog`: список + переименование/порядок (`QSortFilterProxy`-перетаскивание не нужно: кнопки ↑/↓), кружки цвета (`QToolButton` checkable по 8, цвет — производная токена, оф-скин — серые с порядковым номером в tooltip), добавить/удалить. Вход — «+»-меню панели событий. Подключение темы — `attach_theme` (W2a). Диалог событий: `QComboBox` делегат-стиля не нужен: `QComboBox` с `setItemData(icon=...)` цветных точек + `setItemData(text)`; тип — опционален.
- LLM/xlsx-пути типы не заполняют (колонки не добавляются) — событие остаётся без типа.

### D6. Chart-токены: восемь парных цветов, только делегат-читатель

В `tokens.json` добавляются `color.chart.1…8`, каждый `{light, dark}`; имена-значения подбираются так, чтобы (a) различаться попарно на глаз ( Hue-расторы ≥ ~30° + вариация светлоты), (b) контрастировать (WCAG-like различимость цвета точки на `bg.surface` — пиксель-тест: RGB пикселя метки ≠ RGB фона и Δ по каналу ≥ порога, тест фиксирует константой), (c) совпадать по смыслу light/dark (те же hue). `build`-datas токенов не меняется — файл уже едет целиком (W1). QSS/CSS правила для chart не вводятся (проверка — тест-скан генератора/правил). PyInstaller spec не меняется (datas уже включает `app/presentation/theme/`; проверить hiddenimports — новых нет).

### D7. Делегат и палитра: точечная метка типа и позиции единиц

`_Palette` дополняется `type_dots: dict[int, QColor]` (8 derivations) — пересобирается в `_rebuild_palette` (live-retheme уже есть). Вид позиции:
- `EVENT` (DAY): точка типа слева от метрики rail_width + `TEXT_LEFT_PAD`, квадрат `DOT_SIZE=8`, вертикально по центру; поверх выделения рисуется без обводки.
- `UNIT` (MONTH/YEAR): заполненная — «Март 1245 · 4 события» (`fg.primary`), пустая — приглушённая (`fg.muted`), точка не рисуется.
- `SECTION` — `uiRole title` шрифт-вес, текст = `group_key`; рейка секции рисует свои тики единиц.
- Скобки: `bracket_lanes` переезжает в `timeline_rows.py`, получает `unit`-режим: span события маппится на `[first_unit, last_unit]`, lane-упаковка та же (первая свободная, оборот при `BRACKET_MAX_LANES`).
- `ROLE_SHOW_TICK/ROLE_SHOW_MONTH` дополняются `ROLE_SHOW_YEAR` (первая позиция года на MONTH, единственная «подпись года» на YEAR-ступени: подпись года рисуется где подпись месяца на DAY).

### D8. Группировка в ядре: ключ — имя сущности, ties — id сущности

`group_by` в `build_rows` принимает «маппинг события»`(`get_groups(event) -> Sequence[str]`)`— параметр-функцию или готовый `event_groups: dict[int, tuple[str, ...]]`, вычисленный VM (VM читает доменные связи `event.characters`/... — только имена; пустая связь → «Без привязки» как отдельный ключ). Так ядро не знает про домен (те же `_EventLike`-протоколы). Секционные строки-заглушки: позиция `SECTION` перед каждой группой единиц; порядок секций: отсортированные имена, «Без привязки» последней; внутри — только единицы из `event_groups`.

## Risks / Trade-offs

- [Ядро разрастается: четыре вида строк × две опции] → таблица переходов фиксируется юнитами `build_rows` до писка делегата; специрование через matrix-тесты (unit × group_by × filter), делегат остаётся тонким рендерером полей Row.
- [Скорость: MONTH/YEAR перечисляют все единицы окна, YEAR окна в сотни лет — не проблема; MONTH при фильтре на 50 лет — 600 позиций, ок] → равновысокие строки + uniform sizes; при реальной беде — virtualizация QListWidget уже есть.
- [`Ctrl+колесо` на macOS — системный жест масштабирования в отдельных приложениях, внутри Qt приходит как wheel+ControlModifier] → принимаем, не глушим системные: жест работает только над панелью событий.
- [Дублирование события в нескольких секциях ломает «уникальность» позиции при выборе: клик по позиции-месяцу ничего и не выбирает] → выбор остаётся суточным; на крупных ступенях секционные позиции — только счётчики.
- [Тип события в старых играх = NULL везде — шкала с точкой fg.muted изменит привычный вид строк у всех] → принято grill-решением; приёмочный пиксель учитывает и «событие без типа».
- [Миграция с seed не идемпотентна без guard] → `INSERT ... WHERE NOT EXISTS(SELECT 1 FROM event_types)`-стиль внутри той же step-функции init_db (как существующие ad-hoc rebuilds).
- [Инвариант «ни hex» против цвета-в-данных] → color_index не цвет, а индекс токена; валидация диапазона 1..8 на записи.

## Migration Plan

Только forward within `init_db()`: создать таблицу → добавить nullable-колонку → засев по guard → backfill не нужен (NULL везде). Откат версии приложения = игра остаётся с неиспользуемой колонкой/таблицей (SQLAlchemy ignores), совместимость не роняется.

## Open Questions

- Точная раскладка переключателей в шапке (сегмент vs чипы) и текст подписей «сутки/месяц/год» — верстка на apply, контракт фиксирован (D2).
- Эвристика «первый неиспользуемый цвет-индекс» при 9-м типе — детали взаимодействия в диалоге (автоназначение или «выбери цвет») — уточнить на apply, спеке достаточно «цвета из палитры».
