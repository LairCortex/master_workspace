# Proposal: nri-0005-architecture-refactor

## Why

Сплошная ревизия `app/` (2026-09-22, карта находок — `docs/refactoring-audit.md`) зафиксировала системные отклонения от базовых принципов: прикладной слой импортирует представление, модели представления работают с сессией БД напрямую, реестр типов сущностей разбросан текстовыми словарями примерно по 15 местам (объявлённый `EntityType` не используется нигде), владение транзакцией решается комментарием в четырёх слоях одновременно, шесть файлов-гигантов (от 678 до 1711 строк) смешивают по 5+ ответственностей. Сейчас добавление пятого типа сущности или изменение одного правила хранения требует синхронной правки множества файлов, а расхождения не обнаруживаются ничем — словари падают `KeyError` или тихо пропускают записи. Рефакторинг точечный, наблюдаемое поведение, схема БД и форматы файлов не меняются.

## What Changes

Поведение приложения, формат БД, формат `.nex/.nri`, формат `~/.nri_manager/llm_config.json` и внешний API LLM не меняются. **BREAKING-изменений нет.** Волны выполняются строго последовательно, каждая задача — зелёный полный прогон тестов после неё.

- **Волна 1 — слои и приватное (A1, A2, C1):** убрать импорты представлений из прикладного слоя (`character_sheet_service.py` — каталог пресетов переезжает в домен, `_TYPE_UNSET` становится публичной константой прикладного слоя); соединитель `app/application/wiring.py` переезжает в `app/presentation/wiring.py` — он связывает виды с сервисами и по природе принадлежит представлению (импортует его диалоги законно; импортуют его всего два модуля); вывести `AsyncSession` и ORM-модели из `calendar_wizard_viewmodel` (новый метод сервиса настроек вместо прямого `session.get`); в `BaseRepository` — публичные свойства `session`/`model`, сервисы больше не обращаются к `repo._session/_model` (6 мест).
- **Волна 2 — единое знание (A3, A5, C3, C4, C7):** `route_insert_dates` в `coord_mapping.py` переиспользуется xlsx-импортом (уходит дубль правил дат); одна функция подтверждения потери изменений вместо четырёх копий в `main.py`; примесь `IslandDialogMixin` для однотипной QML-обвязки; константы белого списка картинок и пути `~/.nri_manager`; один синхронизатор связей вместо трёх вариаций; параметризуемый репозиторий вместо четырёх копий.
- **Волна 3 — реестр типов (A4, C5, C6):** `EntityType` становится ключом единого реестра (тип → модель/репозиторий/атрибут связи/метка/множественное число); каждый из ~15 потребителей мигрирует отдельным шагом; исчезает ручная морфология `f"{type}s"`.
- **Волна 4 — крупные узлы (B1, B6):** из `Application._wire_ai_buttons` (230 строк в `main.py:952-1183`) выделяется `AiGenerationController` + `Protocol` контракта диалога вместо проверки возможностей через `hasattr`; xlsx-импорт разрезается на разбор / применение / тексты отчёта.
- **Волна 5 — транзакции и контракты (B3, решение Q14 зафиксировано в `docs/refactoring-audit.md`):** заплатки целостности (сохранение LLM-настроек под общий замок, откат-обёртка сохранения типа события, коммит очистки отменённых всплывающих сущностей, вложенный блок вместо тотального отката при коллизии картинки, изоляция послезаписного сборщика xlsx, уведомление об ошибке удаления типа события); затем единица работы `GameSessionUoW` (сессия + общий замок + реестр послезаписных действий) для траектории «сущность/событие», второй волной — календарь, LLM-настройки, хранилище картинок, листы персонажей, xlsx; контракты «диалог → соединитель» типизируются `dataclass` вместо словарей с `pop`; фабрика `open_entity_card` вместо четырёх повторов. Конструкторы репозиториев не меняются — 49 тестовых файлов с голой сессией остаются живы.
- **Волна 6 — декомпозиция гигантов (B2, B4, B5):** из `Application` выносятся `SheetWindowsManager`, `LlmSettingsRepository` (ключи настроек из представления в инфраструктуру), `ExportService`; `character_sheet_viewmodel` разрезается на история/выделение/буфер/перетаскивание с `Protocol` связи; носители формата и ключи настроек уходят из `game_calendar` в инфраструктуру, глобал «текущий календарь» — через внедрение зависимостей. Покрытые тестами части режутся сразу; непокрытые — только после test-first задачи.
- **Волна 7 — пин-тесты, нормы и карта местности:** AST-пины нарушения слоёв (прикладной/доменный код не импортирует `presentation`; `presentation/viewmodels` не импортирует `AsyncSession`/ORM-модели) по прецеденту `tests/test_no_qt_date_carriers.py`; обновление `AGENTS.md` (миграции живут в `infrastructure/db/migrations.py`, раздел устарел — D1/D2) и новый нормативный раздел **«Coding principles»** — постоянные правила для всех будущих правок и сессий ИИ (слои, единое знание, единственная точка транзакции, контракты, композиция, покрытие 100% без права измельчать — шлюз `fail_under = 100` уже в CI); запись в `docs/CHANGELOG.md`.

## Capabilities

### New Capabilities

- `architecture-integrity`: постоянные проверяемые ограничения структуры кода — направление зависимостей между слоями, единый реестр типов сущностей, единая точка владения транзакцией, запрет обращений к приватному чужих объектов; каждую границу сторожит автоматический пин-тест.

### Modified Capabilities

— (нет: поведение пользователя, схема БД и форматы файлов не меняются; ни одна существующая спецификация не меняет требований)

## Impact

- **Код (модификация):** `app/main.py` (−≈500 строк), `app/application/wiring.py`, сервисы (`calendar_settings_service`, `entity_service`, `event_service`, `llm_service`, `search_service`, `xlsx_import_service`), домен (`game_calendar`, `entity_type`), репозитории (`base_repository`, координационный маппинг, 4 одинаковых репозитория), модели представления (`calendar_wizard_viewmodel`, `character_sheet_viewmodel`, `llm_viewmodel`), представления (17+ диалогов QML-обвязки, карточка сущности, диалог события).
- **Код (новое):** `AiGenerationController`, `IslandDialogMixin`, единица транзакции, единый реестр типов, `dataclass`-контракты диалогов, пин-тесты `tests/test_architecture_layers.py` и др.
- **Тесты:** test-first характеризация перед рефакторингом непокрытых мест; при переносе носителей формата `game_calendar` соответствующие доменные тесты переезжают без ослабления утверждений; конструкторные фикстуры `tests/conftest.py` адаптируются по волнам.
- **Документация:** `docs/refactoring-audit.md` (карта находок), `AGENTS.md` (актуализация раздела миграций), `docs/CHANGELOG.md` (запись по изменению, версии не трогаются).
- **Не затрагивается:** схема БД и данные игр, формат `.nri`, `game_settings` (значения и ключи те же), `~/.nri_manager/llm_config.json`, внешние API.
- **Риски:** сконцентрированы в волне 5 (перевод владения транзакцией) и B5 (носители формата календаря с переносом тестов); митигация — порядок волн от застрахованного к менее защищённому, по одному рефу за шаг, полный offscreen-прогон после каждой задачи.
