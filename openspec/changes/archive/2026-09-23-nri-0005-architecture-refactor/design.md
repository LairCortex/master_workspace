# Design: nri-0005-architecture-refactor

## Context

Карта находок — `docs/refactoring-audit.md` (26 находок, метки К1–К3, карта тестовой безопасности, раздел Q14 с полной картой `commit`/`rollback`/`flush`). Ключевые ограничения среды:

- **Одна сессия на игру** (`main.py:175-180`), `expire_on_commit=False` → карта объектов живёт всю игру, ручные `refresh`/`expire_all` — штатный контракт.
- **Сериализация вместо транзакций:** глобальный `asyncio.Lock` в соединителе (`wiring.py:60`, `_spawn:69`) сериализует всю работу с сессией; контракты держания лока описаны комментариями.
- **Тестовая сеть завязана на голую сессию:** 49 модульных файлов + `tests/conftest.py:95-112`, плюс 7 e2e-файлов используют `Application._session` как тестовый API. Смена конструкторов репозиториев ломает до 49 файлов; добавление публичного свойства `session` — ноль поломок.
- Решения grill-сессии 2026‑09‑22: волны строго инкретны (после каждой — зелёный полный прогон), поведение сохраняется, непокрытые гиганты режутся только после test-first задачи, перенос кода допускает перенос тестов без ослабления утверждений, QML-обвязка — через примесь, AGENTS.md обновляется в этой же волне.
- Важно: решение: `init_db`/миграции уже живут в `infrastructure/db/migrations.py` (в отличие от устаревшего `AGENTS.md`).

## Goals / Non-Goals

**Goals:**
- Устранить находки К1 полностью, К2 — кроме явно отложенных; каждую устранённую границу сторожит тест-хранитель.
- Направление зависимостей: presentation → application → domain, инфраструктура подключается через сборку в точке входа; прикладной и доменный слои не знают о Qt и о представлении.
- Единственная точка завершения транзакции на пользовательскую операцию; ошибка нигде в середине не оставляет частичной записи.
- Ни одно наблюдаемое поведение, схема БД или формат файла не меняются.

**Non-Goals:**
- Изменение семантики `expire_on_commit=False` и ручных `refresh` (привязаны к UI-объектам).
- Календарные микро-транзакции стадий мастера (нормативный дизайн: брошенный черновик восстанавливается) и `StubCalendar`.
- Оптимизации ради скорости (в том числе `_refresh_dirty`) вне связей с архитектурой; переезд на alembic; правки версий и схемы данных.

## Decisions

### D1. Слои: каталог в домен, соединитель — в представление, приватное — наружу (A1, C1)

- Каталог пресетов (`presentation/views/character_sheet/presets/catalog.py`, импортируется сервисом `character_sheet_service.py:47`) — это данные без Qt → переезжает в `domain/character_sheets/preset_catalog.py`; представление импортирует его оттуда. Альтернатива (интерфейс + реализация в представлении) отвергнута: знание — данные, а не поведение.
- `_TYPE_UNSET` (`event_service.py:22`) становится публичной константой `TYPE_UNSET`, импорт из `wiring.py:15` легализован.
- Соединитель `app/application/wiring.py` переезжает в `app/presentation/wiring.py`: его суть — связывать диалоги с сервисами; импорт диалогов становится законным. Импортёров единицы: `main.py:51` и `tests/ui/test_e2e_wiring_gaps.py`; `Application._wiring` остаётся публичным свойством `wiring` (закрывает половину законных жалоб закона Деметры B2/C6).
- `BaseRepository` получает публичные свойства `session`/`model`; пять подглядываний `repo._session/_model` (C1) заменяются на них. Альтернатива «сервис получает сессию отдельно в конструктор» отложена до D4, чтобы не менять 49 тестовых файлов вперёд времени.
- `EventTypeRepository(event_repo._session)` при `None` (`event_service.py:45`) — скрытая зависимость «из воздуха»; типизированный конструктор обязателен, ветка `None` убирается вместе с обновлением вызывающих мест (`main.py`, тесты передают явно).

### D2. Реестр типов сущностей (A4, C5, C7)

- Ключом становится `EntityType` (`domain/enums/entity_type.py`, ныне мёртвый). Единый реестр живёт в `domain/entity_registry.py`: тип → отображаемое имя, форма множественного числа, набор атрибутов связей, признаки для поиска/LLM/xlsx.
- Правила морфологии (`f"{t}s" if t != "character"`, `world_snapshot_view_model.py:364`) переезжают в реестр единожды.
- ORM-модели и репозитории в доменный реестр не попадают — сопоставление тип↔репозиторий остаётся в точке сборки (`main.py:_build_entity_services`), сопоставление тип↔ORM — в инфраструктурном словаре `infrastructure/repositories/__init__.py`. Так домен не узнаёт об ORM, а потребители получают один источник.
- Миграция потребителей — строго по одному за шаг (15 шагов), каждый — зелёный прогон; `KeyError`-опасные развилки вида `if rel_type is None: return` по дороге заменяются исчерпывающим `match` по `EntityType` (промах становится ошибкой сборки/теста, а не молчанием).

### D3. Единое знание мелочей (A3, A5, C3, C4)

- Правила координат дат: `xlsx_import_service.py:600-622` удаляется, единственный источник — `coord_mapping.py`, туда добавляется функция `route_insert_dates(obj, fields)`.
- `_confirm_discard(parent, text)` — одна функция (четыре копии в `main.py:364-385,594-606,683-693,766-777` уходят), кладётся в `presentation/dialog_utils.py`.
- `IslandDialogMixin` (`presentation/qml_island.py`) инкапсулирует цикл `QML_IMPORT_PATH / island_context / load / release` для 17 диалогов; диалог по-прежнему сам решает, что грузить (шаблонный метод), примесь владеет жизненным циклом. Смешение «композиция над наследованием» осознанное: жизненный цикл острова неотделим от окна.
- Константы: расширения картинок — `domain/allowed_image_extensions.py` (используют 4 места), корень `~/.nri_manager` — общее семейство настроец (`llm/config.py` уже его строит, к нему подтягиваются `ui_prefs` и `doc_viewer_dialog`).
- Синхронизатор связей один: `sync_related(existing, desired, *, create_missing: bool)` в прикладном слое; три вариации (C3) сворачиваются в вызовы с нужным флагом.
- Четыре одинаковых репозитория (C4) заменяются фабрикой `dated_repository(model)`; классы-обёртки исчезают, потребители в точке сборки получают экземпляр.

### D4. Транзакции: минимум → заплатки → единица работы (решение Q14, находки A2/C1/B3 и сценарии 1–7)

Порядок неизменен, потому что каждый слой ценен и сам по себе, и развязывает следующий:

1. **Минимум:** D1-свойства `BaseRepository`; из `calendar_wizard_viewmodel` удаляются сессия, 6 ORM-импортов и `_TABLE_MODELS` (`:65-72,118-125,549`) — вместо прямого `session.get` новый метод `CalendarSettingsService.record_names(session, report)`; тесты фикстуры почти не меняются.
2. **Заплатки целостности (чинят сценарии независимо от механизма):** `main.py:1216` (сырой `asyncio.ensure_future`) → `run_locked`/`_spawn`; откат-обёртка `save_event_type` (`event_service.py:102-123`); коммит после очистки popup-сущностей (`wiring.py:674-678`); `ImageStore` при `IntegrityError` — `begin_nested()` вместо `rollback()` всей общей сессии (`store.py:79-85` — гасит сценарий 2, самый опасный: тихая потеря половины xlsx-импорта); пост-коммитный сборщик xlsx — собственный `try` с логом (`xlsx:813-814`); ошибка удаления типа события показывается пользователю (`event_service.py:146-148`).
3. **`GameSessionUoW(сессия, лок)`** с `async with uow.transaction():` (внешний коммит, откат на исключении, защита от вложенного входа, реестр послезаписных хуков). Единственная сессия на игру и текущий лок переиспользуются как есть; это надстройка дисциплины, не второй механизм. Переводится траектория «сущность/событие»: `entity_service.update_entity_with_relations` (коммит `:183` и сборщик картинок `:184-188` становятся одним транспортом с хуком — гасит сценарий 3) и `event_service.create/update_event_with_relations`; popup-путь соединителя получает явную транзакцию, накрывающую обе половины (гасит сценарий 1 — «отменённая сущность оседает в базе»). **Конструкторы репозиториев не меняются** (риск для 49 тестов = 0); фикстура `uow(session)` добавляется в `conftest`.
4. **Вторая волна уоу-попадания:** календарь, LLM-настройки, `ImageStore`, листы персонажей, xlsx (дефолтные коммит/откат-колбэки `:777-778` становятся реализацией единицы работы, колбек-параметр уходит). Полностью выводит сессию из представления (`CalendarWizardViewModel` в конструктор получает `uow` вместо `AsyncSession` — закрытие A2).

Отвергнутые альтернативы: «сервис владеет сессией, репозитории получают её параметром» (ломает ~49 файлов, при физически одной сессии — ритуал); шина commands/session-actor (сложность отладки выше профита для одиночного пользователя).

### D5. Контракты диалогов и фабрики (B3, C5)

- Результаты диалогов — `@dataclass(frozen=True)` в `presentation/dialog_results.py` (событие создание/редактирование, сущность создание/редактирование, 4 near-дубля `dict.pop` в соединителе сворачиваются в двух обработчиков); ключ-мусор `_existing_id` становитсяобычным полем.
- Фабрика `open_entity_card(...)` — одна вместо четырёх копий (создание + обвязки).
- Контракт диалога для AI: `Protocol` `AiCapableDialog` (`get_ai_buttons`/`get_entity_button`/`set_save_locked`/`set_close_guard`) вместо проверки возможностей через `hasattr` (B1); реализующие диалоги (карточка сущности, диалог события) объявляют соответствие явно; дубли прокси-геттеров устраняются общей базой диалога.
- Контракт `SheetFieldModel` ↔ модель представления (B4) — `Protocol`, `getattr(self._vm, "read_only", False)` (`:366`) заменяется обязательным полем протокола.

### D6. ДекомпозицияApplication/мастера AI/xlsx (B1, B2, B4, B5, B6)

- `AiGenerationController` (представление): вся оркестрация пакета генерации из `main.py:952-1183`; параметрический набор `GenerationTarget(entity_type, field_id, field_label, current_text, owner)` вместо 6-позиционных вызовов `_launch` и 6-параметрического `request_generation`; `Application` вызывает контроллер одной строкой. Покрыто `tests/ui/test_e2e_llm.py` — рефакторинг проверяем сразу.
- Из `Application` последовательно: `SheetWindowsManager` (жизненный цикл окон листа), `LlmSettingsRepository` (ключи `WORLD_PROMPT_KEY/FIELD_PROMPTS_KEY` переезжают из представления `llm_viewmodel.py:15-16` в инфраструктурный модуль настроек; прямой CRUD `game_settings` из `main.py:1219-1254` уходит), `ExportService`, мастер первого запуска — маленький метод с той же последовательностью шагов.
- `xlsx_import_service` режется на `xlsx_analyze.py` (чистые план/план-книга), `xlsx_apply.py` (запись через репозитории), `xlsx_report_text.py` (тексты пользователю); DB-индекс имён (`:433-469`) переезжает в репозиторный слой.
- `character_sheet_viewmodel` режется частями, в порядке возрастания риска: `_push_undo` (4 копии) → выделение/буфер/история как отдельные не-Qt классы (тестируются без QApplication) → объединение одиночного/множественного перетаскивания в один код с флагом → выделение `SheetFieldModel` в свой модуль с протоколом из D5. Замер `_refresh_dirty` фиксируется ДО и ПОСЛЕ (страховка от тихой деградации).
- `game_calendar`: три носителя формата (`:1092-1265`, `:1267-1408`, `:1410-1500`) и ключи настроек (`:1032-1050`) переезжают в `infrastructure/calendar_storage.py` + слой настроек; доменные тесты переезжают физически за кодом, утверждения не ослабляются; глобал «текущий календарь» (`:501-518`) — исключение из правила: остаётся (проверенная точка процесса со сбросом в `shutdown`), но ленивый циклический импорт `date_era` устраняется явной передажей зависимости. Третья реализация календаря добавляется классом с тем же протоколом — ветвление `_KIND_*` в носителях уходит в реестр реализаций.
- Порядок D6 задан страхованием xlsx → мастер AI → листы → календарь → остальное Application (см. карту тестовой безопасности аудита).

### D7. Хранители границ (новая возможность `architecture-integrity`)

- `tests/test_architecture_layers.py` — AST-скан (прецедент механики: `tests/test_no_qt_date_carriers.py`): запрет импортов `app.presentation.*` из `app/application/**` и `app/domain/**`; запрет импортов `AsyncSession`, `app.infrastructure.db.models` и вызовов `commit()/rollback()` в `app/presentation/**` (список исключений — пусто, исключения запрещены решением grill); запрет имён из модулей с префиксом `_` при импорте из пакета, отличного от пакета импортирующего (запрет приватных импортов между модулями в проде — только внутри модуля).
- Словари тип→сущность в обход реестра (А4) пинятся грепом ключевых паттернов по прикладному слою (тип-литерал + `Model` в одном словаре) с зафиксированным зелёным текущим состоянием; ложные срабатывания проверяются отдельными кейсами.
- Каждый хранитель: сбой — файл и строка; ложные срабатывания — отдельными тестами (тот же прецедент).

### D8. Документация и нормы (D1/D2 аудита; решение пользователя 2026‑09‑22)

- `AGENTS.md`: раздел «Migrations» описывает реальность — миграции в `app/infrastructure/db/migrations.py`, точка входа `init_db()` там, не в `main.py`.
- `AGENTS.md`: новый нормативный раздел **«Coding principles»** — постоянные правила для всех последующих правок (включая будущие сессии ИИ): направление слоёв и запрет сессии/ORM/коммитов в представлении; единый реестр типов и единые места хранилищных правил и сквозных констант; единственная точка транзакции (единица работы) без подглядываний в приватное; замораживаемые контракты результатов диалогов; композиция (единственное исключение — примесь острова); 100% покрытие строк как неизмельчаемый шлюз. Раздел совпадает со списком критериев аудита и становится обязательным; текст фиксируется задачей 7.5 (источник формулировок — `docs/refactoring-audit.md`).
- **Покрытие 100%:** шлюз уже есть (`pyproject.toml`: `[tool.coverage.report] fail_under = 100`, прогоном CI «line coverage gate»; `# pragma: no cover` — ровно 2 узаконенных места). Норма: после применения изменения шлюз остаётся зелёным на 100; новая/изменённая строка без теста шлюз роняет; ослабление `fail_under`, `exclude_lines` или добавление `pragma: no cover` допустимы только с явно обоснованным пунктом в предложении изменения. Проверка неизмельчания — задача 7.6.
- `docs/CHANGELOG.md`: запись по изменению; версии не меняются.

## Risks / Trade-offs

- **Средний риск — D4.3 (единица работы):** контракт «запись без коммита» popup-пути и семантика `expire_on_commit=False` тонкие; митигация — переход одной траекторией (сущность/событие) с сохранением старого публичного API, вторая волна только после зелёного прогона и e2e; конструкторы репозиториев не трогаются → 49 модульных файлов вне риска.
- **Средний риск — B5 (календарь):** перенос носителей формата задевает 2700+ строк доменных тестов; митигация — механический перенос без изменения утверждений отдельным шагом, до любых правок логики.
- **Низкий, но широкий — А4:** 15 потребителей реестра; митигация — по одному потребителю за шаг, e2e-комплект сторожит на каждом.
- **Переезд соединителя (D1)** меняет путь модуля; митигация — один коммит без изменения содержимого плюс замена импорта в `main.py` и файле e2e в том же коммите.
- **Объём изменения:** 7 волн — крупная единица планирования, но не единый PR: применяется задачами по одной, каждая задача — самостоятельный зелёный срез (`docs/refactoring-audit.md` волны 1–7 = группы задач).
- **Trade-off:** примесь QML-обвязки — наследование в проекте, декларирующем композицию; принято grill-решением, зафиксировано в D3.
