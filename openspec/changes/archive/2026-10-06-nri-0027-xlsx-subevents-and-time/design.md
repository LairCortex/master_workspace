# Design: nri-0027-xlsx-subevents-and-time

## Context

Импорт двухфазный: `analyze_workbook` читает файл и строит `ImportPlan` (проблемы строк — до записи), `build_name_index` дополняет план индексом имён базы, `resolve_links` резолвит связи (файл → база → призрак), `xlsx_apply._upsert_row` пишет ORM напрямую, минуя `EventService`. Двухуровневость и валидность родителя сейчас живут только в `EventService` (`ValueError` с русскими текстами «родительское событие … не найдено» / «не может быть подсобытием»). Время начала хранится как минуты от начала суток (`EventModel.start_time_raw`, публичное свойство — доменное `TimeOfDay`); размеры суток/часа — `GameCalendar.day_hours` / `minutes_per_hour` (`GameCalendarSpec`, пресет 24/60). Колонки, шаблон и подсказка диалога печатаются из одного реестра `xlsx_schema`. Мотивация и правила поведения — proposal.md и дельта спеки; здесь только как.

## Goals / Non-Goals

**Goals:**
- Колонки `Время начала` и `Родительское событие` листа «События» без миграций БД и без новых сущностей плана сверх уже существующих механизмов.
- Разрешение родителя тем же каналом, что связи: файл → база → проблема строки; пред-анализ находит все отказы до записи.
- Правило двухуровневости — одно на `EventService` и импорт.
- Шаблон сохраняется «чистым»: обратный импорт шаблона в свою игру — ноль проблем и ноль предупреждений.

**Non-Goals:**
- Отвязка родителя импортом, спецзначения («—»), колонка времени на других листах, авто-создание родителей-призраков, импорт дат-времени задним числом через редактирование файла построчно (обычный upsert-цикл покрывает).
- Подсказка и шаблон других языков — интерфейс русскоязычный в этой части, как и весь формат.

## Decisions

### Д1. Колонки — записи реестра, порядок листа «События» собирается явно
`COL_START_TIME = ColumnSpec(key="start_time", label="Время начала", …)`, `COL_PARENT_EVENT = ColumnSpec(key="parent_event", label="Родительское событие", …)`. `Время начала` стоит сразу после `Дата начала`, поэтому лист «События» больше не собирается из `_common_columns() + extras` — его кортеж колонок полный и явный (`Имя, Дата начала, Время начала, Дата конца, …, Тип, Родительское событие, связи`); остальные четыре листа остаются на общей сборке. Альтернатива (хвостовые extras) отклонена: порядок колонок — часть диалог-контракта подсказки-таблицы, время должно стоять у своей даты. Ключ `parent_event` не совпадает с именем колонки ORM (`parent_id`) — осознанно: `parent_event` не проходит через setattr-цикл `_upsert_row` (его там отсекает явная ветка, Д4), `start_time` совпадает намеренно (Д3).

### Д2. Парсер времени — сосед `parse_cell_date` в схеме
`parse_cell_time(value, calendar) -> int | None`: текст `HH:MM` (обе части 1–2 цифры, разделитель `:`) и нативная ячейка `datetime.time` (секунды отбрасываются); на выходе — минуты от начала суток; не читается или час ≥ `calendar.day_hours` / минута ≥ `minutes_per_hour` → `None`. Границы читаются только из переданного календаря — 24/60 в коде парсера не появляется. Отдельного `DateParse`-побратима с проблемой не заводим: по спеке плохое время — предупреждение, а не проблема строки, и единственному исходному различению «нечитаемое/невлазящее» хватает текста предупреждения, который печатает исходное значение ячейки. Формулировка предупреждения — в `xlsx_report_text` (рядом с переводами проблем дат).

### Д3. Время применяется штатным setattr
Ключ `start_time` совпадает с колонкой ORM; `_row_to_draft` кладёт в `row.fields["start_time"]` уже доменное `TimeOfDay`, и цикл setattr `_upsert_row` пишет его через публичное свойство модели — дата-роутинг (`route_insert_dates`) не трогать, время — скаляр, не дата-слот. Пустая/плохая ячейка → ключа в fields нет → сохранённое не трогается (точь-в-точь семантика «пустая ячейка не затирает»). Плохое значение помечается в `PlannedRow` флагом предупреждения; само предупреждение печатается на проходе применения (там же, где предупреждения изображений) и попадает в итоговый отчёт. Пред-анализ при этом показывает строку в пуле как «импортируется без времени» — одной пометкой, не проблемой.

### Д4. Разрешение родителя — в `resolve_links`, не отдельным проходом
`_collect_wanted_names` собирает, кроме целей связей, имена колонок `parent_event`; `NameIndexEntry` уже держит ORM-модели событий — `parent_id` виден без расширения индекса. После резолвинга связей тот же итерационный проход (пропуск-множество растёт — как с призраками) разрешает `parent_event` каждой живой строки событий:
1. уникальная живая строка файла по `lower(name)` (листы уже смержены — одна строка на имя);
2. иначе уникальная запись базы того же ключа; неоднозначно — проблема строки;
3. найденный родитель запрещён (Д5) — проблема строки; иначе в план ложится `parent_ref` (тип-ключ + id/ссылка на строку плана).
Родитель-призрак не заводится ни при каком исходе — ветка призраков связей для родителя недоступна. Применение: после создания всех сущностей (ссылка на строку плана даёт id после flush) ставит `obj.parent_id` — той же отложной фазой, что связи. Обновление существующего события переставляет родителя; пустая ячейка — ключа нет — не трогает.

### Д5. Двухуровневость — один судья в domain
Новый чистый модуль `app/domain/event_nesting.py`: `parent_refusal_code(parent_found, parent_is_child, is_self) -> str | None` (коды `not_found` / `is_subevent` / `self_parent`) + словарь кодов на русские формулировки, дословно повторяющие сегодняшние тексты `EventService` («родительское событие … не найдено», «родительское событие не может быть подсобытием»). `EventService` переводит свои проверки на этот модуль (тексты не меняются — пины тестов карточки остаются зелёными), пред-анализ импорта получает те же формулировки в причину проблемы строки. Циклы — не свойство одной пары (двухуровневость их запрещает сама: цепочка длины 2 не цикл, но A→B и B→A в одном файле проходит попарино, если не смотреть дальше), поэтому резолвер прохода Д4 обходит цепочку родителя вверх до корня живой графы плана: повторный вход в узел = цикл → проблема строки; глубина > 1 = три уровня → проблема строки. Отдельный графовый модуль не заводится: графа — плоский словарь «строка → родитель», обход — вспомогательная функция резолвера.

### Д6. Шаблон: примеры и подгонка времени под календарь
`SAMPLE_ROWS["event"]`: «Бал» получает `start_time` 19:00, «Дуэль» — `start_time` 06:00 и `parent_event` «Бал» (родитель разрешается среди строк шаблона — чистый обратный импорт без новых сущностей). Рядом с `_adjust_date_cell` — `_adjust_time_cell(value, calendar)`: час → `min(hour, day_hours-1)`, минута → `min(minute, minutes_per_hour-1)`, носитель (текст) сохраняется; для пресета — тождество. Инвариант чистоты D7 распространяется на время (спека). Клетка-в-клетку пресета: тест-пин шаблона перепривязывается — сравнение со старым снимком во всех клетках кроме новых колонок листа «События» (спека); снимок прошлого шаблона остаётся в тесте эталоном.

### Д7. Подсказка — только новые строки таблицы
`build_format_text/html` печатаются из реестра: новые колонки появляются с описаниями из `ColumnSpec.description`; существующие токены не трогаются (пин преемственности текстов подсказки проходит). Русские описания: «Время начала: `HH:MM` или ячейка времени; для игрового календаря — в его границах», «Родительское событие: имя события-родителя (одно)».

## Risks / Trade-offs

- [Родитель разрешается по живой (несброшенной) строке; если строка-родитель позже упала в проблемы, потомок должен упасть тоже] → итерационный резолвер Д4 (пропуск-множество растёт до стабилизации, как `resolve_links`) + тест «родитель сам пропущен».
- [`EventService` сегодня бросает `ValueError` с текстом; замена на общий модуль может случайно переформулировать отказ и сломать пины карточки] → тексты переносятся дословно, существующие тесты `event_service`/карточки — регрессионный щит.
- [Шаблон-пример «Дуэль» — дочка «Бала», хотя дата раньше: пользователь считывает пример как допустимость дат «вне» родителя] → это так и есть (карточка не запрещает), но пример нарочно берёт датское соседство без абсурда; при отзывчивости — заменить на хронологически вложенную пару, правка одной константы.
- [Попытка импортировать файл с новыми колонками в старую версию игры] → неизвестные заголовки игнорируются форматом с самого начала — деградация в «плоский» импорт без потерь.
- [Время до н.э. и вставные дни: время — минуты суток, от эры независимо] → отдельной проверки нет по построению; тест на строке «Заговор» + время.

## Migration Plan

Без миграций (`parent_id`, `start_time` — с NRI-0023). Раскатка — обычный релиз приложения. Откат — откат кода: файлы, подготовленные под новый формат, старая версия импортирует «плоско» без ошибок.
