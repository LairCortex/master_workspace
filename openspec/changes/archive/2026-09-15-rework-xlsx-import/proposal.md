# Proposal: rework-xlsx-import

## Why

Текущий импорт из .xlsx читает один произвольный лист одного типа сущностей за раз (5 отдельных пунктов меню) и не умеет привязывать сущности друг к другу — связи проставляются только вручную через диалоги. Кроме того, импорт не выполняет коммит: созданные строки сохраняются в базе лишь случайно, когда другой поток приложения делает коммит. Нужен единый файл «вся картина целиком», где связи между сущностями видны прямо в таблице.

## What Changes

- **BREAKING** Пять пунктов меню «Импорт … из .xlsx» заменяются одним «Импорт из .xlsx…»; старый формат файла (один произвольный лист с англоязычными заголовками) более не читается.
- Импорт читает один .xlsx с именованными листами «События», «Персонажи», «Локации», «Организации», «Предметы»; импортируются только присутствующие в файле листы.
- Русские заголовки колонок (английские старые принимаются как алиасы); колонки связей по одной на каждый связуемый тип, в ячейке — имена через `;`.
- Двухпроходный импорт: проход 1 создаёт/обновляет сущности всех листов, проход 2 применяет связи (по именам, включая ссылки на строки других листов того же файла).
- Обновление (upsert) по уникальному совпадению имени: непустая ячейка перекрывает поле, пустая не трогает; связи только добавляются, ничего не отвязывается.
- Отсутствие цели связи в базе и файле — автосоздание с датами из ссылающейся строки (мин. дата начала / макс. дата конца при нескольких ссылках); отсутствие типа события — автосоздание типа. Все автоматические решения и пропущенные строки — в итоговый отчёт.
- Пред-анализ всего файла до импорта: фатальные ошибки листов блокируют старт, список проблем строк показывается в диалоге; импорт валидных строк продолжается по выбору пользователя.
- Импорт выполняется в одной транзакции с обязательным коммитом в конце (исправление текущего дефекта «нет коммита»).
- Диалог импорта: подсказка с полным набором колонок, кнопка «Скачать шаблон» (готовый `import_template.xlsx` из бандла через диалог «Сохранить как…»), пред-анализ и итоговый отчёт внутри диалога. Фильтр файлов честно ограничивается `.xlsx` (openpyxl `.xls` не читает).

## Capabilities

### New Capabilities

- `xlsx-import`: импорт сущностей и связей между ними из единого .xlsx-файла с именованными листами: структура файла и колонок, пред-анализ и отчёт, двухпроходная семантика (upsert по имени, автосоздание целей связей и типов событий), транзакционность, скачивание шаблона.

### Modified Capabilities

— (существующие спеки не меняют требований: конвейер изображений `image-storage` переиспользуется без изменений; `ui-testing` уже требует E2E-поток «импорт из .xlsx» без детализации формата; `mentions` сохраняет правило «вставка из xlsx не переписывает маркеры» применимым к новому импорту как к create-пути.)

## Impact

- `app/application/services/xlsx_import_service.py` — переработка целиком (многолистовой парсер, двухпроходная логика, upsert, связи, транзакционность).
- `app/presentation/viewmodels/xlsx_import_view_model.py`, `app/presentation/views/xlsx_import_dialog.py`, `app/presentation/qml/XlsxImportRoot.qml` — единый диалог: пред-анализ, пул проблем, отчёт, скачивание шаблона.
- `app/presentation/views/main_window.py`, `app/application/wiring.py` — один пункт меню вместо пяти; исправление коммита.
- `app/infrastructure/repositories/`, `app/application/services/event_service.py` / `entity_service.py` — переиспользование/расширение для связывания M2M по именам (13 ассоциативных таблиц, кроме `*_rating`).
- Новый ресурс `import_template.xlsx` в репозитории + бандлинг в `nri_manager.spec` (по образцу `docs/`).
- Тесты: `tests/application/test_xlsx_import_service.py`, `tests/presentation/test_xlsx_import_dialog.py`, `tests/ui/test_e2e_import.py`, фикстурный `tests/fixtures/import_sample.xlsx` — переработка под новый формат.
