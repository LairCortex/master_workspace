# Design: nri-0014-window-contract-and-docs

## Context

Три живых аудита зафиксировали четыре класса последствий одного решения «лист поверх родителя вместо окна»: неуправляемая блокировка (AB3, A1), оптические дефекты оболочки (AB2, E1/CR5, D6), нечитаемость содержимого (AB1) и языковое разношерстие (L1). Проект уже имеет работоспособный прецедент правильного поведения: список чар-листов (`sheet_windows.py:89-111` — ленивое создание, `show()+raise_()+activateWindow()`,снятие по `finished`). Grill-сессия 2026-09-24 зафиксировала: норму формата в спеку, единый механизм повторного подъёма, QTranslator для Qt-строк, не-нативные файловые панели, живой ре-аудит финалом.

## Goals / Non-Goals

**Goals:** контракт вход→формат пинируется; ни один диалог не блокирует «молча»; документ читается целиком; слои стеков различимы; стандартный текст Qt — русский; дублей окон нет.

**Non-Goals:** перестройка IslandDialogMixin/рендеринга шумов рендера (A5 — отклонено); NSAppearance (D7 — отклонено); замена нативных попапов на QML-острова; формы/логика мастера календаря (П2); модаленость стартового мастера и FI-6 (П2); компонент ThemeDateField (П4).

## Decisions

### D1. Реестр открытых окон — объект `presentation/window_registry.py`
`MenuWindowRegistry.open(key, factory)` — есть живое окно по ключу → `raise_()+activateWindow()`; иначе создает factory, вешает `finished → forget(key)`, `show()`. Ключи: `docs_readme`, `docs_changelog`, `llm_setup`, `launcher_switch` (плюс существа чар-листов/столов подключаются позднее при случае — вне этого изменения их поведение уже корректно, кроме отмеченных дефектов). Прецедент поведения — список чар-листов; дублирующую механику в `main_window` не заводим (принцип «одно знание»).
*Вместо:* декоратора над `.open()` — отказ, т.к. скрывает жизненный цикл от composition root (AGENTS: main.py/wiring — единственные связывающие).

### D2. DocViewer — окно, не лист
`_DocViewerDialog` остаётся QDialog с островом, показ: `setWindowModality(NonModal)` + `show()` + реестр; `setWindowTitle(«Документация»/«Changelog»)` попадает в настоящую шапку macOS-окна (AB2); QML-корень внутри не дублирует заголовок. Текст оборачивается в штатный `ScrollView` (паттерн `SheetPresetRoot.qml:134-147`) — AB1. `main_window.py:235-245` переписываются на реестр.
*Вместо:* внутреннего ThemeSheetHeader в документах — лишняя двойная шапка на настоящем окне.

### D3. Внутренний заголовок листов — новый компонент `ThemeSheetHeader` в `nri.components`
Строка: `Text` (title) + `ToolButton`/`ThemeIconButton` («Заголовок» и «Крестик» — role Button, name «Закрыть», `onPressed → closeRequested()`), токены темы; ставится сверху `EventDialogRoot.qml`/`EntityCardRoot.qml` (вкладка карточек), текст = существующий контракт windowTitle; закрытие = существующие обработчики reject/Esc без новой дисциплины (CR5-затемнение: при открытии дочернего листа родитель получает дополнительный overlay затемнения (`color.scrim`-токен, слой-стек: alpha растёт с глубиной) — состояние передаёт владелец стека (wiring лист-диалогов), не сам компонент).
*Вместо:* заголовка на уровне QDialog+QLabel над островом — нарушит пиксельный контракт вайр-лайта (`test_theme_grab`).

### D4. «Сменить игру…» — не-модальное окно (A1/A2/A3)
`main.py:433-437`: parent сохраняется (для таскбара/удержания), но не `open()` → `setWindowModality(NonModal)` + `show()+raise_()` через реестр (ключ `launcher_switch`); title лаунчера уже задан (`game_launcher_dialog.py:58`) и становится видимым в шапке окна. Комментарий о модалености приводится в соответствие; пункт меню — `Сменить игру…`. Открытие игры из окна идёт существующим путём; повторное «Сменить игру…» поднимает окно.
*Вместо:* ApplicationModal как есть + починка комментариев — оставляет жалобу AB3-класса (заперт пользователя при «просто посмотреть»).

### D5. Модальные широкие мастера — модальное окно, не sheet (D6)
`CalendarWizardDialog` при размерах, превышающих родителя, не может быть нативным листом: стартовый показ остаётся модален, но `exec()` заменён на показ модального top-level (`setWindowModality(ApplicationModal)` + `show()` вне вложенного цикла — механизм первого запуска чинится в П2, модаленость-без-листа пилотируется уже здесь). Скачка геометрии родителя и «Window move completed without beginning» не будет. Xlsx-лист (617 pt) остаётся листом: для него лечится только D5-вёрстка.
*Вместо:* clamp размера мастера к родителю — ломает приёмку мастера (спека живого экрана фиксировала содержимое, не размер).

### D6. Язык: QTranslator(qt_ru) + не-нативные панели (L1)
После создания `QApplication`, до первого окна: `QTranslator` с `qtbase_ru.qm` (в wheel PySide6: `PySide6/translations/`), путь резолвится через `QLibraryInfo`, в PyInstaller — `datas` в `nri_manager.spec`. Язык фиксируется на `ru` независимо от локали ОС. Все `QFileDialog`-вызовы приложения (экспорт игры, импорт xlsx, картинка, PDF-экспорт) получают `DontUseNativeDialog` — панель Qt переводится тем же qm и одинакова на dev и в `.app`; `QMessageBox/QInputDialog/QDialogButtonBox` перекрываются переводом без ручных setText.
*Вместо:* ручного `setText` по всем вызовам — россыпь мест расхождения; bundle-локализации macOS — на dev всё равно английские панели (проверено аудитом — L1 воспроизведён именно на dev).
Риск: внешний вид qt-панели отличается от нативной — принимаем осознанно (пользовательский контракт — русский интерфейс; пиксельного grab-теста панель не имеет).

### D7. Пиновка и пределы
Оффскрин: `windowModality` каждого диалога контракта; «второй вызов не создаёт второе окно» (реестр); `ScrollView` присутствует + `contentHeight>viewport` + скролл-метод сдвигает `contentY`; тексты стандартных кнопок с переводчиком («Отмена»/«Да»/«Нет»); высота рядов xlsx-вёрстки (нет мёртвых слотов); role/name/Press заголовка листа (паттерн AGENTS). Не пинится оффскрин: живой гейт нативного меню macOS под листом (`AXEnabled`) и чтение заголовков живьем — фиксируется финальным сценарием `window-layout`/`native-focus-repro` компьютерного обзора с допиской в QA-отчёты.

## Risks / Trade-offs

- Смена `open()→show()` меняет порядок закрытия окон при смене игры — существующие e2e смены игры обязаны остаться зелёными (гейт прогона), при необходимости окно закрывается явным `close()` в потоке смены игры.
- Реестр вводит ключ-реестр: расхождение ключей (два пункта → один ключ) даст ложный reuse — пин на все пункты меню реестрового контракта.
- Не-нативная файловая панель не показывает боковое меню macOS — принятый компромисс языка.
- Русификация через qtbase_ru.qm может не покрыть экзотическое стандартное сообщение — guard-тест перечисляет используемые классы; новое обращение в тестах проверяется.
