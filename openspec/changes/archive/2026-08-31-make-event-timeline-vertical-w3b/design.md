# Design: make-event-timeline-vertical-w3b

## Context

HEAD `8e8c2e6` (заархивированный W3): панель `TimelineWidget` = шапка (`CustomDateEdit`×2 + «Применить»/«Очистить» + «+»-меню) + `TimelineCanvas` с Qt-бесплатным ядром `track_layout.py` (горизонтальный Gantt). `TimelineViewModel`: `_all_events`/`events`, `filter_by_dates`, `select_event_by_id(id)`, сигналы `events_changed`/`selected_event_changed` (притенка выбранного при смене видимого набора). Wiring: selection→detail по id, dblclick→edit, search-jump `select_event_by_id`+`scroll_to_event`, слушатель сброшенного выбора чистит панель деталей. Тема: `attach_theme`/`ThemeRuntime.add_listener`, `compiler.token_rgb` (QPainter-цвета вне QSS), инвариант `tests/presentation/test_no_chrome_hex.py` сканирует `views/**`. Мотивация переделки — proposal.md → Why; UX-решения D1–D10 зафиксированы grill-сессией 2026-08-31.

## Goals / Non-Goals

**Goals:**
- Вертикальное перечисление дней с видимыми датами каждого события и пустыми днями без схлопывания.
- Сохранить 1:1 id-контракт W3 (внешние слои — VM, wiring, E2E-контракты выбора — не меняются по семантике).
- Токен-инвариант и live-retheme без новых токенов.
- Избавиться от мёртвого Gantt-ядра.

**Non-Goals:**
- Интерактивная рейка (клик-прыжок, follow-дата, drag диапазона) — W3c.
- Зум, drag-редактирование дат события, дорожки по сущностям, типы/цвета событий — вне карты.
- Виртуализация списка сверх QListWidget-потребностей, правки схемы БД, изменения `Event`-домена.

## Decisions

- **D1 Переделка вперёд, не revert `8e8c2e6`.** Альтернатива (откат к `QListWidget`-списку) возвращает row-контракт, выбрасывает id-контракт/theme-обвязку/Gantt-тесты и откатывает назад уже решённый вопрос формата строк.
- **D2 `QListWidget` + кастомный `QStyledItemDelegate` вместо переработки QPainter-канваса.** Нативные выделение/фокус/клавиатура/скролл бесплатны; делегат дорисовывает рейку/скобки/поворотный текст в `paint()`. Альтернатива (переписать `TimelineCanvas` в вертикаль) оставила бы ручную реализацию того, что список даёт из коробки, и second-class keyboard-навигацию.
- **D3 Чистое ядро строк `timeline_rows.py` (без Qt)** — наследует тест-традицию `track_layout.py`: `build_rows(events, range_start, range_end) -> list[Row]`, `RowKind` ∈ {EVENT, EMPTY_DAY}; диапазон без фильтра = min(start)…max(end|start); событие — только на позиции start; сортировка `(start, id)`. Jump-хелперы `prev/next_event_index`. `track_layout.py` удаляется как мёртвое.
- **D4 Равновысокие строки фиксированной высоты** (константа модуля, стартовое значение 24 px — наследует `min_lane_h` W3; правится только в константе). Пропорциональный длительности масштаб сознательно отвергнут: даты читаются из текста, геометрия не несёт скрытых данных.
- **D5 Пустые дни не схлопываются** (решение пользователя по референсу, Q12a). «Простыня» годового диапазона смягчается D7, не компрессией; toggle-сжатие — кандидат W3c.
- **D6 Рейка рисуется делегатом**: тик на сутки; подпись месяца один раз при первом дне месяца, поворот снизу вверх (пользовательский выбор против «три шкалы» и «цифра каждый день»: подписи каждый день физически накладываются при 24 px); ширина рейки — по самой длинной подписи месяца, минимум константы (60 px). Скобка многодневки — сегмент против тикетов start…end, при пересечении — соседние дорожки рейки по индексу группы конфликтов (детерминированно). Хит-тест рейки отсутствует.
- **D7 Sticky-date — оверлей `QLabel` поверх viewport** (не item и не кастомный paint вьюпорта): обновляется по `valueChanged`/смене модели, позиция — `itemAt(верхний край)`. Выбор против item'а: не тонет при скролле и не участвует в кликах/выделении.
- **D8 Прыжки**: QShortcut `Alt+Up/Down` (context = панель; в приложении свободны — проверено на HEAD) + кнопки `⤒/⤓` во втором ряду шапки, на месте удалённых apply/clear; реализация — от текущего видимого ряда к ближайшему EVENT-row, `setCurrentRow`+`scrollTo`.
- **D9 Чип-фильтр**: кнопка-чип в первом ряду шапки; поповер — top-level `QWidget` (скининг через app-wide popup-лист W2a) с двумя `_CustomCalendar` (`custom_date_edit.py`, кастомные игровые месяцы уже реализованы): первый клик — старт, второй — финиш → live-apply + закрытие; «Сбросить» внутри. Поповер top-level, поэтому не ограничен `minimumWidth(220)` панели. Семантика `filter_by_dates` и VM-контракт не меняются; виджеты apply/clear удаляются из шапки.
- **D10 Тема**: палитра паса делегата — `token_rgb` + альфы от `accent_rgba` (паттерн W3, новых токенов нет); live-retheme пересобирает палитру + `viewport()->update()`, выбор/скролл не трогает; оф-скин — именованные Qt-глобалы. Инвариант hex действует на файл без правок теста.

## Risks / Trade-offs

- Поворотный текст/скобки в делегате — ручная отрисовка → приёмка пиксельными grab-тестами (традиция W1+), не golden-PNG.
- Годовой диапазон min–max = сотни позиций → QListWidget держит 10³–10⁴ item'ов без виртуализации (пересборка модели при мутациях — O(range+events)); при деградации — замена на QAbstractListModel, контракт панели не меняется.
- Пересборка всей модели при каждом `set_events` может сбрасывать фокус/скролл-позицию → пересобирать только при изменении набора (версия событий как в W3-кэше), позицию восстанавливать по выбранному id.
- Два календаря в поповере — нетестованная высота; при низких экранах — один календарь с тапами «старт/финиш» (fallback зафиксирован, контракт чипа не меняется).
- Sticky-оверлей перекрывает первую строку → отступ viewport сверху на высоту оверлея, чтобы ничего не скрывалось.

## Migration Plan

Docs-статусы (W3 «влито/переопределён», строки W3b/W3c) — отдельным коммитом до реализации. Затем один PR в main под `NRI-0009`: `timeline_rows.py` + юниты → список+делегат (строки, рейка, sticky) → чип-фильтр/поповер → jump-навигация → VM-точка → удаление canvas/`track_layout` + перенос тестов → E2E/пиксельный/инварианты → CHANGELOG/roadmap «влито» (только фактом коммита). Откат — revert PR; БД/форматы данных не тронуты.
