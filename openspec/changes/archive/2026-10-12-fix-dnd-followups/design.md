# fix-dnd-followups — Design

## Context

Модуль живёт в `app/dd/`, предупреждения жизненного цикла — константы композиции (`app/main.py`), сводные тексты SRD — в `app/dd/domain/dataset.py`, тексты сервисных подтверждений — у сервисов, тексты листа генерации — в `app/dd/presentation/generation/base.py`. Все нормы-дельты сверялись с этими константами до записи: почти всё уже совпадает, изменения кода точечные. Пробелы тест-процедур 13/14/15 — документированный список из 19 пунктов; живой прогон фазы 2 оставил одно незакрытое наблюдение (модалность SRD-уведомления) без тикета. Дорожная карта требует оба профиля сборки и 100 % покрытия; живой контур — только последовательные прогоны (общее имя процесса, `pkill`-остановка).

## Goals / Non-Goals

**Goals:**
- Довести уведомление автозагрузки SRD до необязывающего поведения с живым воспроизведением до правки (правило roadmap: фикс — это lie до красной пары воспроизведение→починка).
- Перевести все 19 пробелов в зафиксированные нормы или в явные отметки «живой проверки не требует».
- Закрыть 8 живых проверок фикстурами, которые можно собрать по известным схемам без LSS и без LLM.
- Привести четыре документа (roadmap, checklist §25–27, процедуры 13/14/15, отчёт приёмки фазы 2) к фактическому состоянию.

**Non-Goals:**
- Никаких новых экранов, таблиц, форматов; никаких изменений в `dnd:health`/`lss:command` (API LSS не стабилизированы), QWebEngine не входит (фазы 4a/4b сняты владельцем 2026-10-12).
- Генерационные live-кейсы не прогоняются (нет настроенного LLM) — только формальная отсрочка с явной записью.
- Переименование «Встречи», кэш признака модуля, редактируемые промты — решения владельца: не делать (фиксация в docs, код не трогается).

## Decisions

### Д1. Модалка SRD: сначала воспроизвести, потом чинить по cause

Наблюдение приёмки: отложенные закрытия листов ждут «OK» у уведомления об офлайн-ошибке, хотя поза кода — modeless (`box.show()`). Порядок: живой прогон (закрытая сеть, первое включение) → фикс причины в отчёте → правка → оффскрин-пин (бокс не модальный; при открытом боксе лист можно закрыть). Кандидатные причины (проверить по порядку): атрибут модалности QMessageBox по умолчанию у parent-окна; связь с блокировкой стека листов. Альтернатива «заменить бокс на баннер» отвергнута: остальные сводные уведомления — те же боксы, продукт не должен плодить второй канал показов.

### Д2. Журнал как штатный наблюдатель сетевых выходов

Выпуск каждого SRD-запроса (url-название набора) и его исход пишется через стандартный журнал (`logging`, канал `app.dd`); идемпотентная ветка «уже в хранилище» запрос не выпускает и записи о выпуске не оставляет — отсутствие записи есть наблюдаемый факт «сеть не обращалась». Альтернатива «перехватчик на HTTP-клиент для QA» отвергнута: постоянный тестовый механизм ради одной проверки, когда журнал — уже продукт («Сохранять логи в файл»).

### Д3. Нотация пути валидатора упрощается до единой на выходе отчёта

Норма — единый вид `поле.поле[индекс].поле`. Если текущий генератор путей даёт другой единый вид (например jsonpath-префикс), унификация делается форматированием пути при сборке отчёта (одна функция), а не переписыванием путей каждой проверки — золотые тексты сообщений не дёргаются. Guard-тест: все записи отчётов трёх каналов матчат одной регулярной форме.

### Д4. Тексты: один источник — константа; норма сверена с кодом

Все дословные тексты дельт взяты из констант реализации. Два осознанных отклонения нормы от текущего кода: отказ «пусто дозаполнять» (константа — строчная фраза-фрагмент; норма — полное предложение с заглавной, константа повышается, тесты обновляются) — единственный текст, где код подтягивается. Остальные тексты уже соответствуют; тесты-пины добавляют защиту от будущего дрейфа.

### Д5. Неразрешимая привязка в экспорте — только опущение ключа

Сборщик не пишет слаговый ключ недоступной привязки; снимок имени остаётся в карточке. Если сборщик сейчас печатает помеченную форму — меняется он (ветка удаляется), golden-тесты перепиливаются. Обоснование: второй вид никто не потребляет, а LSS-приём понимает отсутствие ключа лучше произвольной пометки.

### Д6. Фикстуры — руками по бандл-схемам, с двойной приёмкой

`docs/qa/fixtures/dnd/`: два файла-экспорта персонажа (`character` v2: первичный и изменённый для перезаписи; содержательная часть заполнена так, чтобы табы показали снимки, привязки и id листа) и один гримуар Foundry на 2–3 предмета. Приёмка фикстур: каждая проходит наш валидатор/импортный конвейер оффскрин-тестом (файл лежит в репо — тест читает его же), и живьём импортируется в `qa-2026-10-12`. Риск «ручная фикстура ≠ живой экспорт LSS» фиксируется в отчёте как известный предел; первый живой экспорт заменит фикстуру по требованию.

### Д7. Живые прогоны — по одному агенту, последовательно

Восемь проверок делятся на два прогона qa-tester (код-фикстуры готовы) и один ui-ux-designer (hover-состояние табов — только снимок живого экрана). Игра `qa-2026-10-12`; каскад удаления — прямой SQL в файле песочницы с явной пометкой способа в отчёте (пользовательского пути удаления в продукте нет — это предел инструмента, не дефект). Упоминания — реальный мышиный клик в попапе (предел ①). Кнопки ИИ-генерации не нажимаются (LLM не настроен, живой контур — вне этого прогона).

### Д8. Документация закрывает пробелы статусами

Процедуры 13/14/15: шапки переводятся с расформированных путей на `openspec/specs/`; каждый пробел получает строку статуса «закрыт нормой <ссылка>» или «живой проверки не требует (оффскрин/дизайн-задача)» — G-03, 14-7, вторая половина 13-5. Отчёт приёмки фазы 2: запись о «зомби-попапе» помечается исправленной (follow-up 12.5, пин `test_mention_field_host.py`). Чек-лист §26 перестаёт утверждать непроверенное, §27 получает явную строку отсрочки. Roadmap: метка «в строке меню», дата статуса, снятие 4a/4b с датой и формулировкой владельца.

## Risks / Trade-offs

- [Норма-текст разойдётся с кодом при применении] → каждый цитируемый текст имеет имя константы в источнике; первый task-шаг — дифф всех цитат против констант, тесты-пины добавляются вместе с правкой.
- [Модалка может оказаться следствием блокировки стека листов, а не бокса] → воспроизведение и запись причины до правки (Д1); если причина в стеке — правка в коннекторе листов, сценарий спеки тот же.
- [Фикстуры-«рукописи» могут не совпасть с живым экспортом LSS в мелочах] → двойная приёмка (Д6) + предел в отчёте; замена фикстуры — по требованию, не молча.
- [Унификация путей отчёта зацепит golden-тесты] → форматирование на выходе отчёта (Д3), единая правка вместо по-проверочной.

## Migration Plan

Изменений схемы/форматов данных нет. Порядок внутри применения: дифф текстов → код-правки → оффскрин-пинны → калитка в обоих профилях → фикстуры + тесты фикстур → живые прогоны → правки доков по фактическим результатам (чек-лист и отчёты пишутся после прогонов, не наперёд) → CHANGELOG.
