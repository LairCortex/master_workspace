# fix-dnd-followups — заметки применения

## 2.1 Красное живое воспроизведение блокирующего SRD-уведомления (2026-10-12, до правки кода)

**Способ закрыть именно сеть SRD.** Приложение запущено из рабочего дерева
(`.venv/bin/python -m app.main`) с окружением `HTTPS_PROXY=http://127.0.0.1:9`:
общий `httpx.AsyncClient` (`trust_env` по умолчанию) проводит HTTPS-запросы
через заведомо мёртвый прокси — `connect refused` → `DatasetsNetworkError`
(«longstoryshort.app недоступен — проверьте подключение к сети»). Затронуты
только обращения к адресам наборов; ИИ-кнопки не нажимались. Игра —
throwaway `qa-2026-10-12`, созданная в лаунчере как D&D (первое включение
модуля: полок `srd51`/`srd52` в глобальном хранилище нет).

**Наблюдение (красное).** После открытия игры attach запланировал автозагрузку;
через несколько секунд поверх главного окна с **открытым и сфокусированным
листом «Настройка календаря»** появился бокс «Не удалось загрузить официальные
наборы SRD. SRD 5.1 (2014): …; SRD 5.2 (2024): …» (окно `<untitled>`, кнопка
«OK»):

1. `Esc` при открытом боксе — лист НЕ закрывается, бокс НЕ закрывается
   (клавиатура до листа не доходит).
2. Клик «OK» закрывает бокс.
3. `Esc` снова — лист закрывается сразу.

Контроль, отделяющий бокс от блокировки стека листов: после закрытия бокса
лист сидел на стеке ровно так же и закрывался по `Esc` мгновенно — т.е.
блокировала не стек-закрытка коннектора, а окно бокса (кандидат Д1 «связь с
блокировкой стека листов» отвергнут).

Дополнительное наблюдение (тот же дефект с той же причиной): кнопка
«Загрузить SRD» в листе «Датасеты D&D…» — бокс результата (`QMessageBox`,
parent — сам лист) перехватывает `Esc` на себя: закрывается бокс, лист
остаётся открытым.

**Причина (записана до правки).** `QMessageBox` по умолчанию имеет
модальность `Qt.ApplicationModal` (проверено и оффскрин:
`QMessageBox(window).windowModality() == WindowModality.ApplicationModal`).
`DndDatasetsBox`-путь `app/dd/module.py::_show_datasets_box` показывает бокс
неблокирующим `show()` (поза PR-010), но модальность по умолчанию не снимает —
на живом cocoa-дисплее окно остаётся апп-модальным и гасит клавиатуру
остальных окон: `Esc` открытого листа до листа не доходит, пользователь обязан
сначала нажать «OK». Живой зонд `System Events` подтверждает: окно бокса —
`subrole=AXDialog`, `AXModal=true`. Починка по Д1: явный
`Qt.WindowModality.NonModal` у бокса (поза PR-012, как у всех окон приложения),
оффскрин-пин + зелёное живое воспроизведение.

**Доказательства.** `evidence/2.1-before-esc-box-and-sheet.png` (бокс поверх
открытого листа), `evidence/2.2-after-esc-sheet-still-open.png` (после `Esc`
лист открыт), `evidence/2.3-after-ok-box-closed.png` (после «OK» бокса нет,
лист жив), `evidence/2.4|2.5|2.6-*.png` (тот же бокс из листа поверх стека).
Журнал запуска (stderr):
`[app.dd.application.dataset_library_service] WARNING: SRD bootstrap failed for srd51: longstoryshort.app недоступен — проверьте подключение к сети` (и `srd52`) — за день прогона три выпуска запросов; записей о выпуске запроса до починки 2.3 в журнале нет (см. 2.3).

## 2.2 (после правки) зелёное живое воспроизведение

Правка: `app/dd/module.py::_show_datasets_box` — бокс явно получает
`Qt.WindowModality.NonModal` перед `show()` (QMessageBox по умолчанию
ApplicationModal — запись Д1/2.1). Оффскрин-пин:
`tests/dd/test_dd_srd_notice_nonbinding.py` (бокс не модальный; при открытом
боксе лист закрывается по Esc без «OK», бокс остаётся открытым).

Тот же живой контур, что и в красном прогоне (тот же закрытый сеть-канал
`HTTPS_PROXY=http://127.0.0.1:9`, та же игра `qa-2026-10-12` — полки SRD
пусты, автозагрузка выпускает запросы):

1. Игра открылась, бокс сводки появился; зонд `System Events` теперь даёт
   окну бокса `modal=false` (было `modal=true`).
2. Пункт меню «Датасеты D&D…» нажимается при открытом боксе — лист поднялся
   без единого клика по «OK» (`evidence/2.7-after-fix-box-nonmodal-sheet-open.png`).
3. `Esc` — лист закрылся, бокс сводки остался открыт
   (`evidence/2.8-after-fix-esc-closed-sheet-box-still-open.png`).

Красное воспроизведение из 2.1 стало зелёным. Кнопки ИИ-генерации не
нажимались; приложение остановлено `pkill -if "app.main"`.

## 2.3 Журнал SRD-выпусков (канал `app.dd`)

Реализация в `app/dd/application/dataset_library_service.py` (сервис — единственное
место выпуска SRD-запросов; канал `app.dd.application.dataset_library_service`
лежит в семействе `app.dd` и через propagate попадает в штатный файл-журнал,
root-уровень приложения — INFO):

- `OfficialDatasetSpec.document_url` — адрес набора попал в спецификацию
  (url есть имя набора, Д2);
- перед каждым выпуском — `_LOGGER.info("SRD: выпуск запроса набора «…» (url)")`
  — ровно по одной записи на выпускаемый набор;
- исход: успех — `_LOGGER.info("SRD: набор «…» загружен: <title>")`, отказ —
  прежняя WARNING; ветка «уже в хранилище» не пишет ничего (её и не было).

Пины (`tests/dd/test_dataset_library_service.py`): идемпотентная волна после
засева не оставляет ни одной записи канала `app.dd` (наблюдаемый оффскрин
факт «сеть не обращалась»); ветка загрузки — ровно по записи о выпуске на
набор с его адресом + по записи об исходе; офлайн-волна — выпуск записан до
провала, провал — WARNING.

Живое подтверждение канала: в красном прогоне 2.1 stderr/журнал не содержал
записей о выпуске (только итоговые WARNING `SRD bootstrap failed`, сохранившиеся
в `dnd_repro_run1.log` как доремонтный контроль).
