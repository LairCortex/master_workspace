# Design: Игровая «текущая дата» (сейчас)

## Context

См. proposal.md — Why. Текущее состояние, важное для решений:

- «Сейчас» в коде нет: все носители вычисляются от `datetime.date.today()` (снимок мира, `_today_page()` попопа окна, дефолты дат карточки/диалога, предпросмотр мастера календаря).
- Даты сущностей живут в координатах активного игрового календаря (`GameCoord` + флаг «до н.э.»), сравнение — через `era_key`/`cmp_era_dates` (`domain/date_era.py`), хранение — маршрут `coord_mapping` (standard → date-колонки, custom → coord-колонки).
- `game_settings` — key/value хранилище настроек игры; типизированные обёртки — образец `LlmSettingsRepository`; повреждённые значения ключей уже имеют прецедент обработки (требование «Повреждённое значение календарь-ключа»).
- Панель деталей собирает сводку одна функция `build_detail_summary`; таймлайн — плоский список, строки считаются Python-стороной (`timeline_rows.build_rows`); правила строк в QML запрещены (qml-shell).
- Однодатовый выбор — widgets-мост `ThemeDatePopup` с сеткой `GameCalendarGrid` по сигналу `datePopupRequested` от `ThemeDateField` (библиотечный чип: роль кнопки, ширину-пол и press несёт внутри).
- Островок поиска — QML-остров с `searchBarVm` над splitter; контексты островов минимальны (qml-shell).

## Goals / Non-Goals

**Goals:**
- Одно значение «сейчас» на игру с тем же календарным представительством, что у дат сущностей (координата + эра).
- Единая доменная функция длительности и одна словесная формула на все поверхности.
- Живой пересчёт: смена «сейчас» обновляет виджет, сводку, открытые карточку/диалог, обводку и доступность кнопки таймлайна без перезапуска.
- Никаких новых колонок/таблиц и миграций схемы.

**Non-Goals:**
- Автоматический перенос «сейчас» при смене календаря (мастер сам правит виджет; переноса в отчёт мастера календаря нет).
- Возраст локаций/организаций, строка-маркер в списке, пометка «сейчас» в сетках календаря, предпросмотр мастера календаря (остаётся на системном дне).
- Фильтр «только сегодняшние события».

## Decisions

### Д1. Хранение: один ключ `game_settings`, всегда coord-кодировка, без посева

Новый ключ `CURRENT_DATE_KEY = "current_date"` (константа в `game_settings_repository.py`); значение — JSON `{"coord": "<encode_coord(GameCoord)>", "bc": 0|1}` (кодек `infrastructure/calendar_storage.py`). Типизированная обёртка — по образцу `LlmSettingsRepository`. Посев не заводится нигде (ни в `migrations.py`, ни в `init_db`): отсутствие ключа при чтении означает «реальное сегодня, переведённое `as_game_coord(date.today())` в активный календарь»; первая явная правка делает `upsert` в транзакции UoW (репозиторий сам не коммитит).
Почему coord-кодировка всегда (а не date-колонка, как у standard-сущностей): значение не участвует в SQL-сравнениях по `*_key`, ему нужна только читаемость и переиспользование кодека; альтернатива «зеркалить дату в date-колонку» не имеет места (key/value таблица одна) и создаёт два источника истины.
Повреждённое или нераскодируемое значение (в т.ч. coordinate вне диапазона после смены календаря) — поведение как у «Повреждённое значение календарь-ключа»: предупреждение в лог и жизнь по правилу отсутствия (реальное сегодня) до первой правки.

### Д2. Сервис-носитель: `CurrentDateService` (application) + одна sync-VM (presentation)

`CurrentDateService` (application/services/current_date_service.py): `load()` при открытии игры (после `CalendarSettingsService.load_and_apply()`), `async set_now(coord, bc)` — ровно одна транзакция UoW на правку, держит текущее значение (`GameCoord`, `is_bc`) и счётчик изменений — без Qt.
Носителем подписки в presentation становится `NowDateViewModel` (sync QObject): свойства `caption` («Сейчас: <дата> формата активного календаря с эрой»), сигнал `datePopupRequested`, слот приёмника выбранного значения; сигнал `now_changed` — единственный источник рассылки. Остальные VM (панель деталей, карточка, диалог события, таймлайн, снимок) получают VM/значение через composition root `main.py` и проводку `ApplicationWiring.connect` (паттерн существующих сигнальных связок), подписки отписываются при закрытии окна (как `ThemeRuntime.add_listener`-хэндлы).
Альтернатива «глобальный process-level holder как `current_calendar()`» отвергнута: значение привязано к открытой игре, глобальный мутабельный синглтон переживает смену игры и ломает правило «один источник с явным жизненным циклом».

### Д3. Длительность: доменная функция на абсолютных днях

`GameCalendar` получает `day_index(coord)` / `days_per_year` (календари имеют постоянную длину года: фиксированные месяцы + вставные дни). Новая чистая функция `domain/date_era.py` (`duration_parts(a, bc_a, b, bc_b) -> (years, months, days)`) считает абсолютные дни через `era_key` (порядок и переход «до н.э. → н.э.» уже решены там, нулевого года нет), декомпозиция жадная: годы (по фактической длине календарного года), затем месяцы от месяца-начала, остаток — дни. Возвращает знак отдельно.
Словесная формула — презентационная: `format_duration_words(parts, ahead) -> str` в `presentation/utils/date_utils.py` (рядом с `month_name`/`format_game_date`): «3 года 2 мес.», «12 дней», «сегодня», префикс «через ». Склонение — табличный помощник (год/года/лет, месяц/месяца/месяцев, день/дня/дней).
Альтернатива «считать годы/месяцы по координатам без абсолютных дней» отвергнута: ошибки на вставных днях и переходе эр; формулировка слов сознательно вне домена (текст — UI).

### Д4. Виджет: `ThemeDateField` внутри островка поиска + новый мини-VM

Строка над полем ввода `SearchBarRoot.qml`, по центру, переиспользует `ThemeDateField` (роль кнопки, press и worst-case ширина уже внутри компонента — контракт доступности выполняется штатно; имя доступа = подпись виджета). Текст чипа — `caption` из `NowDateViewModel`; активация → `datePopupRequested` → `ThemeDatePopup`/`GameCalendarGrid` с предзаполнением текущим значением (тот же путь, что поле «Дата начала» карточки). `searchBarVm` не расширяется (spec qml-shell): остров дополнительно получает context property `nowDateVm` — единственное новое биндинг-поверхность.
Альтернативы отвергнуты: новый остров (тянет фасад, контекст и geometry-роль ради одной строки); нативный widgets-хедер над splitter (ломает договорённость «панели QML-островами»).

### Д5. Отображения — минимальные врезки в существующие места правил

- `build_detail_summary(entity, entity_type)` получает параметр `now` (координата+эра или `None`) и для character/item добавляет строку `Возраст: <формула>` (законченные — до `end_date`); вызывающий `DetailPanelViewModel` подставляет текущее значение.
- `show_event` панели деталей: к `date_text` добавляется суффикс ` · <формула> назад/через N/сегодня` (формула от `start_date` события).
- Карточка сущности: `EntityCardIslandViewModel` получает `now` при сборке и держит вычисляемое свойство `ageText` («Возраст: …») для character/item; `EntityCardRoot.qml` — read-only `Text` с `objectName` под полями дат, в `build_result()` НЕ входит. Диалог события — аналогично `С начала: …` (`eventText`). Обновление при `now_changed` — слот пересчёта в VM.
- Дефолты: `entity_card_island_view_model.py` / `event_dialog_island_view_model.py` и VM снимка мира берут `now` вместо `as_game_coord(date.today())` (значение инжектится проводкой; «Сброс» снимка возвращает поле к текущему `now`).
- Правило «возраст до конца, если конец раньше сейчас» реализовано один раз — в helper'е `current-date`-домена, от него питаются и сводка, и карточка (правило «одно знание — одно место»).

### Д6. Таймлайн: флаг строки + индекс прокрутки считаются Python-стороной

`timeline_rows.build_rows` получает `now` и помечает ровно первую по сортировке строку с `start == now` (тот же день той же эры) флагом `is_now` — делегат `TimelineRowDelegate.qml` по флагу рисует обводку из `color.accent`-производной (отличие от заливки выделения — border против fill).
Кнопка «➜ Сейчас» в шапке (`TimelineRoot.qml`, рядом с чипом окна, `objectName` для оффскрин-пиннов): VM считает индекс целевой строки (первая `start_key > now_key`, иначе последняя) и эмитит запрос прокрутки; доступность — `now` внутри окна (сравнение `era_key`; окно «Все дни» — всегда доступно). Смена `now`/окна/набора пересобирает строки уже существующим механизмом `build_rows` — новых состояний не появляется.
Альтернатива «QML сам ищет строку по дате» нарушает запрет второй реализации правил в QML (qml-shell).

### Д7. Тесты и гейт покрытия

Домен: таблицы длительностей (годы/месяцы/дни, вставные дни, переход эр, ноль, «до н.э.», жадная декомпозиция). Слой БД: отсутствие ключа → реальное сегодня (дата инжектится/замораживается тестом), roundtrip upsert, изоляция игр (in-memory), повреждённое значение → правило отсутствия. VM: caption, `now_changed`, дефолты карточки/диалога/снимка, «возраст» вне результата сохранения, индекс прокрутки и доступность кнопки, флаг `is_now`. QML-остров поиска: строка видна по `objectName`, чип именован, live-retheme без потери состояния; конвенция доступности — guard-тесты (stock-переаннотации нет, role/name на месте, press → сигнал через `QAccessible` actionInterface, паттерн `tests/presentation/test_*_accessibility*.py`). Все новые продуктовые строки покрыты (гейт 100 %).

## Risks / Trade-offs

- [Смена календаря мастером оставляет координату «сейчас» вне нового календаря] → декод-ошибка обрабатывается как «повреждённое значение» (лог + правило отсутствия); отчёт мастера календаря «сейчас» не переносит — осознанно вне объёма, риск закрывается одной правкой виджета.
- [Длительность через абсолютные дни при очень больших годах/до н.э.] → арифметика Python int, ограничений нет; переход без нулевого года закреплён тестом.
- [Открытая карточка получает `now_changed` через проводку — риск утечки подписки при закрытии] → VM карточки/диалога отписывается в существующем close-guard пути; offscreen-тест «после закрытия сигнала нет».
- [Формулировки («2 года 4 мес.», «назад», «сегодня») — продуктовые тексты без первоисточника] → зафиксированы в спеках сценариями, правки только через спеку.
- [ThemeDatePopup над островком поиска без родительского виджета даты] → попоп и так parent-less top-level с зажимом в `availableGeometry` (существующий контракт game-calendar-grid), риск равен нулю.

## Migration Plan

Схема не меняется; данные не мигрируются. Раскатка = обычный релиз. Откат кода безвреден: осиротевший ключ `current_date` игнорируется (неизвестные ключи `game_settings` никогда не читались выборочно).
