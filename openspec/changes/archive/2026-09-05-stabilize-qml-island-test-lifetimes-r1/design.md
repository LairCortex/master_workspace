## Context

Текущее состояние (см. также proposal.md — Why):

- `setup_qml_shell` создаёт один `QQmlEngine` на процесс (parent — `QApplication`); production никогда его не разрушает. `reset_qml_shell` (`app/presentation/qml/engine.py:95-108`) — test-only: `setParent(None)` + сброс ссылки, то есть немедленное C++ разрушение движка (палитра-ребёнок умирает вместе с ним).
- `tests/conftest.py:39-54` — autouse-фикстура `isolated_qml_shell` вызывает reset на входе и на выходе каждого теста; autouse `no_stale_windows` (`:57-80`) на teardown только скрывает видимые top-level'ы, ничего не уничтожая. Итог: пережившие тест `QQuickWidget`-островы (а leaks массовые: `qtbot.addWidget` скрывает, но не удаляет; `deleteLater` без прокачки висит; `QTimer.singleShot(0, …, _release_island)` отложен) доживают до разрушения движка — сцена остаётся висящей на мёртвом движке.
- Острова уже имеют отработанный шов освобождения `setSource(QUrl())` (launcher/timeline/list/editor/preset-фасады; идемпотентен, двойной вызов — no-op; синхронный вызов вне JS-стека безопасен — прецедент `preset_dialog.py`, где синхронный релиз стал сознательной поправкой Q3a). На pytest-teardown JS-стек всегда размотан (файнализаторы исполняются из pytest-кадра).
- Порядок автофикстур на teardown уже закодирован определением: hide (`no_stale_windows`) → движок (`isolated_qml_shell`) → тема-runtime (`isolated_ui_theme_defaults`); палитра острова — слабый слушатель темы, инвариант «ровно один движок» проверяется в `tests/presentation/test_qml_engine.py`.
- DPR: в тестах нет ни одной DPI-переменной; на Retina-хосте (macOS) часть grab'ов возвращается 2× (артефакты 2×128 против 64 в `test_qml_render_smoke.py:33`, `test_launcher_qml.py:445`), CI offscreen — DPR 1; большинство тестов компенсируют измерением idiom'ом `_grab_scaled`, но две проверки захардкодили логический размер.
- API подтверждён в окружении (PySide6 6.10.2): `shiboken6.delete`/`shiboken6.isValid` доступны, `QEvent.Type.DeferredDelete`, `QTest.qWait` — штатные.

## Goals / Non-Goals

**Goals:**
- Инвариант порядка разрушения: живые острова → отложенные уничтожения/релизы → острова → движок → тема-runtime. После сброса не существует объекта «живая сцена на мёртвом движке» ни в какой момент.
- Детерминированный DPR=1 для grab-приёмки на любом хосте + guard-проверка, которая падает раньше случайного пиксельного теста.
- Цена — нулевая для не-QML тестов (sweep условный), полная совместимость с гейтом 100%-покрытия.

**Non-Goals:**
- Не переписываем.facade-островов (их `done()/closeEvent`-швы остаются как есть; при обнаружении реальных попаданий — допустимое точечное усиление `shiboken6.isValid` guard'ами последующим срезом/в этом, если всплывёт на приёмке).
- Не трогаем `tests/ui/conftest.py` (app-fixutre со своим shutdown-порядком уже корректна), production-жизненный цикл движка, контракт «движок один на приложение», плагины pytest (рандомизация порядка не вводим).
- Не переписываем существующие пиксельные idiom'ы `_grab_scaled` — оставляем запасной защитой.

## Decisions

**D1. Sweep живёт в `app/presentation/qml/engine.py внутри reset_qml_shell` (расширение), а не в conftest.**
Reset — единственная точка разрушения движка во вском тест-сте; вся логика порядка в одном месте. Строки выполняются autouse-вызовом на каждом тесте → покрыты 100% без исключений (альтернатива — helper в conftest: вне coverage, дублирование ответственности — отвергнута).

**D2. Алгоритм сброса (условный: только если движок был создан за тест):**
1. `QCoreApplication.sendPostedEvents(None, QEvent.Type.DeferredDelete)` — детерминированно добираем очередь `deleteLater` без ожидания таймеров.
2. `QTest.qWait(≈5 мс)` — прокручивает posted-события и нулевые singleShot-таймеры: отложенные `_release_island` фасадов исполняются, пока движок жив (прецедент прокачки: `qtbot.wait(1)`/`qWait(20)` внутри текущих тестов).
3. Sweep: `QApplication.instance().topLevelWidgets()` → рекурсивно `findChildren(QQuickWidget)`; для каждого живого (`shiboken6.isValid`) — `setSource(QUrl())` (шов фасадов, идемпотентен), затем `shiboken6.delete(widget)` — немедленное C++-уничтожение острова раньше движка.
   Почему сразу, а не `deleteLater`+ожидание: `QQuickWidget`-деструктор обращается к указателю движка — оставленный живым после смерти движка он даёт UAF независимо от предварительного `setSource`;немедленный delete не зависит от таймингов цикла событий (альтернатива «ещё один цикл прокачки»: недетерминизм сохраняется).
4. Разрушение движка как сегодня (`setParent(None)` + сброс ссылки).

**D3. Уничтожаем только `QQuickWidget`-потомков, не целые диалоги.**
Qt сам вычищает умершего ребёнка из parent-списков; видимость/структура остальных top-level'ов не тронута, `no_stale_windows` продолжает работать как hide-страховка для не-QML утечек (альтернатива — удалять все leak-окна: избыточно агрессивный blast radius для не-QML тестов — отвергнута).

**D4. DPR фиксируется переменными окружения у импорта `tests/conftest.py` (рядом с `QT_QUICK_BACKEND`), набором `QT_ENABLE_HIGHDPI_SCALING=0`, `QT_AUTO_SCREEN_SCALE_FACTOR=0`, `QT_SCREEN_SCALE_FACTORS=1`, `QT_SCALE_FACTOR=1`** — до создания `QApplication` (переменные читаются на её старте). Guard-тест проверяет `QApplication.instance().devicePixelRatio() == 1` (плюс grab крошечного виджета = логический размер): если Qt поменяет семантику переменных, падает ровно один guard, а не разбросанные пиксельные проверки. Измерительные idiom'ы остаются (защита в depth).

**D5. Новые тесты изоляции — `tests/presentation/test_qml_shell_isolation.py`:**
- живой остров + ручной `reset_qml_shell()` в теле теста → без падения; `shiboken6.isValid(остров) == False`; Python-ссылка безопасна;
- объект с pending `deleteLater` уничтожен сбросом до смерти движка;
- повторный `setup_qml_shell` после reset даёт ровно один движок (усиление существующего count-assertion рядом с новым порядком);
- DPR/guard-тест (D4).

**D6. Приёмка недетерминированности — повторными прогонами, без новых зависимостей:** полный `python -m pytest` ×3 подряд на macOS (DPR-хост, худший случай) и зелёный CI-offscreen. Плагина permuting-order сознательно не заводим (новый dependency ради одного куска — неоправдан; регрессия порядка покрывается инвариантными тестами).

## Risks / Trade-offs

- [`shiboken6.delete` острова внутри живого диалога → поздний `done()`/`closeEvent` фасада обратится к невалидной обёртке] → Python-исключение в позднем Qt-колбэке печатается и не роняет процесс; после сброса никто не вызывает `done()` уничтоженного leak-диалога (popups-заглушки `tests/ui/conftest.py` и hide-only sweep это ограничивают); если приёмка поймают реальные попадания — точечные `shiboken6.isValid` guarda в фасадах тем же срезом.
- [qWait внутри finalizer'а над qasync-циклом может реактивировать «тихие» coroutine-хвосты] → условность (только при живом движке) и малое окно (≈5 мс); порядок app-fixutre (`wait_until_settled` до shutdown) не затронут — он отрабатывает раньше автофикстурного сброса.
- [`sendPostedEvents(DeferredDelete)` исполняет `deleteLater` быстрее, чем привык тайминг-зависимый тест] → это целевое поведение (уничтожение без ожидания); при попадании — фикс такого теста входит в приёмку (полные прогоны ×3).
- [`QT_SCALE_FACTOR`-набор может не подействовать на какой-то платформе] → guard-тест падает первым и именует причину; fallback (перевод всех grab'ов на измеренный idiom) — известный, но откладывается как не-цель.
- [Двойная работа: фасады и sweep вызывают один и тот же `setSource(QUrl())`] → идемпотентность шва зафиксирована комментариями/тестами Q3a; риск нулевой.
