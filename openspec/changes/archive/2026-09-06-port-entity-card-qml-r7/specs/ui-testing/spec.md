## MODIFIED Requirements

### Requirement: Widget-тесты интерактивных views

Система SHALL иметь изолированные UI-тесты, управляющие мышью и клавиатурой интерактивными views приложения через их актуальную поверхность: реальный QML-остров для перенесённых экранов и widget для оставшихся нативных экранов/мостов. Тесты SHALL покрывать таймлайн (отрисовка событий, выбор элемента, контекстное меню), диалог события (сохранение, связанные сущности), детальную панель (отображение и редактирование), карточку сущности (режим редактирования, дополнительные поля по типам, изображение, связи, AI, сохранение без valid-гейта), редакторы дат (специальные даты), mentions (вставка и клик), обзор мира (режим «Показать всё»), AI-ассистента (статусы) и состояние приложения. Интерактивные QML-контролы SHALL адресоваться по `objectName`; карточка SHALL иметь semantic-приёмку по типам и один live-retheme-тест без потери введённых данных, выбора или скролла. Уже принятая поэлементная pixel-приёмка библиотечных компонентов SHALL не дублироваться в наборе карточки.

#### Scenario: Карточка сохраняет без valid-гейта

- **WHEN** в изолированном тесте пользователь нажимает Save в карточке сущности с пустыми полями
- **THEN** QML-остров эмитит запрос сохранения с текущими данными, не закрываясь до результата владельца

#### Scenario: Ошибка сохранения карточки

- **WHEN** владелец завершает сохранение карточки ошибкой
- **THEN** реальный остров остаётся открыт, сохраняет введённые данные и разрешает повторный Save

#### Scenario: Поля карточки различаются по типу

- **WHEN** тесты открывают карточку последовательно для каждого поддерживаемого типа сущности
- **THEN** через `objectName` доступны ровно базовые, дополнительные, image- и related-контролы, заданные конфигурацией каждого типа

#### Scenario: Валидация блокирует сохранение

- **WHEN** пользователь пытается сохранить событие с незаполненными обязательными полями
- **THEN** диалог события не принимает данные и указывает на ошибку; карточка сущности этим valid-гейтом не ограничена

#### Scenario: Взаимодействие с таймлайном

- **WHEN** пользователь кликает по отображаемому событию
- **THEN** в детальной панели загружаются данные этого события

#### Scenario: Клик по mention-ссылке

- **WHEN** пользователь кликает по mention-ссылке сущности в тексте
- **THEN** открывается соответствующая детальная карточка

#### Scenario: Статусы кнопки AI-ассистента

- **WHEN** LLM не настроен, а затем настроен
- **THEN** AI-действие сначала неактивно, затем активно с соответствующими текстами

#### Scenario: Live-retheme карточки сохраняет состояние

- **WHEN** тема переключается при открытой карточке с введённым текстом, выбранной связью и прокрученной формой
- **THEN** QML-остров использует новую палитру без потери текста, выбора, позиции скролла и без пересоздания общего движка
