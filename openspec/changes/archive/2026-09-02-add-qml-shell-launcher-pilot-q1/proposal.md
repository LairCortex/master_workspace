# Proposal: QML-каркас и пилот лаунчера (Q1)

## Why

Эпик Q начинает переход presentation-слоя на Qt Quick: без проверенного каркаса (движок, мост токенов, контракт биндингов, тесты, сборка) каждый следующий QML-экран в Q2/Q3 будет заново решать эти же вопросы. Дорожная карта требует, чтобы Q1 доказал жизнеспособность второго UI-стека на трёх ОС на реальном, но изолированном экране — им становится стартовый диалог выбора игры: он не зависит от открытой базы, уже темизован W1/W2 и имеет полный набор типовых элементов (список, кнопки, тумблер темы).

## What Changes

- В приложение добавляется QML-каркас: один общий `QQmlEngine` на процесс, поднимаемый при старте; QML-поверхности живут `QQuickWidget`-островами внутри нативных окон, QtWidgets остаётся хозяином приложения (нативные меню/диалоги не затрагиваются).
- Токены W1 приходят в QML через `QmlPalette` — тонкий QObject с плоским набором ключей ровно из `tokens.json` (производные цвета считает Python); live-retheme приходит сигналом палитры; третьего компилятора стилей не появляется.
- Стиль Qt Quick Controls — Basic, задаётся программно; делегаты лаунчера стилизуются inline; библиотека общих QML-компонентов — работа Q2.
- Контракт биндингов: QML вызывает только синхронные входы view model; async остаётся на Python-стороне wiring. Существующие VM не переписываются; там, где VM не было (лаунчер), она заводится по общим правилам.
- **BREAKING (внутри приложения):** `GameLauncherDialog` полностью переезжает на QML-островок: рамка/Esc остаются системными (`QDialog`-обёртка), содержимое (список игр, Открыть/Новая игра/Удалить/Импорт, тумблер темы) — QML. Widgets-версия содержимого удаляется целиком, второй копии за флагом нет. Поведение и пользовательский поток лаунчера не меняются.
- Нативные всплывашки лаунчера остаются widgets: ввод названия — `QInputDialog`, подтверждения/конфликты — `QMessageBox`, выбор файла импорта — `QFileDialog`.
- Сборка: `.spec` получает QML-каталог и модули QtQuick/QtQuickControls2/QtQuickWidgets + qml-плагины; файл-тест бандла по образцу `test_spec_theme_bundle.py`.
- Тесты: `QT_QUICK_BACKEND=software` в `tests/conftest.py`; QML-контролы адресуются по `objectName`; приёмка пикселем (hex токена), не golden PNG; минимум PySide6 поднимается до 6.8.
- Явные запреты куска (фиксируются в спеках): канвас чар-листа, нативные меню/диалоги приложения, mention-edit и любой экран кроме лаунчера в Q1 не переносятся.

## Capabilities

### New Capabilities

- `qml-shell`: QML-каркас приложения — движок и острова, мост токенов `QmlPalette` и live-retheme, стиль Basic, контракт биндингов QML↔VM, размещение qml-файлов и попадание в сборку, инфраструктура тестирования QML-поверхностей.
- `game-launcher`: наблюдаемое поведение стартового диалога выбора игры (список каталога, открытие, создание с валидацией имени, удаление с подтверждением, импорт .nri с подтверждением конфликта, тумблер темы) на QML-островке.

### Modified Capabilities

- `ui-theme`: «Область применения QSS» — содержимое лаунчера выходит из-под QSS (его стиляет палитра для QML), QSS-область лаунчера сокращается до рамки-обёртки; «Переключение без перезапуска chrome» — лаунчер перекрашивается по сигналу палитры, а не сменой QSS; «Хром без палитры ОС и hex» — инвариант зачистки распространяется на qml-код (ни literal-hex, ни палитры ОС в темизуемых поверхностях, вне скина — именованные Qt-глобалы).

## Impact

- `app/main.py` (`Application.start()`) — создание общего `QQmlEngine`, `QQuickStyle.setStyle("Basic")`, wiring палитры.
- `app/presentation/theme/` — `QmlPalette` (новый модуль), подписка на `ThemeRuntime.add_listener`.
- `app/presentation/viewmodels/launcher_viewmodel.py` — новая VM каталога игр (sync-контракт).
- `app/presentation/views/game_launcher_dialog.py` — перестроен в QDialog-обёртку с `QQuickWidget`; `app/presentation/qml/` — новый каталог qml-файлов.
- `app/application/wiring.py` (или эквивалентный wiring лаунчера) — обработка сигналов VM, вызовы каталога, показ нативных всплывашек.
- `nri_manager.spec` + `pyproject.toml` (PySide6 `>=6.8`) + `tests/conftest.py` (`QT_QUICK_BACKEND=software`).
- Тесты: существующие сценарные тесты лаунчера (`tests/ui/`, `tests/presentation/test_theme_apply.py`, coverage-gaps) сохраняют семантику через адресацию QML-объектов; новые — бандл-тест, пиксельная приёмка палитры, контракт sync-билингов.
- БД/миграции: нет. Canvas, mention-edit, остальные экраны:нет изменений.
