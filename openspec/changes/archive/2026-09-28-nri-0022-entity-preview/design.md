## Context

См. proposal.md — Why. Текущее состояние, важное для подхода:

- Главное окно — три колонки `QSplitter` (`main_window.py`): TimelineWidget, DetailPanel, WorldSnapshotWidget (QML-острова через `IslandDialogMixin`).
- Строка DetailPanel: Press (accessibility) и двойной клик мыши ведут в `DetailPanelViewModel.activate` → `Wiring._on_entity_click` → редактируемая `EntityCardDialog`; одиночный клик мыши не занят. Подсветки строк нет.
- HTML-сводки DetailPanel уже рисуют упоминания ссылками (`build_detail_summary`), ссылки перехватываются — тот же приём пригоден для предпросмотра.
- Картинки: sha256-файлы + таблица `images`; ссылки `image_id`+eager `image_ref` есть у организаций, персонажей, локаций; у предметов нет. Послекоммитный хук UoW и startup-сканирование считают владение файлами по списку ссылающихся мест.
- `MenuWindowRegistry` уже реализует «повторный вызов поднимает живое окно», `WindowGeometryMemory` — память рамок по роли; роль `world_snapshot` свободна.
- Хронологический порядок дат с эрами задан координатами (`coord_mapping`/era-ключ); по нему сортируется шкала.

## Goals / Non-Goals

**Goals:**
- Предпросмотр как read-only QML-остров с единым «автобусом выбора» сущностей (средняя колонка, связи, упоминания, поиск — все выбирают через один сигнал).
- Обзор мира — то же содержимое в отдельном окне без правки его внутренней логики.
- Картинка предмета — по колее существующего конвейера, без новых путей хранения.

**Non-Goals:**
- Контекстное меню правой кнопки (жест только зарезервирован).
- Предпросмотр событий, картинки/экспорт-колонки предметов в xlsx, AI-кнопки в предпросмотре, редактирование из предпросмотра.
- Value-мост accessibility (остаётся NRI-0013).

## Decisions

1. **Новый остров `EntityPreviewWidget` + `EntityPreviewViewModel` + `EntityPreviewRoot.qml`** (роль колонки — предпросмотр). Поля рендерятся read-only текстовыми блоками; упоминания — HTML-ссылки тем же генератором, что сводки DetailPanel, перехват `onLinkActivated` → сигнал выбора. Альтернативы: read-only MentionField (тяжёлый, интерактивный контрол против read-only контракта), отдельный WebView (избыточно).

2. **Данные через wiring, не через сессию.** Презентация не видит ORM: остров эмитит `entityRequested(type, id)`; `ApplicationWiring` грузит сущность через entity-сервис (связи уже приходят с `get_entity`) и вызывает `preview.show_entity(...)`; тот же путь — для связей/упоминаний предпросмотра. Обновление после сохранения карточки и очистка при удалении — существующие сигналы сохранения/удаления карточки, которые wiring уже слушает, дополняются вызовом предпросмотра/очистки при совпадении (тип, id).

3. **Выбор в средней колонке.** `DetailPanelViewModel` получает выбранную (тип, id) в ролях модели (`selected`), одиночный клик мыши → `entitySelected(type,id)` (новый сигнал, отдельный от `entityActivated` двойного клика). Enter: `Keys.onReturnPressed` на ListView острова → прежний `activate` (карточка); офскрин-пин через установку фокуса и `QTest.keyClick`, Press-пин как в существующих тестах островов. Выделение одно на панель; смена вкладки скрывает подсветку, не трогая предпросмотр (экранное состояние, не состояние выбора).

4. **Синхронизация центра при переходах из предпросмотра.** Wiring: выбор из предпросмотра → показать в предпросмотре; затем попытка подсветки в DetailPanel (переключение вкладки типа + выделение строки) — no-op, если сущности нет в текущем списке; таймлайн не трогаем.

5. **Окно обзора мира.** `WorldSnapshotWidget` получает обёртку-окно (top-level, `NonModal`, `show()`), регистрируется в `MenuWindowRegistry` под ключом `world_snapshot`, действие «Обзор мира…» прямо в `QMenuBar` главного окна. QML-содержимое и VM не меняются. Первый размер 520×760 — центрированием при отсутствии сохранённой рамки уже заведёт `WindowGeometryMemory`; роль добавляется в его список. Контракт окон в AGENTS.md дополняется в том же изменении.

6. **Картинка предмета.** Миграция `_MIGRATIONS` в `migrations.py`: `ALTER TABLE items ADD COLUMN image_id INTEGER REFERENCES images(id) ON DELETE SET NULL`; у `ItemModel` — `image_ref` (eager, как у остальных); в реестре/`_FIELD_SPECS` предмету добавляется спецификация поля `kind: "image"` — колонка картинки карточки, миниатюры и предпросмотр подхватывают механизм целиком. Обязательно: все места учёта владения файлами (послекоммитный GC изображений, инвариант startup-сканирования, очистка при удалении) дополняются ссылкой предметов — иначе файлы удавятся раньше времени.

7. **Полный путь поиска.** Новый метод сервиса событий: «последнее по началу событие для сущности» (сравнение по хронологическому моменту начала с эрами, при равенстве — меньший id; нет событий — ничего). Wiring поиска: есть событие → выбрать на шкале (со сбросом окна фильтра), открыть детали, выделить строку, показать предпросмотр; нет → только предпросмотр. Правая кнопка мыши в списке поиска не обрабатывается (в QML-делегате только `onClicked`/`onDoubleClicked` левой кнопки).

8. **Accessibility.** Описание строки DetailPanel меняется с «Открывает карточку» на «Выбирает сущность» (содержимое зафиксированного набора в qml-accessibility расширяется); связи предпросмотра — «Переходит к сущности», чипы упоминаний — «Открывает упомянутую сущность». Гвард-тест конвенций обновляется вместе.

## Risks / Trade-offs

- [GC изображений не учтёт ссылку предметов → преждевременное удаление файлов] → все подсчёты ссылок проходят grep-инвентаризацией (`image_id`, `image_ref`), тест «предмет и персонаж делят файл, предмет удалён — файл жив».
- [Enter-пин офскрин нестабилен (фокус QML-острова)] → паттерн стабилизации жизненного цикла островов + `processEvents` перед `keyClick`; в крайнем случае пин через прямой вызов обработчика возврата с сохранением live-проверки в аудите.
- [Одиночный выбор конфликтует с прокруткой/нажатиями по картинке строки] → клик по картинке остаётся отдельным обработчиком (открывает просмотр), выбор строки не гасит его.
- [Предпросмотр «отстаёт» от среднего столбца после смены события — намеренное правило] → принято спецификацией; пустое состояние и заголовок «Карточка: <тип>» делают состояние очевидным.
- [Тестовый teardown: окно обзора живёт после закрытия главного] → закрытие именованных окон уже вшито в teardown-конфиг (NRI-0019-паттерн); роль в `MenuWindowRegistry` подхватывает его автоматически.

## Migration Plan

Добавляющая миграция схемы (колонка `items.image_id` через `init_db()`), обратного преобразования нет; откат изменения — обычным revert коммитов. Формат файлов игр и БД совместимы со старыми версиями (старая версия приложения просто игнорирует новую колонку).
