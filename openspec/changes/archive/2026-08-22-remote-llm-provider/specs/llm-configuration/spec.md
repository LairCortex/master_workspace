## Purpose

Настройка подключения AI-ассистента: глобальный конфиг подключения (endpoint, модель, ключ), модель статусов AI-функциональности и форма подключения в диалоге настройки.

## ADDED Requirements

### Requirement: Глобальный конфиг подключения

Система SHALL хранить настройки подключения LLM (endpoint, модель, ключ API) глобально для всех игр в файле конфигурации приложения, не зависит от системных хранилищ (keychain) операционной системы. Файл конфигурации SHALL быть доступен только текущему пользователю (права 0600). Ключ API SHALL быть необязательным: подключение валидно при непустых endpoint и модели. Настройки SHALL переживать перезапуск приложения.

#### Scenario: Сохранение настроек

- **WHEN** пользователь заполняет форму подключения (endpoint, модель, при необходимости — ключ) и нажимает «Сохранить»
- **THEN** настройки сохраняются и подставляются при следующем запуске приложения независимо от открываемой игры

#### Scenario: Запуск без конфигурации

- **WHEN** файл конфигурации отсутствует
- **THEN** AI-функциональность находится в статусе «не настроено», приложение работает без ошибок

#### Scenario: Права файла конфигурации

- **WHEN** приложение создаёт файл конфигурации
- **THEN** файл читается и записывается только текущим пользователем (0600)

### Requirement: Маскирование ключа в интерфейсе

Система SHALL отображать поле ввода ключа API в замаскированном виде; ключ SHALL не отображаться в открытом виде ни в одном UI-элементе.

#### Scenario: Ввод ключа

- **WHEN** пользователь вводит ключ API в диалоге настройки
- **THEN** вводимые символы отображаются замаскированными

### Requirement: Статусы AI-ассистента

Система SHALL поддерживать ровно два статуса AI-функциональности: «не настроено» (нет непустых endpoint и модели) и «готово» (сохранены непустые endpoint и модель). Переход в «готово» не SHALL требовать обращения к сети: приложение SHALL запускаться и работать офлайн. AI-кнопки активны только в статусе «готово» и при наличии описания мира.

#### Scenario: Настроено подключение

- **WHEN** сохранены непустые endpoint и модель, и описан мир
- **THEN** AI-кнопки активны, генерация доступна без запуска каких-либо локальных моделей

#### Scenario: Не настроено

- **WHEN** пользователь нажимает неактивную AI-кнопку
- **THEN** система показывает подсказку перейти в меню LLM → «Настройка LLM…»

#### Scenario: Офлайн-запуск

- **WHEN** приложение запускается без доступного сервера LLM
- **THEN** запуск проходит штатно, статус и AI-кнопки определяются только по сохранённым настройкам

### Requirement: Форма подключения в диалоге настройки

Диалог «Настройка AI-ассистента» SHALL содержать страницу подключения с полями endpoint, модель, ключ API (маскируется, необязательное) и кнопкой «Проверить соединение». Страница SHALL не содержать функций скачивания, удаления или загрузки модели. Сохранение настроек SHALL быть невозможно при пустых endpoint или модели.

#### Scenario: Открытие диалога

- **WHEN** пользователь открывает «Настройка LLM…»
- **THEN** открывается страница подключения с подставленными значениями сохранённых настроек и кнопкой проверки

#### Scenario: Пустая форма

- **WHEN** поле endpoint или модели пустое
- **THEN** сохранить настройки нельзя

### Requirement: Удаление локальной LLM

Система SHALL НЕ предлагать скачивание, установку зависимостей и запуск локальной GGUF-модели. Механизмы загрузки модели, установки пакетов и удаления модели SHALL быть полностью удалены из приложения и его зависимостей.

#### Scenario: Нет функций скачивания

- **WHEN** пользователь открывает диалог настройки AI-ассистента
- **THEN** кнопки «Скачать модель»/«Удалить модель» и индикатор загрузки отсутствуют

#### Scenario: Работа без локальных зависимостей

- **WHEN** приложение запущено без каких-либо локальных LLM-зависимостей
- **THEN** AI-функциональность полностью доступна при настроенной внешней LLM
