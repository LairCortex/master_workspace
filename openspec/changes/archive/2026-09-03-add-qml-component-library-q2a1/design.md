## Context

Q1 оставил стилизацию внутри `LauncherRoot.qml`: inline-компонент `ThemedButton`, локальные хелперы `token()`/`px()`, делегат-стиль строки. Мост токенов (`QmlPalette` → context property `islandPalette`), один движок (`setup_qml_shell` + `addImportPath(app/presentation/qml)`) и оф-скин-семантика (пустые токены → базовый Basic) уже работают и зафиксированы тестами. Виджетный каталог W2 (`catalog.py`, роли `title/hint/field/list/card/status-*`) — семантический источник ролей, но в этом куске не трогается. Мотивация — proposal.md.

## Goals / Non-Goals

**Goals:**
- Библиотека переиспользуема из любого острова без дополнительной прокладки (контекст, import-путь, qmldir настроены один раз в движке).
- Пилотный лаунчер — потребитель библиотеки (кнопка и делегат строки); регресса видом или поведением не допускается.
- Пиксельная приёмка живёт только в тестах библиотеки; тесты будущих островов её не дублируют.

**Non-Goals:**
- Не переносим и не удаляем widgets-каталог (`catalog.py`) и QSS-роли переживающего хрома.
- Не добавляем компоненты «на вырост» сверх набора из spec (тултипы/поповеры/меню — вне; shim тултипов — другой кусок Q2).
- Не трогаем `tokens.json`, `QmlPalette`, VM и Python-обёртку лаунчера (меняется только qml-код лаунчера: импорт модуля).
- Никаких async, QML-меню, попапов.

## Decisions

### D1. Модуль `nri.components`, каталог `app/presentation/qml/nri/components/`

`qmldir`: `module nri.components` + записи типов. Qt резолвит импорт такого модуля как `<importPath>/nri/components/qmldir`, поэтому код движка не меняется — `QML_IMPORT_PATH` уже настроен.
*Альтернатива:* односложный модуль `components` в `qml/components/` — путь короче, но имя ближе к коллизиям (`Components` — имя QML-типа/модуля Qt), и конфликт регистра на case-insensitive FS неустраним; префикс `nri.` недвусмыслен. Формулировка роадмапа «qml/components/» считается уточнённой этим куском.

### D2. Палитра для компонентов — через цепочку creation context, без нового прокинга

Компоненты обращаются к `islandPalette` через name resolution по цепочке контекстов (так же, как его сейчас видит `LauncherRoot`), со страховкой `typeof islandPalette !== "undefined"`. Хелперы `token(name, fallback)`/`px(name, fallback)` переезжают в `tokens.js` с `.pragma library` (без состояния). Обёртка острова по-прежнему сама кладёт `islandPalette` в свой rootContext.
*Альтернативы:* обязательный property `palette` у каждого компонента — явнее, но обязывает каждый экран прокидывать вручную (забыл = молча деградировал оф-скином, хуже диагностики); singleton с мутируемым полем palette — глобальное состояние, ломает параллельные тесты с разными палитрами.
*Цена:* компонент вне острова без `islandPalette` ведёт себя как оф-скин (задокументировано, совпадает с семантикой D7).

### D3. Экстракция `ThemeButton` один-в-один из `LauncherRoot.ThemedButton`

Свойства `accentBackground`, hover/pressed через `color.accent.hover/pressed`, `skinned`-флаг по наличию `color.bg.surface`, оф-скин = `background.visible: false`. `LauncherRoot` импортирует `nri.components`, inline-компонент удаляется; маркер `defaultButton` (контракт Enter) остаётся на root лаунчера и указывает на библиотечную кнопку.
*Альтернатива:* переиспользование без qmldir через URL-импорты файлов — не даёт штатного `import` модуля и не проверяется в бандле.

### D4. Набор компонентов (= spec) и соответствие ролям W2

`ThemeButton` (акцентная/обычная кнопка), `ThemeField` (`TextField`: bg `color.bg.canvas`, border `color.border`, border в фокусе `color.accent`), `ThemeCheckBox`, `ThemeComboBox` (поле + индикатор по токенам), `TitleText`/`HintText` (роли title/hint: шрифт/вес/цвет — те же токены, что выдаёт `catalog.py` для фабрик title/hint), `CardPanel` (Rectangle: bg + border + radius, роль card), `RowItem` (строка списка из делегата лаунчера: selected → accent + accentFg). Каждому компоненту: оформляющие свойства только из токенов/производных; оф-скин — базовый контроль Basic плюс именованные Qt-глобалы. Строка списка — компонент-обёртка, а не глобальный стиль `ListView`: список остаётся композицией острова (нужно для delegate'атов уровня W3b в Q2b).
*Альтернатива:* глобальные стили Controls — у Basic нет сущности «тема», глобальные переопределения просочились бы в не-темизируемые места; точечные компоненты предсказуемее.

### D5. Пакетирование: расширить существующий datas + бандл-тест

Факт Q1: `nri_manager.spec` кладёт qml в `datas` поштучными записями (`app/presentation/qml/LauncherRoot.qml`), а не деревом. Значит в datas добавляются файлы модуля: `nri/components/qmldir`, каждый `*.qml` компонента и `tokens.js`; бандл-тест `tests/test_spec_qml_bundle.py` дописывается проверкой, что эти файлы присутствуют в собранном дереве. Runtime-резолв модуля из исходников покрывается обычными qml-тестами (тот же import-путь, что и в бандле).

### D6. Тесты: gallery-остров + pixel только здесь

`tests/presentation/qml_components_gallery.qml` — демонстрационная сцена со всеми компонентами (у каждого `objectName`), поднимается `QQuickWidget` с реальным движком/палитрой (оффскрин-backend из `conftest.py`, паттерн `qml_helpers.py`). Проверки: (1) pixel-совпадение ключевой поверхности каждого темизируемого компонента с hex токена для обеих тем (текстовые роли — наличием пикселя exact-цвета внутри bounds текста, без golden); (2) live-retheme: смена темы палитрой → новый hex без пересоздания острова; (3) off-skin: пустые токены → скина нет, `quick.errors()` пусто, взаимодействия работают; (4) отсутствие палитры в контексте = эквивалент оф-скина, без exceptions. `test_no_chrome_hex.py` расширяется glob'ом на `app/presentation/qml/**/*.qml` и `tokens.js` (ни hex, ни палитры ОС в оформляемых свойствах). `test_launcher_qml.py` остаётся зелёным без ослабления (objectName-контракты сохранены в местах использования).

## Risks / Trade-offs

- [Pixel-тесты текста хрупки между ОС/рендерерами] → проверка «внутри bounds текста есть пиксель exact-цвета токена», фиксированные размер и набор глифов, без golden-PNG; при отказе одной ОС CI работает уже принятое правило qml-shell «пиксель — на работающих ОС».
- [Компонент вне острова без `islandPalette` деградирует молча] → это задокументированный оф-скин (D2); отдельный тест фиксирует отсутствие exceptions; обязательность прокида проверяется retheme-тестами самих островов.
- [qmldir-формат/регистр пути в PyInstaller-дереве] → файловый бандл-тест проверяет точное имя `nri/components/qmldir`; runtime-тесты идут через тот же относительный layout.
- [Два источника ролей: qml-библиотека и `catalog.py`] → роли заимствованы один раз (D4) как таблица соответствия в этом design; расхождение поимеет pixel-тест библиотеки; дублирования цветов нет.
- [Рефактор лаунчера может сдвинуть пиксель (паддинги/шрифты после извлечения)] → objectName-контракты и поведение жёсткие; golden'а на лаунчер нет (Q1 пиксели проверяли токены палитры) — сохранность подтверждает прогон существующих тестов как есть.

## Migration Plan

Обычный merge в `main` одним куском: библиотека → рефактор лаунчера → тесты/бандл → CHANGELOG (пометка: эпик Q открыт, это Q2a1). Rollback = revert commit; данные и схемы не затронуты; вторая (widgets) копия лаунчера не заводится ни на одном шаге.
