# Design: Drag-редактирование дат на шкале (W5)

## Context

См. proposal.md — Why; поведение — в delta-спеке `specs/event-timeline/spec.md`. Текущее состояние, влияющее на подход:

- Шкала — `QListWidget` (`TimelineListView`) с равновысокими строками (`ROW_HEIGHT = 24`); модель строк строит Qt-нулевое ядро `timeline_rows.build_rows`; hit-test позиции — `index_at_y` (деление на высоту строки + сдвиг скроллбара).
- Зоны мыши уже поделены: рейка (`x < rail_width()`) целиком принадлежит жестам W3c (клик-прыжок / drag-фильтр / заглушённый dblclick); текстовая зона — выбор/двойной клик (событие) и zoom-клик (позиции единиц). Порог «нажатие стало drag'ом» — `DRAG_START_THRESHOLD_PX = 4`.
- Состояния незавершённых рейковых жестов (`_rail_press`, `_drag_range`) уже сбрасываются в `_rebuild()` — готовый механизм «внешняя пересборка убивает жест».
- Запись дат событий идёт только через wiring (`on_edit_event` → `update_event_with_relations`) под захватом сессии (`self._spawn`); глобального undo нет; сбой — молчаливый `rollback()`.
- VM фильтрует выборку по правилу «событие целиком внутри границ» (`_apply_filter`) — вышедшее за фильтр событие выпадает из видимой выборки.

## Goals / Non-Goals

**Goals:**

- Три жеста (перенос закрытого события с grab-offset, тяга за нижнюю засечку, тяга начала бессрочного события с start-строки) с ровно одной мутацией на отпускание, не трогая ни семантику W3b/W3c/W4, ни id-контракт.
- Вся новая геометрия (целевой день с экстраполяцией, сдвиг диапазона, hit-зона засечки) — в Qt-нулевом ядре, юнит-тестируемой без QApplication.
- Мутация живёт в существующем wiring-канале под session-lock; ViewModel не узнаёт о drag'е ничего нового.

**Non-Goals:**

- Закрытие открытого события жестом, растягивание однодневного в многодневное, global undo/Ctrl+Z, автопрокрутка краёв таймером, клавиатурные эквиваленты жестов, editing на ступенях «месяц»/«год» (зафиксировано grill-сессией 2026-09-01 и delta-спекой).

## Decisions

### D1. Жесты живут в `TimelineListView.mousePressEvent/mouseMoveEvent/mouseReleaseEvent`, рейковая машина не переписывается

 Press в текстовой зоне на `RowKind.EVENT` строке закрытого события вооружает `_EventPress(event_id, press_y, anchor_index, start, end, mode=MOVE)` (по образцу `_RailPress`); press на **start-строке открытого события** (строка, чей день равен `start_date` события) вооружает тот же state с `mode=START` (тяга начала, grill 2026-09-01: перенос бессрочному запрещён, строки продолжения/хвост не вооружаются вовсе); past-threshold move по y переводит armed-press в активный жест. Press в hit-зоне нижней засечки (`|x - serif_x| ≤ SERIF_HIT_PX` и y в пределах вертикального размера засечки) вооружает режим растягивания (`mode=RESIZE_END`); проверяется раньше общей рейковой ветки в `mousePressEvent`. Подпороговое отпускание в любом режиме — штатный клик (выбор/dblclick), ветки `super()` не тронуты. Альтернатива — отдельный viewport-оверлей с собственным mouse-слоем — отвергнута: второй источник мышиной войны поверх `QListView` дороже в обслуживании, чем несколько веток в существующих обработчиках, которые уже так работают (W3c).

### D2. Экстраполяция вместо живой перестройки модели

Целевой день считается в ядре (`target_day(rows, row_height, y_viewport, scroll_value)`) и clamp'ится к календарю приложения `CALENDAR_MIN = date(100, 1, 1)` / `CALENDAR_MAX = date(9999, 12, 31)` (те же границы, что у `CustomDateEdit`, — жест не создаёт дат, не выражаемых карточкой): внутри блока строк — как `index_at_y`, за краями — `±ceil(Δy / ROW_HEIGHT)` суток от крайнего дня, сверх календаря — clamp. Призрак превью за краем рисуется на последнем видимом дне, липкая дата показывает истинный целевой день. Из целевого дня режимы получают даты по-разному: **MOVE** — `delta = target - grabbed_day`, новый диапазон `translate_span(start, end, delta)` (grab-offset; строка захвата — день `_EventPress.anchor_index`, НИКОГДА не `event.start_date` — реализация группы 2 до ревизии считала `target - start` и теперь правится, grill Q1); **START** (бессрочное) — `new_start = target` напрямую, `end=None`; **RESIZE_END** — `new_end = target` с clamp `end ≥ start`. Живое расширение модели отвергнуто: prepend дней сдвигает все индексы и скролл-якоря под активным жестом. После commit пересборка сама выведет расширенный min–max (без фильтра — тривиально, новый `end` переносимого события и есть новая граница).

### D3. Фильтр расширяется на commit одним путём чипа

`TimelineWidget` на приём `event_dates_moved` сравнивает новые границы с `self._filter_range`; при выходе — до записи дат посылает существующий `_on_filter_range(new_start, new_end)` (тот обновляет чип и `filter_changed`), затем пишет даты. Порядок именно такой: иначе новый `_apply_filter` выбросит событие из выборки между записью и пересборкой. Альтернатива «clamp к фильтру» отвергнута grill-решением Q7-Q8 (свободный перенос с расширением рамки).

### D4.Commit — единственный новый сигнал панели, запись через wiring

`TimelineListView.event_dates_moved(event_id, start, end)` → дуплик в `TimelineWidget` → wiring `_spawn`-обработник: `event_service.update_event(eid, start_date=…, end_date=…)` → `commit` → `timeline_vm.load_events()` → `update_events` → `detail_vm.load_details`/`show_event`; выбор — `vm.select_event_by_id` перед показом деталей (он же даёт спуск лестницы, если вдруг не сутки — на суточной ступени no-op). Исключение → `rollback()`, шкала перезагружается из БД — строка возвращается, и ровно один `QMessageBox` с понятным текстом ошибки (единственная принятая в приложении конвенция об ошибках записи — прецеденты импорта XLSX и ingest картинок; молчаливый откат drag-пути запрещён grill-решением Q3). Расширение фильтра, случившееся до записи, при откате не сворачивается (компромисс в Risks). Для бессрочного события сигнал несёт `end=None`, запись — ровно одно изменение `start_date`. Диалог-путь (`update_event_with_relations`) не меняется, его молчание при сбое — зафиксированный долг (в CHANGELOG); `update_event` годится, потому что drag трогает не больше двух полей.

### D5. Подавление побочных жестов на время активного edit-drag

Пока `_event_press` активен: в `wheelEvent` ветка Ctrl/Cmd returns (прокрутка без модификаторов проходит); `_on_scale_chosen/_on_group_chosen` игнорируют клики (checked-state возвращается); `mouseDoubleClickEvent` в текстовой зоне глушится (drag уже владеет кнопкой — защита на случай быстрых dblclick-последовательностей). Любая внешняя пересборка уже попадает в `_rebuild()` — там же сбрасывается `_event_press` наравне с рейковыми состояниями (отмена без записи). `Esc` — `keyPressEvent` во время жеста = отмена (после начала drag'а; до порога Esc и так ничего не значит).

### D6. Превью — состояние view + отрисовка в `_RowDelegate`

Новое поле view: `_edit_preview: (event_id, target_start, target_end) | None` (для бессрочного `target_end=None`). Делегат читает `edit_preview()` (сейчас не читает — группа 4): на целевой позиции — призрак (wash-заливка `token_rgb(color.accent, DRAG_WASH_ALPHA=0.35)` + приглушённый текст `_row_line`), исходная строка — приглушённый вид (не hover-wash); при `RESIZE_END` — скобка live-draw до целевого дня; при `START` — призрак-подсветка на целевой start-строке, тело перерисуется только после commit'а (строки до commit не мутируем, grill Q14). Новых токенов не заводим: палитра — та же `_Palette`, live-retheme меняет только палитру (решение D10 W3b работает и во время жеста). Все цвета — только деривации токенов; инвариант `test_no_chrome_hex.py` продолжает сканировать файл.

### D7. Константы

`DRAG_START_THRESHOLD_PX` переиспользуется (тот же смысл порога дрожания); `SERIF_HIT_PX = 4` — новая константа hit-зоны засечки; шаг экстраполяции — `ROW_HEIGHT` ядра (`timeline_rows.EXTRAPOLATION_STEP_PX`, именованная); границы календаря жеста — `timeline_rows.CALENDAR_MIN/CALENDAR_MAX` (совпадают с границами `CustomDateEdit`, вью их не дублирует). Юниты ссылаются на имена.

### D8. Позиция засечки для hit-test

Хит-зона не хранится «на глаз»: `_rebuild()` уже раскладывает `_BracketSeg` по позициям; вид дополняет карту `_serif_target_by_row: row_idx → (event_id, serif_center_y, x_lane)`для нижней засечки закрытых многодневок (serif_bottom сегментов, у которых `serif_bottom=True` и событие закрытое). Промахов «засечка есть, а не попал» ждёт пиксель/юнит-тест: x = `BRACKET_X0 + lane*BRACKET_LANE_STEP`, y — центр нижней половины строки конца диапазона.

## Risks / Trade-offs

- [Отпускание после внешней пересборки] Wiring-путь фильтра на commit сам перестраивает модель; сигнал отпускания уже разобран, состояние жеста сброшено `_rebuild()` до применения — порядок в обработчике отпускания: снять состояние → посчитать данные → эмитить (наследует выученный W3c-D6 паттерн «drop state before resolve»).
- [Mac/Windows перетаскивание текста] `QListWidget` может пытаться начать собственный DND/text-drag; `setDragDropMode(NoDragDrop)` уже стоит — regression-тест не нужен, но manual-чек в задачах есть.
- [Расширение фильтра при отмене записи] Если commit дат упал после расширения фильтра — фильтр остался шире без причины; принято как малозначимый компромисс (фильтр — view-состояние, сбрасывается чипом), обратный порядок (сначала запись) создаёт окно «событие выпало из выборки» — хуже.
- [Экстраполяция «в прошлое» за голову без фильтра] Мин диапазона — самый ранний `start`; перенос за голову возможен только у не-минимального события и упирается в clamp `end ≥ start`, а не в границу — целевые дни до головы существуют (в отличие от хвоста), риск только в тестах.
- [Двойная ответственность рейки] Хит-зона засечки вырезает ~8px из рейки против дней конца закрытых многодневок; там прыжок/drag невозможны. Осознанная мелкая потеря плотности — компромисс ради жеста без модификаторов.
