# Переход хранения изображений с base64 в DB на файловое хранилище с адресацией по sha256

## Why

Изображения сущностей (организации, персонажи, локации) хранятся в SQLite-колонках в виде base64-строк. Базы игр разрастаются непроизводительным образом: каждая картинка раздувает файл БД на ~33% (base64-надув), каждая перезапись оставляет старые версии в файле, копирование и экспорт игры тянут за собой весь «мусор» страниц. Цель — вынести пиксели на диск в виде файлов, а в БД оставить только метаданные и sha256, и при этом получить честный «оригинал» без текущей обрезки 1000px, дедупликацию, восстановление и предсказуемый экспорт.

## What Changes

- **BREAKING (внутренний формат данных):** игра превращается из одного файла `games/<name>.db` в каталог `games/<name>/` с `game.db` и деревом `images/`. Старые одиночные `.db`-игры автоматически мигрируются при первом открытии.
- **BREAKING (внешний формат архива):** экспорт `.nri` получает версию 2 — в архив попадёт не только `game.db`, но и вся `images/`. Архивы v1 (без изображений) по-прежнему импортируются; архив v2, импортированный старой версией приложения, теряют изображения (принятое ограничение).
- Новая таблица `images` (`sha256 UNIQUE`, `ext`, `width`, `height`, `size_bytes`, `created_at`); у сущностей `organization`/`character`/`location` появляется `image_id` FK (`ON DELETE SET NULL`). Пути файлов нигде не хранятся — выводятся из sha256.
- Legacy-колонка `image` (base64 Text) после миграции обнуляется и остаётся в схемах инертной (удаление — отдельный будущий release).
- Оригиналы сохраняются в исходном размере (снят cap 1000px, действовавший при импорте); создаётся preview-копия 512px в формате WebP (lossy, q80).
- Новый конвейер ингеста `ImageStore` (единая точка входа для диалога карточки и xlsx-импорта): валидация → sha256 → dedup-hit или атомарная запись (temp+rename) оригинала и preview → строка в `images`.
- Семантика замены/«Убрать»/удаления сущности: сначала commit в БД, затем best-effort GC (refcount по `image_id` == 0 → unlink файлов + удаление строки). Ошибка удаления файла не ломает пользовательскую операцию.
- Startup-GC при открытии игры с фиксированным инвариантом: у каждой строки `images` существует оригинал; preview детерминированно пересоздаётся; каждый файл storage принадлежит ровно одной строке.
- UI: все существующие слоты показывают preview; кликом по изображению открывается in-app просмотрщик полного размера (открывается системный просмотрщик не используется).
- Иммпорт архива становится атомарным (temp-каталог + верификация sha256 каждого файла + rename).
- В `init_db()` появляется идемпотентная миграция legacy-base64 → файлы + VACUUM (только если миграция что-то перенесла).

## Capabilities

### New Capabilities
- `image-storage`: файловое хранилище изображений игр — раскладка каталогов, таблица `images`, адресация по sha256, конвейер ингеста с dedup, генерация preview, семантика замены/удаления и GC, startup-сканирование с фиксированным инвариантом, миграция legacy-base64.
- `image-display`: отображение изображений в UI — preview в существующих слотах (24/100/280px), in-app просмотрщик полного размера, управляемая деградация при отсутствующих/битых файлах.
- `game-archive`: формат экспортного/импортного архива `.nri` v2 — состав архива (game.db + images/ + meta), versioning, атомарность импорта, верификация sha256, совместимость v1↔v2.

### Modified Capabilities
(нет: ни одна из существующих спецификаций — `entity-generation`, `related-entity-creation`, `llm-*`, `ui-testing` — не меняет требований)

## Impact

- `app/infrastructure/db/game_manager.py` — каталог-игра (create/list/delete), экспорт/импорт v2, атомарная распаковка.
- `app/infrastructure/db/models.py` — таблица `ImageModel`, `image_id` на трёх сущностях.
- `app/main.py` — `init_db()`: миграция legacy + VACUUM; DI-привязка `ImageStore`; точка запуска startup-GC.
- Новый `app/infrastructure/images/` (или аналог) — `ImageStore`: конвейер, резолвер путей, GC.
- `app/presentation/utils/image_utils.py` — замена base64-функций на загрузку preview/оригинала с диска; добавление просмотрщика.
- `app/presentation/views/entity_card_dialog.py` + ViewModel — ингест через `ImageStore` (без прямого доступа к диску из диалога), уведомление об ошибке файла.
- `app/application/services/xlsx_import_service.py` — images-колонка через `ImageStore`, предупреждение в отчёте при битом файле.
- View-точки: `detail_panel.py`, `world_snapshot_widget.py` — preview вместо base64.
- Тесты: в `tests/` — DB-фикстуры (in-memory aiosqlite) + tmp-каталоги; ветки GC/миграции/деградации покрываются по gate 100% line coverage.
- Зависимости: новых пакетов нет (WebP-плагин входит в PySide6 wheels; PyInstaller собирает Qt-плагины штатными hooks — `.spec` не меняется).
