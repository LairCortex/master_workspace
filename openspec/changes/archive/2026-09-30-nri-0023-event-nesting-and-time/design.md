## Context

Мотивация — в proposal.md; требования — в дельтах specs девяти возможностей. Текущее состояние, важное для решений:

- Лестница — плоский `QAbstractListModel` (`TimelineRowModel`) поверх Qt-free ядра `build_rows()`; сортировка `(era_key(start), id)`, материализованные колонки `start_key`/`end_key` пересинхронизируются хуками `_sync_era_keys` (`app/infrastructure/db/models.py`).
- Даты событий живут в двойном хранилище (legacy-колонки дат + coord-слоты), маршрутизация — `coord_mapping.py`; размер суток к этому хранилищу не относится: время — отдельная величина, не координата.
- Календарь — процессный синглтон `current_calendar()`; `CalendarSpec` заморожен и не знает про сутки; кодеки календаря/черновика версионированы (`app/infrastructure/calendar_storage.py`, `v: 1`).
- «Сейчас» — JSON `{"coord", "bc"}` в `game_settings["current_date"]` (`CurrentDateService`); виджет — `ThemeDateField`-чип в острове поиска.
- EventDialog — widgets-каркас с QML-островом (`EventDialogRoot.qml`); даты — `ThemeDateField` с попапом `ThemeDatePopup`; списки в проекте — `ThemeComboBox` (выпадающий список чисел не нужно городить заново).
- Иконки в островах — текстовые глифы на `ThemeIconButton`; контекстные меню в приложении — нативные `QMenu` (переведены `QTranslator`).
- Удаления событий/сущностей в продукте нет; мигации — список `_MIGRATIONS` (`ALTER TABLE ADD COLUMN`), alembic не используется.

## Goals / Non-Goals

**Goals:**
- Дерево двух уровней без перестройки модели ленты: та же модель, то же ядро `build_rows`, строки получают глубину/тип.
- Время суток как независимая величина: ни координаты, ни `era_key`/`start_key`, ни age/duration-машинерия не затрагиваются.
- Единственный источник границ суток — активный календарь; ни один список часов/минут не хардкодит 24/60.

**Non-Goals:**
- Время окончания, длительности со временем, возраст «N часов» — вне объёма (решения пользователя зафиксированы в specs).
- LLM, xlsx-шаблон, экспорт `.nri` — без изменений.
- Персистентность раскрытия шевронов, drag-n-drop перецепка, произвольная глубина — запрещены спеками.

## Decisions

### Д1. Вложенность — self-FK `events.parent_id`, а не ассоциативная таблица
Родитель ровно один, ребёнок принадлежит одному дереву — это отношение «один-ко-многим», колонка NULLable `INTEGER REFERENCES events(id)` выражает его прямо; ассоциативная таблица (как M2M с сущностями) добавила быjoin без нужды. Два уровня проверяются на записи в `EventService` (родитель обязан быть событием без родителя и не самим собой; ошибка доходит до пользователя русским текстом) — в UI список родителей изначально только основные, сервисный guard страхует обход. `ON DELETE CASCADE` в объявлении — формальность (удалений нет), зато ссылка не может осиротеть даже при ручной правке БД.

### Д2. Время — одна колонка `events.start_time` (минуты от начала суток, NULLable)
Хранение в минутах даёт линейное сравнение без парных колонок; `NULL` честно означает «без времени» (сравнение с `COALESCE(start_time, -1)` ставит бесвремянные первыми — ровно спека). Домен: замороженный `TimeOfDay(hour, minute)` в новом `app/domain/time_of_day.py` с `to_minutes()/from_minutes()/format_hhmm()`; в `Event` — поле `start_time: TimeOfDay | None`. Альтернативы — текстовый `HH:MM` (ломает сортировку в SQL) и две колонки (два NULL-состояния вместо одного) — отвергнуты.

### Д3. Порядок — вторичный ключ в модели и запросах, `start_key` не трогаем
`EventRepository.list` добирает вторичную сортировку `(start_time IS NOT NULL, start_time, id)`; `build_rows` при группировке дерева сортирует детей тем же кортежем. Материализованный дневной `start_key` остаётся дневным: фильтрация окном, междневные сравнения и все существующие потребители ключа не меняются — это и требование спеки («дневной ключ не трогать»), и минимальный риск.

### Д4. Размер суток — поля `CalendarSpec` со значениями по умолчанию
`day_hours: int = 24`, `minutes_per_hour: int = 60` в замороженном датаклассе: десятки существующих конструкторов спеки (тесты, кодек) продолжают работать без правок. `validate()` дополняется причинами `day_hours_below_min`/`minutes_per_hour_below_min`; продуктовых потолков нет — существующая философия. Протокол `GameCalendar` получает необязательные свойства `day_hours`/`minutes_per_hour`; обе реализации их дают (стандарт — константы 24/60). Потребители (списки карточки, список «сейчас») читают `current_calendar()` — единый источник, как и с именами месяцев.

### Д5. Кодеки — v2 с молчаливой поддержкой v1
`CALENDAR_STORAGE_VERSION = 2`: `custom` дописывает поля суток, чтение принимает `v: 1` (сутки → 24/60, без предупреждения и без каскада пересчёта — ключи координат от суток не зависят), запись всегда v2. Черновик мастера (`game_calendar_draft`) — тот же версионный формат, тоже v2 с приёмом v1. Значение «сейчас»: опциональный ключ `h` в том же JSON; при чтении час вне `0 … day_hours−1` трактуется как «не выставлен» — сужение суток чистит подпись без записи. Альтернатива «миграция ключей при открытии игры» отвергнута: лишняя запись молча живущих файлов.

### Д6. Лестница — строки трёх видов в одной модели
`TimelineRow` получает `kind` (event/stub), `depth` (0/1) и `parent_id`; `build_rows` собирает детей под развёрнутых родителей, схлопнутые — без строк детей; строка-заглушка — `kind=stub` (имя, без дат, не выбирается, шеврон неактивен) только когда ребёнок в окне, а родитель вне. Состояние раскрытия — `set[expanded_parent_id]` во `TimelineViewModel`, по умолчанию пусто (свёрнуто), не персистится. Авто-раскрытие: точки выбора (поиск, двойной клик, панель деталей, обзор) вызывают `expand_to(event_id)` перед подсветкой. Анимация — штатные `add/displace` transition'ы `ListView` + height-анимация блока: без нового тайминг-кода.

### Д7. Контекстное меню и создание — `QMenu` на делегате, предзаполнение через viewModel
Правый клик (`ContextMenuRequested` у строки-родителя) открывает нативный `QMenu` с пунктом «Создать подсобытие» → сигнал вью-модели ленты → `ApplicationWiring` открывает `EventDialog` в режиме создания с `prefill(parent_id, parent_start_date)`; остальное (пустое время, тип без типа) — штатные дефолты диалога. По-подсобытию и заглушке меню не создаётся вовсе. Нативное меню — за пределы accessibility-острова, но доступно клавиатуре ОС и переведено; QML-попап меню потребовал бы нового компонента и a11y-контракта.

### Д8. Поле родителя и время в карточке — `ThemeComboBox` + состояние в island viewModel
«Родительское событие» — `ThemeComboBox` со списком `[«—»] + основные события (имя, id)`, исключая редактируемое событие; «Час»/«Минута» — `ThemeComboBox` чисел (`0 … day_hours−1`, минуты — шаг 5, если `minutes_per_hour % 5 == 0`, иначе полный перебор; пустое «—» первым; список минут активен только при выбранном часе). Значения живут в `EventDialogIslandViewModel`, форматирование минут — чистый помощник рядом с `time_of_day`. A11y: `ThemeComboBox` — штатный контрол (триггер именуется usage-site: «Родительское событие», «Час начала», «Минута начала»), `value`-слот штатный. Шеврон — `ThemeIconButton` с глифом `▸/▾`, `Accessible.name` = «Развернуть подсобытия»/«Свернуть подсобытия», описание из уже закреплённой лексики «Развернуть или свернуть раздел», press — собственный обработчик строки (не пресc строки-события); офскрин-пин через `actionInterface().doAction("Press")` по образцу `tests/presentation/test_*_accessibility*.py`.

### Д9. Представление времени и родителя на поверхностях — один помощник форматирования
`date_utils.format_event_start(coord, is_bc, start_time)` дописывает `, HH:MM` (двузначные с ведущим нулём) при заданном времени; все пять поверхностей (лестница, карточка, предпросмотр, поиск, обзор) вызывают его — прежний формат при `None` побитово сохраняется (пин-тест сравнением со старой формулировкой). Префикс родителя в поиске и дерево обзора: сервис отдаёт `parent_id`, presentation собирает `id → имя` одним проходом по списку событий (поиск уже держит результаты в памяти; обзор и так получает срез целиком). Обзор мира всегда развёрнут (это снимок, не интерфейс навигации).

### Д10. Миграции — две колонки в `_MIGRATIONS`
`("events", "parent_id", "INTEGER REFERENCES events(id) ON DELETE CASCADE")`, `("events", "start_time", "INTEGER")` — идемпотентный `ADD COLUMN` текущего шаблона; кодеки и «сейчас» — значения в `game_settings`, ALTER не нужен. Откат не требуется: старые версии приложения новые NULLable-колонки просто игнорируют.

### Д11. Линия дерева — угол у последнего ребёнка (live-аудит P1/A4)
Живой аудит подтвердил: ствол последнего ребёнка висит на всю высоту строки ниже локтя — дерево «обещает» несуществующего ребёнка. `build_rows` (который уже решает состав и порядок группы) дописывает в `TimelineRow` скаляр `is_last_sibling`; `TimelineRowModel` отдаёт его ролью наравне с `hasChildren`; делегат у последнего ребёнка ведёт ствол не до низа строки, а до линии локтя (угол «└»), средние дети остаются с полным стволом («├»). Заодно линия дотягивается до родителя: строка развёрнутого родителя с детьми рисует внутри себя сегмент от уровня своей подписи до нижнего края — линия начинается не «из пустоты» границы строк. Правка по скриншотам пользователя (2026-09-30): та же линия стоит не под меткой типа родителя, а на левом краю строки (`trunkX` = 0) — ствол визуально продолжает левый край карточки родителя, ту самую улицу, с которой начинаются его залировка/обводка. Альтернатива — выводить «последний» в QML из `index` и соседних строк — отвергнута: делегат рисует доставленное и ничего не пересчитывает (контракт файла).

### Д12. Шеврон — ghost-лицо библиотеки, привязка к строке дат (live-аудит P2/A1/A3)
Глиф 8×6 pt в обведённом квадрате 32×32 читается точкой; на акцентной залировке выбранного родителя квадрат прорезает полосу чипом противоположного цвета; hover-отклика нет; вертикаль центрирована по строке и гуляет от текста у двухстрочных родителей. Решение — не приватный контрол лестницы (запрет «локальной стилизации библиотечных контролов»), а property `ghost` в `ThemeButton` (прозрачно по умолчанию, hover/pressed — деривации компилятора), который `ThemeIconButton` пропускает через себя, сохраняя калибр 32×32 и компонентно-собственный контракт доступности (роль Button, `onPressAction`). Точка применения шеврона: `ghost: true`, кегль глифа — крупнее подписного (токен `font.size.lg`-семейства), вертикальный якорь — `rowText.verticalCenter` (та же линия, что у метки и локтя), а на залировке — `accentBackground: row.selectedRow`, дающий глиф `color.accent.fg` поверх акцента при прозрачном фоне.

### Д13. Полоса ребёнка — от колонки отступа; сервисный ранг на залировке (live-аудит P3/A2/A5/A6; правка геометрии 2026-09-30)
Заливка выделения/hover на всю ширину стирает отступ дерева: ребёнок под полосой перестаёт выглядеть ребёнком. `rowWash`/hover-полоса строк `depth > 0` начинается от колонки дочернего отступа (`childWashX`): гуттер остаётся холстом, ширина полосы сама читается признаком уровня (родитель — полная, ребёнок — короче на шаг). В правке 2026-09-30 ствол переехал из-под метки родителя на левый край строки (`trunkX` = 0, продолжение левого края карточки родителя) — полоса больше не может висеть на линии, не сливаясь с родительской, и висит на колонке отступа; гуттер между линией и полосой остаётся холстом. Внутри выбранной строки ствол, локоть и приглушённая метка без типа переключаются в `color.accent.fg` (тот же приём, что у заголовка) — серый по акценту больше не грязнит. Обводка «сегодня» поверх выделения меняет цвет на контрастное семейство (тот же приём): оранжевый по оранжевому невидим. Скругление полосы в гуттере (A6) перестаёт быть проблемой, поскольку край полосы не пересекается со стволом. Пиксельные проверки — по правилу пиксельной приёмки библиотеки/панели для обеих тем.

### Д14. Селектор часа и список комбобокса — по живому аудиту (docs/qa/2026-09-29-now-hour-chip-design.md)
Аудит подтвердил H1 (нет видимой подписи; «иконка часов» — слившиеся значение и наложенная стрелка), H2 (селектор 32 pt против чипа 24 pt, ширина скачет 35…45 pt, попап в 41 pt поверх поля поиска) и блокер A1 (в раскрытом списке реализуются только две строки из 25: часы 1…23 мышью не выбираемы). Решения:
- **A1 — список полон и прокручиваем** (Д14.1): в `ThemeComboBox` высота попапа становится явной — `Math.min(list.implicitHeight, maxRows × rowHeight)` с включённой прокруткой (`boundsBehavior: StopAtBounds`), а не `implicitHeight` ленивого `ListView`; при открытии — `positionViewAtIndex(highlightedIndex, Begin)`, ширина попапа `Math.max(control.width, delegate contentWidth)`. Это чинит не только часы чипа, но и `ThemeComboBox` карточки события («Родительское событие», «Час», «Минута») — тот же дефект. Пин — pytest-qt на число реализованных делегатов и высоту попапа (дереву доступности попап-окно невидно, предел ③).
- **H1 — подпись внутри displayText** (Д14.2): VM отдаёт селектору отображаемое «Час: —»/«Час: 14» (модель списка остаётся цифрами — строки не превращаются в «Час: N»), пустое значение печатается `color.fg.muted`, реальное — `color.fg.primary`; у контрола правый карман `rightPadding = arrowSize + space.xs` — стрелка физически не может накрыть значение.
- **H2 — единая геометрия пары** (Д14.3): вертикальные паддинги селектора приводятся к чипу (`space.xs` сверху/снизу; пин `nowDateField.height == nowHourCombo.height`), ширина селектора фиксирована худшим значением активного календаря (тот же приём `worstCase*`, что у чипа; VM добавляет `worstCaseHourOption`) — дёрганье пары исчезает.
- **Состояния** (Д14.4): раскрыт — акцентная рамка + перевёрнутая стрелка; наведение — wash из `color.accent.hover`; фокус без раскрытия остаётся без переворота. Строки попапа разводятся hairline-разделителем `color.border` (фон строки к фону попапа различается слабо).
- **A9 — узел перестаёт быть сиротливой полосой** (Д14.5): строка «сейчас» выравнивается по левому краю поля поиска (убрать центрирующие спейсеры `RowLayout` в `nowDateRow`) и читается частью панели поиска — тот же левый край, примыкание к строке поля; вариант переноса узла в другую полосу главного окна отвергнут (менять компоновку окна ради подписи — лишний риск, а связь с полем решается выравниванием).
Вариант «слить час в хвост чипа» (B из отчёта) отвергнут: он ломает побитовую пин-форму подписи чипа («при пустом — выглядеть ровно как прежде») и смешивает два контрола с разными a11y-ролями в одном `ThemeDateField`.

### Д15. Чекбоксы библиотеки: действие на `onClicked`, не на `onToggled` (OBS-2 живого аудита дерева)
Живой аудит дерева зафиксировал: accessibility-активация штатного CheckBox пишет `checked` без пользовательского жеста, поэтому проводка на `onToggled` («Бессрочно» в `EventDialogRoot.qml`, чекбоксы `SheetFillRoot`/`SheetEditorRoot`) двигает галочку, но не доносит действие до вью-модели. Рабочая конвенция уже существует и прокомментирована в `EntityCardRoot.qml` (D1, живой аудит 2026-09-27) и в лаунчере (`onClicked: themeToggleRequested`): галочка — отражение состояния VM (привязка), любое нажатие — запрос переключения от источника истины (`onClicked: vm.setNoEnd(!vm.noEnd)`), а не от наполовину переключённого контрола. Правка — перевести оставшиеся точки применения на эту конвенцию (не изобретая новый компонент), пин — оффскрин `doAction("Press")` по образцу существующих тестов доступности; живым повтором проверить лаунчер (в аудите он не применил тему, хотя уже на `onClicked` — исключить, что виной координатная доставка OBS-1, а не сам обработчик).

## Risks / Trade-offs

- [Правый клик конфликтует с будущими пунктами меню строки] → меню заводится одним расширением (список пунктов в одном месте делегата), сейчас один пункт — решение пользователя.
- [Анимация раскрытия в `QQuickWidget`-острове может дёргаться на больших списках] → при проблемах анимация отключается флагом модели без изменения семантики (спека требует плавность «желательно» — фиксируем допустимость статического раскрытия только при подтверждённом дефекте и QA-заметке).
- [Час «сейчас» соблазнительно использовать в производных] → прямо запрещено спекой current-date; тест-пин: смена часа не двигает возраст/обводку/прокрутку.
- [Сужение суток делает сохранённый `start_time` недоступным] → трактуем как «время не участвует, пока не выбрано допустимое» (спека event-time); явной миграции событий нет — обратное расширение суток возвращает значение.
- [Двойной источник порядка (SQL и `build_rows`)] → общая функция сравнения одна (`timeline_rows`), SQL-сортировка — только оптимизация; тест сверяет оба пути на одном наборе.
- [Поле родителя при сотнях событий — длинный список] → принимается осознанно (перецепка редка); поиск по списку — задел на будущее, вне объёма.

## Migration Plan

Миграция отгружается обычным `init_db()` при открытии игры (колонки NULLable — старые данные валидны); кодеки читают v1 как прежде. Раскатка — замена сборки, обратная совместимость БД в обе стороны сохраняется (старое приложение не читает новые колонки и не пишет кодеки v2). Никаких ручных шагов пользователя.
