## Context

Текущее состояние (измерено 2026-08-23): 559 тестов, прогон 5.8 с, покрытие 85% (строки+ветки суммарно; по строкам ~92%), CI-гейт `--cov-fail-under=79` (только строки). Основные дыры: `application/wiring.py` 24% (137 stmts сигнала-вейринга), `main.py` 55% (DI/старт), `presentation/state/app_state.py` 0%, views 76–81% (timeline, event_dialog, detail_panel, entity_card). Стек тестов: pytest + pytest-qt (`qt_api = "pyside6"`), `asyncio_mode = auto`, offscreen в CI. Ключевые факты о швах: полный старт `Application(qapp)` + `await start(db_path)` уже работает в pytest-тесте (prototype — `tests/test_application_start.py`); `AppHttpClient(client: httpx.AsyncClient | None)` принимает готовый клиент; `LlmConfigManager(config_file: Path | None)` принимает путь, но `Application` его не использует; константа `CONFIG_FILE` резолвится в момент вызова `LlmConfigManager()`; `get_games_dir` вызывается только внутри `game_manager.py` (единая точка захвата для `list_games`/`create_game`/`delete_game`/`export`).

## Goals / Non-Goals

**Goals:**
- 100% строкового покрытия `app/` как обязательный CI-гейт
- Двухслойная UI-тест-система: E2E (полный старт, 10 потоков) + widget (интерактивные views)
- Детерминированность: нулевая реальная сеть, нулевые артефакты вне per-test tmp
- Веточное покрытие — видимость в отчёте без гейта

**Non-Goals:**
- Изменение пользовательского функционала (единственное изменение прода-кода — опциональный конструкторный параметр)
- Visual regression / скриншот-сравнение
- PR-триггеры CI и 3-OS-матрица для UI-тестов
- Миграция веточного покрытия до 100% (трекинг без гейта)
- Новые тестовые фреймворки (Robot Framework и др.)

## Decisions

**D1. Стек — pytest-qt.** Варианты: pytest-qt / Robot Framework + Qt-библиотека / гибрид. Выбран pytest-qt: уже в dev-зависимостях и сконфигурирован, один раннер с 559 юнит-тестами, offscreen-совместим (CI уже ставит нужные системные libs), ноль новой инфраструктуры.

**D2. Два слоя вместо «только E2E».** 10 E2E-потоков закрывают `main.py`/`wiring.py`/`app_state.py` (единственный способ прогнать DI-клейку), но не покрывают ветки валидации и special-cases в views (специальные даты, mention-клики, «Показать всё» в world snapshot) — на них идёт 50% оставшихся дыр. Отдельные «E2E на всё» удвоили бы время прогона без прироста покрытия. Widget-тесты инстанцируют view напрямую с фиктивным VM/сервисами.

**D3. Боот-фикстура (function-scoped).** `tests/ui/conftest.py`: pytest-qt `qapp` (session) → `Application(qapp, http=llm_client)` → monkeypatch `get_games_dir` → `tmp_path/games` → monkeypatch `CONFIG_FILE` → `tmp_path/llm_config.json` → `await start(tmp .db)` → teardown `window.close()` + `await application.shutdown()`. Пер-тестный scope: каждый E2E стартует в чистом состоянии (БД, конфиг, каталог игр), что делает тесты независимыми. Prototype — существующий smoke-тест; стоимость старта мала (всё на aiosqlite-файле).

**D4. DI-шов в `Application.__init__`.** Опциональный параметр `http: AppHttpClient | None = None` в конструкторе; `start()` использует `self._http`, если передан, иначе создаёт `AppHttpClient()` как сейчас. Альтернатива — monkeypatch `AppHttpClient` в namespace `app.main` — отклонена: хрупко (зависит от импортов в main.py), неявно в тесте, против конвенции ручного DI проекта. ЛLM-конфиг шов НЕ добавляем: monkeypatch константы `CONFIG_FILE` работает, т.к. она резолвится в момент вызова.

**D5. Мок-LLM — один MockTransport-хендлер.** `llm_client` фикстура: `AppHttpClient(httpx.AsyncClient(transport=handler))`, где хендлер отвечает на `POST */chat/completions` canned JSON (`choices[0].message.content`). «Проверить соединение» (`max_tokens=1`) и генерация хитят один хендлер — как в жизни, через тот же единственный клиент приложения.

**D6. Изоляция данных — monkeypatch единой точки.** `get_games_dir` захвачена в одном месте (все функции game_manager идут через неё), конфиг LLM — константа. Реальный `.db`-файл (не in-memory) — чтобы E2E прогонял `init_db()` и ad-hoc-миграции как в продакшене. Прода-код не меняется.

**D7. Файловые диалоги — stub.** `QFileDialog.getSaveFileName`/`getOpenFileName` подменяются в E2E (флоу «открыть игру», «экспорт .nri»): в offscreen модалки не поднимать, предопределённые пути в tmp.

**D8. Механика гейта — два прогона в CI.** coverage.py с `branch=true` считает `fail_under` от суммарного % (строки+ветки, текущие 85%), а «100% по строкам при частичных ветках» одной конфигурацией не выразить. Поэтому:
- прогон 1 (гейт): `python -m pytest --cov=app --cov-report=term-missing` — строки, `fail_under` из `[tool.coverage.report]` (PR1: 95 → PR2: 100), `exclude_lines` для `__main__`-гарда
- прогон 2 (видимость): `python -m pytest --cov=app --cov-branch --cov-fail-under=0 --cov-report=term` — ветки в отчёте, гейт отключён (CLI-флаг переопределяет конфиг)

Альтернатива «один прогон branch + fail_under=100» отклонена: гейт молча стал бы веточным 100% (суммарная метрика), что противоречит принятому решению «ветки не гейтуются». Цена: +~1–2 мин к test-job — приемлемо при быстрой suite.

**D9. Прагмы — кап 2.** `# pragma: no cover` только для недостижимых в тестах строк, каждая с inline-обоснованием; `__main__`-гард — через `exclude_lines`. Контроль: grep-проверка числа прагм в финальном гейте.

**D10. Два PR.** PR1 «UI test system»: шов + фикстуры + E2E(10) + widget-тесты по главным дырам + CI-конфиг, гейт 95, без бампа версии. PR2 «100% + 0.13.1»: доводка оставшихся дыр (по списку из `term-missing`), гейт 100, версия 0.13.1 синхронно в трёх местах + CHANGELOG-секция «Инфраструктура/Тесты». Гейт поднимается только после локального достижения целевого значения, чтобы merge-контур оставался зелёным.

## Risks / Trade-offs

- [Два coverage-прогона удваивают время test-job] → базовая suite 5.8 с + E2E ~30–60 с; итоговый рост +1–2 мин — приемлемо, алерт о бюджете < ~2 мин на весь прогон.
- [Модальные QFileDialog в offscreen неустойчивы/виснут] → все файловые диалоги в E2E stub-ятся (D7); реальные диалоги проверяются только widget-тестами диалогов без модалок.
- [qasync-петля + async signal handlers в длинных E2E: возможны зависания в ожидании] → ожидание через `qtbot.waitUntil(условие, timeout)` вместо sleeps/`processEvents`-хаков; таймауты ожидания фиксированы в фикстуре.
- [Оффскрин-рендер в CI может давать флаки (тайминги анимаций/отрисовки)] → в UI-тестах проверяем состояние (модель/текст виджетов), не пиксели; детеминированные ожидания.
- [Monkeypatch точек захвата ломается при появлении прямых импортов `get_games_dir`/`CONFIG_FILE` из других модулей] → сейчас проверено (единые точки); риск вернётся красным тестом, а не тихим артефактом в `games/` или `~/.nri_manager`.
- [Гейт 100% делает любой коммит с новым неконтролируемым кодом красным] → принят intentionally (тесты — верификационный гейт проекта): автор кода закрывает покрытие в том же коммите.

## Migration Plan

Миграция данных не требуется. Сед DI-шва обратно совместим (`None` = текущее поведение), откат PR1/PR2 = обратный коммит (гейт и конфиг coverage вернутся со старым значением). Версионирование 0.13.1 — только в PR2, три места синхронно (pyproject, spec, CHANGELOG) с последующим grep-контролем.
