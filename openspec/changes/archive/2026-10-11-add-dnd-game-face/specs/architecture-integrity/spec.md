## MODIFIED Requirements

### Requirement: Единый реестр типов сущностей

Знание о множества типов сущностей (тип → модель хранения, хранилище, атрибуты связей, отображаемое имя, форма множественного числа) SHALL находиться в одном месте, ключом SHALL служить перечисление `EntityType`; код приложения НЕ SHALL хранить собственные параллельные словари типов. Добавочные типы внешних систем SHALL приходить в тот же реестр только через единый механизм внешних источников, зарегистрированный в composition root: описатель внешнего типа живёт рядом с ядерными, признаки поиск/упоминаний/иконки читаются поверхностями из реестра, а не из догадок; обход реестра внешним типом SHALL считаться нарушением той же охраны.

#### Scenario: Отображение связей карточки сущности

- **WHEN** карточка сущности показывает доступные связи для любого типа сущности
- **THEN** набор и подписи связей взяты из единого реестра и совпадают для карточки, диалога события, поиска и снимка мира

#### Scenario: Проверка отсутствия параллельных реестров

- **WHEN** в коде приложения появляется словарь, сопоставляющий строковое имя типа сущности с классом, атрибутом или подписью, в обход реестра
- **THEN** автоматическая проверка падает с указанием места нарушения

#### Scenario: Внешний тип входит через реестр, а не мимо него

- **WHEN** система-модуль регистрирует свой тип сущности
- **THEN** описатель попадает в единый реестр через механизм внешних источников; без включённого модуля реестр содержит ровно ядерные типы
