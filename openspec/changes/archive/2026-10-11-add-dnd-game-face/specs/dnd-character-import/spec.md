## Purpose

Импорт персонажа из файла-экспорта Long Story Short (документ `character` версии 2): проверка формата, полное раскладывание в хранилище модуля, создание нового персонажа или явная перезапись существующего.

## ADDED Requirements

### Requirement: Точки входа явные, сопоставления по имени нет

Импорт SHALL быть доступен из двух мест: создание нового персонажа из файла и «Перезаписать из файла LSS…» из карточки конкретного персонажа с подтверждением полной перезаписи. Автоматическое сопоставление файла с персонажем (по имени или иному полю) SHALL NOT выполняться: экспорт LSS не содержит идентификатора, и выбор цели — всегда действие пользователя.

#### Scenario: Перезапись требует подтверждения

- **WHEN** выбрана перезапись персонажа из файла
- **THEN** показано подтверждение; без него персонаж и его файл-снимок не изменились

### Requirement: Документ проверяется по схеме формата, предупреждения не блокируют

Импорт SHALL проверять документ по схеме `character.json` (бандл изменения) и списку документных проверок: нечитаемый файл, неверный `jsonType`/`version` или разрушенная структура `data` — ошибки с отказом; устаревшие каналы бонусов, служебные ключи живого экспорта и им подобные — предупреждения, импорт разрешён со списком (тот же отчёт error/warning, что у датасетов).

#### Scenario: Живой экспорт проходит с предупреждениями

- **WHEN** импортирован файл, скачанный из LSS, с устаревшим каналом бонусов
- **THEN** импорт выполнен, показан список предупреждений, данные устаревшего канала не растрачены (сохранены в сырой части)

### Requirement: Раскладывание полное: поля, аватар, именованные блоки, читаемый рендер структуры

Импорт SHALL заполнять: имя, D&D-набор полей (значения блока `info` со снимками имён и слагами из датасета, если запись подключена; иначе — снимок имени из файла), аватар. Каждый текстовый блок документа SHALL раскладываться именованным блоком «название → текст» (документ форматированного редактора конвертируется; формульные и бросковые узлы — текстом с формулой в квадратных скобках; неизвестные типы узлов не порождаются). Структурные данные (навыки, спасброски, бонусы, оружие, ресурсы, монеты, счётчики ячеек) SHALL рендериться человекочитаемыми именованными блоками в тот же список. Ни один текстовый блок документа НЕ SHALL быть потерян молча: нераспознанные разделы получают блок с исходным именем.

#### Scenario: Черты и заметки доезжают текстом

- **WHEN** импортирован персонаж с блоками «Черты» и «Заметки»
- **THEN** в табе «D&D» есть одноимённые блоки с конвертированным текстом, формулы сохранились нотацией `[STR]`

#### Scenario: Структура читается без LSS

- **WHEN** импортирован воин с навыками и списком оружия
- **THEN** видны читаемые блоки владений навыками и оружия, а не пустота

### Requirement: Сырой файл хранится всегда и остаётся источником правды

Импорт SHALL сохранять исходный файл персонажа целиком (в хранилище записи персонажа) при любом раскладе; перезапись заменяет снимок новым; повторное раскладывание SHALL опираться на сохранённый файл, а не на пересобранный из наших полей.

#### Scenario: Файл можно забрать обратно

- **WHEN** для импортированного персонажа запрошено сохранение исходного файла на диск
- **THEN** на диск записан байт-в-байт тот же документ, что был импортирован
