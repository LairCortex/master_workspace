## ADDED Requirements

### Requirement: D&D-модуль изолирован от ядра

Модуль `app/dd/` SHALL соблюдать общие правила слоёв наравне с ядром; production-код ядра (`app/` вне `app/dd/`) НЕ SHALL импортировать `app.dd` — знание о модуле ограничивается точкой композиции `app/main.py`, которая решает, собирать ли состав модуля, по публичному признаку игры. Ограничение сторожится автоматическим статическим тестом общего прогона.

#### Scenario: Импорт модуля из ядра

- **WHEN** в `app/` вне `app/dd/` (кроме точки композиции) появляется импорт `app.dd`
- **THEN** автоматический статический тест падает с указанием файла и строки

#### Scenario: Обратная зависимость модуля к ядру

- **WHEN** код `app/dd/application/` или `app/dd/domain/` импортирует `app.presentation.*` или сессию базы данных
- **THEN** существующий тест границ слоёв падает

### Requirement: Модуль полностью извлекаем из состава

Composition SHALL работать в профиле, где модуль `app/dd` не загружается вовсе (код модуля не импортирован): приложение полностью функционально для обычных игр, состав строится без модуля. Ни один модуль ядро-профиля НЕ SHALL тянуть импорт `app.dd`.

#### Scenario: Состав без модуля живёт

- **WHEN** приложение собрано в профиле без модуля (переключатель профиля включён)
- **THEN** ядро запускается и работает, ни один модуль процесса не импортировал `app.dd`
