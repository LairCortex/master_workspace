# Proposal: add-dnd-module-foundation

## Why

Дорожная карта `docs/dnd-module-roadmap.md` зафиксировала D&D-модуль: встроенный модуль приложения для игр D&D 5e с интеграцией форматов Long Story Short (LSS). Фаза 1 — фундамент: модуль включается/выключается на любой игре без потерь, а датасеты LSS (SRD 5.1/5.2 и хоумбрю) становятся проверяемым общим достоянием приложения. Без фундамента каждая последующая фаза (D&D-поля персонажей, генерация, живые листы) начинает с нуля спорить о швах; с ним фазы 2–4 только надстраивают экраны и связи.

## What Changes

- D&D-модуль — внутренний модуль `app/dd/`, подключаемый в композиции `main.py` только для игр с включённым признаком модуля. Ядро приложения не знает о D&D; обратная зависимость запрещена охранкой.
- Включение на любой игре: выбор системы «Обычная / D&D» при создании игры в лаунчере и пункт меню «Включить D&D-модуль…» на открытой игре с подтверждением. Включение — только запись признака (`game_settings`), ни одна существующая таблица/строка не меняется.
- Выключение с сохранением: признак гаснет, данные модуля остаются, повторное включение возвращает всё. Открытая D&D-игра показывает метку системы; игра с данными модуля при выключенном признаке — предупреждение о том, что модуль выключен и данные не видны.
- Флаг версии модуля в признаке: игра, созданная более новой версией модуля, открывается обычным ядром без повреждения данных (аддитивность закреплена тестом round-trip на уровне `.nri` и старого профиля открытия).
- Глобальное хранилище датасетов `~/.nri_manager/datasets/`: датасет живёт один раз на все игры; игра хранит список подключённых id в `game_settings`.
- Первое включение модуля скачивает SRD 5.1 и SRD 5.2 с longstoryshort.app (общий `httpx.AsyncClient`). Офлайн — понятная отказоустойчивость: игра открывается, скачивание предлагается повторить.
- Импорт хоумбрю-датасета файлом JSON через штатный лист: проверка лицензии (только CC0/CC-BY/CC-BY-SA с версией), валидация по встроенной JSON-схеме и списку межполевых проверок LSS; отчёт error/warning; error — отказ импорта с русскими формулировками, warning — импорт с перечнем.
- Python-валидатор датасетов: JSON Schema draft-07 (схемы вкладываются в пакет приложения) + полный список проверок error/warning из документации LSS, включая рекурсию в `pick-one`, резолвинг ссылок `classId`/`raceId`/`featId` по всем подключённым наборам и проверку лицензий.
- Экран «Датасеты D&D…» (лист по контракту `modal-sheets`): состояние хранилища, скачивание SRD, импорт файла, подключение/отключение наборов от игры, отчёт валидатора. Правка датасетов не входит.
- Профиль без модуля: переключатель профиля исключает `app/dd` из состава (код модуля не импортируется); приложение полностью работает для обычных игр; приёмочный прогон выполняется в двух профилях — «ядро» и «ядро + модуль» — и оба обязаны быть зелёными.
- Приёмка изменения включает запуск скилла `openspec-test-case-generator` по спекам изменения: тест-кейсы с трассировкой требований в `docs/qa/test-cases/`.

Не входит (следующие фазы карты): сущности и типы реестра D&D, D&D-поля персонажей, импорт файлов-экспортов персонажей LSS, монстры/встречи, ИИ-генерация, живые листы (QWebEngine, мост, ретранслятор), логин/аккаунты.

## Capabilities

### New Capabilities

- `dnd-module-lifecycle`: признак модуля на игре и его версия; включение (лаунчер/меню с подтверждением) и выключение с сохранением данных; метка системы; предупреждение при выключенном модуле с данными; композиция модуля только для D&D-игр; поведение в профиле без модуля.
- `dnd-dataset-library`: глобальное хранилище датасетов, автозагрузка SRD 5.1/5.2, импорт хоумбрю-файлов, подключение наборов к игре списком id; офлайн-поведение и повтор скачивания.
- `dnd-dataset-validator`: валидация датасета по встроенным JSON-схемам и полному списку межполевых проверок LSS; категории error/warning; русские сообщения; чистая функция без сети.

### Modified Capabilities

- `game-launcher`: «Новая игра» получает выбор системы (по умолчанию «Обычная»); в списке игр у D&D-игр метка «D&D».
- `main-window`: у D&D-игры в окне видна метка системы; в меню появляется группа модуля только для D&D-игр.
- `architecture-integrity`: новые требования — модуль `dd` соблюдает те же правила слоёв; production-код ядра (`app/` вне `app/dd/`) не импортирует `app.dd`; модуль полностью извлекаем из состава (профиль без модуля).
- `ui-testing`: приёмочный прогон выполняется в двух профилях («ядро», «ядро + модуль») и проходит только обоюдно зелёный.

## Impact

- Код: `app/dd/` (domain/application/infrastructure/presentation модуля), ветвление композиции в `app/main.py`, меню и лист «Датасеты D&D…» через `ApplicationWiring`; новая группа тестов-охранок в `tests/`.
- БД: схема игры не меняется — признак и список подключённых датасетов живут в `game_settings` (ключи репозитория настроек). Таблицы модуля появятся в фазе 2 и будут создаваться аддитивно, о чём этот фундамент закрепляет тестом round-trip.
- Файлы: `~/.nri_manager/datasets/` (рядом с `ui.json`/`llm_config.json`, тот же config home); JSON-схемы LSS вкладываются в пакет (`app/dd/resources/schemas/`, фиксация версии за релизом, changelog интеграций LSS — вход для обновлений).
- Зависимости: `jsonschema` (валидация draft-07) в зависимости приложения; сеть — только через общий `httpx.AsyncClient`.
- Документация: CHANGELOG, functional-checklist, раздел `docs/qa/test-cases/` — в этом же изменении.
- Гейка не меняется: `ruff check app/ tests/` + `QT_QPA_PLATFORM=offscreen python run_tests_isolated.py`, покрытие 100 %.
