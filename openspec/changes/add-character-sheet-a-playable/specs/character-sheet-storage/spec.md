## ADDED Requirements

### Requirement: Схема шаблона версии 2

Новые и сохранённые после A-playable шаблоны SHALL иметь `schema_version` равный 2. Загрузка шаблона версии 1 SHALL восстанавливать все поля и единственную страницу без потери. Если в данных встречается значение `type` не из каталога (label, text, textarea, checkbox, number, dropdown, image, rect, line), система SHALL не открывать шаблон и SHALL сообщить об ошибке. Запись SHALL не сохранять неизвестный тип.

#### Scenario: Чтение шаблона v1

- **WHEN** открыт шаблон, сохранённый как schema_version 1 с подписью и однострочным полем
- **THEN** оба поля на месте с теми же идентификаторами и геометрией, ориентация книжная, одна страница

#### Scenario: Сохранение поднимает версию

- **WHEN** шаблон v1 открыт и пользователь сохраняет макет
- **THEN** в базе `schema_version` равен 2

#### Scenario: Неизвестный тип

- **WHEN** в JSON шаблона поле с type, которого нет в каталоге
- **THEN** шаблон не открывается в редакторе, пользователю показывается ошибка, база не меняется

### Requirement: Несколько именованных страниц в данных

Шаблон v2 SHALL содержать упорядоченный список страниц; у каждой страницы SHALL быть имя и список полей. Поле SHALL принадлежать ровно одной странице. Число страниц SHALL быть не меньше одной и не ограничено сверху.

#### Scenario: Две страницы в базе

- **WHEN** пользователь добавил вторую страницу, поставил на неё поле и сохранил
- **THEN** после повторного открытия у шаблона две страницы, поле на второй, идентификатор поля тот же

## MODIFIED Requirements

### Requirement: Шаблоны принадлежат текущей игре

Шаблоны чар-листов SHALL храниться в базе данных текущей игры. Смена открытой игры SHALL показывать только шаблоны этой игры. Шаблон SHALL включать: уникальное в пределах игры имя, `schema_version` (1 у ещё не сохранённых после A-playable; 2 у новых сохранений), ориентацию книжную или альбомную, одну или более страниц формата A4 и упорядоченный список полей на каждой странице.

#### Scenario: Пустой шаблон после создания

- **WHEN** пользователь создаёт шаблон с именем, которое ещё не занято в этой игре
- **THEN** шаблон сразу записан в базу с этим именем, `schema_version` 2, одной пустой книжной страницей A4 с именем «Страница 1» и без полей

#### Scenario: Смена игры меняет набор шаблонов

- **WHEN** в игре A есть шаблон, пользователь переключается на игру B, где этого шаблона нет
- **THEN** список шаблонов игры B этот шаблон не содержит

#### Scenario: Шаблон уезжает с экспортом игры

- **WHEN** игра с шаблонами экспортирована в `.nri` и импортирована как новая игра
- **THEN** импортированная игра содержит те же шаблоны (имена, страницы, поля, картинки полей)
