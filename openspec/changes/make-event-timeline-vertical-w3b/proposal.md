# Proposal: make-event-timeline-vertical-w3b

## Why

W3 (горизонтальный Gantt, влит `8e8c2e6`) отвергнут UX-практикой: диапазон целиком сжимается в ширину панели (горизонтального скролла нет by design), даты событий видны только в tooltip и «не совпадают» со старым списком, плотность шкалы зависит от размера панели. Grill-сессия 2026-08-31 зафиксировала решение: переделка вперёд (не откат `8e8c2e6`) в вертикальную шкалу дат по референсу «таймлайн-плеер»: слева шкала дат, справа события как раньше, пустые дни внутри диапазона — пустые строки, даты всегда видны в строках.

## What Changes

- Панель таймлайна: `TimelineCanvas` (горизонтальные полосы) заменяется вертикальным `QListWidget` с кастомным delegate. Строки двух типов: событие (`start — end · имя`, игровой формат дат, открытый конец `—`) и пустой день (заглушка той же высоты).
- Каждые сутки видимого диапазона — ровно одна позиция; пустые дни НЕ схлопываются (решение по референсу). Сортировка по `(start_date, id)`; многодневное событие стоит на позиции даты начала.
- Date-rail слева (в delegate, декоративный): тик на каждые сутки, подпись месяца (игровое название, короткая форма, поворот снизу вверх) при первом дне месяца, скобка-привязка против дней многодневного события.
- Липкая дата-оверлей сверху вьюпорта: полная игровая дата верхней видимой строки, роль `title`, accent-hairline; скрыт при пустом списке.
- Фильтр диапазона — один чип («Все даты» / `Дд Мес ГГГГ — Дд Мес ГГГГ` ▾) вместо полей+apply/clear; поповер с двумя мини-календарями (`_CustomCalendar`), live-apply, сброс внутри поповера. «+»-меню без изменений.
- Навигация по пустым дням: кнопки «к пред. событию» / «к след. событию» (второй ряд шапки) + `Alt+Up`/`Alt+Down` при фокусе панели.
- Удаление: `app/presentation/views/track_layout.py` и его юнит-тесты (мёртвое Gantt-ядро); widget-тесты канваса и пиксельный tok-тест переписываются на delegate.
- **BREAKING нет**: id-контракт W3 (`event_selected(event_id)`, `select_event_by_id(id)`, `scroll_to_event(id)`) сохраняется поверх списка через itemData; контракт ViewModel/wiring не меняется.

### Modified Capabilities

- `event-timeline`: горизонтальная геометрия полос/дорожек заменяется вертикальным перечислением дней с рейкой дат, липкой датой, чип-фильтром диапазона и jump-навигацией; id-контракт выбора, игровые месяцы, пустые/фильтрационные состояния и токен-инвариант сохраняются вadaptированном виде.

## Impact

- `app/presentation/views/timeline_widget.py` — `TimelineCanvas` удаляется; `QListWidget` + delegate (строки события/пустого дня, rail, скобки), sticky-оверлей, чип-фильтр с поповером, jump-кнопки.
- `app/presentation/views/track_layout.py` — удалить вместе с `tests/presentation/test_track_layout.py`.
- Новый чистый модуль `app/presentation/views/timeline_rows.py` — `build_rows(events, range_start, range_end)` (дни→строки, jump-индексы; без Qt).
- `app/presentation/viewmodels/timeline_viewmodel.py` — точечно: производные строки поверх существующего контракта select/selected_event; сигналы не меняются.
- `app/application/wiring.py` — semantic-правок нет (id-контракт совпадает); проверка совпадения API панели.
- `app/presentation/views/custom_date_edit.py` — переиспользование `_CustomCalendar` в поповере (видимых изменений может не быть).
- Тесты: `tests/presentation/test_views.py`, `test_viewmodels.py`, `tests/ui/helpers.py`, E2E `test_e2e_events/ months/ wiring_gaps/ images/`, `test_application_boot.py`, пиксельный `test_e2e_timeline_theme.py`; инвариант `test_no_chrome_hex.py` действует без правок (`views/**`).
- Вне скоупа (W3c): клик по шкале = прыжок, follow-дата под курсором, drag диапазона. Вне карты: зум, drag-редактирование дат события, дорожки по сущностям, типы/цвета событий.
