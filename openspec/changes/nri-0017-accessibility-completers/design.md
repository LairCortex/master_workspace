# Design: nri-0017-accessibility-completers

## Context

NRI-0012 ввёл контракт (роль — за компонентом, name — у потребителя, press — только через `Accessible.onPressAction`, оффскрин-пин `doAction`), живой аудит добил оставшееся: `ThemeDateField` = `Control` с `contentItem: Text{elide}` (не имеет ни роли, ни press-пути — FI-1; elide режет год — M2); табы островов не проверялись на Press; `RowItem` эмитит `activateRequested`, диалог пресетов слушает `selectedRequested` — активация до обработчика не доходит; `QMenuBar` на QDialog на macOS не проецируется никогда (справедливо для платформы: бар принадлежит QMainWindow), а редактор/Fill построены именно так; ListItem→cocoa в Qt 6.10 проецируется StaticText (FI-2, наблюдалось сырым деревом); карта NRI-0012 обещала строкам описания «Открывает игру», слота нет (FI-3). Чекбоксы посадок после П3 — штатные `QCheckBox`, просят закрепляющий тест.

## Goals / Non-Goals

**Goals:** ни один интерактив islands не молчит по прессу; дата — полноценный контрол; действия правки видны и reachable; расхождения проекции легитимизированы документом или починены.

**Non-Goals:** value-мост через `QAccessible.installFactory` (NRI-0013 — отдельный зарезервированный follow-up); тултип-мост (предел ④); аннотации попапов (предел ①); редизайн редактора.

## Decisions

### F1. `ThemeDateField` — контрол с ролью и шириной внутри
Корень — `Button`-подобная семантика: `Accessible.role: Accessible.Button`, `Accessible.name` из usage-site (уже есть), `Accessible.onPressAction` → существующий обработчик открытия попапа; `minimumWidth` = измеренная ширина наихудшей формы (компонент получает свойство `worstCaseText` от хостящего VM/форматтера — форматтер календаря уже умеет длинные формы; fallback — встроенная наихудшая маска) + padding; `elide` остаётся как последний барьер, но на `worstCaseText` заведомо не срабатывает. Off-screen-пины: интерфейс кнопки, Press → сигнал открытия попапа у хоста, `implicitWidth >= текст worst-mask`.

### F2. «Правка» — action-row кнопок вместо меню диалога
Из `editor_dialog.py`/`fill_dialog.py` удаляется `QMenuBar` (`:131-160`/`:124-143`); QML-корни получают row из существующих библиотечных кнопок: Editor — «Отменить», «Повторить», «Копировать», «Вставить», «Дублировать»; Fill — «Отменить», «Повторить» (скрыты в read-only, как `.hide()` сейчас). Хоткеи Ctrl/Cmd-Z/Y/C/V/D регистрируются на уровне диалога как прежде (существующие QAction-обработчики переиспользуются через существующий VM/командный слой — без второго пути). Имена/роли дают штатные текстовые кнопки (контракт NRI-0012: не переименовывать штатные — guard не мешает). Размещение row (верхняя chrome-строка окна) — пиксельный grab тест переснимается.
*Вместо:* репатриинга меню в нативный bar MainWindow (переключение баров под модальным окном на macOS — непредсказуемо для QDialog, третий путь после B2 «невидим» и «тулбар» — отклонено); только хоткеев — возвращает B2.

### F3. Сигнатурная размолвка RowItem↔пресеты
Правится usage-site `SheetPresetRoot.qml:109`: слушать `activateRequested` (окно принимает выбор), `selectedRequested` оставить для изменения выделения (курсор стрелками); аналогичный аудит listener'ов по всем островным спискам (греп `selectedRequested`). Пины: Press=принятие, одиночный select≠принятие.

### F4. Табы: Press-контракт
`ThemeTabButton` (штатный `TabButton`-потомок в библиотеке) — проверить/добавить, что дерево доносит кнопку и Press переключает `currentIndex` (обычно штатно; живой отказ B1 мог быть от владения «фрейм вне окна» — проверить на реальном дереве лаунчер-списка чар-листов). Оффскрин: `doAction("Press")` вкладка «Листы» → сигнал смены VM; при подтверждённой невозможности (нативный tabbar-мост) — сценарий живого предела с записью в AGENTS.

### F5. Проекция ListItem (FI-2): починить или задокументировать
Шаг 1 — проба минимальной правки: `Accessible.role` уже ставится на `RowItem` (Item-корень); в 6.10 cocoa проецирует ListItem→StaticText — проверить переизобретение роли через `Accessible.Button` fallback/Qt-обновления (фиксированная версия Qt в пирамидах — апгрейд вне пакета). Шаг 2 (если не доезжает): пункт в поименованном списке пределов AGENTS («роль строк списков теряется cocoa-проекцией — читаются как статический текст, пресс работает») в П4 же, карта дерева в design NRI-0012 не врёт. Решение принимается по факту прогона в таске; спека требует именно «либо/либо» (см. qml-accessibility delta).

### F6. `RowItem.description` + точечные описания (FI-3)
Компонент получает `property string accessibleDescription` → `Accessible.description`; usage-sites: строки лаунчеров — «Открывает игру», списки карточек — существующие описания DetailPanel не трогаются (карта). Guard-тест конвенций: `Accessible.description` разрешён (не противоречит запретам). Живая проверка через raw `AXDescription` (tool не рисует — предел не меняется).

### F7. ✎-кнопка и чекбоксы (FI-4, TB3-пин)
Иконка-кнопка музыки в `EntityCardRoot.qml:118-ряд` — имя «Изменить ссылку на музыку» (usage-site name, role уже Button). Чекбоксы посадок (реализованы в П3 `QCheckBox`): закрепляющий тест оффскрин `doAction("Press")` → seat/drop-сигналы (мок-хост) — спеку дублировать не нужно, поведение описано в `character-sheet-host` П3.

## Risks / Trade-offs

- Добавление row кнопок в редактор — давит канву на 40 pt; высота окон не фиксируется (не grab-контракт) — принимаем, пиксель-test переснимается.
- Если cocoa-проекция ListItem окажется неизлечимой на текущем Qt — список пределов растёт (пять вместо четырёх); это легальный путь по контракту «молчаливое расхождение = дефект».
- `worstCaseText` требует поддержки форматтера (календарь меняет формы дат) — расчёт в одном месте (хост/VM), в спецификациях зафиксирован шириной-гарантией, не конкретным текстом.
- Удаление QMenuBar — риск потери хоткеев, если QAction содержали только menu; проверка: shortcuts живут на диалоге до/после (тест keyPressEvent).
