# Design: nri-0016-table-llm-logging

## Context

Факт-разведка: PIN генерится `table_host_service.py:78-82` (`secrets.randbelow(10000):04d`), сверяется строками — клиент не знает протокольную длину, но веб-страница фиксирует 4 в двух местах (`index.html:12 maxlength`, `app.js:49-50`); `panel.py` (221 строка) без `closeEvent` (`stop_requested` висит неподключённым к закрытию); `runtime.py:209-212` глотает `RuntimeError` мёртвого C++-слушателя (weak-контракт не снят, `remove_listener` нет); версии в UI нет при трёх синхронных кодовых местах; `ui_prefs/config.py` — готовый канал prefs, переводы/локаль не задействованы. Формат окон П1 (не-модален + реестр) предполагается влитым.

## Goals / Non-Goals

**Goals:** закрытие панели гасит хост; реквизиты соответствуют фактическому запуску; ни одна кнопка не молчит попусту; подписи LLM не гуляют; лог живёт дома, не разрастается, слушатели не зомби; версия видна.

**Non-Goals:** протокол/HTTP-слой и эндпоинты стопа — без изменений (сверка строками переживает длину); веб-клиентский UI, кроме двух констант длины; QML-острова вместо попапов; DEBUG-рубильник; AX-пины чекбоксов-посадок (П4 — дождаться QCheckBox из этого пакета).

## Decisions

### V1. Закрытие панели с остановкой — асинхронное, не «убить и забыть»
`TableHostPanel.closeEvent`: при `running` — `QMessageBox.question` («Остановить стол?» Да/Нет — кнопки русские по П1); при Да — `event.ignore()`, emit `stop_requested` (существующий сигнал, подключение в `main.py:595-600` остаётся), по завершении остановки сервис шлёт существующий сигнал состояния → панель делает `accept()`/`close()` повторно с флагом `_stopping`. Оффскрин-пин с fake-host: close→подтверждено→`stop_requested`→по finished close без диалога; отказ — окно живо.
*Вместо:* синхронного `service.stop()` прямо в closeEvent-потоке — нарушает «одна точка финализации»/сигнальный контур composition-root (AGENTS: панель не лезет в сервисы напрямую).

### V2. Реквизиты по факту запуска
Панель: блоки URL/QR/PIN скрыты, пока не `running`; `refresh_urls()` вызывается по переходу в `running` от `host.port`/`host.host_urls()`; `port_spin.valueChanged` (до старта) — сброс скрытых блоков/подписей на заготовки; QR после старта — адрес-хост списка (первый неплейковой IPv4, при loopback-only — `127.0.0.1`), текстом показываются все адреса (существует). `pin_label/urls_label` — `setTextInteractionFlags(TextSelectableByMouse)` (urls уже имеет, pin — нет). Кнопки панели — `setAutoDefault(False)`/`setDefault(False)` (TB5).
*Вместо:* live-обновления QR «вживую с правкой порта» — QR до запуска вводит в заблужнение «стол уже доступен»; аудит предложил именно показ после старта.

### V3. Посадки — `QCheckBox` в строках, без кастомного AX-интерфейса
`QListWidgetItem`-чекейблы (`ItemIsUserCheckable`) не доносят действий в дерево; замена — `setItemWidget(row, widget с ThemeCheckBox? — нет, widgets-слой: штатный QCheckBox в row-виджете)` + QLabel имени; логика `itemChanged`-обработчика переезжает на `toggled/QAbstractItemView`-селекты без изменения вызовов seat()/drop_seat(); `currentRow` выбирается кликом по строке (для «Выгнать»-гейта). Пиновка: поведение (seat/drop) — сейчас; «Press из дерева» — П4.
*Вместо:* `QAccessibleInterface`-подкласса для чек-элементов QListWidget — ручной AX-мост fragile, нативные чекбоксы дешевле и надёжнее (решение грилла).

### V4. PIN — 6 цифр синхронно в трёх точках
`_new_pin → f"{secrets.randbelow(1_000_000):06d}"`; `index.html: maxlength=6`, `app.js: length !== 6`; сервисные тесты (динамический `host.pin`) проходят без правок, единственное исключение-литерал в `test_table_host_service.py:107` — проверить. Длина не в URL-контракте/JSON — браузер+HTTP сверку не ломают.

### V5. LLM-вёрстка — пары в одном Repeater
`LlmSetupRoot.qml:174-203`: два Repeater'а → один, делегат `RowLayout { TitleText; ThemeField }` (или GridLayout `Layout.column` из delegate-пар); порядок в дереве — «подпись, поле, подпись, поле…»; пин: развёртка children-последовательности страницы. LS2: в футере StackLayout — Label «N из M» (M = pages count VM) + `ThemeButton «Закрыть»` (result reject без подтверждения); окно через реестр П1 (NonModal, заголовок из windowTitle). LS3: `llm_setup_view_model.py:91` «Промт», «Промты полей — <тип>» (корень «промпт» — выбор словарной формы «промпт», в AGENTS-терминологии «промт мира» соседствует — приводим всё к «промпт»; правка только строк VM/текстов). LS4: имя поля — константа «Ключ API» в property корня; проверить, что usage-site не перебивает значение плейсхолдером (факт агента: аннотация есть — значит плейсхолдер просачивается в Name-слот живьём; оффскрин-ассерт Name==«Ключ API», Description/placeholder — отдельно).

### V6. Лог — path по `paths.py` + ротируемый handler; слушатели — с отпиской
`_file_handler = RotatingFileHandler(NRI_MANAGER_DIR / "nri_manager.log", maxBytes=2_000_000, backupCount=3, encoding="utf-8")`, создаётся каталог; `_app_root()`-логика из `main_window.py` удаляется вместе с импортом (frozen-частный путь больше не нужен); у handler'а `setLevel` не ставится вообще (наследует root). `ThemeRuntime.add_listener` → возвращает handle; новый `remove_listener(handle)`; `game_launcher_dialog` снимает подписку в `finished` (все лаунчер-циклы из меню); `_notify_listeners` остаётся защитным, но живые-внутренние слушатели в него не попадают. Пиновка: tmp_path подменяет `NRI_MANAGER_DIR` (monkeypatch) — создание/повторное включение/выключение (lsof-equivalent: handler закрыт, `handler.stream.closed`); ротация — маленький maxBytes в тесте; слушатель — смена темы после закрытия лаунчера → `caplog` пуст.

### V7. Версия — `app/__init__.py::__version__` + неактивный пункт меню
`__version__ = "0.17.2"`; меню: `addAction("Неактивен…")` неактивная строка f-«Версия {__version__}»; тест `tests/test_version_consistency.py`: tomllib(pyproject).project.version == __version__ (CHANGELOG — живой ре-аудит/релизный процесс, в тест не берём из-за хвоста релизных записей — фиксируем в design; spec-проверка «релиз-процедурой» остаётся с докой). AGENTS-абзац про три места синхронизации обновляется на « четыре места: + __version__».

### V8. Семантика темы и экспорт (D2, A4)
Лаунчер-кнопка темы (`LauncherRoot.qml:151`) переделывается на чекбокс-режим: фиксированная подпись «Светлая тема» + `checked` из темы (компонент `ThemeCheckBox`; VM/сигнал переключения существующий — переворот `set_theme` меняет только состояние, не текст). Меню-чекбокс `main_window.py:96` остаётся — он уже эталон. Экспорт (`main.py:406-421`: стартовый каталог) — директория db-файла текущей игры (`games/`, из менеджера сессий — не хардкор-литерал) + имя `<игра>.nri`.

## Risks / Trade-offs

- Асинхронное закрытие (V1): при уходе приложения во время подтверждения закрытие может «зависнуть» — закрытие через `shutdown()` гасит сервис сам (main.py:848-849); окно подтверждений не всплывает при programmatic-close (флаг `_programmatic`).
- 6-значный PIN меняет пользовательский ритуал (набирать длиннее) — принято гриллом как ожидание безопасности; веб-страницы старых сессий несовместимы не будут (длина только клиентская валидация).
- `setItemWidget`-строки дороже штатных чек-элементов по памяти (десятки экземпляров — несущественно) и требуют аккуратности стилизации выбранного состояния (grab-тест списка чар-листов не должен поехать — строки «Стола» вне grab-контрактов).
- Терминология «промпт» против «промт» в доках: один греп-all в таске, иначе словесный распад.
