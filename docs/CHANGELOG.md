# Changelog

### Единая визуальная сетка: квадратные глифы, оптические чекбоксы, полные вкладки, шкала ширин и мастер по содержимому (change `nri-0018-grid-alignment-and-card`; версии не трогаем)

#### Новое
- **`ThemeIconButton` — квадратный калибр мелких действий (spec `qml-components` «Квадратная мелкая кнопка действия библиотеки», Д1):** новый компонент библиотеки — фиксированные 32×32 (константа компонента, не токен), оформление/состояния унаследованы от `ThemeButton`, контракт доступности штатный (роль привезён контролом, имя — за точкой применения); ✕ шапки листа, ✎ музыкальной ссылки, «+» шкалы таймлайна (локальный `squareSide: 30` снят), ↑↓−+ рейки редактора и стрелки типов событий пересели на него, `ThemeAiButton` принял тот же квадрат (константа стороны проставлена внутри обеих компонент, дрейф ловит пин) без потери оформления, состояний «✨»/«…» и наблюдаемого `aiState`; греп-пин: ни один остров и ни одно место применения больше не размеряет глиф (1.1–1.3, `tests/presentation/test_theme_icon_button.py`, `test_theme_icon_button_usage.py`, переснятые эталоны `tests/ui/test_theme_grab.py`)
- **Оптический центр `ThemeCheckBox` (spec `qml-components` «Чекбокс ставит индикатор и подпись на один оптический центр», Д2):** метрики подписи (`FontMetrics` descent+leading, кап 1 px — решение владельца 2026-09-25) опустили индикатор в общий чернильный центр строки, верх/низ padding из `space.sm` сравняли полосу чекбокса с полосой кнопок ряда; поведение, состояние и имя в дереве не изменились, места применения (7 островов) правки не потребовали (2.1–2.2, `tests/presentation/test_theme_checkbox_optical.py` — геометрия с точностью растра в обеих темах)
- **Слот действия в `ThemeSheetHeader` (spec `qml-components` «Действие стоит за заголовком», Д3):** default-свойство ряда — группа действий между текстом заголовка и «✕» (фиксированный отступ `space.sm`, центрирование по строке заголовка, чистые якоря — порядок «заголовок → действие → … → закрытие» в любой теме); заголовок перестал обрезаться (правый якорь снят), сигнал закрытия прежний (3.2, `tests/presentation/test_sheet_header_actions.py`)
- **Тематизированные индикаторы нативных переключателей (spec `ui-widget-catalog` «Нативные индикаторы проверки тематизируются», Д8):** лист chrome-области (`compile_qss`) получил `QRadioButton`/`QCheckBox::indicator` из токенов (бокс 16, чек — `radius.sm`, радио — круг, выбранное — accent-заливка), popup-лист — `GameCalendarEraCheck::indicator` для флага «до н.э.» (новая STYLE-FACING-имя сетки, синхронность имени с листом пинится с обеих сторон); белой нативной ячейки на тёмном фоне нет, off-skin лист не применяется — нативность автоматом (6.1–6.2, 7.1–7.2, `tests/presentation/test_calendar_nav_band.py`, `tests/presentation/test_theme_compile.py`)
- **Строка навигации календарной сетки — одна полоса 32 (spec `game-calendar-grid` «Строка навигации — единая полоса высот», Д8):** стрелки ◀▶ выросли с 28 до 32 и встали в общий калибр, комбо месяца, спиннер года и чекбокс эры зафиксированы той же высотой с общим вертикальным центром (6.2, там же)

#### Изменено
- **Шапка карточки — русское имя и полная генерация (specs `qml-shell` «Шапка карточки сущности названа по-русски…», `entity-generation` «Кнопка стоит у заголовка», Д3/Д4):** заголовок карточки каждого типа собирается через `entity_registry.display_label` — «Карточка: Организация», сырой ключ (`organization`) в видимых заголовках отсутствует (греп-пин); кнопка полной генерации переехала из строки «Название» в слот шапки сразу за текстом заголовка — в карточке (`entityGenerateButton`) и, той же фразой размещения, в диалоге события (`eventEntityAiButton`); `objectName`/имена доступности/aiState/гейты не изменились, в строке «Название» осталась только генерация названия (3.1–3.4, `tests/presentation/test_sheet_header_actions.py`, обновлённые родители кнопок в `test_sheet_parity.py`/`test_dialogs.py`/`test_sheet_header_dialogs.py`)
- **Полные вкладки деталей и старт 1280×800 (spec `main-window`, Д5):** поле коротких подписей `tab_label` удалено из реестра — вкладка носит полное `plural_label`, и оно же имя доступности и подсказка (пины NRI-0015 про короткие подписи переустановлены на полные); дефолтный фрейм главного окна при отсутствии сохранённого — 1280×800 (минимум 1024×680 остался); восстановление роли `main` расширил бы сохранённую ширину до порога «все вкладки целиком», который панель измеряет по делегатам вкладок (`minTabsWidth` → `min_tabs_width()`), позиция и высота не двигаются; он же — минимум панели деталей и правой панели сплиттера (4.1–4.4, `tests/presentation/test_detail_tabs_labels.py`, `test_geometry_memory.py`, `test_main_window_default_start.py`) — **так закрывается OBS-1**: «Показать всё» строки «Дата:» снимка целиком умещается уже на дефолте (пин в `test_main_window_default_start.py`)

### Доделанный accessibility-контур: живые даты, пресс-действия, описания строк (change `nri-0017-accessibility-completers`; версии не трогаем)

#### Новое
- **`ThemeDateField` — живой контрол (FI-1=M3, M2, spec `qml-components`):** роль `Button`, имя и `Accessible.onPressAction` живут внутри компонента (usage-site «роль на role-less Control» вычищена, имя остаётся у точки применения), AX-активация открывает попап наравне с мышью; `minimumWidth` — нижний порог по наихудшей подписи хост-форматтера (`worstCaseText`, fallback-маска в самом компоненте), год больше не срезается, elide остаётся запасным; хосты снимка/диалога передают наихудшую форму активной календарь-даты (1.1, `tests/presentation/test_theme_date_field_accessibility.py`, пиксельная проба «год цел» в `tests/ui/test_theme_grab.py`)
- **Описание-слот у `RowItem` (FI-3, spec `qml-accessibility`):** строковое `accessibleDescription` → `Accessible.description` — слот, обещанный картой NRI-0012, починен по минимуму без пере-архитектуривания; usage-site лаунчера заполняет «Открывает игру», сырой `AXDescription` читается живьём (4.1, `tests/presentation/test_rowitem_accessibility.py`)

- **Табы чар-листов переключаются с `doAction("Press")` (B1, design F4, spec `character-sheet-editor`):** у штатного checkable-кнопки мост доступности не выдаёт ни одного действия (offscreen-проба + живой B1), поэтому `ThemeTabButton` получает `Accessible.onPressAction: control.click()` внутри компонента (правило NRI-0012 «роль за компонентом»): один AX-пресс кликает вкладку ровно как мышь — тот же click state machine двигает `currentIndex` и checked-состояния; Face (роль/имя) штатный, не пере-аннотирован (2.1, `tests/presentation/test_sheet_list_accessibility.py`)
- **Пресет принимается однократной активацией (B3, spec `character-sheet-editor`):** `SheetPresetRoot` слушает `activateRequested` (принятие) отдельно от `selectedRequested` (только выделение); греп-обход остальных слушателей аналогичной размолвки не нашёл (2.2, `tests/presentation/test_character_sheet_preset_dialog.py`)
- **Кнопка «✎» ссылки на музыку именована (FI-4=CR2):** «Изменить ссылку на музыку» в Name-слоте, роль уже `Button` (4.2, `tests/presentation/test_entity_card_accessibility.py`)
- **Пин посадочных чекбоксов (TB3-усиление, spec `character-sheet-host`):** поведение из П3 закреплено AX-пинем — `doAction("Press")` по чекбоксу строки ведёт прежний обработчик ровно один раз, `_seats_loading`-гард без эхо-вызовов; временная подмена пина проходит тот же путь, что мышиный клик (5.1–5.2, `tests/ui/test_table_host_seats_accessibility.py`)

### Дата игры становится координатой игрового календаря: coord-колонки, маршрут записи по активному календарю, старт-сдвиг невалидных (change `wire-game-calendar-coordinates`; кусок C3a дорожной карты кастомного календаря — кусок C3 остаётся частичным до C3b; версии не трогаем)

#### Новый функционал
- **Доменный кодек хранимого представления координаты:** `encode_coord`/`decode_coord` в `app/domain/game_calendar.py` — обычный день `"M:год:месяц:день"`, вставной `"I:год:индекс_правила"`, числа без ведущих нулей; кодирование инъективно и обратимо ровно, неразбираемый текст отвечает машиночитаемыми причинами (`CoordCorrupted`: пустой текст, бессементный, нечисловой, неполный) вместо исключения; существование координаты в календаре кодек не проверяет — это дело чистой политики сдвига (кусок C1)
- **Координатные колонки шести датированных таблиц:** `start_coord`/`end_coord` (TEXT, nullable) во всех таблицах `_ERA_TABLES`; единственная ветка хранилищ — резолвер `resolve_coord`/`assign_coord` в `app/infrastructure/db/models.py` рядом с `_sync_era_keys` и маппинг репозиториев через `CoordMappingMixin` (`app/infrastructure/repositories/coord_mapping.py`). Чтение: coord-колонка заполнена ⇒ истина в ней; битый текст ⇒ `None` + очистка колонки + строка в логе (таблица, id) — игра открывается на прежних date-колонках; пусто ⇒ прежние даты. Запись: coord в строке заполнен → coord; активный кастом → coord, и date-колонки не обновляются никогда (мёртвое наследие, не зеркало); пресет «Стандартный» → прежние date-колонки. `_sync_era_keys` считает ключ от разрешённой `resolve_coord` координаты; ни один слой выше о двух хранилищах не знает (specs `date-eras`)

Состояние «вручную выставил кастом в настройках ⇒ игра падает на старте» исчезает; обход идемпотентен, для стандартной игры — no-op (spec `game-calendar-settings`)

### Даты двух эр: 1…9999 гг. до н.э. и н.э. (change `add-era-aware-dates`)

#### Новый функционал
- **У каждой даты свой признак эры:** у начала и конца всех шести сущностей с датами (`events`, `organizations`, `characters`, `items`, `locations`, `ratings`) появился независимый флаг «до н.э.»; событие может начинаться в одной эре и заканчиваться в другой. Диапазон обеих эр — 1…9999 год, прежний порог «от 100 г. н.э.» снят, нулевого года нет; календарь до н.э. зеркальный: месяцы и високосность — как у нашего года с тем же числом (решение Q11)
- **Единый хронологический порядок:** `app/domain/date_era.py` — общий ключ `era_key = ordinal` (н.э.) / `ordinal − 732·год` (до н.э.) - **Ввод:** границы календарей `0001-01-01…9999-12-31`, спин года 1…9999, чекбокс «до н.э.» у каждого календаря (в одиночном попапе и независимо у двух календарей попапа диапазона) без смены чисел выбранной даты; попапы и диалоги (событие, карточка сущности, снимок мира) отдают пары (дата, эра), QML-поля получают готовые строки отображения и флаги `startBc`/`endBc`
- **Формат и импорт:** год до н.э. печатается суффиксом «44 г. до н.э.» (`format_game_date`); `parse_cell_date` принимает текстовый «5 марта 44 г. до н.э.» и знаковый ISO `-0044-03-05` (нативные дата Excel и голый ISO — по-прежнему н.э., неразбираемая дата — прежняя проблема строки); границы призраков колонок связей (минимум начал / максимум концов) считаются тем же ключом

### Импорт из .xlsx: одна книга на пять листов со связями между сущностями (change `rework-xlsx-import`)

#### Новый функционал

### Чар-листы A-playable: страницы и каталог типов (незавершённый)

#### Новый функционал
- Страницы без лимита: канвас — вертикальная лента A4 (листы столбиком, как Word, зазор 24 pt) + рейка слева (имя, добавить, удалить, ↑↓ порядок, переименование); новая страница вставляется после текущей с именем «Страница N»; последнюю страницу удалить нельзя, непустую — только с подтверждением; клик по пункту рейки прокручивает канвас к листу, при прокрутке в рейке подсвечивается лист с большей видимой площадью
- **BREAKING относительно A1-редактора**: колесо = прокрутка ленты, Ctrl+колесо = зум (25–400%); при открытии вписывается **ширина** одного листа A4 (не вся лента), первая страница сверху
- Ориентация одна на шаблон: переключение книжная/альбомная меняет размер всех листов, не влезшее зажимается в новый лист без масштабирования
- Перенос поля между страницами: перетаскивание через зазор с дропом на другой лист переносит поле туда (координаты от точки дропа, затем зажим в новый лист); бросок в зазор — поле остаётся на исходном листе; перемещение и ресайз всегда зажаты в **страницу поля**
- Каталог типов расширяется с 3 до 10: чекбокс (квадрат on/off, default выкл, даблклик/панель переключают), число (дроби, запятая → точка, необязательные min/max, не-число и вне границ отвергаются), выпадающий список (упорядоченные опции без пустых, default — на канвасе текст), картинка (рамка-плейсхолдер, выбор/очистка файла через ImageStore текущей игры, даблклик открывает выбор), декоративная рамка (только обводка, данных не хранит) и осевая линия (шире → горизонталь, иначе вертикаль); постановка по-прежнему разовая
- `schema_version = 2` (страница теперь `{name, fields}`): v1-шаблоны читаются без потери (на диск v1 возвращается только после Save), неизвестный тип поля — отказ открыть шаблон с ошибкой, база не меняется
- Картинка поля листа — ссылка на запись `images` (sha256, без пути в JSON): refcount/GC учитывают поля `pages` всех шаблонов: файл снимается только если на него не ссылаются ни сущности, ни поля листов (очистка поля + save, удаление шаблона); нечитаемый файл — ошибка, поле остаётся пустым

#### Инфраструктура
- Domain: `FieldType` +6 значений; геометрия ленты (`page_origin`, `scene_to_page`, GUTTER 24 pt); `clamp_rect` в локале страницы (у линии толщина ≥ 1 pt); парсер v1/v2 (`UnknownFieldTypeError`); `iter_sheet_image_ids` / `null_sheet_image_ids` для GC
- `CharacterSheetService`: create сразу v2 («Страница 1»); load v1/v2 с отказом на неизвестный тип; save всегда v2 + `gc_after_commit` по старым image-id; delete шаблона гоняет GC картинок
- `ImageStore`: `refcount` / `_null_references` / `startup_gc` сканируют `image_id` в `pages`-JSON всех шаблонов (помимо FK трёх сущностей)
- Представление: сцена-лента в одном QGraphicsScene, рейка-виджет, `wheelEvent` (скролл/зум), fit по ширине, per-type секции панели свойств и палитра (указатель + 9 типов)

#### Тесты

## [0.15.0] — 2026-08-24

### Файловое хранилище изображений с адресацией по sha256 (breaking формат игры)

#### Новый функционал
- Изображения организаций/персонажей/локаций больше не хранятся как base64 в SQLite: файлы (оригинал + preview 512px WebP q80) лежат на диске в `games/<name>/images/`, адресованы по sha256 содержимого; дедупликация в пределах одной игры — одинаковый файл хранится один раз
- Игра — теперь каталог `games/<name>/` (`game.db` + `images/`), а не одиночный `.db`-файл; имя игры = имя каталога
- Полный просмотрщик изображения в приложении: клик по изображению в карточке сущности или по миниатюре в панели деталей открывает окно с оригиналом на весь размер (прокрутка для крупных изображений, закрытие по Esc/кнопке); при отсутствии оригинала показывается preview, при отсутствии обоих — сообщение
- Экспорт `.nri` v2: архив каталога целиком (`game.db` + `images/**` + `meta.json` с `archive_version: 2`); импорт распаковывает во временный каталог и верифицирует sha256 каждого файла `images/**` до атомарного переноса — повреждённый архив отклоняется, ничего не остаётся в `games/`
- Импорт `.xlsx`: столбец `image`/`изображение` идёт через тот же конвейер `ImageStore`, что и карточка сущности; нечитаемый/повреждённый файл не прерывает импорт строки — сущность создаётся без изображения, путь попадает в отчёт как предупреждение

#### Миграция и совместимость
- При первом старте existing игры: плоский `games/<name>.db` переносится в каталог `games/<name>/game.db`; legacy base64-изображения (`image` колонки) переносятся в файловое хранилище построчно (с построчным commit — прерывание не портит уже перенесённое), после переноса — один `VACUUM`
- После каждого открытия игры инвариант хранилища восстанавливается автоматически (`startup_gc`): файлы-сироты без записи в БД удаляются; записи без оригинала снимаются со ссылок и удаляются; отсутствующий preview перегенерируется; неиспользуемые записи с файлами удаляются
- **Принятое ограничение**: экспорт v2 нельзя открыть старой версией приложения без потери изображений (`images/**` тихо игнорируется старым импортом) — обратной миграции `v2 → v1 с base64` не делаем; откат версии приложения для игр с изображениями не поддерживается
- Legacy-колонки `image` в схеме не удаляются (только обнуляются после миграции) — сам drop колонок отложен на будущий релиз

#### Инфраструктура
- `app/infrastructure/images/`: `ImageStore` (ingest с dedup/валидацией через `QImageReader`, `refcount`, `gc_after_commit`, `startup_gc`), path-резолвер (`images/<hash[:2]>/<hash>.<ext>` / `<hash>.preview.webp`), preview-генератор (512px WebP q80, детерминированный)
- Схема: таблица `images` (sha256 UNIQUE, ext, width, height, size_bytes) + `image_id` FK (`ON DELETE SET NULL`) на 3 сущностях; `image_ref` (`lazy="selectin"`) для синхронного доступа из презентационного слоя
- `image_utils`: base64-функции заменены null-safe `load_preview`/`load_original`/`load_entity_preview`/`load_entity_original`, работающими от файлового пути; глобальный `image_dir` игры (мирроринг паттерна `date_utils`)
- GC замены/удаления картинки в `EntityCardDialog` идёт через `EntityService.update_entity_with_relations` (`gc_after_commit` после commit, не во view)

#### Тесты
- 100% построчное покрытие сохранено; новые сценарии: path-резолвер, preview-генератор, ingest/dedup/race, refcount/GC (все состояния + сбои unlink), миграция legacy + `VACUUM`, порядок старта `Application.start()`, каталог-игра (create/list/delete), экспорт/импорт v2 (верификация sha256, конфликт имён, v1-совместимость), полный viewer, ingest/замена/удаление изображения через карточку (E2E), xlsx-импорт изображений (дедуп, битый/отсутствующий файл)

## [0.14.0] — 2026-08-24

### «Сгенерировать сущность»: параллельная генерация всех полей, отмена и видимые ошибки

#### Новый функционал
- Кнопка «Сгенерировать сущность» (✨) в правом верхнем углу форм события и карточки сущности: одним нажатием запускает генерацию всех AI-полей диалога, включая поля с уже написанным текстом (текст учитывается в промте, результат заменяет содержимое поля)
- Генерация всех полей — параллельная, а не последовательная: результат подставляется в поле по факту его завершения, разблокируя только его, остальные продолжают генерироваться
- Кнопка «Сохранить» заблокирована на время любой генерации в диалоге (одиночной и бандла)
- Отмена: во время волны кнопка сущности превращается в ⏹ и отменяет все запросы этого диалога. Отмена не считается ошибкой: диалога об ошибке нет, пришедшие результаты сохраняются, незаполненные поля возвращаются в редактируемое состояние с прежним содержимым
- Изоляция по диалогу: отмена во вложенной карточке прерывает только её запросы — генерация родительского диалога не затрагивается
- Защита от закрытия во время генерации: ESC игнорируется; X / «Отмена» при in-flight запросе — только после подтверждения с предупреждением (отказ — диалог остаётся открытым, генерация продолжается), при запросах только в ожидании ретраев — закрывается без подтверждения, запросы отменяются
- Видимые ошибки: ошибка одиночной генерации показывает диалог-предупреждение с названием поля и причиной (ранее ошибка глоталась молча); завершение бандла с неудачами — один агрегированный диалог со списком неудавшихся полей (одна общая причина — один раз, разные причины — построчно); успешные поля остаются заполненными
- Кнопка сущности активна только когда AI-ассистент «готово», описано описание мира и в диалоге не выполняется другая генерация; на одном диалоге одновременно не более одной волны

#### Инфраструктура
- `LlmService` — параллельное выполнение: `asyncio.Task` на запрос вместо последовательной очереди (очередь, worker, `queue_size`, `start_worker`/`stop_worker` удалены)
- Реестр активных запросов `owner → field_id` (identity-ключ по диалогу): `cancel_all(owner)`, `any_in_flight(owner)`, `count_in_flight(owner)`; `CancelledError` не перехватывается и не конвертируется в ошибки
- `on_phase`-хук `RemoteLlmProvider`: фаза запроса (`in_flight` — отправлен LLM / `waiting` — backoff между ретраями) видна оркестрации диалога
- Пост-сигналы отменённого запроса (ответ «пересёк» линию отмены) в диалоге отбрасываются: ни текст, ни ошибка не применяются

#### Тесты
- Тесты sequential-очереди `LlmService` заменены параллельными (два медленных запроса завершаются быстрее, чем дважды по одному) + тесты реестра/отмены
- Тесты phase-хука провайдера (MockTransport: 503 → 200 даёт `in_flight, waiting, in_flight`)
- E2E-сценарии бандла: старт → частичные результаты → завершение; старт → отмена; старт → ошибка (агрегированный диалог); закрытие в полёте (подтверждение/отказ/тихое); вложенная карточка (отмена не затрагивает родителя)

- Статусы AI-ассистента: `not_configured` / `ready` (готовность определяется по сохранённым настройкам, сеть при старте не требуется)

#### Инфраструктура
- `app/infrastructure/http/` — единственный `httpx.AsyncClient` приложения (connect 10 c, read 120 c), создаётся в `Application.start()`, закрывается в `shutdown()`
