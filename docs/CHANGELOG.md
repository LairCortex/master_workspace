### Редизайн таймлайна: лента дней вместо шкалы с рейкой, drop-меню и Alt/Opt-зум (change `redesign-timeline-day-ladder`; версии не трогаем — правки только UI-логики, синхронизация на релизе)

#### Новый функционал
- **Лента дней (ядро `timeline_rows.py` переписано):** без окна диапазон «от самого раннего начала до **дна ленты**» (`content_bottom` = max(позднее закрытое окончание, старт бессрочного + 1 год, clamp `CALENDAR_MAX`)); каждое событие — карточкой в **каждый** день своего протекания (бессрочное — до дна с пометкой «бессрочно»), пустой день — ровно одна позиция «нет события» (клик = инлайн-создание: поле + Enter; пустое поле не создаёт), провалы > 14 дней — одна схлопнутая позиция с игровыми границами (клик = предзаполненный «Выбор даты»); сортировка `(start_date, id)`, все позиции равновысокие (`ROW_HEIGHT`)
- **Sticky push-out:** липкий заголовок текущей секции (сутки — полная игровая дата, месяц/год — подпись периода) переехал с rail-follow на пару `QLabel`-оверлеев с анимацией выталкивания ~120 ms (`QPropertyAnimation`, ядро `sticky_state`); мыши не перехватывает, при пустоте скрыт
- **Ступени только жестом:** Alt/Opt + колесо — сутки ↔ месяц ↔ год с якорем от строки под курсором (miss по строкам — якорь от первой видимой, правило «верхняя позиция»); **внутренний шаг = проваливание: окно ставится равным периоду-якорю** (`period_span` — карточки и заголовки одинаково; спецификация «Приближение от карточки события»: «ступень — сутки, окно — август»; наружу окно не трогаем — «Якорь при отдалении» фиксирует только верхнюю единицу); клик по карточке периода проваливает глубже с окном = период; Ctrl/Cmd-колесо, кнопки ступени и `LADDER_CAPTIONS` удалены (мёртвый жест)
- **Drop с контекстным меню вместо засечек:** press на карточке → порог 4 px → приглушённая карточка + призрак на целевом дне (sticky = целевая дата); отпускание в другой день → `QMenu` у курсора из чистой `drop_actions`: «Перенести» (всегда, длина сохраняется, у бессрочного `end` открыт), «Расширить вниз до этого дня» (закрытые, ниже конца), «Начать раньше в этом дне» (выше начала); провал/отпускание вне дней/Esc/одновременный rebuild = cancel без записей; коммит — прежний канал `event_dates_moved` (одна запись, выбор сохранён); `cover_filter_for_span` → `cover_window_for_span` (расширение ACTIVE-окна до записи); на месяц/год жест недоступен
- **«Выбор даты» вместо чипа-фильтра:** кнопка «Все дни ▾» / границы окна игровым форматом; попап с двумя календарями применяется сразу, «Сбросить» — единственный сброс; окно — навигация с OVERLAP-видимостью (`start ≤ win_end AND (end is None OR end ≥ win_start)`), не фильтр свойств; тумблер «Скрыть даты без событий» (по умолчанию выкл, nothing persists) вырезает пустые дни/схлопнутые провалы/пустые периоды на всех уровнях; ни уровень, ни окно, ни тумблер не сохраняются между сессиями
- **Зеркалирование окна в шапке (дефект, исправлен на финальной проверке):** подпись «Выбор даты» — единственный пишущий `_set_window_caption`, следует `vm.window` с любого пути: проваливание кликом, внутренний Alt-зум (общий канал `period_drilled`), внешний сброс в «Все дни» через `_sync_from_vm` — чип больше не может показать «Все дни» под активным окном; заодно `cover_window_for_span` видит настоящее drilling-окно
- ViewModel knobs: `unit`/`group_by`/`_current_filter` → `level` (DAY/MONTH/YEAR)/`window`/`hide_empty` (сеттеры — единственная точка мутации, `_version_of` расширена; внешний выбор невыставленного события спускает лестницу и при необходимости сбрасывает окно)

### Дизайн-система W5: drag-редактирование дат на шкале (эпик W закрыт этим срезом; change `add-event-date-drag-editing-w5`, дизайн grill-сессий 2026-09-01; статус «влито» — по факту merge-коммита)

#### Новый функционал
- На суточной ступени закрытое событие переносится вертикальным drag'ом текстовой зоны: grab-offset от строки захвата (в т.ч. пустой день внутри диапазона многодневки), длительность сохраняется, цель снапится к суткам и clamp'ится к календарю карточки `0100-01-01 … 9999-12-31`; за краем модели цель экстраполируется шагом высоты строки
- Нижняя засечка скобки закрытой многодневки — ручка растягивания `end` (hit-зона над рейкой, `end ≥ start`); однодневные не растягиваются (долг: удлинение только диалогом)
- С start-строки бессрочного события тянется только начало (`end` остаётся открытым); тело/хвост/засечка открытой скобки — no-op
- Превью до отпускания: приглушённая исходная строка, призрак на целевом дне (wash `color.accent` α=0.35), live-скобка при растягивании; Esc и внешняя пересборка отменяют без записи; колесо скроллит и пересчитывает цель, Ctrl/Cmd-колесо и переключатели шапки погашены
- Commit: ровно один `event_dates_moved` → wiring под session-lock (`update_event` + commit), выбор на отпускании, унос за фильтр расширяет чип до записи; сбой — rollback, строка на прежних датах, один `QMessageBox`. **Долг:** диалог-путь `update_event_with_relations` по-прежнему молчит при сбое сохранения

### Дизайн-система W4: лестница ступеней просмотра, группировка по сущностям и типы событий (эпик W: база W1–W3c влита и принята, статусы W1–W3c — записями ниже; W4 реализована change `add-event-timeline-scale-views-w4`, дизайн зафиксирован grill-сессией 2026-08-31; статус «влито» фиксируется по факту merge-коммита — hash подтверждается на ревью; дальше — W5, QML-черта «после W4» пройдена)

#### Новый функционал
- Лестница единиц просмотра вместо «зума»: ступень **сутки · месяц · год**, каждая позиция = одна календарная единица ступени. На MONTH/YEAR строка-позиция показывает игровую подпись единицы и счётчик («Март 1245 · 4 события»), пустая единица — приглушённая заглушка «… · нет событий» (сжатие пустоты — сама лестница, отдельных строк-пропусков нет). Управление: **Ctrl/Cmd + колесо** с якорем (приближение — единица из-под липкой, отдаление — первая видимая дата), клик по позиции месяца/года приближает на ступень с этой единицей как якорем (без выбора и id-сигналов), переключатели «сутки · месяц · год» и «выкл · персонажи · локации · организации · предметы» в шапке; колесо без Ctrl, жесты рейки W3c и Alt+↑/↓ — без изменений. Вид (ступень/группировка) не сохраняется: при открытии панели всегда «сутки · выкл»
- Единый закон единицы ступени: тик, клик-прыжок, липкая подпись и drag-диапазон считаются по текущей единице; drag месяцами/годами эмитит ровно один `day_range_applied` с границами, нормализованными к полным датам единиц (1 число / last-day месяца, 1 янв / 31 дек) — через неизменный чип-путь, семантика попадания фильтра не менялась. Внешний выбор (поиск) и jump-кнопки с крупной ступени сами спускают лестницу до суточной строки события — id-контракт W3 неизменен
- Группировка по сущностям: на MONTH/YEAR список разбивается `SECTION`-заголовками по сущностям выбранного вида (алфавит, «Без привязки» последней), событие дублируется в каждую свою секцию, внутри секции только тронутые ею единицы; на сутках группировка лишь упорядочивает события внутри дня `(has_group, group_name, start, id)`
- Типы событий — новые данные per-game; **миграции через `init_db()`** (alembic не используется): таблица `event_types (id, name, color_index, sort_order)` создаётся штатным `Base.metadata.create_all`; в список `_MIGRATIONS` добавлен `ALTER TABLE events ADD COLUMN event_type_id INTEGER REFERENCES event_types(id) ON DELETE SET NULL` (nullable FK); conditional-засев шести НРИ-дефолтов (`Сюжет, Побочное, Слух, Встреча, Ров будней, Находка` → `color_index=1..6, sort_order=i`) с guard «только пустая таблица» — идемпотентен, правки пользователя не затирает; откат only-forward (таблица/колонка остаются неиспользуемыми). Удаление типа отвязывает события (`UPDATE events SET event_type_id=NULL` затем DELETE в одной транзакции); `color_index` замкнут диапазоном 1..8, colorpicker'а нет
- Диалоги типов: `EventTypesDialog` (по образцу `MonthSettingsDialog`, точка входа — пункт «Типы событий…» в «+»-меню панели) — список, переименование, ↑/↓ порядок, добавление, удаление, выбор цвета из 8 токено-кружков (оф-скин — нумерованные серые образцы), `attach_theme` + live-retheme; изменения применяются к игре сразу и видны в шкале без перезахода. Селектор типа (current + «Без типа», цветные точки из токенов) — в диалоге события; тип опционален
- Токены: в `tokens.json` заведены обязательные `color.chart.1…8` (пары light/dark, hue-расторы + вариация светлоты, различимы на `color.bg.surface` обеих тем; Readers — только шкала и диалог типов, в chrome-QSS/CSS правил с chart нет); отсутствие/битый chart-токен гасит тему по общей судьбе «Битые токены». Точка типа слева от суточной строки события — `color.chart.k`, событие без типа — `color.fg.muted`; при live-ре-теме восемь цветов перекрашиваются, выбор и скролл не теряются
- Скобки многодневок unit-aware: `bracket_lanes` переехал из виджета в Qt-нулевое ядро `timeline_rows.py`, span красит все единицы ступени, которых касается событие (сутки — побитово прежний выход); ROLE-роли делегата дополнены `ROLE_SHOW_YEAR` (YEAR: подпись года на каждой позиции, MONTH: раз в год на январе)
- Приёмка: юниты ядра (единицы × фильтр × секции, unit-скобки, нормализация гранул), widget-тесты лестницы/жестов/делегата (`test_timeline_scale_widget.py`), диалоги типов и селектор (`test_event_types_dialog.py`, `test_event_dialog_types.py`), E2E (`test_e2e_timeline_scale.py`, `test_e2e_event_types.py`: переименование цвета видно в назначении, «назначил Слух — точка в hex токена», drag месяцами → чип с целыми границами); §7: пиксель-приёмка всех восьми `color.chart.k` в обеих темах и live-retheme восьми цветов с сохранением выбора/скролла (grab/pixel), оф-скин-путь делегата на Qt-глобалах (точка типа/UNIT/SECTION без токенов), инвариант `test_no_chrome_hex.py` явно фиксирует `timeline_widget.py` в сканируемом списке

### Дизайн-система W3c: интерактив шкалы — клик-прыжок, follow-дата и drag диапазона по рейке (эпик W: W1/W2 влиты — W2b в main с `4810755`; W3 влит с `8e8c2e6` и переопределён W3b; W3b влит с `289bfa4`; дизайн W3c зафиксирован grill-сессией 2026-08-31, change `refine-event-timeline-scale-w3c`; W3c влит с `eb7640b`, статус фиксируется этим docs-коммитом по факту коммита, как `289bfa4`+`0acc53e` для W3b; база W (W1–W3c) влита — эпик продолжается: W4, W5)

#### Новый функционал
- Рейка перестала быть декоративной: eventFilter, глотавший press/dblclick левее текстовой зоны, удалён; жест рейки живёт в собственных обработчиках view (`mousePressEvent`/`mouseMoveEvent`/`mouseReleaseEvent`/`mouseDoubleClickEvent`, D1). ЛКМ-нажатие при `x < rail_width()` захватывает день под курсором (якорь — первый ряд дня) и не доходит до базового класса — рейка ничего не выделяет и не испускает; при `x ≥ rail_width()` список ведёт себя как раньше (клик/dblclick выбирают и открывают событие)
- Клик-прыжок (D4): release до порога drag'а (`DRAG_START_THRESHOLD_PX = 4`, D2) → `scrollToItem(PositionAtTop)` ставит день верхним рядом под липкую дату, позиция чтения переезжает через selection model с `NoUpdate` (базовый `setCurrentIndex` по команде ещё и выделял бы и не пускал на disabled-заглушку пустого дня) — выделение, `_selected_id` и id-сигналы не тронуты; пустые дни — валидные цели; нажатие против второй строки дня делает верхним первый ряд дня
- Follow-дата (D5): пока курсор в рейке (и всё время drag'а, включая выход за рейку и за пределы списка), sticky-оверлей показывает полную игровую дату дня под курсором; на уход из рейки без drag'а — возврат к дате верхнего ряда. ### Чар-листы A-playable: страницы и каталог типов (незавершённый)

#### Новый функционал
- Страницы без лимита: канвас — вертикальная лента A4 (листы столбиком, как Word, зазор 24 pt) + рейка слева (имя, добавить, удалить, ↑↓ порядок, переименование); новая страница вставляется после текущей с именем «Страница N»; последнюю страницу удалить нельзя, непустую — только с подтверждением; клик по пункту рейки прокручивает канвас к листу, при прокрутке в рейке подсвечивается лист с большей видимой площадью
- **BREAKING относительно A1-редактора**: колесо = прокрутка ленты, Ctrl+колесо = зум (25–400%); при открытии вписывается **ширина** одного листа A4 (не вся лента), первая страница сверху
- Ориентация одна на шаблон: переключение книжная/альбомная меняет размер всех листов, не влезшее зажимается в новый лист без масштабирования
- Перенос поля между страницами: перетаскивание через зазор с дропом на другой лист переносит поле туда (координаты от точки дропа, затем зажим в новый лист); бросок в зазор — поле остаётся на исходном листе; перемещение и ресайз всегда зажаты в **страницу поля**
- Каталог типов расширяется с 3 до 10: чекбокс (квадрат on/off, default выкл, даблклик/панель переключают), число (дроби, запятая → точка, необязательные min/max, не-число и вне границ отвергаются), выпадающий список (упорядоченные опции без пустых, default — на канвасе текст), картинка (рамка-плейсхолдер, выбор/очистка файла через ImageStore текущей игры, даблклик открывает выбор), декоративная рамка (только обводка, данных не хранит) и осевая линия (шире → горизонталь, иначе вертикаль); постановка по-прежнему разовая
- `schema_version = 2` (страница теперь `{name, fields}`): v1-шаблоны читаются без потери (на диск v1 возвращается только после Save), неизвестный тип поля — отказ открыть шаблон с ошибкой, база не меняется
- Картинка поля листа — ссылка на запись `images` (sha256, без пути в JSON): refcount/GC учитывают поля `pages` всех шаблонов: файл снимается только если на него не ссылаются ни сущности, ни поля листов (очистка поля + save, удаление шаблона); нечитаемый файл — ошибка, поле остаётся пустым

#### Инфраструктура
- Domain: `FieldType` +6 значений; геометрия ленты (`page_origin`, `scene_to_page`, GUTTER 24 pt); `clamp_rect` в локале страницы (у линии толщина ≥ 1 pt); парсер v1/v2 (`UnknownFieldTypeError`); `iter_sheet_image_ids` / `null_sheet_image_ids` для GC
- `CharacterSheetService`: create сразу v2 («Страница 1»); load v1/v2 с отказом на неизвестный тип; save всегда v2 + `gc_after_commit` по старым image-id; delete шаблона гоняет GC картинок
- `ImageStore`: `refcount` / `_null_references` / `startup_gc` сканируют `image_id` в `pages`-JSON всех шаблонов (помимо FK трёх сущностей)
- Представление: сцена-лента в одном QGraphicsScene, рейка-виджет, `wheelEvent` (скролл/зум), fit по ширине, per-type секции панели свойств и палитра (указатель + 9 типов)

#### Тесты
- Приёмка каждого типа — фиксированный набор (постановка+select, move, resize+зажим, свойства/default, save/open, книжная→альбомная) + per-type сценарии; E2E: поле на второй странице переживает save/открытие, v1-шаблон после Save пишется как v2; `.nri` roundtrip с картинкой на листе (ссылка в `pages` + файлы `images/**`)

## [0.15.0] — 2026-08-24

### Файловое хранилище изображений с адресацией по sha256 (breaking формат игры)

#### Новый функционал
- Изображения организаций/персонажей/локаций больше не хранятся как base64 в SQLite: файлы (оригинал + preview 512px WebP q80) лежат на диске в `games/<name>/images/`, адресованы по sha256 содержимого; дедупликация в пределах одной игры — одинаковый файл хранится один раз
- Игра — теперь каталог `games/<name>/` (`game.db` + `images/`), а не одиночный `.db`-файл; имя игры = имя каталога
- Полный просмотрщик изображения в приложении: клик по изображению в карточке сущности или по миниатюре в панели деталей открывает окно с оригиналом на весь размер (прокрутка для крупных изображений, закрытие по Esc/кнопке); при отсутствии оригинала показывается preview, при отсутствии обоих — сообщение
- Экспорт `.nri` v2: архив каталога целиком (`game.db` + `images/**` + `meta.json` с `archive_version: 2`); импорт распаковывает во временный каталог и верифицирует sha256 каждого файла `images/**` до атомарного переноса — повреждённый архив отклоняется, ничего не остаётся в `games/`
- Импорт `.xlsx`: столбец `image`/`изображение` идёт через тот же конвейер `ImageStore`, что и карточка сущности; нечитаемый/повреждённый файл не прерывает импорт строки — сущность создаётся без изображения, путь попадает в отчёт как предупреждение

#### Миграция и совместимость
- При первом старте existing игры: плоский `games/<name>.db` переносится в каталог `games/<name>/game.db`; legacy base64-изображения (`image` колонки) переносятся в файловое хранилище построчно (с построчным commit — прерывание не портит уже перенесённое), после переноса — один `VACUUM`
- После каждого открытия игры инвариант хранилища восстанавливается автоматически (`startup_gc`): файлы-сироты без записи в БД удаляются; записи без оригинала снимаются со ссылок и удаляются; отсутствующий preview перегенерируется; неиспользуемые записи с файлами удаляются
- **Принятое ограничение**: экспорт v2 нельзя открыть старой версией приложения без потери изображений (`images/**` тихо игнорируется старым импортом) — обратной миграции `v2 → v1 с base64` не делаем; откат версии приложения для игр с изображениями не поддерживается
- Legacy-колонки `image` в схеме не удаляются (только обнуляются после миграции) — сам drop колонок отложен на будущий релиз

#### Инфраструктура
- `app/infrastructure/images/`: `ImageStore` (ingest с dedup/валидацией через `QImageReader`, `refcount`, `gc_after_commit`, `startup_gc`), path-резолвер (`images/<hash[:2]>/<hash>.<ext>` / `<hash>.preview.webp`), preview-генератор (512px WebP q80, детерминированный)
- Схема: таблица `images` (sha256 UNIQUE, ext, width, height, size_bytes) + `image_id` FK (`ON DELETE SET NULL`) на 3 сущностях; `image_ref` (`lazy="selectin"`) для синхронного доступа из презентационного слоя
- `image_utils`: base64-функции заменены null-safe `load_preview`/`load_original`/`load_entity_preview`/`load_entity_original`, работающими от файлового пути; глобальный `image_dir` игры (мирроринг паттерна `date_utils`)
- GC замены/удаления картинки в `EntityCardDialog` идёт через `EntityService.update_entity_with_relations` (`gc_after_commit` после commit, не во view)

#### Тесты
- 100% построчное покрытие сохранено; новые сценарии: path-резолвер, preview-генератор, ingest/dedup/race, refcount/GC (все состояния + сбои unlink), миграция legacy + `VACUUM`, порядок старта `Application.start()`, каталог-игра (create/list/delete), экспорт/импорт v2 (верификация sha256, конфликт имён, v1-совместимость), полный viewer, ingest/замена/удаление изображения через карточку (E2E), xlsx-импорт изображений (дедуп, битый/отсутствующий файл)

## [0.14.0] — 2026-08-24

### «Сгенерировать сущность»: параллельная генерация всех полей, отмена и видимые ошибки

#### Новый функционал
- Кнопка «Сгенерировать сущность» (✨) в правом верхнем углу форм события и карточки сущности: одним нажатием запускает генерацию всех AI-полей диалога, включая поля с уже написанным текстом (текст учитывается в промте, результат заменяет содержимое поля)
- Генерация всех полей — параллельная, а не последовательная: результат подставляется в поле по факту его завершения, разблокируя только его, остальные продолжают генерироваться
- Кнопка «Сохранить» заблокирована на время любой генерации в диалоге (одиночной и бандла)
- Отмена: во время волны кнопка сущности превращается в ⏹ и отменяет все запросы этого диалога. Отмена не считается ошибкой: диалога об ошибке нет, пришедшие результаты сохраняются, незаполненные поля возвращаются в редактируемое состояние с прежним содержимым
- Изоляция по диалогу: отмена во вложенной карточке прерывает только её запросы — генерация родительского диалога не затрагивается
- Защита от закрытия во время генерации: ESC игнорируется; X / «Отмена» при in-flight запросе — только после подтверждения с предупреждением (отказ — диалог остаётся открытым, генерация продолжается), при запросах только в ожидании ретраев — закрывается без подтверждения, запросы отменяются
- Видимые ошибки: ошибка одиночной генерации показывает диалог-предупреждение с названием поля и причиной (ранее ошибка глоталась молча); завершение бандла с неудачами — один агрегированный диалог со списком неудавшихся полей (одна общая причина — один раз, разные причины — построчно); успешные поля остаются заполненными
- Кнопка сущности активна только когда AI-ассистент «готово», описано описание мира и в диалоге не выполняется другая генерация; на одном диалоге одновременно не более одной волны

#### Инфраструктура
- `LlmService` — параллельное выполнение: `asyncio.Task` на запрос вместо последовательной очереди (очередь, worker, `queue_size`, `start_worker`/`stop_worker` удалены)
- Реестр активных запросов `owner → field_id` (identity-ключ по диалогу): `cancel_all(owner)`, `any_in_flight(owner)`, `count_in_flight(owner)`; `CancelledError` не перехватывается и не конвертируется в ошибки
- `on_phase`-хук `RemoteLlmProvider`: фаза запроса (`in_flight` — отправлен LLM / `waiting` — backoff между ретраями) видна оркестрации диалога
- Пост-сигналы отменённого запроса (ответ «пересёк» линию отмены) в диалоге отбрасываются: ни текст, ни ошибка не применяются

#### Тесты
- Тесты sequential-очереди `LlmService` заменены параллельными (два медленных запроса завершаются быстрее, чем дважды по одному) + тесты реестра/отмены
- Тесты phase-хука провайдера (MockTransport: 503 → 200 даёт `in_flight, waiting, in_flight`)
- E2E-сценарии бандла: старт → частичные результаты → завершение; старт → отмена; старт → ошибка (агрегированный диалог); закрытие в полёте (подтверждение/отказ/тихое); вложенная карточка (отмена не затрагивает родителя)
