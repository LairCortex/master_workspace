# Live-аудит: пришитая полоса связей в сборке с табами (D&D-модуль) — 2026-10-13

Checkpoint 3/4 серии live-проверок `dd-card-redesign`. Профиль: **по умолчанию, модуль
включён** (`python -m app.main` без env-переменной). Метод: реальное приложение,
управление через accessibility (computer-use), только честные жесты и AXPress по
element_id; кнопки ИИ-генерации не нажимались; чужие игры не открывались.

## Окружение

- Игра: `qa-2026-10-13-b` (одноразовая, мир D&D). Персонаж «QA Проверщик» (id=1).
- Экран 2560×1374 pt (Retina), macOS.
- Снимки **сохранены** в `docs/qa/references/2026-10-13-band-*.png` (в этой сессии
  запись экрана из терминальной цепи доступна: `screencapture` работает, TCC выдан).
- Данные, созданные в ходе проверки (разрешено задачей, только qa-игра):
  событие «QA Полоса» (с Characteristics-текстом), предмет «QA Меч»,
  связи `character_item` (Проверщик↔Меч) и `event_item` (Полоса↔Меч).
  Остальные строки каталога не трогались.

## Находки (по убыванию тяжести)

### 1. BLOCKER (render/state) — в карточке персонажа с табами полоса связей и ряд кнопок не отрисованы никогда

Карточка «QA Проверщик» (лист «Карточка: Персонаж», четыре вкладки Основное →
Способности → Личность → Заклинания): лист открывается высотой ≈1141 pt, полоса
групповых табов и контент модуля рисуются, но **внизу окна нет ни пришитой полосы
связей, ни «Сохранить»/«Отмена»** — ни на одном табе. Контент обрывается ровно по
скруглённому нижнему краю листа посреди строки (на «Основное» — таблица Навыков на
полуровне «Медицина», на «Личность» — «Черты характера») без какого-либо признака
прокрутки ниже.

Воспроизведено дважды: **без связей** (после раскатки первой попытки, см. Finding 2)
и **с сохранённой связью** (sqlite: `character_item = 1|1`, предмет «QA Меч») —
поведение идентично. Значит отсутствующая полоса — не «честное отсутствие блока
связей», а сломанное сиденье.

Дерево доступности листа обрывается на `ScrollBar` прокрутки ядра; в листе нет ни
одного узла полосы (табы «Предметы/Локации/Организации», «Привязать существующего»,
«Создать нового», «Отвязать») и ни одного из «Сохранить»/«Отмена» (целевые запросы
`Привязать`, `Сохранить`, `Отмена`, `Закрепить` — 0 совпадений; сканирование
проверяло весь лист — `Добавить …` модуля диалога находится).

Тот же Component в том же рантайме рисуется корректно в двух других сиденьях:
в окне события полоса прибита внизу на обоих табах, а в дочерней карточке предмета
(глубина 1, без табов) раздел связей в конце прокрутки рабочий — им создана и
привязана связь в этом же прогоне. То есть сломано specifically сиденье
`entityRelationsBand` окна карточки с внешними табами.

Направления для интегратора (по коду, без правок):
- `EntityCardRoot.qml`: Loader `entityRelationsBand` (≈697–718, `Layout.maximumHeight:
  root.height / 3`), формула `implicitHeight`/`bandShare` (≈70–90) — запрос размера
  окна с табами;
- `presentation/views/entity_card_dialog.py`: `_refit_for_guest_tabs` на `groupsChanged`
  (≈405) — ре-фит окна по приходу табов; `qml/island_size.py` — измерение natural
  размера и ограничение экраном (`fit_dialog_to_island`). Признаком рассинхронизации
  сцены и окна в логе служат `QQuickRenderControl: beginFrame()/endFrame()` ошибки
  (строки 12–16 лога запуска; та же линия, что в чекпоинте 2).
- Оффскрин-пины чинили только безтабовые сценарии (`test_kernel_*` в
  `tests/presentation/test_card_group_tabs.py`); геометрию band-сиденья с модульными
  табами живой кадр не подтверждает.

Evidence: `2026-10-13-band-character-card-with-relation.png` (связь есть — полосы
нет), `-character-card-osnovnoe.png` (обрезка по краю), `-character-card-zaklinaniya-empty-band-slot.png`
(короткий контент, пустое полотно внизу — полосы всё равно нет), инлайн-кадры всех
четырёх вкладок.

### 2. MINOR (data/ux, OBS) — сущность дочерней карточки «Создать нового» существует в БД до решения родителя и стирается по «Отмена»

Первый цикл: из окна нового события создано «Создать нового» → карточка предмета
«QA Меч» → привязка персонажа → «Сохранить» карточки (commit виден внешним
sqlite-читателем: `items=1, character_item=1|1`). После «Отмена» в родительском окне
события обе строки исчезли. При втором цикле с «Сохранить» события строки пережили
закрытие. Возможно, сознательный каскадный откат созданий сессии — но между
коммитом и отменой данные физически лежали в файле игры; просьба к владельцу
изменения зафиксировать норму (или пин на раскатку).

### 3. MINOR (инструментальный OBS) — нестабильность перечисления a11y-дерева после закрытия листа

Сразу после закрытия окна события один отфильтрованный запрос дерева кратковременно возвращал
его «Сохранить» (узел распускающегося острова), а последующие перечисления большого
дерева карточки обрезались на разных элементах. Для вердиктов использованы
повторные целевые запросы + скриншоты; на judgement это не повлияло.

### 4. INFORMATIONAL — белая полоса внизу экрана не принадлежит приложению

Zoom нижнего края на 2560×1374 показал: слева «светлая полоса» — окно Telegram
(композер «Write a message…») поверх главного окна; справа — тёмный канвас главного
окна со скруглённым углом, белого неокрашенного полотна (Finding 2 чекпоинта 2) нет:
после правки sheet-canvas нижний край чист.

## Что подтверждено позитивно (окно события)

- Полоса пришита внизу: табы «Организации/Персонажи/Предметы/Локации», список
  раздела, кнопки «Привязать существующего» / «Создать нового» / «Отвязать» — над
  рядом «Сохранить/Отмена», под контентом активного таба; **на обоих табах**
  («Основное» и «Встреча»; у нового события «Встреча» есть — штатно по спеке).
- Геометрия: полоса ≈223 pt при окне ≈747 pt → ≈0,30 ≤ ⅓ ✓. «Сохранить»/«Отмена»
  видны и кликабельны прессом (сохранение закрывает лист и пишет событие; отмена
  закрывает).
- Требование 3: выбранный под-таб «Персонажи» + привязанная строка пережили
 туда-обратно «Основное → Встреча → Основное» (value=1 и строка в дереве).
- Привязка «Привязать существующего» → попап «Выберите персонажи» → пресс строки
  привязывает сразу; «Отвязать» disabled при невыбранной строке — штатно.
- `valid` окна события: имя + (характеристики|предыстория) — «Сохранить» disabled
  при пустых обязательных, включается после заполнения; AX `SetValue` доходит до
  модели (PR-016 жив: событие «QA Полоса» сохранилось с именем из value-слота).

## Особые обстоятельства канала ввода

- Зафиксировано известное ограничение: синтетическое колесо/фон-скролл до островов
  не доходит (скролл по содержимому карточки — no-op, кадр не изменился). Своя
  прокрутка полосы поэтому проверена геометрией/деревом и компонентом
  (`RelatedSection.qml`: собственный `ListView` с `boundsBehavior: StopAtBounds`,
  полоса вне основной прокрутки — структурно независима), плюс live-подтверждением
  служит работа списка в окне события; демонстрация скролла с переполнением живьём
  в этом кадре невозможна (строк меньше, чем вмещает список).
- Фоновые AXPress по element_id работают; `type_text` попадает в field (value слот
  обновился), но клавиатурные события (Tab/focus-out) на остров не доставляются.
- Снимки экрана: в этой сессии `screencapture` доступен (в отличие от чекпоинта 2) —
  все ключевые кадры сохранены в `docs/qa/references/`.

Вне чекпоинта: стол, xlsx, LLM, экраны документов.
