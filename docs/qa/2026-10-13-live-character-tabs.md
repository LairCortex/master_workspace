(`python -m app.main`), управление через accessibility (computer-use), только честные
жесты; кнопки ИИ-генерации не нажимались.

## Находки (по убыванию тяжести)

### 1. BLOCKER (regression/state) — на «Основное» нет ни одного модульного блока
Карточка сохранённого персонажа на вкладке «Основное» показывает только ядро
(Название, Рейтинг, даты, Музыка, Личность, Задачи, картинки, реляции Предметы/
Локации/Организации). Отсутствуют: раса/подраcа, класс/подкласс + уровни, таблица
6 характеристик с производными (модификатор, спасброски), прыжок/вес/скорость,
строка двери LSS, кнопка «Дозаполнить ИИ». Accessibility-дерево листа (Sheet, pid
91006) не содержит ни одного из этих контролллов; воспроизводится детерминированно
до и после рестарта. При этом ядро-блок «Характеристики/Предыстория» корректно
СКРЫТ — т.е. канал hide работает, канал блоков пуст.
Направление для интегратора: канал `module_blocks` до QML не доходит —
`app/dd/presentation/character_tab_source.py` / `app/presentation/module_block_host.py`
(проверить репаблиш блоков при первом открытии редаг-карточки).
Оффскрин-тесты механизма вкладок зелёны (37 passed) — ломается содержимое/вайринг, не мост.

### 2. MAJOR (regression/visual) — белая неокрашенная полоса внизу листа карточки
В листе «Карточка: Персонаж» под рядом «Сохранить/Отмена» — чисто-белая
неокрашенная область ~840×390 pt (при окне 2560×1374), с белыми же скруглёнными
нижними углами. Это оконный холст QDialog под QML-островом: нарушена норма
«полотно листа — SHEET surface с первого пикселя, никакая хром-полоса не лежит
поверх хедера/контента» (контракт `modal-sheets`). Белый виден на всех четырёх
вкладках. В логе рядом — ошибки QQuickRenderControl beginFrame/endFrame.
Основание: главный холст QML-острова не растягивается на всю высоту диалога,
нижняя часть окна остаётся нетронутой.

### 3. MAJOR (state/spec-gap) — новая карточка персонажа вообще без вкладок
У ещё не сохранённого персонажа полоса вкладок отсутствует (видны только ядерные
поля) — против сценария спеки «новая карточка с пустыми разделами»
(`openspec/changes/dd-card-redesign/specs/entity-card-tabs/spec.md`).
Причина в коде: `character_tab_source.card_tabs()` возвращает `()` для
`target_id=""`; оффскрин-тест `test_card_module_tab_follows_the_populated_record`
закрепляет ровно это поведение — тест и спека противоречат друг другу, нужна
развязка владельца изменения.

### 4. MINOR (ux) — креш лаунчера при synthetic press под вложенным диалогом
AXPress по строке игры в лаунчере, пока поверх открыт модал «Новая игра», убил
процесс: «QML object was not properly cleaned… Object destroyed while one of its
QML signal handlers is in progress» (LauncherRoot.qml:163). Мышиный пользователь
до строки не дотянется (modal), accessibility-ридер может. Воспроизведено один раз.

### 5. MINOR (ux) — Tab внутри многострочных полей вставляет символ табуляции
В «Внешность» (TextArea) клавиша Tab добавляет `\t` вместо перехода фокуса —
в сохранённых данных осталось «Шрам над левым бровью\t». Для полей сетки ячеек
(TextField) всё штатно: Tab = commit + переход.

### 6. INFORMATIONAL — центральный «DetailPanel» событийно-центричен (НЕ дефект)
Список «Персонажи» в средней колонке пуст даже при существующем персонаже и после
рестарта: хинт «Выберите строку — тут появятся детали» привязан к
`!detailPanelVm.eventSelected` (`DetailPanelRoot.qml:381`) — без выбранного события
панель пуста по дизайну NRI-0015 M4; навигация к сущностям — поиск (проверена:
«QA Проверщик [13 Октябрь 2026]» находится, двойной клик открывает карточку).
Первоначальная гипотеза о «несвежем списке после сохранения» СНЯТА.
Repaint главного окна после закрытия листа штатный (хинты на месте, артефактов нет).

## Особые обстоятельства канала ввода

- Значения полей островов коммитятся по честным пользовательским жестам
  (набор + Tab/focus-out). Программный `SetValue` через accessibility заполняет
  поле визуально, но `editingFinished` не вызывает — модель не обновляется.
  Все проверки персистентности выше выполнены честными жестими и подтверждены
  SQL-срезом `dd_character_ext` + повторным открытием.
- «Заклинания» и «Личность» переживают: переключение вкладок в сессии →
  сохранение → закрытие → повторное открытие → полный рестарт приложения и
  повторный вход в игру.
- Вкладки: ровно 4, порядок Основное → Способности → Личность → Заклинания,
  старых вкладок нет; на «Способности» — дружелюбный пустой стейт без падений.
