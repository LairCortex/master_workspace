## 1. Раскладка 2–4 равных pane-ов

**Разделители — не линия, а «рамка + воздух».** Текущая колонка — это
`CardPanel` (1 px `color.border`, `radius.sm`, канва `color.bg.canvas`) на
острове `color.bg.surface`. Булавка в полосе говорит «это независимые
карточки», поэтому каждый pane сохраняет собственную рамку `CardPanel` —
2 pane = два стека карточки, 1 pane = ровно сегодняшняя колонка (без
визуального скачка при первом закреплении). Специальный 1 px разделитель между
pane’ами отвергнут: он разрушает «карточную» идентичность pane-а и не даёт
ничего поверх рамки.

Числа (токены из `tokens.json`):

| Параметр | Значение | Источник |
|---|---|---|
| Отступ колонки-ColumnLayout | `space.xs` = 4 px | как сегодня у корня |
| Зазор между pane-ами | `space.sm` = 8 px | группировка по близости: полоса ближе к своей канве (`space.xs` = 4 px внутри pane) |
| Полоса заголовка pane-а | 32 px, `PanelHeader.band()` | общая ось колонок (live-fix 2026-09-26) |
| Мин. высота pane-а | 88 px = полоса 32 + 4 + канва ≥ 48 | см. ниже |

Минимальная высота 88 px: 48 px канвы = две читаемые строки body (body =
`font.size.md` + 2 = 15 px, строка ≈ 19 px) плюс отступы Flickable; ниже —
pane превращается в мёртвую полосу. Проверка порога: при 708 px окна
4 pane = 4×88 + 3×8 + 2×4 = **384 px ≤ 535 px** — минимум не выбирается даже на
маленьком окне; он страхует только экстремальный ресайз. Рекомендация owners-стороне:
если у `MainWindow` нет нижнего guard’а высоты — поставить `minimumHeight ≈ 600`
(4 pane ≥ 4×88+24+8 ⇒ окно ≥ ~570). Это не меняет равные высоты.

Полоса заголовка pane-а:
- **Высота** 32 px (`PanelHeader.band()`); первый pane встаёт ровно на общую ось
  заголовков трёх колонок (колонная полоса «Карточка» при pane > 0 исчезает —
  см. п. «Ось заголовков» ниже).
- **Закрепление**: полоса лежит ВНЕ Flickable (структура pane:
  `ColumnLayout { headerBand(32); CardPanel { Flickable } }`) —
  прокрутка контента структурно не может зайти под полосу; «прижатие» не
  требует ни sticky-логики, ни оверлея.
- **Фон при прокрутке**: `color.bg.surface` (цвет корня острова, как сегодня);
  подложка под текстом полосы всегда однотонная, т.к. контента под ней нет.

Ось заголовков: при нуле pane-ов — сегодняшняя полоса «Карточка» + канва с
хинтом; при pane > 0 колонная полоса не рисуется вовсе, её место занимает полоса
первого pane-а («Карточка: <тип>») — той же высоты 32 px и на том же `space.xs`
всоте, поэтому выравнивание трёх колонок по оси (норма 2026-09-26) сохраняется
автоматически. Это же соответствует дельте: «полностью пустая колонка
подписывается словом Карточка», у живых карточек своя полоса — единственная.

Эскиз delegate для реализатора (имена объектово-нейминга — предложены под guard-тесты):

```qml
ColumnLayout {                      // корень острова, margins: space.xs, spacing: space.sm
    // при panes.length === 0: сегодняшняя разметка — полоса TitleText "Карточка"
    //   + CardPanel с previewEmptyHint (без изменений бит-в-бит)
    Repeater {
        model: entityPreviewVm.panes    // закрепления в порядке + живая последней
        ColumnLayout {
            objectName: "previewPane_" + modelData.slotIndex
            Layout.fillWidth: true
            Layout.fillHeight: true
            Layout.minimumHeight: 88
            spacing: Tokens.px(root.islandTokens, "space.xs", 4)

            Item {                      // полоса заголовка, 32 px
                objectName: "previewPaneBand_" + modelData.slotIndex
                Layout.fillWidth: true
                Layout.leftMargin: root.contentPadding   // space.sm = 8
                Layout.rightMargin: root.contentPadding
                implicitHeight: PanelHeader.band()       // 32
                TitleText { /* "Карточка: <тип>" из modelData.title */ }
                ThemeIconButton {
                    objectName: "previewPinButton_" + modelData.slotIndex
                    ghost: true
                    iconName: "pin"      // вендоринг — см. п.3
                    // имя — местом применения, четыре формулировки — см. п.3
                }
            }

            CardPanel {                 // ровно сегодняшний previewCanvas
                Layout.fillWidth: true
                Layout.fillHeight: true
                color: root.canvasColor
                clip: true
                Flickable {             // anchors.margins: 1 + contentPadding
                    boundsBehavior: Flickable.StopAtBounds
                    // содержимое карточки — текущая previewContent 1-в-1
                }
            }
        }
    }
    // пустая живая область под закреплениями (liveEmpty && panes.length > 0):
    // CardPanel БЕЗ полосы, Layout.fillHeight + тот же minimumHeight 88,
    // внутри HintText по центру — см. п.2
}
```

Контракт VM уже готов (`panes`/`liveEmpty`, группа VM переписана). Одно
необходимое дополнение контракта — см. п. 3 про `pinState`.

## 2. Пустая живая область

- **Рамка остаётся**: пустая живая область — это `CardPanel` (1 px
  `color.border`, `radius.sm`, канва `color.bg.canvas`) **без полосы заголовка**
  (дельта entity-preview: «пустая живая область SHALL не иметь собственной
  полосы»). Рамка даёт аффорданс «слот под карточку» и отличает её от голого
  фона: закреплённый pane всегда имеет полосу «Карточка: <тип>» с булавкой,
  пустая живая — только рамку и текст. Пустой закреплённый pane невозможен по
  жизненным правилам, путаницы нет.
- **Текст** — ровно из дельты: «Выберите сущность — здесь появится её
  карточка» (в текущем QML старый текст «…в среднем столбце…»; менять его —
  работа реализатора). Тот же текст и в полностью пустой колонке.
- **Оформление**: `HintText` — `color.fg.muted`, `font.size.md` (13 px),
  italic (как сегодня). Контраст muted на канве: **4,98:1 (light) / 5,68:1
  (dark)** — выше 3:1 для не-текста и близко к 4,5:1 для текста; допустимо
  (это второстепенная подсказка, не контент; эталон — сегодняшняя пустая
  колонка, живой аудит не жаловался).
- **Центрирование**: `anchors.centerIn` канвы, но в отличие от сегодняшнего
  однострочного `HintText` (elide) — включит `wrapMode: Text.WordWrap`,
  `horizontalAlignment: Text.AlignHCenter`, ширина = канва − 2×contentPadding,
  до 3 строк. На колонке ≈420 px (окно 1028) текст влезает в 1–2 строки; на
  минимальной ширине pane 220 px elide съедал бы половину фразы — обёртка
  обязана.
- Пустая живая область участвует в равных высотах на тех же правах:
  `Layout.fillHeight: true` + `Layout.minimumHeight: 88` (spec-сценарий
  «Первое закрепление делит колонку» = 50/50).

## 3. Булавка в полосе заголовка

- Компонент: `ThemeIconButton` (квадрат 32×32, `ghost: true`) — ровно как
  шеврон шкалы NRI-0023: роль `Button` и Press принадлежат компоненту, имя —
  месту применения. Полоса 32 px = квадрат 32 px, кнопочный квадрат встаёт в
  неё точно, без нахлёста (нахлёст допустим только у ghost по нормe Д12, здесь
  он и не нужен). Посадка: `anchors.right: parent.right`, полоса уже имеет
  `rightMargin = contentPadding (8)` ⇒ правый край булавки на 8 px от края pane,
  как контент карточки; вертикаль — `verticalCenter` полосы.
- **Глиф**: в вендореном `icons.js` имени «pin» НЕТ (есть «map-pin»,
  «bring-to-front» — оба не то). Реализатору: добавить Lucide `pin` через
  `scripts/vendor_lucide.py` (генерируемая карта), имя `name: "pin"`.
  Никакого второго пути глифов быть не должно.
- **Имена (ровно четыре, Д5), пинятся guard-тестом соглашений**:
  - `!pinned` и можно → «Закрепить карточку», enabled;
  - `pinned` → «Открепить карточку» (ровно спекинская формулировка), enabled;
  - живая копия уже закреплённой → «Уже закреплена», disabled;
  - три закрепления и живая → «Можно закрепить только 3 карточки», disabled.
  Те же строки — `Nri.tooltip` (в дерево не попадает — известный предел ④).
  `Accessible.description` не заполняется (имя называет действие;
  `DESCRIPTION_VOCABULARY` не расширяется).
- **Неактивное состояние при призрачном лице**: `ThemeButton.ghost` даёт
  прозрачный фон в любом состоянии, а `iconTint` на disabled —
  `color.fg.muted`. То есть неактивная булавка = серый глиф без всякой
  подложки; активная = глиф `color.fg.primary`. Контрасты глифа на полосе
  (`color.bg.surface`):
  - active: **16,3:1 (light) / 11,4:1 (dark)**;
  - disabled: **5,6:1 (light) / 4,9:1 (dark)** — оба выше 3:1 (WCAG 1.4.11 для
    UI-компонентов); различие active/disabled видно по яркости глифа.
  Hover у ghost-лица сознательно нет (норма Д12 после живого аудита 2026-09-30:
  собственное лицо ghosts-набора запрещено) — ответ hover = tooltip, как у
  шеврона. Курсор-стрелка сохраняется как у всех icon-кнопок библиотеки.
  Закрашивать «закреплённое» состояние не стоит — призрачное лицо не имеет
  права на собственный цвет, а различие уже есть в порядке (закрепления выше,
  живая ниже) и в имени.
- Откуда QML берёт состояния: `pane()`-словарь VM содержит `pinned`,
  `entityType`, `entityId`, `slotIndex` — этого достаточно, чтобы отличить
  «Открепить» от всего, и «Уже закреплена» (живая пара совпадает с закреплённой
  парой в `panes`), и лимит (счёт `pinned == true` в кадре ≥ 3). Рекомендую
  добавить в `pane()` одно поле `pinState: "unpin" | "duplicate" | "limit"`
  (для живой карточки), чтобы строка-четвёрка и её guard жили в одном месте
  рядом с VM, а не в QML-ветвлении. Выбор VM vs QML — за реализатором;
  запрет один: не вычислять «3» в двух местах.

## 4. Доступность / пределы координатности

- Новый интерактив ровно один — булавка: штатный `Button`-seat `ThemeIconButton`
  (роль+нажатие в компоненте), имя — 4 фиксированные формулировки местом
  применения. Offscreen-пин `doAction("Press")` по образцу
  `test_theme_checkbox_accessibility.py`; строки — в guard `DESCRIPTION_VOCABULARY`
  не идут (это имена, не descriptions).
- Полоса заголовка и `HintText` — не-интерактив; в дереве остаются StaticText
  подписями (не «безымянный мусор» — текст есть).
- Полосы прокрутки pane-ов — нативный `Flickable` без фокус-стопа: не новые
  узлы дерева; клавиатурная работа с длинным текстом pane-а — текущий статус
  одиночной колонки, новых дыр не появляется.
- Шесть зафиксированных пределов координатности не расширяются: булавка
  адресуется id + именем, pane-ы — структура, а не цели.
- `objectName`-контракты для тестов: `previewPane_<slotIndex>`,
  `previewPaneBand_<slotIndex>`, `previewPinButton_<slotIndex>`,
  `previewLiveEmptyHint` (отличается от сегодняшнего `previewEmptyHint` для
  полностью пустой колонки — оба живут одновременно в разных состояниях).

## 5. UX-трение: читаемость при 3–4 pane-ах на окне ~708 px

Арифметика от живого замера (хром 165 px, нижний 8 px, зазоры 8 px):

| pane-ов | pane | канва | что видно без прокрутки |
|---|---|---|---|
| 1 | ≈ 527 | ≈ 491 | карточка целиком по большей части |
| 2 | ≈ 263 | ≈ 227 | identity-полоса целиком |
| 3 | ≈ 175 | ≈ 139 | name + рейтинг/даты/возраст справа от картинки (4 строки ≈ 88 px влезают) |
| 4 | ≈ 131 | ≈ 95 | только имя + 2–3 строки фактов; картинка 4:3 (≈205×273 на колонке 420 px) целиком НЕ влезает никогда |

Пороги/компромиссы в рамках равных высот (менять равные высоты нельзя — принято):

1. **Минимум pane 88 px** (п.1) — гарантирует, что pane не схлопнется в
   нечитаемую щель даже при экстремальном ресайзе; на типовых 708 px не
   достигается, это страховка.
2. **Правило верхнего среза**: раскладка identity-полосы (картинка слева,
   короткие поля справа) уже даёт максимум смысла в верхних 95 px — имя,
   рейтинг, даты, возраст стоят справа от картинки и читаются на 4 pane без
   скролла, при условии что имя не съедает всю колонку: у `previewName`
   оставить `wrapMode: WordWrap` как есть, но на pane’ах с канвой < 110 px
   допустимо ограничить имя 2 строками (`maximumLineCount: 2` + elide) —
   иначе длинные имена вытесняют рейтинг/даты за срез. Это единственная
   правка читаемости, которую рекомендую завязать на высоту (VM не трогает,
   QML-свойство делегата).
3. **Скролл обязателен как норма, не как деградация**: при 4 pane почти любая
   карточка длиннее вьюпорта — это принятая цена равных высот (Risks в
   design.md). Колонка растёт с окном; на типовом сохранённом фрейме этой
   машины (1374 px) 4 pane = ≈ 295 px каждый — нормально.
4. Окну — рекомендуемый `minimumHeight ≈ 600` (см. п.1), чтобы минимальные
   pane-ы никогда не обрезались сплиттером.

## Резюме решений для реализатора

1. ColumnLayout: pane = 32 px полоса `PanelHeader.band()` + `CardPanel` с
   личным `Flickable`; зазор между pane-ами `space.sm` (8), внутри pane
   `space.xs` (4), минимум pane 88 px; без отдельных разделительных линий.
2. Колонная полоса «Карточка» только при нуле pane-ов; при pane > 0 ось
   колонок занимает полоса первого pane-а.
3. Пустая живая область = `CardPanel` без полосы + `HintText`
   «Выберите сущность — здесь появится её карточка» по центру с переносом,
   равной высоты с pane-ами.
4. Булавка = `ThemeIconButton ghost 32×32` справа полосы, глиф Lucide `pin`
   (довендорить через `scripts/vendor_lucide.py`), 4 фиксированных имени,
   disabled = muted-глиф без подложки; описания нет; контрасты проверены
   (≥ 4,9:1 во всех состояниях).
5. VM: дополнить `pane()` признаком состояния булавки живой карточки
   (`pinState`), чтобы четверка имён и лимит имели одно место.
