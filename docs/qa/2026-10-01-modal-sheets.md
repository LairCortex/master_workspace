### Находки прогона

- **F1 (major, a11y/state) — посадка стола недосягаема без мыши, стол нельзя запустить.**
  В листе «Стол» строка посадки проецируется в дерево доступности только как
  `StaticText "QA-Игрок"` — узла `CheckBox` в дереве нет (фильтр `CheckBox` — 0 совпадений),
  с клавиатуры чекбокс не достижим: Tab из списка перескакивает его, Space на выбранной строке
  не переключает. Обещание TB3-ремонта в `panel.py:213-216` («an accessibility tool can press an
  actual checkbox») на живой cocoa-проекции не выполнено. Следствие: без посадочного места
  `EmptySeatingError` («Нет посадки») — живой кластер проверить нечем.
  Рекомендация: вернуть чекбоксу адресность (нативный checkable-делегат с Accessible-прессом
  либо узел чекбокса в дереве + focus policy), запинить оффскрин-тестом.
- **F2 (major, consistency) — закрытие листа выглядит по-разному в двух семействах.**
  QML-листы (EventDialog, карточка) несут глиф «✕» (`ThemeSheetHeader`, имя в дереве «Закрыть»),
  виджетные SheetFrame-листы (мастер, Обзор мира, Документация, Changelog, LLM, Сменить игру,
  Стол) — словесную кнопку «Закрыть». Контракт по дереву выполнен (имя всегда «Закрыть»), но
  формулировка AGENTS «виджетная шапка стилизована one-to-one с QML-шапкой» визуально не бьётся:
  это два разных аффорданса. Рекомендация: унифицировать глиф/подпись или зафиксировать
  различие в норме окон.
- **F3 (minor, consistency) — дубль заголовка в «Обзоре мира»:** под строкой шапки «Обзор мира»
  контент снова начинается с подписи «Обзор мира». Одна из двух избыточна.
- **F4 (minor, layout) — мастер календаря на высоком окне:** между сеткой превью и футером
  «Применить» — пустая полоса ~330 pt (тело прижато к верху, футер к низу). Прокрутки нет,
  контент не режется — косметика на растянутом окне.
- **F5 (suggestion, ux) — два «Закрыть» в листе LLM** (в шапке и в футере «1 из 8») — легально по
  контракту (футер сохранён), но дублирование стоит осознать.

- **H1.** Синтетические координатные клики computer-use («in background») не долетают до контента

### Находки прогона

- **A1 (major, a11y/состояние) — строки без «activation»-обработчика: AXPress молчит,
  единственное мышиное действие (выбор строки) читателю недоступно.** `RowItem` принципиально
  зеркалит прессом двойной клик («accessibility has no double press», RowItem.qml:55-61);
  в местах использования без двойного клика это ломается:
  * рельсы связей EventDialog/карточки (`RelatedSection.qml:44-54` соединён только
    `onSelectedRequested`) — AXPress строки «QA-Организация» не выделяет, «Отвязать» не
    активируется; синтетическая мышь не долетает (H1) → поток «выделить → Отвязать» для
    читателя закрыт;
  * строки окна «Чар-листы» (`SheetListRoot.qml:144-155`: «Double-click stays unwired»
    — сознательно) — AXPress строки «QA-Персонаж» не выделил и не открыл редактор; гейты
    «Открыть/Переименовать/Удалить» не включились.
  Координатным пределом НЕ является (role+name адресуемы, предел ⑤ как обычно) — но
  семантика выделения не имеет accessibility-пути. Рекомендация: на этих местах использования
  повесить `Accessible.onPressAction` = выбор строки (паттерн DetailPanelRoot.qml:90) либо
  добавить строкам focus + Enter; запинить оффскрин доAction("Press").
- **A2 (подтверждение/уточнение F1, major) — чекбокса посадки нет в дереве.** Raw-дамп листа
  «Стол» (17 узлов, роли+subrole+desc): `AXList → AXRow → AXStaticText «QA-Игрок»` — имя
  строки через AccessibleTextRole доехало, но `AXCheckBox` отсутствует целиком: QCheckBox из
  row-widget (`panel.py:232`) cocoa-проекцией не публикуется, обещание TB3 («an accessibility
  tool can press an actual checkbox», panel.py:213-216) на живом дереве не выполнено.
  AXPress строки молчит (select-обработчик живёт только у press чекбокса/вьюпорта),
  Tab чекбокс минует (см. отчёт window-layout). Следствие: без мыши не посадить → «Нет
  посадки» → **живой кластер на дисплее не проверяем** (контракт «Остановить стол» /
  «Стол · N игроков» + `d=Открывает пульт стола` остаётся оффскрин-пином группы 5.2).
  Рекомендация та же, что в F1: адресный checkable-узел (нативный делегат с Accessible-прессом
  или focus-политика + имя «Посадка: <игрок>») + оффскрин-пин.
- **A3 (minor, ux/состояние) — пикер «Выберите <тип>» недосягаем и молчит.** Кнопка
  «Привязать существующего» всегда enabled, а обработчик при пустых кандидатах молча
  выходит (`event_dialog.py:620-621`, `entity_card_dialog.py:736-737`): в QA-игре единственная
   организация уже привязана → пресс (доведённый до обработчика) без единого фидбека. Сам лист
  «Выберите <тип>» на живом дереве не наблюдался (для кандидатов нужна вторая сущность —
  создание данных выходило за минимальный след прогона); его шапка — тот же SheetFrame,
  «Закрыть» коего проверен на восьми листах. Рекомендация: гейтить enabled кнопки по
  `candidates()` или показывать «нет доступных».
- **A4 (minor, a11y) — безымянные заполняющие ячейки календарных сеток.** В предпросмотре мастера
  четыре `AXButton` без имени (disabled), в попапе даты — четыре `AXButton` без имени
  (хвостовой padding строки grid): VoiceOver читает безымянную кнопку; в попапе
  disabled-пометка не видна. Рекомендация: `setAccessibleName` в духе «пусто» либо не
  создавать узлы-заглушки.
- **A5 (suggestion, a11y) — безымянные `AXScrollBar`** у скроллируемых островов (карточка,
   Документация/Changelog, xlsx, пресет-окно). Роль есть, имя в слоте пустое (macOS-норма —
  скроллбары безымянны) — фиксируем как наблюдение, контрактного словаря для них нет.

- **HANG-1 (critical, пользовательское репро 2026-10-02) — зависание «Сменить игру…» → «Новая игра».**
  Внутри открытой игры: меню → «Сменить игру…» → «Новая игра» → UI замирал. Причина:
  `_on_game_selected` (`app/main.py`) снимает стек листов и закрывает старое `MainWindow`
  до показа замены; в безоконный момент Qt на живом qasync-цикле применял правило
  quit-on-last-window-closed: `lastWindowClosed` → `quit()` → `run_forever()` возвращался
  посреди пересборки, задача смены не возобновлялась (ни нового окна, ни мастера). Оффскрин
  набор этого не видел: на pytest-asyncio цикле `quit()` инертен. Исправлено в композиционном
  корне: правило приостанавливается на безоконный участок и восстанавливается, когда новое
  окно на экране (`finally`); остальные выходы не затронуты. Пиновка:
