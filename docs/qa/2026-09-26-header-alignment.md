# Живой аудит 2026-09-26 — выравнивание шапок трёх колонок главного окна

Правка по явной просьбе пользователя: шапки трёх панелей главного окна не
лежали на одной горизонтальной линии. Решение — «среднее»: одна общая
шапочная полоса и одинаковый верхний отступ для всех трёх колонок, надпись
центрируется **посередине** полосы (ни к верхней, ни к нижней границе).

Проверялось на живом экране (computer-use, реальное окно) и закреплено
оффскрин-тестами (pytest-qt), как требует AGENTS.

## Как воспроизводилось

- Запущено `python -m app.main`, открыта **одноразовая** игра `qa-2026-09-26`
  (без AI-кнопок, без касания реального LLM-эндпоинта).
- `get_app_state` + `screenshot`/`zoom` подтвердили симптом: строка вкладок
  «Организации / Персонажи / Предметы / Локации» в средней колонке заметно
  ниже обеих текстовых шапок.
- Точные числа сняты оффскрин-щупом: три фасада (`TimelineWidget`,
  `DetailPanel`, `WorldSnapshotWidget`) собраны в один ряд, как в
  `main_window` (QSplitter), каждый `QQuickWidget` со своим `y=0`; центры
  считаны как `mapToScene(0,0).y + height/2` (координаты столбца ==
  координаты сцены, боковой сдвиг колонок не влияет на вертикаль).

## Замеры ДО (островные координаты, pt; верх острова = 0)

| Колонка | Элемент шапки | y | h | центр_y |
|---|---|---|---|---|
| Таймлайн | текст «Таймлайн событий» | 11.0 | 17.0 | **19.5** |
| Обзор мира | текст «Обзор мира» | 4.0 | 17.0 | **12.5** |
| Детали (без события) | подпись вкладки (`detailTab` caption) | 53.0 | 16.0 | **61.0** |

Разброс центров: **19.5 / 12.5 / 61.0** (крайние различаются на 48.5 px).
Причина по коду: `timelineTitle` уже центрирован в полосе 32 px (y=4..36,
chip/кнопка тоже h=32); `snapshotTitle` стоит первым элементом layout без
полосы → жмётся к верхнему margin (центр 4+8.5=12.5); в DetailPanel перед
вкладками идут `detailTitle`+`detailDate`, которые **при пустом событии
пусты, но занимают высоту строки** и с двумя spacing'ами уводят полосу
вкладок на центр 61.

Дополнительно: chip «Все дни ▾» и кнопка «+» имеют h=**32**; полоса вкладок
(`detailTabBar`) имеет h=**32** — обе ровно по калибру NRI-0018.

## Выбранное «среднее» общее значение

Одна общая шапочная полоса **32 px** под общим верхним отступом **4 px**
(`space.xs`) → вертикальная **ось на y = 20 px**, надпись центрируется на оси
(внешний вид, который у таймлайна был изначально).

Почему 32, а не больше/меньше: и чип таймлайна, и полоса вкладок деталей уже
имеют ровно 32 px по живой и оффскрин-проверке — полоса вкладок входит в
полосу целиком, центр подписи совпадает с осью без запаса. 32 — уже
установленный калибр приложения (общая 32×32 `ThemeIconButton` и 32-px
nav-band календаря из NRI-0018). Верхний отступ — свой `space.xs` каждого
острова (все три уже = 4). Число вынесено в одно место — `panelHeader.js`
(`function band() { return 32 }`), по принципу AGENTS «одно знание — одно
место».

## Правки

QML (только `presentation/qml`, поведение VM не тронуто):

- `app/presentation/qml/nri/components/panelHeader.js` — **новый**: общий
  home константы полосы (`.pragma library`, `band() == 32`), комментарии.
- `TimelineRoot.qml` — шапочный `Item` перешёл с литерала `implicitHeight: 32`
  на `PanelHeader.band()` (то же значение); добавлен `objectName`
  `timelineHeaderBand` (для адресации в тестах).
- `WorldSnapshotRoot.qml` — «Обзор мира» завёрнут в `Item`-полосу
  `snapshotHeaderBand` (32 px, тот же margin 4), заголовок на
  `anchors.verticalCenter`; анкоры вместо вложенного layout — caption
  обрезается по краю панели, как заголовок таймлайна.
- `DetailPanelRoot.qml` — `detailTitle`/`detailDate` получили
  `visible: detailPanelVm.eventSelected` (пустые строки уходят из
  ColumnLayout, а не занимают место); `ThemeTabBar` завёрнут в
  `Item`-полосу `detailTabBand` (32 px) и посажен на
  `anchors.verticalCenter`. При выборе события блок шапки растёт **только
  вниз** (заголовок→дата→полоса→панель), полоса не уезжает ни вверх, ни
  врозь.

Пакет/спека (обязательны, т.к. бандл QML — данные):

- `nri_manager.spec` — явная `datas`-запись на `panelHeader.js`
  (директория `nri.components` — данные, их нет в PYZ; каждый файл
  перечисляется).
- `tests/test_spec_qml_bundle.py` — `panelHeader.js` добавлен в
  `EXPECTED_COMPONENT_FILES` (тест требует и наличия файла, и его
  `datas`-записи — иначе не проходит).

Тесты:

- `tests/presentation/test_panel_header_band.py` — **новый**: (1) три
  центра надписей (текст таймлайна, текст обзора, подпись вкладки деталей)
  лежат на оси 19.5..20.5 в пределах 1 px и на оси полосы; (2) каждая
  колонка кладёт шапку на общую полосу: `band`=32 под margin=4, пустые
  meta-строки невидимы, полоса вкладок заполняет свою полосу целиком; (3)
  выбранное событие растит блок шапки вниз в порядке заголовок→дата→полоса,
  пересечений нет (детерминированно через `qtbot.waitUntil` — перераскладка
  ColumnLayout асинхронна); (4) константа живёт в одном месте: все три
  корня импортируют `panelHeader.js` и нигде не переобъявляют приватный
  `implicitHeight: 32`.

## Ограничение метода

Фоновый ввод клавиш/координатный клик computer-use не доходят до MouseArea и
валидации QML-полей (не поднимается `Сохранить` в карточке), поэтому
состояние «событие выбрано» для живого замера получено через поиск по
одноразовой игре с существующим событием (`qa-2026-09-25d`), а не созданием
нового события кликами. Это методическая пометка к способу получить замеры,
не дефект интерфейса.
