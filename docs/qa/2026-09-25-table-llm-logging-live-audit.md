Диагноз уточнён по исходникам Qt 6.10 (`qquickaccessibleattached.cpp`, `qquicktextinput.cpp`):
живой cocoa обнуляет `Accessible.name` password-поля в момент подключения AT, а fallback-подпись
поле держит из `placeholderText` — поэтому Name-слот и показывал подсказку. Фикс: подпись поля
объявлена константой корня `apiKeyFieldName: "Ключ API"`, и `Accessible.name`, **и**
`placeholderText` связаны ей (placeholder теперь и есть подпись), а пояснение вынесено в
отдельный текстовый узел `apiKeyHint` («Необязательно для локальных серверов.») — ни один
читаемый AT слот больше не содержит подсказку.
Оффскрин-пины: существующий `QAccessible.Name == "Ключ API"`
(`tests/presentation/test_llm_setup_island.py`) + новый
`tests/presentation/test_llm_setup_pair_layout.py::test_key_api_field_name_is_the_caption_not_the_hint`
(Name == подпись, placeholder == подпись и без подсказки, hint живёт своим узлом); половина
«cocoa обнуляет name» остаётся live-only проверкой (зафиксировано в докстринге теста).
Живой прогон дважды (открытие из меню, повторное открытие): дерево отдаёт
`TextField "Ключ API"` — раньше `TextField "Ключ API — необязательно для локальных серверов"`.
