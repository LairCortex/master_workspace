## F4 — креш лаунчера: accessibility-press по строке игры под вложенным системным диалогом

- **Класс:** MINOR (ux / crash). Синтетический пресс (`AXPress`) обходит модальность.
- **Сценарий:** лаунчер открыт → «Новая игра» (или «Импорт»/«Удалить») поднял вложенный
  системный диалог (`QInputDialog`/`QFileDialog`/`QMessageBox`, свой `exec()`-цикл внутри
  QML-обработчика) → accessibility-ридер посылает `AXPress` по строке существующей игры
  ПОД этим диалогом → срабатывает активация строки → `gameSelected` → хост закрывает
  лаунчер ВНУТРИ вложенного цикла → отложенный релиз острова исполняется под живым
  QML-обработчиком.
- **Симптом:** `QML object was not properly cleaned… Object destroyed while one of its
  QML signal handlers is in progress` (`LauncherRoot.qml:163`); SIGABRT в
  `QQmlData::destroyed` на деструкторе `QQuickAbstractButton` (та же сигнатура, что в
  `~/Library/Logs/DiagnosticReports/Python-2026-10-14-0037*.ips` / `…0038*.ips`).
- **Мышиный пользователь** до строки не дотянется (модальность блокирует указатель);
  accessibility-ридер — может. Воспроизведено живьём.
- **Файл/место правки:** `app/presentation/views/game_launcher_dialog.py` —
  `GameLauncherContent._request_shielded()` + шлюзы в `_on_open_requested`,
  `_on_create_requested`, `_on_import_requested`, `_on_delete_requested`,
  `_on_theme_toggle`.
- **Статус: РЕШЕНО в этой сессии.** Каждый контроллерный запрос отвечает no-op, пока над
  экраном активен ЧУЖОЙ модал/попап (`QApplication.activeModalWidget()/activePopupWidget()`
  не равен собственному окну); собственная `exec()`-модальность лаунчера-первого-экрана
  вложенностью не считается — экран остаётся живым. Оффскрин-пины:
  `tests/presentation/test_launcher_request_shield.py` (чужой модал → no-op; own-frame →
  открыт; попап → no-op; каждый запрос no-op под модалом). Живая самопроверка 2026-10-14:
  экземпляр на этом дереве не упал при открытии карточки через accessibility.

## F5 — Tab внутри многострочных полей вставляет `\t` вместо перехода фокуса

- **Класс:** MINOR (ux). Штатное поведение `TextArea` против ожидания пользователя.
- **Сценарий:** карточка персонажа → многострочное поле (напр. «Внешность» на «Личность»,
  ядерные «Личность»/«Задачи») → нажать Tab → в текст вставляется символ табуляции вместо
  перехода фокуса на следующий контрол. В сохранённых данных остаётся «…\t».
  Для полей сетки ячеек (`TextField`) всё штатно: Tab = commit + переход.
- **Файл/место:** библиотека `app/presentation/qml/nri/components/ThemeTextArea.qml:8`
  (голый `TextArea` без `Keys.onTabPressed`) — единая точка, чинится один раз для всех
  многострочных полей островов.
- **Ожидаемо:** Tab (и Shift+Tab) переводят фокус вперёд/назад по цепочке, как у `TextField`.
- **Статус: ОТКРЫТО.** Не входит в чекапанте 2/4 (косметика ввода), не блокирует требования
  спеки. Правка библиотечная — требует отдельного изменения с пином перехода фокуса
  (паттерн `Keys.onTabPressed: <focus-forward>`; сверить с поведением `ThemeField`).
  Не чинится здесь, чтобы не смешивать с правками находок 1–4 того же аудита.

## F6 — выбранный под-таб раздела связей сбрасывается при повторном открытии карточки

- **Класс:** MINOR (ux / состояние). Наблюдение владельца по итогам live-проверок
  `dd-card-redesign`; в требованиях спеки закреплён только round trip внутри
  открытой карточки («Смена таба не сбрасывает выбранный под-таб раздела связей»,
  ПРОВЕРЕНО живьём — `docs/qa/2026-10-13-live-relations-band.md`, требование 3).
- **Сценарий:** карточка сущности → раздел связей: выбрать под-таб (напр.
  «Локации») → закрыть карточку → открыть ту же карточку заново → полоса связей
  стартует с первого под-таба, выбор прошлого сеанса не восстановлен.
- **Файл/место:** `app/presentation/qml/EntityCardRoot.qml` (`relatedTabMirror` —
  состояние корня острова живёт ровно одну сессию диалога); при желании сохранять —
  это посадочное место (сверять с позой памяти вкладок `activeGroup`).
- **Ожидаемо?** Решение продукта: штатная поза окон изменения — «листы не помнят
  размещение», но память под-таба — состояние контента, не размещения. Не чинится
  здесь: наблюдение вне требований чекапанте, правка требует решения владельца и
  отдельного пина.
- **Статус: ОТКРЫТО (задокументировано по указанию владельца, правка не входит в
  `dd-card-redesign`).**
