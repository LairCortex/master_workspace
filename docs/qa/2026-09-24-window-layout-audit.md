# Аудит окон, раскладки и переходов — 2026-09-24

Метод: живой прогон `python -m app.main` через computer-use (дерево доступности + скриншоты + zoom),
одноразовая игра `qa-2026-09-24`; карта переходов дополнительно сверена с исходниками
(`app/main.py`, `app/presentation/**`). Отладочные врезки в код не коммитились, рабочее дерево чисто.
Номера FI-1…FI-6 — дефекты вчерашнего аудита (`2026-09-23-accessibility-audit.md`).

## Найденные проблемы

### Мастер календаря (первый запуск) — W-серия

- **W1 (макет, критично).** Панель «Предпросмотр»: строка дней недели («Понедельник…Воскресенье»)
  висит посреди панели, а числа прижаты к самому низу — между ними пустая зона примерно в 4 строки.
  Шапка визуально оторвана от сетки дат; правый столбец «Воскресенье» впритык к границе.
- **W2 (логика/доступность, критично).** Press по радио «Кастомный» через доступность переворачивает
  только галочку: обработчик `clicked → choose_kind` не вызывается (проверено отладочной врезкой —
  `choose_kind` не срабатывает ни разу), VM остаётся на «Стандартный»: «Далее» вечно выключена,
  «Применить» продолжает вести себя как для стандарта. Через обычную мышь путь, вероятно, живёт
  (оффсик-приёмка `tests/ui/test_e2e_custom_calendar_acceptance.py` проходит), но контракт
  доступности (`QAccessible … doAction("Press")`) для радио мастера мёртв — нужен оффсик-пин и
  подключение `toggled` вместо/наряду с `clicked`.
- **W3 (FI-6 воспроизведён).** «Применить» на первом запуске: в консоль qasync падает
  `RuntimeError: Cannot enter into task … ApplicationWiring._run_locked … while … Application.start()`;
  пользователь не видит НИЧЕГО — диалог остаётся открытым, ошибка только в логе.
- **W4 (макет).** При ширине 1477 pt левая половина 1-го шага пуста (текст+радио прижаты влево),
  кнопка «Отменить» улетает вправо к границе панели предпросмотра и стоит строкой ниже
  «Назад/Далее/Применить» — выглядит как кнопка предпросмотра, а не мастера.
- **W5 (мелочь).** Числа предпросмотра выглядят «серыми/отключёнными» — нечитаемый контраст
  для сетки, которая и так интерактивна=False.

### Главное окно — M-серия

- **M1 (обрезка, важно).** При дефолтной ширине 1028 pt вкладки панели деталей показываются
  «Орган… Перс… Пред… Локац…» — ни одна подпись не читается целиком (полные имена есть только в
  дереве доступности). Нужны min-ширина, короткие подписи или тултип при elide.
- **M2 (обрезка).** Поле «Дата:» снимка мира: «24 Сентябрь 20…» — год отрезан.
- **M3 (FI-1 подтверждён живьём).** Поле «Дата:» целиком отсутствует в дереве доступности
  (запрос «Дата» → 0 элементов); то же с полями дат в EventDialog/карточке — роль/имя недоступны.
- **M4 (непоследовательность).** Таймлайн («Событий ещё нет») и обзор мира
  («Выберите дату и нажмите „Показать“») имеют заглушки, а пустая панель деталей —
  абсолютно пустой прямоугольник без единой подсказки.
- **M5 (поведение окон).** Геометрия окон не сохраняется: главное окно каждый запуск открывается заново
  (0;30) размером 1028×708, мастер — 1477×648; `saveGeometry/restoreState` в коде нет.
- **M6 (мелочь).** Иерархия дерева доступности главного окна странная: «Показать/Сброс/Показать всё»,
  TabGroup и «Добавить событие» висят дочерними у кнопки «Найти» (следствие встраивания QML-островов).

### EventDialog (лист) — E-серия

- **E1 (формат).** Заголовок «Новое событие» существует только как `windowTitle` невидимого окна:
  на экране — лист без шапки (в дереве — безымянный `Sheet`). При стеке листов (событие поверх,
  карточка сверху) пользователь не видит, какой слой активен, и title главного окна не меняется.
- **E2 (выравнивание/текст).** Метка «Предыстория *» без двоеточия, тогда как все соседние строки —
  «Название *:», «Дата начала *:», «Тип:», «Характеристики *:».
- **E3 (принадлежность элемента).** Кнопка «Сгенерировать: Событие» (✨) висит между
  «Предысторией» и вкладками справа, без подписи и визуальной связи с полем — непонятно, чья она.
- **E4 (макет).** У комбо «Тип:» стрелка индикатора отрисована вне рамки поля, в углу сверху-слева
  («▼» поверх границы) — выглядит как артефакт.
- **E5 (хорошо).** Даты «24 Сентябрь 2026» полные, чекбокс «Бессрочно» на месте, лист целиком
  влезает в 1028×708 без скролла и обрезков; «Сохранить» корректно выключена до заполнения.

### Карточка сущности (лист создания) — C-серия

- **C1 (ошибка имени, важно).** AI-кнопка в карточке ПЕРСОНАЖА подписана «Сгенерировать: Событие»
  (`EntityCardRoot.qml:118` fieldLabel: "Событие" — копия из диалога события). В карточке нет
  «события» — имя вводит в заблуждение.
- **C2 (FI-4 подтверждён).** Кнопка правки музыки — `Button "✎"` без нормального имени.
- **C3 (непоследовательность гейтов).** «Сохранить» карточки активна при пустом обязательном
  «Название:», а в EventDialog пустое «Название *» блокирует сохранение. Разный контракт
  в двух родственных листах.
- **C4 (текст).** В карточке обязательные поля не помечены «*» («Название:»), в событии — помечены.
- **C5 (стек).** Второй лист перекрывает первый почти полностью; затемнение/рамка одинаковые —
  глубина не читается (ср. E1). Плюс: есть скролл-бары C7, кнопка «Убрать» корректно disabled.

### Попап «Выбор даты» — P-серия

- **P1 (UX, не баг-кандидат).** При пустом диапазоне обе сетки открываются на «Январь, год 1»
  (штатный defaults попапа, предзаполнение работает только для уже выставленного диапазона),
  а соседнее поле «Дата:» показывает реальную сегодня-дату — две разные привязки в одном ряду
  выглядят согласованными только для глаз.
- **P2 (подсказка).** Подсказка у сеток ровно одна («Кликните дату начала»); для второй (даты конца)
  своей подписи нет, пока не выбрана начальная.
- **P3 (восприятие).** В режиме «Все дни» ВСЕ ячейки обоих месяцев залиты акцентным (оранжевым) —
  выбранное/доступное сливаются, фон рябит.

### Лаунчер — L-серия

- **L1 (формат).** «Новая игра» открывается нативным QInputDialog с кнопками `OK/Cancel` —
  островки английского языка в полностью русском интерфейсе.
- В остальном лаунчер аккуратен: отступы, выравнивание ряда кнопок, состояние «Удалить» без выбора — корректны.

### Общее

- **S1.** В меню приложения (на dev-запуске) имя «Python» вместо продукта — артефакт упаковки
  (у `.app` из PyInstaller ожидается корректное); учитывать в проверках с real display.
- **S2 (замечание теста).** Фоновые координатные клики не доставляются окнам приложения
  (проверено на мастере: чек-позиции не реагируют, тогда как AXPress по кнопке месяца/сетке работает).
  Проверку «физической» мыши для W2/W4 этот прогон НЕ подтверждает — нужна сверка реальной мышью.

## Итог

Переходы между окнами логичны и покрываются картой выше — тупиков нет; формат окон выбран уместно:
отдельные окна для выбора/настроек, листы для сущностей. Главная боль — мастер календаря
(W1–W3: сломанная раскладка предпросмотра, мёртвая доступность радио, тихий qasync-конфликт FI-6)
и обрезки подписей в главном окне (M1/M2). Проблемы C1/C3/E1–E4 — точечные, но бьют по
единообразию дизайна. Каждый пункт требует закрепления pytest-тестом (оффсик) перед/вместе с правкой:
по контракту реального экрана эти проверки в CI невыполнимы, но W2, C1, M1/M3 пинятся без дисплея.

## Живой ре-аудит NRI-0014 — дописка 2026-09-24 (вечерний прогон)

нативный гейт `AXModal`, `zoom`; пункты системного меню — тот же press-канал через Accessibility
`System Events`, поскольку фоновые координатные клики в строку меню не доставляются — уже
зафиксированный предел канала S2, не пределы дерева приложения). Одноразовая игра
`qa-2026-09-24b`, AI-кнопки не нажимались, существующие игры не открывались/не удалялись.
Рабочее дерево — с правками групп 1–6 изменения `nri-0014`.

Живые наблюдения этого прогона (вне скоупа P1, фиксируются как есть):

- **First-run мастер по-прежнему укладывает процесс** (W3/FI-6, вложенный цикл первого запуска — скоуп
  П2 `nri-0015`, design NRI-0014 явно не трогал механизм): закрытие стартового мастера *красным крестом*
  после «ОК» новой игры — процесс гаснет с `RuntimeError: Event loop stopped before Future completed`
  (qasync), флаг `calendar_wizard_seen` не дописывается. Чтобы продолжить проверку остальных окон
  в той же throwaway-игре, флаг был выставлен напрямую в её базе — приёмку формата мастера из
  *меню* это не отменяет (строка D6 выше).
- Лист xlsx-импорта остаётся листом с фиксированной высотой: пустой «хвост» под кнопками — остаточная
  косметика (спека требует непрерывности видимых секций — выполнено).
- Заголовок карточки «Карточка: organization» наследует машинный идентификатор из существующего
  windowTitle (NRI-0014 вывел существующий текст как шапку; перевод типов — слой P2-единообразия).

Пределы дерева доступности прогоном не расширялись: новых не заведено (норма AGENTS сохранена).
