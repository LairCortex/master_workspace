## Шаг 0 — наблюдение о методе ввода (важно для будущих аудитов)

Синтетические фоновые события computer-use (`click x,y`, `type_text` клавишами, `press_key`) до QML-островов этого приложения **не доходят**: вкладки, строки таймлайна, кнопка «+» не реагировали; до полей sheet-диалогов клавиатура доходила частично и с задержкой. Доступность по element id (AXPress/AX set_value) работает штатно, но AX-Press строки таймлайна/результата поиска = эквивалент Enter (открывает карточку), т.е. одиночный клик через AX недостижим. Одиночные клики и скролл колеса выполнялись HID-событиями CoreGraphics (`osascript -l JavaScript` + `CGEventPost` на целевых координатах) — только так удалось получить настоящий пользовательский сценарий. Это ограничение инструмента аудита, **не дефект приложения**.

## Находки

1. **major / state — сброс скролла всех закреплённых карточек при каждой смене live-выбора.**
   Location: правая колонка `MainWindow`, закреплённые карточки `EntityPreview`.
   Evidence: снимки 01 vs 02, 03 vs 06, 07 vs 08 (пути выше).
   Issue: пользователь, читающий несколько закреплённых карточек в разных местах длинного текста, теряет позицию во всех них при любом новом выборе сущности (клик в средней колонке или в поиске). Выживание скролла подтверждено только для no-op повторного выбора той же пары; раскрытие поиска без выбора скролл не трогает — значит обнуление происходит на кадре с новым live-слотом, а не из-за ресайза колонок. Механизм (пересоздание делегата карточки / сброс `contentY` при обновлении слота) — за скоупом живой проверки, кандидата указывает параллельный разбор кода.
   Recommendation: сохранить `contentY` каждого закреплённого слота между кадрами (например, запоминать позицию в модели слота и восстанавливать после обновления содержимого; либо не пересоздавать делегат при обновлении frame).

2. **minor / ux — неочевидность персистентности «Создать нового» внутри несохранённого события.**
   Карточка создания сущности из диалога события закрывается «как сохранение», но запись существует только до сохранения события; отмена события молча откатывает сущность. Соответствует правилу «одна транзакция на операцию», но пользовательский опыт — иллюзия сохранения. Вне текущего чекпойнта, к рассмотрению.
