## Методические рамки (читать перед вердиктами)

1. **Фоновые координатные клики/колёсико в этой сборке не долетают до QML-островов** (повторно подтверждено: клик и double-click по строке таймлайна, колёсико по Flickable предпросмотра — без эффекта; скриншоты не меняются). Работа шла accessibility-нажатиями (`AXPress` по element id) и вводом `type_text` с element id (путь `SetFocus`). Поэтому «одиночный клик по строке средней колонки» проверялся как **AXPress строки** — с NRI-0022 это ровно тот же канал выбора (`DetailPanelRoot.qml:90 onPressAction → vm.select`).
2. Среднеколоночные строки и весь предпросмотр достижимы без мыши только обходным путём (FU-2 предыдущего аудита жив): выбор события на шкале не имеет AX-действия (Press строки шкалы = `rowDoubleClicked` → редактор). Наполнение выполнялось так: Press строки события → редактор → «Привязать существующего» (в списке-пикере MultiSelection — выделение строки пробелом с фокуса) → «Сохранить»; обработчик `on_event_updated` вызывает `show_event`, средняя колонка заполняется. Затем одиночные Press строк «Экзодия…», «Мариса…», строки связи в предпросмотре.
3. `set_value` (AX SetValue) в штатные TextField карточки («Название», «Ссылка на музыку») текст показывает, но до ViewModel не доносит (сохраняется старое значение); вложенные слои `MentionField` тем же путём сохраняются корректно. Для полей использован `type_text` (SetFocus) — он доносит.
4. `~/.nri_manager/ui.json` временно перезаписывался (роль `main`: 1100×800, затем 1100×1360) для теста переносов — восстановлен из резервной копии в teardown. Заодно воспроизведён факт: завершаемый экземпляр гарантирует сохранение кадра при уборке, поэтому правку конфига нужно делать после полного выхода процесса.

## Вердикты по пунктам задачи

### 1. Картинка/плейсхолдер слева, имя ПРАВЕЕ правого края блока картинки, на одном уровне с его верхом — PASS

- Узкая колонка (~450 pt): блок ≈194 pt (45 % от контента), факт-столбец справа, имя сверху выровнено по верху картинки.

### 2. Рейтинг/даты/возраст целиком, при узкой колонке переносятся — PASS
- Широкая: «Рейтинг: 14/20», «27 Сентябрь 2026 — 27 Сентябрь 2026», «Возраст: сегодня» — по одной строке, без элизий; у Марисы «15 Сентябрь 2001 — Бессрочно», «Возраст: 25 лет» (ветка INFINITE и возраст-формула показаны живьём).
- Узкая (1100 pt): имя перенеслось в 3 строки («Экзодия Тенеплёт, / странствующая травница / северных пределов»), даты — в 2 строки, многоточий/обрезки нет (zoom 2 px/pt).

### 3. Длинные секции начинаются НИЖЕ полосы картинки — PASS
«Характеристики:» стартует с y≈482 (широкая) при нижнем крае блока y≈463; в узкой колонке (1100×1360, без скролла) видно всю стопку: Characteristics/Предыстория/Личность/Задачи идут на всю ширину под полосой, не сбоку от неё.

### 4. Секции связей под длинными текстами — PASS

- Полоса «Карточка» и заголовок «Карточка: Персонаж / Организация» над полосой идентичности во всех состояниях.

## Дефекты и находки

### D1 (major, a11y/состояние) — повторное подтверждение: AXPress чекбокса «Бессрочно» не доходит до ViewModel, состояние теряется при сохранении
**Воспроизведение (этот прогон, чистая сессия)**: карточка нового персонажа → AXPress «Бессрочно» (value 0→1, галочка визуально проставлена, поле «Дата конца» затемнено) → «Сохранить».
**Фактически**: в БД `characters.end_date = 2026-09-27` (явная дата вместо NULL), предпросмотр показывает «27 Сентябрь 2026 — 27 Сентябрь 2026» вместо «… — Бессрочно». Ветка предпросмотра `INFINITE_LABEL` при этом исправна (Мариса с NULL из БД: «15 Сентябрь 2001 — Бессрочно»).
**Ссылка**: это ровно D1 из `docs/qa/2026-09-27-nri-0022-entity-preview-island.md`; правка 4.6 его не чинила. Офскрин-пин `doAction("Press")` для чекбокса карточки по-прежнему не написан.

### D2 (minor, состояние) — картинка, сохранённая карточкой НЕПОКАЗАННОЙ сущности, не доходит до средней колонки/предпросмотра до перезапуска
**Воспроизведение**: Экзодия показана не была; через её карточку выбран png («Убрать» стал активен) → «Сохранить» (в БД `image_id=2`, файлы `.png` + `.preview.webp` на месте) → одиночный Press её строки в средней колонке — слот предпросмотра остаётся «Нет изображение», миниатюра не появляется и в строке. Пересохранение события (перезагрузка `show_event`, новые модельные строки) тоже не помогает — панель получает тот же устаревший экземпляр общей AsyncSession (тот же корень, что FU-4, но теперь воспроизведено **штатной записью самого приложения**, не внешним писателем). После перезапуска (`python -m app.main`, заново) картинка отображается корректно в строке и в полосе.
**Оговорка по спецификации**: пункт «Сохранение карточки обновляет предпросмотр» относится к показанной сущности — для показанной живой путь проверен и работает (см. ниже), так что формального нарушения сценария нет; фиксация касается свежести данных при **новой** выборке в той же сессии.
**Живое обновление показанной карточки — PASS**: Экзодия показана → карточка → «Изменить ссылку на музыку» → ввод `-v2` → «Сохранить» → строка «Музыка:» в предпросмотре обновилась сразу, без перезапуска.

### OBS-1 (minor, a11y-методика): SetValue штатных TextField карточки виджет показывает, но VM не уведомляет
`set_value` «Название»/«Ссылка на музыку» меняет value-слот и даже отрисовку, но `textEdited→VM` не срабатывает — сохранение пишет старое значение (музыка Экзодии после первой попытки осталась пустой). AT-пользователь, набирающий текст посимвольно (путь SetFocus + клавиши), не затронут — ввод доходит. Фиксируется как методическая ловушка автоматизации и кандидат на офскрин-проверку «SetValue не является каналом ввода острова».

### OBS-2: ре-подтверждён предел выбора без мыши (FU-2 жив)
Press результата поиска по-прежнему открывает карточку (`RowItem` press → `activateRequested` → `editRow`), полный путь с заполнением средней колонки — только одиночный ЛКМ. Окно «Обзор мира» → Press строки сущности открывает её карточку (`entity_clicked → _on_entity_click`), предпросмотр не заполняет. Без мыши средняя колонка наполняется только «сохранением события из его редактора» (обходной путь этого аудита).

## Что осталось непроверенным живьём
- Нижняя граница блока картинки 120 px и «сжатие вместе с колонкой» — перетащить сплиттер фоном невозможно; ветка `Math.max(120, …)` пиннута офскрин-тестом группы 4.
- Прокрутка Flickable в узком окне (колёсико не долетает); корректность composition при переполнении — офскрин-пин + отсутствие наложений на 1100×1360.
