### Наблюдения (не layout-дефекты)

1. **minor / a11y**: текстовые подписи островов — полоса «Карточка», полосы
   «Карточка: <тип>», имя карточки, `HintText` — не появляются в дереве
   доступности (`query` «Карточка» = 0 и при 0 pane-ов, и при 4). Части
   expectation п.4 checkpoint («полоса/HintText остаются StaticText-подписями в
   дереве») реализация не даёт: в дереве видны только интерактивные строки
   (link-переходы, шапка шкалы). Фоллоу-апил в сценарий `accessibility-audit`.
   Шаги: открыть qa-игру, `get_app_state`, запрос «Карточка»/«Выберите».
2. **info**: строки списков панели деталей (вкладка «Персонажи») в живом дереве
   не адресуются (видны только вкладки TabGroup) — FI-5 «DetailPanel content»
   остаётся частичным; выбор сущности через link-переход карточки работает
   (AXPress «Лампа джина» → живая область показала её).
3. Зависимость проекции от вьюпорта: link-строки карточек появляются в дереве
   только когда секция связей в него попадает (узкие pane-ы — нет). Чинить не
   требуется, но live-аудит обязан скроллить контент до вердиктов дерева.

### 2. Полосы заголовков pane-ов и текст пустой живой области

- **Факт:** `query «Карточка»` = 0 совпадений (при 3 pane-ах), `query «Выберите»`
  = 0 (пустая живая область + хинт средней колонки). Подписи полос
  «Карточка: <тип>», колонная «Карточка» и `HintText` в живом дереве
  **отсутствуют** — подтверждение наблюдения 1 layout-смены.
- **Причина (по исходникам, без правок):** `TitleText`/`HintText` — чистые
  `QtQuick.Text` без `Accessible.*`; непоannotated Text внутри QML-острова в
  cocoa-дерево не попадает (в отличие от annotated-строк связей — те видны).
- **Противоречие контракту?** Прямого нарушения нет: AGENTS.md требует
  role+name у *интерактивных* контролов и запрещает безымянный AXStaticText-мусор
  от `NoRole`-реаннотации, но не предписывает обязательную проекцию
  не-интерактивных надписей. Однако expectation checkpoint-а design.md
  («полоса/HintText остаются StaticText-подписями в дереве») живьём не выполнен,
  и это UX-шероховатость для читателя: три булавки «Открепить карточку» идут без
  заголовков pane-ов — какой слот какой карточки, непонятно.
- **Фоллоу-ап (не правка этой смены):** в библиотеке `TitleText`/`HintText`
  завести компонент-владеющую аннотацию по образцу пассивного слота `RowItem`
  (`Accessible.role: Accessible.StaticText` + `Accessible.name: text` внутри
  компонента; место применения имя не трогает), expectation design.md привести в
  соответствие; diff живого дерева в следующем `accessibility-audit`.

### 3. Пределы координатности

Новых пределов **нет**. Всё новое либо адресуется без координат (булавка —
`AXButton` с именем и рабочим Press; строки связей превью — адресуются и
прессуются, их потеря Link/ListItem-роли в cocoa — уже зафиксированный предел ⑤,
имя полное, Press работает), либо является не-интерактивной подписью (полосы,
хинт — см. п.2). Tooltip булавки = имя (предел ④, предсуществующий). Запись в
AGENTS.md не требуется.

### 4. Штатные контролы острова

Остров предпросмотра штатных **текстовых** кнопок не содержит вообще
(`EntityPreviewRoot.qml`: только `ThemeIconButton` + annotated-Items; TextField
