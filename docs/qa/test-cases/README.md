  спеке нет (пробел №7 файла 03); норма метки требует записи в спеку.

  при открытом документе (G-10 файла 01).
- Противоречие `qml-shell` «Save без valid-гейта» vs «Обязательные поля листов единообразны»
  и `ui-widget-catalog` vs `qml-shell` про widgets-редактор (П5/П6 файла 10).
- `image-storage`: «ссылка цела при битом файле» vs «сканирование обнуляет ссылки» (G11 файла 09).
- Открытая находка аудита: в raw-дереве посадки стола нет адресного чекбокса (F1/A2
  модал-листов) — закреплена как живая строка TC-CHST-010, не принимать как норму.
- Общая системная дыра спек: тексты подтверждений/ошибок почти нигде не нормированы —
  почти в каждом файле есть пробел «задан только факт диалога, не формулировка».

## Идентификаторы

`TC-<АББРЕВ>-<NNN>` — три цифры, сквозная нумерация внутри одной спецификации.
Существующие ID не перенумеровывать; новые кейсы получают следующий свободный номер.

## Формат кейса

```
### TC-XXXX-001 — краткое название

- Требование: <точный заголовок «### Requirement: …» из спеки>
- Сценарий: <точный заголовок «#### Scenario: …» из спеки или «производный из требования»>
- Тип: положительный | негативный | граница | авторизация | состояние | хранение | повтор | регрессия
- Приоритет: P0 | P1 | P2
- Статус: уточни | выведен | пробел
- Предусловия: …
- Шаги: 1) … 2) … 3) … (исполняемые глазами/руками; терминал — только если спека явно требует)
- Ожидаемый результат: … (только наблюдаемое; без «работает корректно»)
- Источник: openspec/specs/<домен>/spec.md#<точный заголовок требования или сценария>
```

## Статусы

- **уточни** — поведение прямо записано в спеке (требование или сценарий);
- **вывед** — разумная декомпозиция записанного поведения (граница вокруг записанного
  предела, повтор операции, порядок шагов);
- **пробел** — поведение нужно для проверки, но спецификацией не задано. Кейс с этим
  статусом НЕ выдумывает ожидаемое: он фиксирует вопрос в разделе «Пробелы» файла.

## Приоритеты

- **P0** — основной сценарий работы функции, риск потери/порчи данных, безопасность;
- **P1** — сценарии приёмки требований;
- **P2** — второстепенные, краевые, косметические.

## Правила генерации

1. Норма — `openspec/specs/<домен>/spec.md`. Код, `AGENTS.md`, отчёты `docs/qa/*` —
   контекст, но требование из них не сочиняется.
2. Каждый `Scenario` получает как минимум один кейс; независимые измерения сценария
   могут получить отдельные кейсы.
3. Покрывать, только когда спека это задаёт: позитив, негатив/отказ, явные границы,
   пустые значения, состояния и переходы, хранение/побочные эффекты, повтор операции.
4. Не выдумывать: лимиты без указания спеки, коды ошибок, тексты фатальных сообщений,
   селекторы интерфейса, схему БД. Нет нормы — «Пробелы».
5. Дубликаты не плодить: кейсы различаются входом, состоянием, ожидаемым, ролью или
   режимом отказа — иначе объединять.
6. Каждый кейс исполним независимо, если иное не указано в предусловиях.

## Живые проверки (UI)

Запуск: `python -m app.main` (или `python dev_run.py`). Изоляция по соглашению репозитория:
одноразовая игра `qa-<дата>`, кнопки генерации ИИ не нажимать, завершение —
`pkill -if "app.main"`. Детали экранов и флоу — в `app-map.md`.

## Открытые вопросы, перенесённые из аудитов

- **H1** — синтетические координатные клики харнесса долетают не до всех целей (виджетные
  листы и контролы островов молчат при живом AX-прессе); молчание клика — не дефект,
  повторять через доступность или реальную мышь (примечание в файле 11, предупреждение в карте).
- **H2** — AX-рамки островных текстовых полей спроецированы со смещением экранного положения;
  в поля заходить только пресс-действием и вводом по элементу с визуальным подтверждением фокуса.
- **F1/A2 + кластер стола** — посадка не имеет адресного чекбокс-узла, потому живой кластер
  над рядом поиска ни разу не наблюдался; его контракт пинен только оффскрин, живая половина
  открыта до починки адресности посадки (TC-CHST-010/036/037).
- **OBS-1** — строка действий обзора мира на узкой сохранённой рамке обрезает «Показать всё»;
  default-половина закрыта, живая половина открыта (TC-SNAP-040).
- **OBS-3** — нативные радио мастера календаря рисуются стилём ОС вне тематизации;
  процедура наблюдения зафиксирована (TC-CALW-033).
- **Цвета (F07/F10)** — цвет фона рейтинга карточки/предпросмотра и цвета снимка мира
  ⏳ не подтверждены с прежних прогонов; zoom-процедура обеих тем в TC-EADD-002,
  TC-PREV-001, TC-SNAP-023.
