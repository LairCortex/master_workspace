# 07. Чар-листы: редактор, стол, экземпляры, PDF, пресеты, хранение

Источники:
- openspec/specs/character-sheet-editor/spec.md
- openspec/specs/character-sheet-host/spec.md
- openspec/specs/character-sheet-instance/spec.md
- openspec/specs/character-sheet-pdf/spec.md
- openspec/specs/character-sheet-preset/spec.md
- openspec/specs/character-sheet-storage/spec.md

Общие предусловия (далее не повторяются): запущено `python -m app.main`, открыта одноразовая игра `qa-<дата>`; кнопки генерации ИИ не нажимать; завершение `pkill -if "app.main"`. Кейсы CHST требуют браузера по URL из пульта стола. Термины: Design — редактор макета, Fill — окно заполнения листа, рейка — панель страниц, посадка — экземпляры, отмеченные «за стол».

## character-sheet-editor (CHED)

### TC-CHED-001 — Меню «Чар-листы» открывает список с вкладками

- Требование: Оболочка списка и одного редактора
- Сценарий: Меню открывает список
- Тип: положительный
- Приоритет: P0
- Статус: уточни
- Предусловия: в игре есть хотя бы один шаблон и один лист
- Шаги: 1) Открыть меню приложения 2) Выбрать «Чар-листы»
- Ожидаемый результат: открылся список текущей игры; видны вкладки «Шаблоны» и «Листы»; в них строки этой игры
- Источник: openspec/specs/character-sheet-editor/spec.md#Оболочка списка и одного редактора

## Пробелы

Поведение нужно для проверки, но перечисленными спеками не задано; кейсы со статусом «пробел» ожидаемое не выдумывают.

1. Тексты подтверждений (закрытие Design/Fill, смена игры, старт стола, удаление шаблона/листа/непустой страницы) и тексты ошибок (занятое имя, занятый порт, неизвестный тип, ошибка записи PDF) — задан только факт диалога/сообщения, формулировки не нормированы.
2. Что именно выбрасывается из стека отмены при 51-м действии (старейший снапшот или запрет операции) — TC-CHED-027 и TC-CHED-101 проверяют только глубину отмены в 50 шагов.
3. Диапазон допустимых значений порта пульта и поведение при заведомо невозможном порту (занятый порт — задан, «некорректный» — нет).
4. Правила имени игрока в веб-входе: максимальная длина, имя из одних пробелов, различение регистра, совпадение с именем уже вышедшего игрока — TC-CHST-017 фиксирует только «непустое».
5. Может ли PIN совпасть с ранее выдававшимся (не со смежным рестартом) и обязан ли он отличаться от всех прежних.
6. Содержание и формат QR-кода; обязан ли QR вести именно на первый из показанных адресов.
7. Допустимые форматы и размер файла изображения поля чар-листа (в этих спеках только «читаемый файл» и конвейер ImageStore).
8. Что рисует Design в поле-картинке при недоступном/битом файле (для PDF поведение задано, для редактора — нет).
9. Вид ручек ресайза при множественном выделении: скрыты или показаны и неактивны (запрет действия задан, форма — нет).
10. Способ воспроизвести невалидные токены темы для TC-CHST-032 руками не задан; проверка сводится к анализу тела отдаваемого CSS.
11. Как получить вручную шаблон со schema_version 1 и шаблон с неизвестным `type` в данных (импорта шаблонов нет) — от этого зависят TC-CHSR-013, TC-CHSR-014, TC-CHSR-015.
12. Запоминание размещения окон «Лист» (и других окон чар-листов) в этих спеках не описано — TC-CHST-041.
13. Семантика доступной записи (`SetValue` в value-слот) для полей чар-листов с коммитом по завершению (Fill `commitLine` на `onEditingFinished`, числовой черновик редактора `applyNumberDraft`): должна ли запись считаться завершением ввода или обязателен finish (Enter/blur) — TC-CHIN-025.
13. Навигация по полям Fill (Tab/Enter между полями) и перемещение выделенного поля стрелками — не заданы.
14. Что происходит с dirty-состоянием Fill, если сохранение шаблона удалило поле со значением — не задано.
15. Верхняя граница числа страниц шаблона («не ограничено сверху») — числовое значение для проверки границы не задано; TC-CHSR-016 проверяет только «не меньше одной» и сохранение порядка.
