# 13 — Фундамент D&D-модуля: жизненный цикл, датасеты, валидатор, переносимость

Источники (дельта изменения `add-dnd-module-foundation` заархивирована 2026-10-10; нормы
влиты в сводные спеки — прицельно по изменению смотрят их версии в
`openspec/changes/archive/2026-10-10-add-dnd-module-foundation/specs/`):
`openspec/specs/dnd-module-lifecycle/spec.md`,
`openspec/specs/dnd-dataset-library/spec.md`,
`openspec/specs/dnd-dataset-validator/spec.md`,
`openspec/specs/game-launcher/spec.md` (модифицированные требования),
`openspec/specs/main-window/spec.md`,
`openspec/specs/architecture-integrity/spec.md`,
`openspec/specs/ui-testing/spec.md`.

Аббревиатуры ID: dnd-module-lifecycle (DNDL), dnd-dataset-library (DNLB), dnd-dataset-validator (DNDV); дельты существующих спецификаций получают суффикс D — game-launcher (LNCHD), main-window (MAIND), architecture-integrity (ARIND), ui-testing (UITTD) — чтобы не конфликтовать с ID файлов 01/04/12.

Общие предусловия (по своду правил `README.md`): живые UI-проверки — `python -m app.main`, одноразовая игра `qa-<дата>`, кнопки генерации ИИ не нажимать, завершение `pkill -if "app.main"`. Проверки «строка таблицы не изменилась» и «ключ настроек появился/не появился» выполняются чтением `games/<имя>/game.db` утилитой `sqlite3` — спеки этих требований фиксируют сам факт неизменности данных, поэтому терминал здесь разрешён сводом правил. Профили запуска: переключатель «без модуля» — переменная окружения `NRI_DISABLE_DD_MODULE=1` (design Д11 изменения; в UI для пользователя выключателя нет). Хранилище датасетов — `~/.nri_manager/datasets/`; живой прогон меняет его глобально, после проверок удалите добавленные файлы набора вручную.

## dnd-module-lifecycle (DNDL)

### TC-DNDL-001 — D&D-игра собирается с модулем

- Требование: Признак модуля определяет состав приложения
- Сценарий: D&D-игра собирает модуль
- Тип: положительный
- Приоритет: P1
- Статус: уточни
- Предусловия: в каталоге есть игра с включённым признаком модуля поддерживаемой версии (создана лаунчером с системой «D&D» или включением через меню).
- Шаги: 1) открыть игру 2) осмотреть строку меню 3) выполнить несколько обычных действий (создать событие, открыть карточку)
- Ожидаемый результат: экраны и команды модуля доступны (метка «D&D», группа меню модуля), поведение обычного ядра не изменилось
- Источник: openspec/specs/dnd-module-lifecycle/spec.md#Признак модуля определяет состав приложения

## dnd-dataset-validator (DNDV)

Ручная QA-проверка валидатора строится вокруг кнопки «Перепроверить» на экране датасетов и окна импорта: отчёт — русские сообщения с путём к месту. Формат пути к месту не нормирован грамматически («Пробелы» 5), поэтому кейсы проверяют наличие пути, ведущего к месту, а не его синтаксис.

- Ожидаемый результат: на один вход — один и тот же отчёт (те же проверки, тот же порядок, то же число)
