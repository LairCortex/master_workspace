# Тест-кейсы: настройка LLM и внешний OpenAI-совместимый провайдер

Источники:

- openspec/specs/llm-configuration/spec.md
- openspec/specs/llm-remote-provider/spec.md

Общие предусловия (не повторяются в кейсах): запуск `python -m app.main`, одноразовая игра `qa-<дата>`; реальные ключи не используются; там, где нужен живой API, в предусловиях указано «нужен тестовый OpenAI-совместимый сервер». Завершение проверки — `pkill -if "app.main"`.

## llm-configuration (TC-LLMC)

### TC-LLMC-001 — Сохранённые настройки подставляются при следующем запуске независимо от игры

- Требование: Глобальный конфиг подключения
- Сценарий: Сохранение настроек
- Тип: хранение
- Приоритет: P0
- Статус: уточни
- Предусловия: приложение закрыто; игра A и игра B в архиве
- Шаги: 1) открыть игру A, меню LLM → «Настройка LLM…», заполнить endpoint и модель (ключ не вводить), «Сохранить» 2) закрыть приложение и снова запустить 3) открыть «Настройка LLM…» 4) закрыть игру, открыть игру B, снова открыть «Настройка LLM…»
- Ожидаемый результат: в обеих играх форма показывает те же сохранённые endpoint и модель
- Источник: openspec/specs/llm-configuration/spec.md#Requirement: Глобальный конфиг подключения

## Пробелы

1. Путь/имя файла конфигурации LLM спецификацией не зафиксирован — где проверять отсутствие файла (TC-LLMC-002) и права 0600 (TC-LLMC-003).
2. Не зафиксировано раздельно, какое сообщение относится к таймауту установления соединения (10 с), а какое — к ожиданию ответа (120 с): общий текст «время ожидания ответа истекло» vs «сервер LLM недоступен» (TC-LLMP-007/013).
3. Способ искусственно растянуть окно сохранения до `finish_saving` (задержка/хук) не задан — надёжно поймать блокировку Esc на быстром сохранении руками сложно (TC-LLMC-016/017).
4. Не раскрыто поведение диалога после успешного сохранения («закрытие разрешено согласно прежнему результату операции»): закрывается ли оно само или остаётся открытым (TC-LLMC-017).
5. Единственность источника полей `FIELD_CONFIG` и отсутствие независимого списка в QML не проверяются глазами/руками — нужен код/AST-уровень (TC-LLMC-013).
6. Python-фасадность `check_connection` (запрос идёт из QML, объект выполняется на Python без передачи HTTP/service-объектов в QML) визуально недоступна ручной проверке (TC-LLMC-015).
7. Способ ручного чтения имён доступности полей (кем/чем читать дерево) спецификацией не фиксирован (TC-LLMC-023).
8. Минимальность проверочного запроса («генерация одного токена») не подтверждается без серверного лога запросов (TC-LLMP-014/015).
9. Точная формулировка подсказки при нажатии неактивной AI-кнопки не задана — зафиксировано только направление «меню LLM → Настройка LLM…» (TC-LLMC-008).
10. Критерий «наличие описания мира» не определён: активна ли кнопка при описании из пробелов/переводов строки (TC-LLMC-007/011).
