# Живой прогон доводки D&D — `fix-dnd-followups` (2026-10-12)

Прогон 7.1: один экземпляр приложения, строго последовательно, throwaway-игра `qa-2026-10-12`
(файлы чужих игр не открывались и не удалялись; кнопка «Сгенерировать ИИ» не нажималась
ни разу). Запуск: `python dev_run.py` (PySide6, macOS). Остановка после серии:
`pkill -if "app.main"`. Снимки: `docs/qa/assets/2026-10-12-dnd-followups-live/`.

Инструмент управления: accessibility-дерево (роль/имя/значение каждого контрола) +
координатные снимки экрана. Для полей ввода, куда фоновые клавиши не доходят,
использовалось AX-значение (Set Value) — в этом режиме карточка D&D корректно
подхватывает текст и включает кнопку «Сохранить».

## 5. Каскад удаления прямым SQL (событие-носитель пережило каскад)

**Шаги.** Способ: приложение остановлено (`pkill -if "app.main"`), в `sqlite3` по базе игры
выполнено `PRAGMA foreign_keys=ON;` (в приложении FK включены через
`PRAGMA foreign_keys=ON` на connect — прямое CLI-соединение требует включить их явно),
`DELETE FROM characters WHERE id=1;`, счётчики до/после; затем приложение перезапущено
и состояние проверено живьём.

**Факты.**
- До удаления: characters=1, `dd_character_ext`=1, `dd_character_spell_link`=0,
  `event_character`=1 (Грог привязан к событию «Засада у брода» через вкладку «Связи»).
- После удаления персонажа: `dd_character_ext`=0, `dd_character_spell_link`=0,
  `event_character`=0 — каскад FK сработал, висячих ссылок нет
  (`… where character_id not in (select id from characters)` → 0 строк).
- Событие-носитель пережило каскад: `events`=1, `dd_encounter`=1 — событие и его состав
  встречи целые; FK `dd_encounter.event_id` ведёт в `events`, а не в `characters`,
  поэтому удаление персонажа его не задело. Это соответствует дельтам
  (`dnd-encounters`: FK каскада — событие; `dnd-character-import`: удаление персонажа
  каскадом снимает только надстройки персонажа).
  Снимок до удаления: `15-before-sql-cascade.png`.
- Живая проверка после перезапуска: поиск «Грог» — пусто (`19-search-grog-empty-after-cascade.png`);
  событие открыто, вкладка «Встреча» цела с составом ×3

## 7.2 — наведение на полосу табов карточки (ui-ux-designer)

**Что проверялось.** Живое состояние наведения (hover) неактивного таба полосы табов
карточки в средней колонке главного окна (`DetailPanelRoot.detailTabBar`,
компонент `ThemeTabButton.qml`) и сверка отрисованных пикселей с токенами темы.

**Сессия.** Второй экземпляр прогона дня: `python -m app.main`, игра
`qa-2026-10-12` (другие строки каталога не открывались, кнопка «Сгенерировать ИИ»
не нажималась). Тема — тёмная (`~/.nri_manager/ui.json: theme=dark`). Полоса:
«Организации» (активный, индекс 0 по умолчанию) / «Персонажи» / «Предметы» /
«Локации». Наведение — на «Персонажи» (неактивный). Снимки региона полосы
(экранные координаты `690,160,840,48` pt) — `screencapture` в нативном 2×
(2 px/pt, как zoom-контракт Retina). Цикл снят трижды: покой → наведение →
снятие наведения, чтобы состояние гарантированно принадлежало курсору.

**Как доставлялось наведение (инструментальное наблюдение, не дефект).**
Фоновый `hover` из computer-use (по element id и по координатам) в этом окружении
не доносил hover-события до QML-острова: пиксели не менялись. Состояние
наведения было получено реальным HID-перемещением курсора (`CGEventPost`
mouseMoved из мини-утилиты Swift; тулзу можно выбросить, она вне репозитория) —
тот же канал, через который 7.1 подтверждал реальный HID-клик. Первый запуск дня
после долгой серии синтетических вводов «залипал» без hover-перерисовки; после
чистого перезапуска цикла покой→наведение→покой всё воспроизвелось за один такт.
К продукту это не относится: при настоящем движении мыши hover-переход работает.

**Токены (тёмная тема, `app/presentation/theme/tokens.json` + деривация
`accent_argb` с `HOVER_ALPHA=0.85` в `qml_palette.py`):**
`color.fg.primary #e8e6e1`, `color.accent #b9863c`, `color.border #3a3a44`,
`color.bg.surface #2a2a32`, `color.accent.hover = #d9b9863c`.

**Сверка токен↔пиксель.** Измерялась мода полностью перекрытых пикселей глифов
(AA-обводка глифов даёт субпиксельные синий/тёплый франджи и в сравнение не
бралась). Композит hover-подписи поверх подложки: 0.8510·accent + 0.1490·surface
= ожидаемо (163.7, 120.3, 58.5).

| Поверхность | Токен | Ожидалось (RGB) | Измерено (RGB) | Δ |
|---|---|---|---|---|
| Покой, неактивный таб («Персонажи», подпись) | `color.fg.primary` | 232,230,225 | 232,230,225 | 0 |
| Покой, активный таб («Организации», подпись) | `color.accent` | 185,134,60 | 185,134,60 | 0 |
| Покой, 2px подчёркивание активного таба | `color.accent` | 185,134,60 | 185,134,60 | 0 |
| Покой, 1px хайрлайн полосы под неактивным табом | `color.border` | 58,58,68 | 58,58,68 | 0 |
| Подложка под полосой | `color.bg.surface` | 42,42,50 | 42,42,50 | 0 |
| **Наведение, подпись «Персонажи»** | `color.accent.hover` (композит) | 163.7,120.3,58.5 | 164,120,58 / 164,120,59 | ≤0.5 |
| Снятие наведения — возврат подписи | `color.fg.primary` | 232,230,225 | 232,230,225 | 0 |

Контроль разделения состояний: наведение (164,120,58) отличается и от активного
таба (185,134,60), и от pressed-деривации (`alpha=0.7` → ≈142,106,57), — т.е.
наведённый неактивный таб печатает ровно `color.accent.hover`, не подмену.
Соседние табы во время наведения не сдвинулись ни на единицу; хайрлайн под
наведённым табом остался `color.border` (hover не трогает линию полосы —
соответствует `ThemeTabButton.qml`, где hover влияет только на цвет подписи).
Допуск на растеризацию: ±1 на канал для перекрытых пикселей; фактические
расхождения — 0…0.5.

**Снимки** (`docs/qa/assets/2026-10-12-dnd-followups-live/`):
`25-tabstrip-detail-rest.png` — полоса в покое (2×), `26-tabstrip-detail-hover-personazhi.png`

`26b-tab-personazhi-hover-closeup.png` — крупный план подписи «Персонажи»
покой/наведение.

**Вердикт: расхождений с токенами нет.** Follow-up не заводятся.

**Земляника:** экземпляр остановлен `pkill -if "app.main"`; данные не менялись

## Инструментальные заметки (не дефекты продукта)

- Фоновые координатные клики и `AXPress` не доходят до стрелок QSpinBox и до строк
  QML/QComboBox-попапов; для счётчика использован `AXIncrement`, для ввода в MentionField —
  `AX SetValue` (в обоих случаях продукт повёл себя штатно: значение дошло до модели,
  «Сохранить» стала активной, popup открылся).
- Реальный HID-клик по строке popup-кандидатов работает — это ровно тот путь,
  который задокументирован в AGENTS.md (предел ①), и он подтверждён.
- **Журнал SRD (отрицательная половина)**: реальных SRD-документов в среде нет
  (адрес недоступен), поэтому идемпотная ветка проверена через пред-заливку
  `srd51`/`srd52` в `~/.nri_manager/datasets/`; пре-заливка удалена после прогона,
  полка возвращена к состоянию до прогона (только `qa-local`). Это допущение метода,
  а не наблюдение продукта.
- Имя таба «D&D» в дереве доступности показывается как «DD» — `&` съедается
  accessibility-проекцией Qt; видимый текст вкладки корректен (наблюдение, не дефект).
