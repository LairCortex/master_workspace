# Живой аудит accessibility (сценарий `accessibility-audit`, 2026-09-23)

Change `nri-0012-qml-accessibility`, задача 5.4. Стенд: macOS; приложение запущено из рабочего дерева
(исходники уже содержат аннотации NRI-0012), throwaway-игра `qa-2026-09-23`, сервер `munim-computer-use`.
AI-кнопки не нажимались; существующие игры каталога не открывались и не удалялись.

Что снималось: `get_app_state` каждого экрана, `AXPress` по element id, `zoom`/`screenshot` для сверки «вид ↔ дерево».
Расхождения пронумерованы FI-1…FI-6 — это пункты follow-up (перечислены и в AGENTS.md), а не молчаливое
расширение области change.

## Экран: лаунчер

- Кнопки «Новая игра», «Импорт», «Светлая тема», «Удалить», «Открыть» — `Button` с именем ровно по видимому тексту
  (живая половина контракта 4.2 подтверждена); три безымянные нативные кнопки-«светофоры» окна — ожидаемо.
- Строки игр (`RowItem`): в дереве **есть** с правильным именем («qa-2026-09-23 (…)`), узел помечен `StaticText`
  (см. FI-2); `AXPress` по строке **открыл игру** — одиночная активация = открытие, как требует спека. До NRI-0012
  строк в дереве не было вовсе (`query` по имени игры давал 0 совпадений) — видимость по имени новый факт.

## Экран: мастер календаря (первый запуск новой игры)

- Радио «Стандартный»/«Кастомный» со слотом `value`, кнопки «Назад/Далее/Применить/Отменить», кнопка месяца
  `MenuButton`, спиннер года `Incrementor`, дни сетки `Button "1".."30"` — всё адресно без координат.
- Попутно зафиксирован продуктовый дефект старта (не accessibility): FI-6 ниже.

## Экран: главное окно (таймлайн + детальная + снимок мира + поиск)

- Поиск: `TextField "Поиск по всем сущностям" value="Дожд"` — name из usage-site-аннотации, value штатный.
  Кнопки «Найти»/«Показать»/«Сброс»/«Показать всё», табы-`RadioButton`, «Добавить событие», «Все дни ▾» — имя=текст.
- Строка результата поиска и строка таймлайна (`TimelineRowDelegate`): адресуются по полному имени-подписи
  (ровно по карте — «… · Дождливая ночь»), помечены `StaticText` (FI-2); `AXPress` строки таймлайна **открыл
  диалог события** — элементное действие выполняется из дерева.
- Снимок мира: заголовок секции — `Button "📅  Активные события (1)"` (роль корректна, toggle по `AXPress`
  подтверждён); строка сущности — именованный узел с рабочим `AXPress` (переход выполнен).
- Видимые поля дат (snapshot/таймлайн) и кнопка «✎» — см. FI-1/FI-4.
- Живое состояние чекбокса «Бессрочно» переключается `AXPress` (value 0→1), т.е. `Accessible.checked` штатных
  контролов в живом дереве корректен.

## Экран: диалог события и попап-карточка сущности (QML-острова)

Подтверждено живьем по карте design.md (с поправкой на реализованные имена): «Название события», `MenuButton
"Тип события"`, mention-поля «Характеристики»/«Предыстория» (роль редактируемого + вложенный plain-слой),
«Ссылка на музыку», «Рейтинг» (`Incrementor` со `value`); extra-поле карточки подписано `modelData.label`
(«Задачи»); AI-кнопки **с реализованной конвенцией** «Сгенерировать: Название/Характеристики/Предыстория»,
кнопка целика — «Сгенерировать: Событие» (НЕ «Сгенерировать AI: …» из устаревшей formulировки design.md — AGENTS
фиксирует фактическую конвенцию). Кнопки «Сохранить», «Отмена», табы — имя=текст, не пере-аннотированы.

## Пределы (сверка с AGENTS-списком из четырёх)

1. **Попап упоминаний** — живьем не воспроизведён (на префикс `@хра` попап не открылся: единственная сущность не
   подошла по времени обновления данных попапа); по источнику делегаты попапа не аннотированы — предел в силе.
2. **value MentionField/инлайн-редактора** — подтверждён в части слота: у аннотированного корня слота значения
   нет, только name. Уточнение к формулировке: вложенный **штатный** plain-слой живьем показывает набранный текст
   как своё имя — «невидимость» текста мягче, чем буквальный предел (текст читается, но не через value-слот).
   Value-мост остаётся follow-up NRI-0013.
3. **Нативные попапы дат/выпадаюков** — подтверждён живьем: попап календаря (`«Все дни ▾»`) открылся **отдельным
   окном** (readable как окно); выпадаюк `ThemeComboBox` синтетическим `AXPress` не открылся — в дереве остаётся
   именованный триггер, items за пределом. Ограничение соблюдено списком.
4. **Tooltip-мост** — синтетически не проверяется (hover-тултип без реального курсора не вызывается); по источнику
   (`tooltip_shim.py`) текст в дерево не переносится — предел в силе.

Пятый предел не обнаружен: всё остальное на пройденных экранах адресовалось без координат, а недоступное было
либо пределом из списка, либо FI.

## Расхождения → пункты follow-up

- **FI-1 (дефект live-адресации): `ThemeDateField` («Дата начала»/«Дата конца» в диалоге события и в карточке,
  поле даты снимка мира) отсутствует в живом дереве** — видим на экране (сверено zoom-ом), в `get_app_state` узла
  нет даже как `StaticText`. Кандидат-причина: usage-site вешает `Accessible.name` на `Control` без роли, и
  живая cocoa-проекция такой узел не отдаёт (оффскрин точечно имя читается — поэтому оффскрин-тесты зелёные).
  Это расходится со спекой «каждый интерактивный элемент … с ролью и именем». Fix: роль+press внутрь
  `ThemeDateField` по образцу D2 — отдельный тик.
- **FI-2: строки `RowItem`/таймлайна/снимка показываются как `StaticText`, а не `ListItem`.** Имя, адресация и
  press-действие корректны (открытие подтверждено), координатная зависимость не возникает; теряется семантика
  «пункт списка». Проверить маппинг `QAccessible.ListItem` → AX в Qt 6.10/cocoa; при невозможности починить —
  это кандидат на явное уточнение в AGENTS (не «молчаливый» пятый предел, т.к. адресация работает).
- **FI-3 (карта design.md ↔ дерево):** описания строк из карты («Открывает игру», «Выбирает тип», «Открывает
  страницу», …) фактически не заведены — у `RowItem` нет слота описания usage-site; строки несут роль+имя+press.
  В AGENTS описан фактический набор. Reconcile в группе 6: либо добавить `RowItem.accessibleDescription`, либо
  поправить карту design.md.
- **FI-4 (мелочь):** кнопка «✎» (переключение режима правки музыки в карточке) безымянна в дереве; в карте не
  упомянута. По конвенции «иконка — глаголом» дать имя («Редактировать ссылку на музыку»).
- **FI-5 (предел среды прогона):** DetailPanel (строка-карточка + картинка) и islands, открываемые из меню
  (чар-листы: список/редактор/заполнение/пресет, DocViewer, XlsxImport, LLM-setup, «Стол», EventTypes из «+»-меню),
  живьем не открыты — фоновые клики по координатам до Qt-холста и нативного меню-бара в этом окружении не доходят,
  а выбор события доступен только мышью. Их деревья закреплены оффскрин-тестами; живая сверка требует прогона
  с реальной мышью/ручным открытием экранов.
- **FI-6 (попутный продуктовый дефект, вне accessibility):** стартовый мастер календаря, запускаемый изнутри
  `Application.start()`: `Отменить` завершает приложение (`RuntimeError: Event loop stopped before Future
  completed`), а `Применить` порождает qasync-конфликт («Cannot enter into task Application.start»).
  Воспроизведено дважды на throwaway-игре. Отдельный тик: мастер должен заводиться после показа окна/через
  `run_locked`, отмена не должна ронять event loop.

## Итог

По всем доступным островам живое дерево даёт роль, имя и press-действие без координат; конвенция имён (включая
фактические AI-имена «Сгенерировать: …») подтверждена; реализованные описания соответствуют AGENTS-набору.
Список четырёх пределов живьем не расширен. Все расхождения оформлены пунктами FI-1…FI-6 и перенесены в AGENTS.md
(раздел computer-use) — ни одно не «прикрыто» тестом и не стало скрытым пределом.
