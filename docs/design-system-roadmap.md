# Дорожная карта: дизайн-система

**Статус на 2026-09-05: эпик Q закрыт.** База эпика W — W1–W5 — реализована; эпик W закрывается W5 (drag-редактирование дат). Черта «QML стартует после W4» пройдена. Q1 реализован: QML-каркас + пилот лаунчера. Q2a1 реализован: библиотека `nri.components` + лаунчер на ней (эпик Q открыт). План Q2 зафиксирован grill-сессией 2026-09-02: изменения Q2a1, Q2a2, Q2b; шкала и mention-редактирование вынесены в отдельный пункт Q2.5. Q2.5 обсуждена grill-сессией 2026-09-03: состав — гашение долга сохранения (отдельный `fix-silent-dialog-save-debt`) и переезд шкалы в QML (`port-event-timeline-qml-island-q2-5a`); обе половинки реализованы («шкала+долг»), tooltip-шим шкалы выпущен и зафиксирован картой; `MentionTextEdit` с диалогами события и карточки — по-прежнему заблокированный пункт Qx вне порядка. Q3 разделён на два куска: **Q3a реализован** (`port-sheet-list-preset-dialogs-qml-q3a` — список чар-листов и диалог «Создать из пресета…» на QML-островах, widgets-вёрстка удалена без флага); **Q3b реализован** (`port-character-sheet-canvas-qml-q3b` — канвас чар-листа и окна Design/Заполнения на QML-островах, `QGraphicsView`/`QGraphicsProxyWidget`-механика удалена целиком). Заградитель закрытия эпика — канвас (формулировка куска Q3b: «последний кусок, без него эпик Q не закрыт») — снят: **эпик Q закрыт**; финальный инвентарь островов спека `qml-shell` — лаунчер, шкала событий, список чар-листов, «Создать из пресета…», канвас с окнами Design/Заполнения. **Статус 2026-09-05 (вторая grill-сессия): Qx разблокирован, открыт эпик R.** Формат упоминаний `@[Имя](тип:id)` не меняется — QML-редактор возможен двухслойным зеркальным решением (R5), запрет показа сырых маркеров и запрет гибридов сохранены. Куски Q2a2 и Q2b перенесены из «вне закрытого эпика» в инвентарь эпика R (куски R3 и R4): оставшиеся widgets-экраны закрываются цепочкой R1–R7. Хвостовые отметки Qx стали кусками карты: срез инфраструктур тестов → R1, просроченные описания main.py → делаются вместе с mention-стеком в R6/R7.

Два эпика подряд, не параллельно: сначала токены на текущем QtWidgets, потом перенос presentation в QML. QML не стартует, пока W4 не влит; W5 желательно до Q2.

Источник правды для цвета/типа/отступа — один набор semantic tokens. Из него: QSS (мастер) и CSS (HTML игрока D1). Не два независимых скина.

QML как «дизайн-система с нуля» отклонено как первый шаг. Канвас чар-листа (`QGraphicsView`) в эпике W не переписываем.

попавер завершения — **widgets-мост** (второй после поповера «Выбора даты»: QML-Popup обрезался бы границами острова, прецедент Q2.5a); клик по чипу = открыть карточку, каретка внутрь чипа не встаёт (семантика тестов widgets-редактора переносится, Ctrl-обход не вводится); AI-кнопка — кнопка из `nri.components` внутри острова с маркером `aiState`, async остаётся Python-фасадом, текст поля фасад берёт в storage-формате. Приёмка: round-trip формата, семантика попавера (≥2 символа, отмена Esc/Space/backspace-за-`@`, вставка Enter/click), послойное пиксельное совпадение в обеих темах с DPR — пиксельная часть только на готовом R1. **R6** — `event_dialog` на остров; **R7** — `entity_card_dialog` (динамические mention-поля: character — 4, organization/location — 3, item — 2). В R6/R7 внедряется унаследованное от Qx требование: провал сохранения **не закрывает диалог** (значения формы живут на QML-стороне, rollback из Q2.5c + ровно один `QMessageBox.critical`); widgets-вёрстка каждого диалога удаляется в его же куске без флага (прецеденты Q1/Q2.5a/Q3a); просроченные описания main.py (`(with its QGraphicsScene)`, комментарии `sheet_font.py`) снимаются здесь же вместе с mention-стеком (запрет задачи 3.3 «main.py не трогать» больше не действует с началом R6). **Принято и R не меняет (не молчаливый долг):** копирование из mention-поля наружу теряет `тип:id` (plain text); глобальный `LIKE`-поиск матчит сырые маркеры; LLM-промпт получает маркеры как есть.

## Зафиксированные рамки

- **Ценность** — одна палитра на мастере и игроке; потом смена тулкита, не наоборот.
- **W раньше Q.** Полный уход в QML включая канвас — эпик Q, не W.
- **Две поверхности:** десктоп + HTML D1. Телефон/софт-AP берут тот же CSS, что fill.
- **Не аргумент за QML:** текущие timeline и snapshot — список и дерево; «плотный IDE-layout» закрывается токенами и W2.
- **Не в этой карте:** карта мира вместо дерева snapshot; Figma-live preview; сторонний UI-kit.
- **Чар-листы** (A1–P) не открываем заново, кроме Q3 (тот же контракт, другой рендер).
- **Нативный шелл** — каркас окна на весь эпик Q: `QMainWindow`, нативная `QMenuBar` с тумблером темы, `statusBar`, `QSplitter`; все contents внутри — islands. Это не молчаливый долг: системное меню (macOS), ресайз панелей, рамка/Esc диалогов — нативные; полное QML-окно — отдельный архитектурный эпик, не в карте.
- **Системные попапы** `QMessageBox`/`QInputDialog`/`QFileDialog` действуют на все приложение (правило Q1, распространено с лаунчера); тултипы QML-островов — нативный shim-мост, не QML-overlay.
- **Поповеры выше края острова — widgets-мост** (правило grill 2026-09-05): QML-Popup обрезается границами `QQuickWidget`, поэтому любой всплывающий за край острова поповер — widgets-мост с координацией Python-стороной; сейчас это поповер «Выбора даты» (Q2.5a) и попавер завершения упоминаний (R5). QML-Popup не заводим, пока в карте нет решения о всплытии островов выше их краёв.
- **`table_host`** — не chrome для QML: он уже темится теми же токенами через CSS (путь D1), в QML не переносится.
- **`MentionTextEdit` вне Q2, Q2.5 и Q3:** вместе со своими диалогами (`event_dialog`, `entity_card_dialog`) был вынесен в заблокированный Qx (решение grill 2026-09-03: QML не редактирует богатый текст); **разблокирован grill 2026-09-05 без смены формата** — переезжает в R5–R7 двухслойным зеркальным редактором; деградация «показывать сырые маркеры» запрещена и после разблокировки (её снимает зеркальный слой, а не снятие запрета); гибридные формы «QML-остров с widgets-редактором» запрещены — переезжают оба стека одного поля одновременно или никто.
- **Tooltip-шим островов:** прикреплённое свойство в `nri.components` (объявление текста в QML), показывает Python-сторона острова одним системным `QToolTip` (уже темизован общим листом попапов); вводится Q2.5a, переиспользуется Q2b; собственных QML-оверлеев-подсказок не заводим.

## Как работать с куском

1. `/grill-me` этого куска (W1, W2, …).
2. `/opsx-propose` — только этот кусок.
3. `/opsx-apply` после ревью плана.

В `main` вливаем по кускам: в CHANGELOG пометка, если эпик ещё не закрыт.
