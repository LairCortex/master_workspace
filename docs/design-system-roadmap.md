# Дорожная карта: дизайн-система

**Статус на 2026-08-31 (черта зафиксирована grill-сессией):** база эпика W — W1–W3c — влита и принята. Эпик W продолжается и закрывается W5: впереди W4 (просмотр шкалы) и W5 (drag-редактирование дат). QML стартует после W4.

Два эпика подряд, не параллельно: сначала токены на текущем QtWidgets, потом перенос presentation в QML. QML не стартует, пока W4 не влит; W5 желательно до Q2.

Источник правды для цвета/типа/отступа — один набор semantic tokens. Из него: QSS (мастер) и CSS (HTML игрока D1). Не два независимых скина.

QML как «дизайн-система с нуля» отклонено как первый шаг. Канвас чар-листа (`QGraphicsView`) в эпике W не переписываем.

```
W1 → W2 → W3 → W3b → W3c → W4 → W5 → Q1 → Q2 → Q3
```

База W1–W3c влита и принята (черта 2026-08-31). Q1 не начинать, пока **W4** не влит: зум/компрессия/типы/группировка меняют компоновку шкалы, и переносить её в QML дважды незачем. **W5** Q1 не блокирует, но желателен до Q2 — иначе семантику шкалы переносим в QML с неучтённым редактированием. Исторические рамки прошлых срезов («W3 до Q1», «Q1 после W1–W3») выполнены и заменены этой формулировкой.

**W1** (grill закрыт): `app/presentation/theme/tokens.json` — semantic, каждый токен `{light, dark}`; цвет + spacing/radius/type (имена — propose). Генератор Python в памяти при старте и смене темы; QSS/CSS не коммитить. Тема в `~/.nri_manager/ui.json`; default **dark**; нет/битый preference → dark; битые токены → лог + палитра ОС, тумблер no-op. Поверхности: QSS на `centralWidget` + `menuBar` (+ statusbar) и корень **GameLauncherDialog** — не на весь `QMainWindow` (иначе parented-диалоги наследуют скин). Тумблер: меню MainWindow + лаунчер. D1: динамический `/app.css`, `:root` из токенов, `var()` только landing/toolbar/status; бумага листа без theme-var; открытые вкладки не пушим. `tokens.json` в PyInstaller `datas`. Приёмка: смена токена меняет лаунчер, chrome MainWindow и CSS chrome игрока без трёх копий цветов. Тесты: генератор light/dark; round-trip `ui.json`; смена stylesheet; `/app.css` с `:root`; бумага без theme-var; E2E `grab()` + пиксель = hex токена (не golden PNG). Нет каталога контролов, нет QML, нет новой шкалы.

**W2 (влит целиком: W2a + W2b):** тонкие обёртки над QtWidgets, читают токены. Не копировать Material/Fluent. Миграция экранов кусками внутри W2. ~~**Остаток после W1:** все диалоги кроме лаунчера; тултипы (`QToolTip` — top-level попо-ап, chrome-QSS до него не достаёт, нужен app-wide лист); inline hex (`#2d5a88`, LLM green/red, `#888`, …); не заменять title/`setStyleSheet` лаунчера на обёртки в W1.~~ Закрыто W2a+W2b. Канвас и `QGraphicsProxyWidget` полей — вне скоупа (остаётся вне). HTML игрока не дублирует виджеты: только те же токены в CSS.

**W2a (влито; change `add-widget-catalog-chrome-mechanics-w2a`, заархивирован):** механика и каталог — роли через dynamic property `uiRole` (+ модификаторы `uiRoleSize`/`uiRoleItalic`) вместо objectName-селекторов; `app/presentation/theme/catalog.py`: `attach_theme(root)` (одна точка подключения экрана), `set_role`, фабрики `title`/`hint`; роли title/hint/field/list/card/status-ok/status-error; app-wide лист только для top-level попапов (`QToolTip`, `QMenu`, combo-лист, календарь, `_MentionPopup` + `MentionPopupListView`); +3 обязательных токена; hover/pressed — производная accent (`accent_rgba`). Пилоты: `MonthSettingsDialog`, `WorldSnapshotWidget`; e2e AI-кнопки проверяют маркер `aiState`.

**W2b (влито — `4810755` в main; change `migrate-remaining-chrome-w2b`, заархивировать PR'ом):** миграция остатка ~12 экранов/виджетов — обычные диалоги (llm_setup status-роли, event/xlsx mono-токен, image_viewer/entity_card card-роль, table_host), панели главного окна (detail_panel rating-концы из `color.rating.low/high`, timeline/search_bar list-роли и border-токен, `QSplitter::handle`, doc-viewer mono), character_sheet-диалоги (chrome форм, канвас и proxy-поля — не тронуты, пиксельный regression), mention inline-HTML и AI-кнопка — производные `color.accent` (`compiler.mention_style`, `accent_rgba`) + live-retheme через `attach_theme(on_retheme=…)` (панели) / `ThemeRuntime.add_listener` (`MentionTextEdit`) с сохранением каретки и чистоты `document().isModified()`; введены `font.family.mono`, `color.rating.low/high` (namespace обязателен: каждый ключ — CSS var web-игрока); оф-скин rating-карточки теряют тинт полностью (D7: выдуманный серый конец градиента не рисуется); инвариант зачистки — `tests/presentation/test_no_chrome_hex.py` (ни hex, ни `palette()` в chrome-коде кроме канвас-слоя). Accent-slip выделений — целевой вид, `color.selection` не заведён. Приёмка specs: смена `color.accent` меняет mention, AI-active, выделения и «Показать» без правок экранов (автотест, обе темы).

**W3 (влито — `8e8c2e6`):** Gantt-like дорожки событий — реализовано как `TimelineCanvas` (`QWidget` + `QPainter`) с чистым ядром геометрии `track_layout.py` (без Qt): greedy first-fit упаковка по `(start, id)`, линейная шкала на весь отфильтрованный диапазон, ось по границам игровых месяцев, адаптивные дорожки с внутренним вертикальным скроллом, идущие события со скосом, tooltip при нехватке места; стили только из токенов W1/W2 с live-retheme (оф-скин — только именованные Qt-глобалы, ни одного собственного hex). Тики оси — строго границы месяцев (старт диапазона подписью не считается); колесо мыши крутит одну строку дорожки за нотч; смена набора событий отматывает скролл в начало, выбор при этом чистится синхронно в канвасе, VM и панели деталей. Не дерево snapshot и не «красивее список». Snapshot остаётся деревом, пока не будет отдельного куска (его нет на этой карте). **Ранее «вне карты»:** зум, сжатие пустых периодов, типы/цвета событий, дорожки по сущностям — распланированы в W4; drag-редактирование дат — распланировано в W5. Молчаливого долга нет: у каждого пункта есть стадия на этой карте.

**W3b (влито — `289bfa4`; дизайн зафиксирован grill-сессией 2026-08-31; change `make-event-timeline-vertical-w3b`):** вертикальный `QListWidget` + кастомный delegate, id-контракт W3 (`event_selected(id)`, `select_event_by_id`, `scroll_to`) сохраняется. Каждые сутки видимого диапазона — ровно одна позиция: строка событий дня или пустая строка-заглушка высотой с событие (без схлопывания — решение по референсу); сортировка по `start`, затем `id`; событие — строка `start — end · имя` в игровой форме дат (открытый конец — `—`). Слева рейка дат: тик на день, подпись месяца (короткая форма, поворот снизу вверх) при входе в месяц, скобка-привязка против дней многодневного события; шкала декоративна. Липкая дата сверху вьюпорта (полная игровая дата верхней видимой строки, роль `title`, оверлеем; скрыта при пустом списке). Фильтр вместо полей+apply/clear: один чип («Все даты» / `Дд Мес ГГГГ — Дд Мес ГГГГ` ▾) с поповером из мини-календарей (custom months), live-apply при выборе финиша, сброс внутри поповера; «+»-меню без изменений. Навигация по пустым дням: кнопки «к пред. событию»/«к след. событию» во втором ряду шапки + `Alt+Up/Alt+Down` (свободны). Поиск, мутации и сброс выбора фильтром — семантика W3 без изменений. `track_layout.py` и его юниты удаляются, пиксельный tok-тест переписывается на delegate.

**W3c (влито — `eb7640b`; дизайн зафиксирован grill-сессией 2026-08-31; change `refine-event-timeline-scale-w3c`):** декоративная рейка W3b стала интерактивной зоной шкалы: клик-прыжок (день под нажатием — верхним рядом под липкой датой, якорь — первый ряд дня, пустые дни валидны, выбор/`_selected_id`/id-сигналы не тронуты), follow-дата (sticky-оверлей показывает день под курсором в рейке и всё время drag'а, на уход — возврат к верхнему ряду), drag диапазона (порог `DRAG_START_THRESHOLD_PX = 4`, значим только y с clamp к видимому, wash-полоса из производной `color.accent` c альфой 0.35, ровно один emit на отпускании через chip-путь `_on_filter_range`, однодневный drag = клик, dblclick глушится, сброс — только поповер). ## Зафиксированные рамки

- **Ценность** — одна палитра на мастере и игроке; потом смена тулкита, не наоборот.
- **W раньше Q.** Полный уход в QML включая канвас — эпик Q, не W.
- **Две поверхности:** десктоп + HTML D1. Телефон/софт-AP берут тот же CSS, что fill.
- **Не аргумент за QML:** текущие timeline и snapshot — список и дерево; «плотный IDE-layout» закрывается токенами и W2.
- **Не в этой карте:** карта мира вместо дерева snapshot; Figma-live preview; сторонний UI-kit.
- **Чар-листы** (A1–P) не открываем заново, кроме Q3 (тот же контракт, другой рендер).

## Как работать с куском

1. `/grill-me` этого куска (W1, W2, …).
2. `/opsx-propose` — только этот кусок.
3. `/opsx-apply` после ревью плана.

В `main` вливаем по кускам: в CHANGELOG пометка, если эпик ещё не закрыт.
