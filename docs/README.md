# Master Workspace

Приложение для мастера настольных ролевых игр (НРИ): в нём ведутся сценарий, мир и всё, что к нему относится — события по датам, персонажи, организации, локации, предметы, а также листы персонажей. Всё лежит в папке игры на вашем компьютере и никуда не отправляется: работает без интернета, интернет нужен только если вы сами захотите пользоваться AI-подсказками.

Документы: [история изменений](CHANGELOG.md) · [листы персонажей (план)](character-sheets-roadmap.md) · [оформление (план)](design-system-roadmap.md) · [календарь (план)](custom-calendar-roadmap.md)

## Для чего это

Мир кампании обычно живёт в блокнотах, таблицах и переписке, и на подготовку к игре уходит время, которое хочется потратить на саму игру. Здесь всё в одном месте:

- события выстроены на шкалу времени — видно, что происходит в мире в любой день кампании
- персонажи, организации, локации и предметы связаны друг с другом, и в описаниях можно ссылаться на них прямо текстом
- мир на выбранную дату собирается в один обзор — кто жив, что активно, где кто находится
- листы персонажей делаются один раз и заполняются самими игроками за общим столом
- текстовые поля можно дописать через AI, если он у вас есть

## Где взять

Готовые сборки для трёх систем лежат во вкладке **Releases** на странице репозитория: папка «Master Workspace.app» для macOS, программа `.exe` для Windows и бинарник для Linux. Устанавливать ничего не нужно — папку с файлами копируют на компьютер и запускают. Название под значком приложения — Master Workspace. Игры создаются при первом запуске в папке `games/` рядом с приложением: у каждой игры своя папка, в ней база данных и картинки.

**macOS:** при первом запуске система может запретить открытие от неизвестного разработчика. Разрешите запуск в **Системных настройках → Конфиденциальность и безопасность** либо снимите признак карантина:

```bash
xattr -cr "/путь/к/Master Workspace.app"
```

Можно и запустить через **Control + клик** по значку приложения.

**Windows и Linux** запускаются сразу после распаковки.

Требования к компьютеру: macOS, Windows или Linux с графической оболочкой; отдельных библиотек и Python в собранной версии не требуется.

## Возможности

### Игры

- несколько игр одновременно, каждая в своей папке, переключение без перезапуска (**Файл → Сменить игру**)
- создание, открытие и удаление игры из окна выбора при запуске
- перенос игры между компьютерами: **Файл → Экспорт игры…** собирает всё в один архив `.nri`, импорт — кнопкой **«Импорт»** в окне выбора

### Шкала времени

- плоский список событий: `начало — конец · название`, даты в игровом календаре, слева цветная метка типа события
- вторая строка — краткое описание события (характеристики, а если их нет — предыстория)
- событие без последней даты помечается знаком бесконечности и считается идущим до конца кампании
- фильтр по диапазону дат — **«Выбор даты»** на двух календарях, у каждого со своим флажком эры «до н.э.»; сбрасывается кнопкой «Сбросить»
- кнопка **«+»**: создать событие или отдельную сущность (персонажа, локацию, организацию, предмет) и открыть настройку типов событий
- клик по строке показывает содержимое в панели рядом, двойной клик открывает карточку события, в ней же меняются даты

### Сущности мира

- четыре вида сущностей: персонажи, организации, локации, предметы. Общее для всех — название, даты, описание, предыстория и ссылка на музыкальную тему
- «личность» есть только у персонажей, «задачи» — у персонажей, организаций и локаций
- изображение (портрет, карта локации, герб организации) берётся из файла (PNG, JPG, BMP, GIF, WebP), сохраняется в папке игры и показывается в карточке и в списках
- важность от 1 до 20 задаётся стрелками в карточке и подсвечивается цветом: от серого к красному
- связи между сущностями: привязать уже существующих, создать новых прямо из карточки, отвязать (сама сущность при этом остаётся)

### Ссылки в тексте

В любом многострочном поле достаточно ввести `@` и первые две буквы имени — появится список найденных сущностей. После выбора имя становится кликабельной ссылкой: нажатие открывает карточку. Ссылки работают между всеми видами сущностей, включая события.

### Типы событий

Свои типы (например «Завязка», «Погоня», «Свидание») с названием и цветом из готовой палитры. Цвет виден на шкале времени, в карточке и в обзоре мира. Изменения применяются сразу, без кнопки «Сохранить».

### Обзор мира

Панель, которая по выбранной дате показывает, что активно в этот день: события, а внутри них — локации, организации, персонажи и предметы. Каждая сущность показывается один раз, цвет отражает важность, наведение мыши даёт краткое описание, двойной клик открывает карточку. Внизу — счётчики, кнопка **«Показать всё»** снимает привязку к дате.

### Поиск

Строка сверху ищет по всем сущностям сразу: по названию, характеристикам и предыстории, без учёта регистра. Результаты группируются по видам; переход по результату открывает карточку, а для события — выделяет его на шкале времени.

### Календарь игры

Календарь мира можно сделать своим: своё число месяцев с собственными именами и длиной каждого, своя длина недели и имена её дней, а также вставные дни. Встроенный пресет «Стандартный» — привычные 12 григорианских месяцев и семидневная неделя. Настройка хранится отдельно в каждой игре и переезжает вместе с ней при экспорте и копировании папки.

- Вход — **Настройки → Календарь…**, доступен в любой игре. В новой игре настройка предлагается сама при первом запуске, до показа главного окна; закрытая без выбора кастомного календаря игра остаётся на «Стандартном». Игры, созданные до появления настройки, молча живут на «Стандартном», и мастер им не навязывается; заданные в прежних версиях названия месяцев переносятся автоматически. Имена календаря видны на шкале времени, в деталях, в обзоре мира, в календарях выбора даты и в поиске.
- Мастер ведёт по порядку: неделя → месяцы → вставные дни → предпросмотр, справа на каждом экране — живая сетка будущего календаря. Пройденные ступени сохраняются сразу: можно выйти, ничего не применив, и при следующем входе продолжить с того же места.
- Вставной день — это не название поверх обычного дня и не праздник, а отдельный добавочный день года: он прикрепляется после выбранного месяца, повторяется каждый год и не участвует в недельном цикле — имена дней недели вокруг него не сдвигаются. Ставить на него события можно как на обычный день; в подписи он показывается своим именем без номера дня, а в сетке — отдельной плашкой после месяца-хозяина.
- Правка календаря в середине игры безопасна: переименование месяцев и дней и смена недели даты не двигают. Укорочение или удаление месяца — другое дело: часть дат записей может оказаться невалидной. Тогда перед применением открывается отчёт «Перенос дат» со списком затронутых записей и полей и с прежней и новой датой; невалидные даты переносятся на последний валидный день месяца, а отказ от переноса ничего не меняет, только возвращает к настройке.
- Применённый календарь интерфейс подхватывает сразу, без перезапуска.

Годы обеих эр поддерживаются от 1 до 9999, нулевого года нет. Эра «до н.э.» остаётся зеркалом игрового календаря и не настраивается; год до нашей эры показывается с суффиксом: «44 г. до н.э.». В календарях выбора даты эра включается флажком «до н.э.», при этом числа выбранной даты не меняются. Дата и начало, и конец любой сущности получают эру независимо — событие может начинаться до нашей эры и заканчиваться в нашей, порядок на шкале и в фильтрах при этом остаётся хронологическим: любая дата до н.э. раньше любой даты н.э.

### Листы персонажей

- **шаблон** рисуется на холсте как лист бумаги: поля разных видов (текст, числа, флажки, списки, картинки), страницы, книжная или альбомная ориентация, зум, перенос и изменение размера полей
- **готовые заготовки** для Fate Core и Mörk Borg — свои макеты с русскими подписями
- **заполненный лист** игрока — отдельный экземпляр шаблона, который можно привязать к персонажу из сценария
- **вывод в PDF**: листы печатаются, интерактивные поля (текст, флажки, списки, числа) можно заполнять прямо в PDF
- меню **«Чар-листы → Чар-листы…»** — список шаблонов и заполненных листов, создание, переименование и удаление

### Стол игрока

Меню **«Чар-листы → Стол…»** открывает стол в местной сети: выбирается порт, лист закрепляется за игроком, на экране появляются адрес и квадратный код для быстрого открытия. Игрок открывает свой лист в любом браузере на телефоне или ноутбуке — по адресу, четырехзначному коду доступа и своему имени. Всё, что игрок пишет в листе, сразу сохраняется в игре, мастер видит те же цифры и строки. Пока стол открыт, значения меняет только игрок; выход игрока освобождает лист, кнопка «Выгнать» снимает его принудительно.

### AI-подсказки

Кнопка с искрой есть у каждого текстового поля: поле дописывается или заполняется заново по описанию мира и вашим указаниям. Работает с любым внешним сервисом, говорящим на языке OpenAI — облачным (OpenAI, OpenRouter, Groq) или запущенным на своём компьютере (Ollama, vLLM, LM Studio, llama.cpp). Ключ доступа не обязателен: локальные сервисы работают без него.

- настройка — **LLM → Настройка LLM…**: адрес, модель, ключ, проверка соединения, описание мира и отдельные указания для каждого поля у каждого вида сущности
- адрес и ключ хранятся один раз для всех игр в `~/.nri_manager/llm_config.json`, доступ к файлу — только у вашего пользователя
- описания мира и указания полей — свои в каждой игре
- заказанные тексты собираются в очередь и обрабатываются по очереди, поле на время генерации блокируется
- при недоступности сервиса приложение объясняет ошибку по-русски; сетевые сбои и временные отказы повторяются сами

### Оформление

Тёмная и светлая темы: переключатель в окне выбора игры и **Настройки → Светлая тема**. Выбор сохраняется между запусками и применяется сразу, без перезапуска.

### Загрузка данных из таблиц

**Настройки → Импорт … из .xlsx…** — события, персонажи, локации, организации и предметы можно завести разом, из обычной электронной таблицы. Первая строка — заголовки; порядок столбцов произвольный, строки без обязательных полей пропускаются с предупреждением, в конце показывается отчёт «создано / пропущено».

#### Общие правила

Дата — в виде `2026-09-06` текстом или как обычная дата таблицы (это наша эра). Дату до нашей эры можно записать текстом `5 марта 44 г. до н.э.` или знаковым ISO `-0044-03-05`; неразбираемая дата начала помечает строку проблемой и не импортируется. Изображение задаётся путём к файлу (относительным к файлу таблицы или полным), поддерживаются PNG, JPG, BMP, GIF, WebP; вместо `image` можно написать `изображение`.

| Столбец | Обязательный | Есть у | Что содержит |
|---|---|---|---|
| `name` | да | все | название |
| `start_date` | да | все | дата появления |
| `end_date` | нет | все | дата исчезновения |
| `characteristics` | нет | все | описание |
| `backstory` | нет | все | предыстория |
| `tasks` | нет | персонажи, локации, организации | задачи |
| `personality` | нет | персонажи | личность |
| `music_url` | нет | все | ссылка на музыкальную тему |
| `image` | нет | персонажи, локации, организации | путь к картинке |

### Обязательные поля

Любой сущности нужны описание (характеристики и/или предыстория) и дата появления. Дату исчезновения можно не указывать: флажок **«Бессрочно»** прячет её, а на шкале времени появляется пометка о бесконечном конце.

### Прочее

- **О приложении → Документация / Changelog** — этот текст и история изменений прямо в окне приложения
- **О приложении → Сохранять логи в файл** — переключатель записи журнала, если нужно разобраться с неполадкой
- сборку для каждой системы делают на такой же системе; тесты, проверка полноты покрытия и сборки для трёх систем запускаются автоматически при каждом изменении

## Как устроено приложение

Нижележащее устройство важно только если вы читаете или меняете код; пользовательски значимо лишь то, что игра — это папка с базой данных SQLite и картинками, а настройки интерфейса и доступа к AI лежат в вашем домашнем каталоге.

| Слой | Что делает |
|---|---|
| Экраны и модель представления | окна, шкала времени, панели, диалоги (Qt + QML), в них нет правил работы с данными |
| Службы | порядок действий: создание события, поиск, связь сущностей, генерация текста, стол игрока |
| Хранилище | таблицы игры, картинки, настройки игры, обращения к AI и сетевой клиент |

Меню главного окна:

| Меню | Пункты |
|---|---|
| **Файл** | Сменить игру · Экспорт игры… |
| **Чар-листы** | Чар-листы… · Стол… |
| **Настройки** | Светлая тема · Календарь… · Импорт событий, персонажей, локаций, организаций, предметов из .xlsx… |
| **LLM** | Настройка LLM… |
| **О приложении** | Документация · Changelog · Сохранять логи в файл |

## Стек технологий

| Компонент | Технология |
|---|---|
| Интерфейс | PySide6 (Qt 6), часть экранов на QML |
| Хранилище | SQLite (SQLAlchemy 2.0 в асинхронном доступе), своя база на каждую игру |
| Асинхронность | asyncio + qasync |
| Картинки | файлы в папке игры, для списков готовятся уменьшенные копии |
| Стол игрока | локальный сервер + страница в браузере |
| PDF | reportlab |
| AI | httpx, обращения к сервису с интерфейсом OpenAI |
| Сборка | PyInstaller, значок приложения в `app/resources/` |
| Проверки | pytest, pytest-qt; сборочные задачи — в GitHub Actions для macOS, Windows и Linux |
| Устройство кода | модель–представление, ручная передача зависимостей |

Разработчикам: как собирать приложение, запускать тесты и вносить изменения в схему — в `AGENTS.md`, история изменений — в `CHANGELOG.md`.
