# Дорожная карта: чар-листы

Эпик не входит в пользовательский релиз, пока нет **D1**. D1 (стол в LAN) — change `add-character-sheet-d1`. После D1 отдельно: телефон открывает тот же HTML; софт-AP. В `main` вливаем по кускам: меню видно, в CHANGELOG пометка «незавершено».

NRI-0007 (канвас + PDF скоупом) не воскрешаем.

Текущие срезы (порядок apply): [`add-character-sheet-a1`](../openspec/changes/add-character-sheet-a1/), [`add-character-sheet-a-playable`](../openspec/changes/add-character-sheet-a-playable/), [`add-character-sheet-a-editor`](../openspec/changes/add-character-sheet-a-editor/), [`add-character-sheet-b`](../openspec/changes/add-character-sheet-b/), [`add-character-sheet-c`](../openspec/changes/add-character-sheet-c/), [`add-character-sheet-d1`](../openspec/changes/add-character-sheet-d1/).

## Куски (порядок)

| # | Кусок | Что это | Статус |
|---|---|---|---|
| 1 | **A1** | Тонкий канвас: 1 книжная A4, 3 типа (подпись / однострочное / многострочное), сохранить в `game.db` | влито — `add-character-sheet-a1` |
| 2 | **A-playable** | Страницы без лимита (лента как Word + рейка) + каталог типов + тесты на каждый тип. Не удобство редактора | влито — `add-character-sheet-a-playable` |
| 3 | **A-editor** | Undo, мультиселект, snap, z-order, duplicate/paste. Последний редактор эпика | готово — план `add-character-sheet-a-editor` |
| 4 | **B** | Экземпляр в игре; Fill на канвасе; до хоста заполняет мастер | готово — план `add-character-sheet-b` |
| 5 | **C** | Движок пресетов + Fate Core + Mörk Borg (свои макеты, RU, 1 страница) | готово — план `add-character-sheet-c` |
| 6 | **D1** | Хост в LAN: браузер игрока по HTTP, мастер смотрит Qt | готово — план `add-character-sheet-d1` |
| 7 | **P** | PDF, не основной флоу. Можно последним, после экземпляра | не начат |

После D1, отдельными кусками: телефон открывает **тот же HTML**; софт-AP («мастер раздаёт Wi‑Fi»). Десктоп-приложение как клиент игрока в D1 нет.

```
A1 → A-playable → A-editor → B → C → D1
                                  ↘ P когда угодно, хоть после D1
```

**A-playable, каталог типов (закрытый):** A1 (label / text / textarea) + чекбокс, число, выпадающий список, картинка/портрет (ImageStore), декоративная рамка и линия. Нет: таблица, формулы, repeating, rich text, радиогруппы, часы/dots как отдельные типы.

**A-playable, страницы:** без потолка; последнюю удалить нельзя; если на странице поля — подтверждение. Канвас — лента A4 столбиком (как Word) + рейка (имя, +, удалить, ↑↓). Колесо = скролл, Ctrl+колесо = зум (A1 «колесо = зум» здесь меняется). Вписать **ширину** страницы. Зажим по странице; перетаскивание через зазор переносит поле на другой лист. Ориентация одна на шаблон; книжная/альбомная — не влезшее зажимается, не масштабируется.

**A-playable, схема:** `schema_version = 2`; чтение v1 без потери; неизвестный тип — отказ открыть. Число дробное, min/max необязательны, `,` → `.`. Приёмка типа — набор тестов (постановка, select, move, resize+зажим, свойства, round-trip, книжная и альбом; картинка + ImageStore ref).

**A-editor:** меню «Правка» + StandardKey (один UI на 3 ОС); undo снапшот×50; snap 4 pt выкл по умолчанию; z-order только крайние; рамка = тот же набор, что Shift-набор (рамка без Shift заменяет, Shift+рамка добавляет); schema 2. Не в эпике: JSON шаблона, выравнивание, дубль шаблона, группы. **A (редактор эпика) закрыт** — дальше B.

**B:** своя сущность (имя уникально в игре, `template_id`, карта `{field_id: значение}`, необязательный уникальный FK на Character). Лейаут всегда из сохранённого шаблона. Новое поле шаблона → default; существующий ключ шаблон не перетирает; сиротский id хранится, не рисуется. Шаблон с экземплярами не удалить, шаблон у листа не сменить. Fill: тот же канвас, ввод кликом; без палитры/snap/z-order/duplicate/правок страниц; рейка только навигация. Одно окно Fill + одно Design. Save шаблона → Fill перечитывает лейаут. Undo Fill — снапшоты значений. Удаление персонажа — SET NULL.

**C:** вкладка «Шаблоны» → «Создать из пресета…»; в диалоге только Fate Core и Mörk Borg; спросить имя (подстановка имени пресета) → INSERT снимка в `game.db` → Design. Макеты **свои**, не Anima и не официальный PDF. Одна книжная A4, RU, пустой портрет, без бандл-арта. Лицензия на листе и в диалоге. После копии — обычный шаблон; обновление приложения его не переписывает.

**C, TODO на карте (не этот срез):**
- виджеты: таблица, радио, repeating (новый кусок редактора);
- контент C2+: D&D 24, VtM 5e, Daggerheart, Shadowdark, VtM V20, Cyberpunk 2020, Mothership (после письма TKG), DnD 5.14e NPC — свои макеты, одностраничный минимум.

**D1:** меню «Стол». Посадка экземпляров → HTTP в LAN (порт 7845, можно сменить до старта) → URL+QR+PIN. Игрок в браузере: PIN, уникальное имя, свободный лист. Fill экземпляра B, HTML по геометрии, лента страниц, без undo. Фиксация поля сразу в `game.db`. Картинки → ImageStore мастера. Мастер: список + один Qt read-only; значения сам не пишет. Один сокет на лист; повторный вход тем же именем вытесняет. Стоп: клиенты отрезаны, значения в БД. Save шаблона обновляет веб. Не интернет, не HTTPS, не аккаунты.

## Зафиксированные рамки

- **Ценность для пользователя** — вся цепочка (чертёж + хранение заполненного + раздача). Первый *срез реализации* — A1.
- **Шаблон** живёт в `game.db` игры, не в глобальной библиотеке. Пресет (C) копируется в игру.
- **A1** — чертёж, не заполнение персонажа. Страница A4, pt, origin сверху, зажим в край.
- **Редактор эпика закрывается в три OpenSpec:** A1 → A-playable → A-editor. Дальше B. Anima-complete (JSON, направляющие, группы) в этот эпик не входит.
- **B** — отдельное изменение *перед* D, даже если до хоста пишет только мастер.
- **D1** — браузер в существующей LAN, не интернет и не облачные аккаунты. Идентичность — имя за стол + PIN. Десктоп игрока в D1 нет; телефон позже открывает тот же HTML.
- **C** не входит в приёмку A. Макеты свои; Anima/официальные PDF не копируем. В C — только Fate Core (CC BY) и Mörk Borg (3PP).
- **P** не обязан стыковаться с хостом; пустой fillable PDF как способ «раздать игрокам» в A не делаем.

## Как работать с куском

1. `/grill-me` этого куска (A-playable, A-editor, B, …).
2. `/opsx-propose` — только этот кусок.
3. `/opsx-apply` после ревью плана.

A1 уже прошёл шаги 1–2. B, C и D1 — тоже (`add-character-sheet-b`, `add-character-sheet-c`, `add-character-sheet-d1`).
